## v1.0.0 milestone

- [x] 줄 수가 1000 을 넘는 파일로 tab 을 옮기면 번호 칸이 한 칸 늘어 본문 시작 칸이 밀린다. vim 도 같아서 그대로 둔다 — vim 9.1 로 재보니 번호 칸 폭이 `max('numberwidth'(기본 4), 전체 줄 수 자릿수 + 1)` 이고 window 마다 따로여서, 999 줄까지 4 칸이고 1000 줄에서 5 칸으로 늘며 tab 을 옮기면 본문 시작 칸이 밀린다. 최소 자릿수 3 도 vim 의 기본값과 같은 자리다 (ADR-0007)
- [x] 아주 큰 디렉터리를 펼치면 한 키가 멈추던 것을 고친다. 디렉터리 읽기를 백그라운드 작업으로 내리고 **끝까지 읽어 다 보여준다** — 읽는 동안은 자식 자리에 `… 읽는 중` 한 행이다. `File.ReadDir(n)` 으로 끊는 것은 정렬을 포기하는 것이라(이름순은 `os.ReadDir` 만 준다) 쓰지 않았다. 표시 상한 1000 개 + `… N개 더` 로 먼저 만들었다가 되돌렸다 — 재보니 자식 5 만 개에서 키 한 번이 1.2ms(20 만 개 4.5ms) 라 상한이 사는 값이 사람에게 닿지 않고, 대신 이름순 뒤쪽의 파일과 디렉터리가 트리에서 사라졌다 (ADR-0025, ADR-0032)
	- [x] `git check-ignore` 도 같은 작업 안에서 돈다. 펼치는 길에 동기 호출이 하나도 남지 않았다. 재보니 경로 100 개에 20ms 라 작은 디렉터리에서도 매번 물던 값이다 (ADR-0032)
	- [x] reveal 도 비동기다. 갈 자리를 들고 한 층씩 읽어 내려가고, 이어서 미는 자리는 `handleJob` 한 곳이다. reveal 을 부르는 함수들(`nextTab`·`openTab`·`toggleTree`·`clickTabline` 등) 이 Cmd 를 돌려준다. 트리 첫 읽기는 normal mode 의 `Init` 이 낸다 (ADR-0032)
- [x] tabline 이 편집 영역 너비를 넘칠 때 활성 tab 이 잘려서 안 보이던 것을 고친다. 이름을 줄이지 않고 활성 tab 이 온전히 보이는 자리까지 가로로 민다. 나간 만큼만 밀어서 `gt` 한 번에 한 tab 씩 움직이고, 자리가 남으면 도로 당긴다. 가려진 개수는 양끝의 `<n`·`n>` 이 알리고 그것을 누르면 활성 tab 은 그대로 두고 그 방향으로 민다. 반쯤 걸친 tab 은 그리지 않는다 (ADR-0029)
- [x] `:w <파일>` 을 넣는다. 이름 있는 tab 에서는 사본만 쓰고 이름·dirty 는 그대로다(vim 과 같다). 이름 없는 tab 만 그 이름을 받아서 `:tabnew` 로 만든 tab 을 저장할 길이 생겼다. 이미 있는 파일은 막고 `:w!` 로 덮어쓴다(vim 의 E13). 보고 있는 파일을 주면 제자리 저장이고, 이름을 받으려는 파일이 다른 tab 에 열려 있으면 막는다 (ADR-0024)
- [x] CLI 인자로 같은 파일을 두 번 주어도(`zn a.txt a.txt`) tab 은 하나다. `openBuffers` 가 경로를 정규화해서 걸러 낸다. 표기가 달라도(`a.txt` 와 `./a.txt`) 같은 파일이면 한 번만 연다
- [x] tab 문자와 space 를 구분해서 보여준다. tab 은 `»`(U+00BB), space 는 `⋅`(U+22C5) 이고 흐린 색(240) 이다. 줄 앞 들여쓰기와 줄 끝 공백에만 찍는다 — 줄 가운데까지 찍으면 산문이 점으로 뒤덮인다. 항상 켜져 있다. 검색 강조와 겹쳐도 강조가 끊기지 않도록 행을 조각으로 나눠 조각마다 style 을 한 번씩 입힌다 (ADR-0020)
- [x] 공백 마커의 폭이 확실한지 확인한다. `»`(U+00BB) 는 Neutral 이라 그대로 두고, Ambiguous 인 space 마커 `·`(U+00B7) 만 `⋅`(U+22C5 DOT OPERATOR) 로 바꿨다. 터미널의 "ambiguous 를 2 칸으로" 설정은 Ambiguous 에만 걸린다 (ADR-0020)
- [x] 비동기 작업 지원. 작업은 goroutine 에서 돌며 조각을 채널로 밀고, 조각 하나를 msg 로 바꾸는 `tea.Cmd` 를 받을 때마다 다시 발행해 고리를 잇는다. 진행률만 실행기가 알고 결과를 어디에 어떻게 넣을지는 작업이 보낸 `apply` 가 정한다. mode 마다 `case jobProgressMsg, jobDoneMsg:` 한 자리를 두고 공용 처리로 넘긴다 — 하는 일은 한 곳에 모이고 어떤 msg 를 받는지는 mode 에 보인다 (ADR-0025)
	- [x] command palette 의 파일 찾기를 위한 인덱싱. `ctrl+p` 를 누를 때 시작하고 목록은 차는 대로 붓는다. 파일 십오만 개짜리 디렉터리에서도 팔레트가 즉시 뜬다 (ADR-0011, ADR-0025)

	- [x] 작업 관리자를 넣는다. `:jobs`(팔레트의 「작업 목록」) 으로 도는 것과 최근에 끝난 것 스무 개를 보고, `x` 로 취소한다. 작업마다 ctx 를 나눠 주어서 `git ls-files` 프로세스까지 끊기고, 편집기를 끝내면 도는 것이 전부 정리된다. 실패는 statusBar 아래 줄이 알린다 (ADR-0027)

	- [x] `:jobs` 가 편집 화면처럼 보이던 것을 고친다. tabline·sidebar 까지 덮는 전체 화면으로 그리고 맨 위에 제목줄을 둔다. statusBar 만 남기되 트리가 없는 것으로 치고 그린다. 키 안내는 statusBar 안이 아니라 그 바로 위 줄에 흐린 글씨로 둔다 (ADR-0027)

- [x] `ctrl+z` 로 셸에 내려간다(suspend). normal 과 트리에서만 받고, 종료가 아니라 멈춤이라 저장하지 않은 변경을 묻지 않는다. `fg` 로 올라오면 보고 있는 tab 하나가 밖에서 바뀌었는지 보고 알리기만 한다 — 가져오는 것은 `:e` 다 (ADR-0023)
