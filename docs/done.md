
## v1.0.0 milestone

- [x] 줄 수가 1000 을 넘는 파일로 tab 을 옮기면 번호 칸이 한 칸 늘어 본문 시작 칸이 밀린다. vim 도 같아서 그대로 둔다 — vim 9.1 로 재보니 번호 칸 폭이 `max('numberwidth'(기본 4), 전체 줄 수 자릿수 + 1)` 이고 window 마다 따로여서, 999 줄까지 4 칸이고 1000 줄에서 5 칸으로 늘며 tab 을 옮기면 본문 시작 칸이 밀린다. 최소 자릿수 3 도 vim 의 기본값과 같다. (ADR-0007)
- [x] 아주 큰 디렉터리를 펼치면 한 키가 멈추던 것을 고친다.
	- 디렉터리 읽기를 백그라운드 작업으로 내리고 **끝까지 읽어 다 보여준다**
	- 읽는 동안은 자식 자리에 `… 읽는 중` 한 행이다. `File.ReadDir(n)` 으로 끊는 것은 정렬을 포기하는 것이라(이름순은 `os.ReadDir` 만 준다) 쓰지 않았다(ADR-0025, ADR-0032).
- [x] `git check-ignore` 도 같은 작업 안에서 돈다. 펼치는 길에 동기 호출이 하나도 남지 않았다. 재보니 경로 100 개에 20ms 라 작은 디렉터리에서도 매번 물던 값이다 (ADR-0032)
- [x] reveal 도 비동기다. 갈 자리를 들고 한 층씩 읽어 내려가고, 이어서 미는 자리는 `handleJob` 한 곳이다. reveal 을 부르는 함수들(`nextTab`·`openTab`·`toggleTree`·`clickTabline` 등) 이 Cmd 를 돌려준다. 트리 첫 읽기는 normal mode 의 `Init` 이 낸다 (ADR-0032)
- [x] tabline 이 편집 영역 너비를 넘칠 때 활성 tab 이 잘려서 안 보이던 것을 고친다.
	- 이름을 줄이지 않고 활성 tab 이 온전히 보이는 자리까지 가로로 민다. 나간 만큼만 밀어서 `gt` 한 번에 한 tab 씩 움직이고, 자리가 남으면 도로 당긴다.
	- 가려진 개수는 양끝의 `<n`·`n>` 이 알리고 그것을 누르면 활성 tab 은 그대로 두고 그 방향으로 민다.
	- 반쯤 걸친 tab 은 그리지 않는다 (ADR-0029)
- [x] 오른쪽 가려짐 표시 `n>` 이 tab 이름 길이 따라 옮겨 다니던 것을 고친다. 왼쪽 `<n` 처럼 줄 끝에 고정하고, 마지막 tab 과 표시 사이에 남는 잘린 tab 자리는 점으로 채운다. 점은 눌러도 아무 일도 없다 (ADR-0029)
- [x] `:w <파일>` 을 넣는다. 이름 있는 tab 에서는 사본만 쓰고 이름·dirty 는 그대로다(vim 과 같다).
	- 이름 없는 tab 만 그 이름을 받아서 `:tabnew` 로 만든 tab 을 저장할수 있다.
	- 이미 있는 파일은 막고 `:w!` 로 덮어쓴다(vim 의 E13).
	- 보고 있는 파일을 주면 제자리 저장이고, 이름을 받으려는 파일이 다른 tab 에 열려 있으면 막는다 (ADR-0024)
- [x] CLI 인자로 같은 파일을 두 번 주어도(`zn a.txt a.txt`) tab 은 하나다.
	-  `openBuffers` 가 경로를 정규화해서 걸러 낸다.
	- 표기가 달라도(`a.txt` 와 `./a.txt`) 같은 파일이면 한 번만 연다
- [x] tab 문자와 space 를 구분해서 보여준다.
	- tab 은 `»`(U+00BB), space 는 `⋅`(U+22C5) 이고 흐린 색(240) 이다.
	- 줄 앞 들여쓰기와 줄 끝 공백에만 찍는다
	- 줄 가운데까지 찍으면 산문이 점으로 뒤덮인다.
	- 항상 켜져 있다.
	- 검색 강조와 겹쳐도 강조가 끊기지 않도록 행을 조각으로 나눠 조각마다 style 을 한 번씩 입힌다 (ADR-0020)
- [x] 공백 마커의 폭이 확실한지 확인한다. `»`(U+00BB) 는 Neutral 이라 그대로 두고, Ambiguous 인 space 마커 `·`(U+00B7) 만 `⋅`(U+22C5 DOT OPERATOR) 로 바꿨다.
	- 터미널의 "ambiguous 를 2 칸으로" 설정은 Ambiguous 에만 걸린다 (ADR-0020)
- [x] 비동기 작업 지원. 작업은 goroutine 에서 돌며 조각을 채널로 밀고, 조각 하나를 msg 로 바꾸는 `tea.Cmd` 를 받을 때마다 다시 발행해 고리를 잇는다. 진행률만 실행기가 알고 결과를 어디에 어떻게 넣을지는 작업이 보낸 `apply` 가 정한다. mode 마다 `case jobProgressMsg, jobDoneMsg:` 한 자리를 두고 공용 처리로 넘긴다 — 하는 일은 한 곳에 모이고 어떤 msg 를 받는지는 mode 에 보인다 (ADR-0025)
	- [x] command palette 의 파일 찾기를 위한 인덱싱. `ctrl+p` 를 누를 때 시작하고 목록은 차는 대로 붓는다. 파일 십오만 개짜리 디렉터리에서도 팔레트가 즉시 뜬다 (ADR-0011, ADR-0025)
	- [x] 작업이 있을때 status bar 위 줄 git 왼쪽에 점자 막대로 진행 표시. 칸당 여섯 단계라 열 칸이면 예순 단계다. 전체를 모르는 동안에는 막대 없이 개수만 찍는다. 칸이 모자라면 막대를 떼고, 그래도 모자라면 진행 표시를 통째로 뺀다 (ADR-0025)
	- [x] 작업 관리자를 넣는다. `:jobs`(팔레트의 「작업 목록」) 으로 도는 것과 최근에 끝난 것 스무 개를 보고, `x` 로 취소한다. 작업마다 ctx 를 나눠 주어서 `git ls-files` 프로세스까지 끊기고, 편집기를 끝내면 도는 것이 전부 정리된다. 실패는 statusBar 아래 줄이 알린다 (ADR-0027)
	- [x] 보내다 막힌 goroutine 이 남던 것을 닫는다. 조각을 보낼 때 `ctx.Done()` 을 같이 본다 (ADR-0025, ADR-0027)
	- [x] `:jobs` 가 편집 화면처럼 보이던 것을 고친다. tabline·sidebar 까지 덮는 전체 화면으로 그리고 맨 위에 제목줄을 둔다. statusBar 만 남기되 트리가 없는 것으로 치고 그린다. 키 안내는 statusBar 안이 아니라 그 바로 위 줄에 흐린 글씨로 둔다 (ADR-0027)
	- [x] 확인창(`viewConfirmDiscard`) 도 `*editor` 를 들고 다른 mode 와 같은 `case` 로 진행을 받는다. 창이 떠 있는 동안 온 진행이 버려지지 않는다 (ADR-0025, ADR-0026)
- [x] `editor` 를 포인터로 든다. 편집기가 도는 동안 하나뿐이라 전환할 때 빼먹는 실수 지점이 사라지고, 나중에 도착하는 것이 언제 닿아도 지금 상태에 닿는다. 값 복사 때문에 있던 slice 재할당 방어는 걷어냈다. 값 수신자는 "상태를 고치지 않는다" 는 표시로 그대로 뒀다 (ADR-0002, ADR-0025, ADR-0026)
- [x] 보는 파일이 바뀌면 sidebar 트리가 그 자리를 펼치고 고른다. CLI 시작, 팔레트·트리로 열기, `gt`/`gT`·tabline 클릭, `:q` 로 tab 닫기, `:tree` 다시 열기가 부른다. 이미 펼쳐진 디렉터리는 다시 읽지 않고, sidebar 를 열지는 않는다 (ADR-0019)
- [x] 지금 보고 있는 파일을 트리에서 굵은 글씨로 나타낸다. 고른 자리(커서) 는 포커스가 트리에 있을 때만 보여서 편집 중에는 표시가 아예 없었다. 굵기는 이 한 뜻으로만 쓰고 디렉터리에서는 뗐다 (ADR-0022)
	- [x] 굵은 글씨가 잘 안보여서 밑줄을 같이 걸었다. 뜻은 그대로 하나이고 밑줄은 이름에만 그린다 — 들여쓰기까지 이으면 무엇을 가리키는지 흐려진다 (ADR-0022)
- [x] `r`(글자 바꿔 넣기) 를 넣는다. `3rx` 는 세 글자를 바꾸고 줄이 짧으면 아무 일도 하지 않는다. `r<Enter>` 는 그 자리에서 줄을 가른다. 글자가 아닌 키는 무른다. `r` 뒤의 한 키만 한글 되돌림을 건너뛰어서 `r한` 이 한글을 넣는다 (ADR-0018)

- [x] `p`/`P`(붙여넣기) 와 `y`(복사) 를 넣는다. register 는 무명 하나뿐이고 tab 을 넘어 붙는다. 줄 단위면 커서 줄 아래·위에 줄로 끼우고 글자 단위면 커서 뒤·자리에 끼운다. 커서는 한 줄이면 붙인 마지막 글자, 여러 줄이면 첫 글자, 줄 단위면 첫 비공백이다. `3p` 도 `u` 한 번에 사라진다. `y` 는 `d` 의 범위 계산을 그대로 쓴다 (ADR-0017)
- [x] `c`(고치기) operator 를 넣는다. 파서와 범위 계산은 `d`·`y` 와 같이 쓴다 — `case "d", "y":` 에 `"c"` 를 더한 것이 파서 변경의 전부라 `c3w` `3cc` `cgg` `c$` 가 그대로 딸려 왔다. `cw` 는 vim 의 예외를 따라 커서가 공백 아닌 글자 위일 때만 `ce` 이고 첫 걸음에만 걸린다. `cc` 는 줄을 없애지 않고 첫 줄의 들여쓰기를 남긴다. 지운 것과 이어 친 글자는 `resumeEdit` 로 한 구간이 되어 `u` 한 번에 함께 돌아간다. 모르는 motion 이면 mode 도 바뀌지 않는다 (ADR-0033)
- [x] `ctrl+z` 로 셸에 내려간다(suspend). normal 과 트리에서만 받고, 종료가 아니라 멈춤이라 저장하지 않은 변경을 묻지 않는다. `fg` 로 올라오면 보고 있는 tab 하나가 밖에서 바뀌었는지 보고 알리기만 한다 — 가져오는 것은 `:e` 다 (ADR-0023)

		- **interface 는 `press`·`showcmd` 둘뿐이다.** 풀린 키 하나를 먹이는 자리(`step`) 를 따로 두었다가 걷어냈다 — 계약에 있으면 밖에서 `state.step("한")` 처럼 풀리지 않은 키를 먹여 조용히 모르는 동작이 되는 길이 생긴다. 되먹이는 것은 `press` 자신이고, 조각이 전부 ASCII 라 각자의 첫머리에서 곧바로 빠져나와 재귀가 한 겹에서 끝난다. 그 근거(편 조각은 다시 펴지지 않는다) 를 `expandHangul` 주석에 박고 테스트로도 잡았다
