# ADR-0013: `d` 는 이동 키를 그대로 motion 으로 쓰고, 범위는 이동을 실행해서 얻는다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

이동 키(ADR-0006) 까지 넣고 나니 편집기에 **지우는 키가 하나도 없었다**. normal mode 에서 글자
하나를 지우려면 `i` 로 들어가 `Backspace` 를 치고 `Esc` 로 나와야 했다. `dd` `dw` `x` 를 넣기로
했다.

ADR-0006 이 상태 기계를 만들면서 "앞으로 들어올 operator-pending(`d` `c` `y`)" 을 근거로 삼고,
그 상태 이름과 `3d2w` 같은 문법은 정하지 않은 채로 남겼다. 그 자리가 여기다.

정할 것이 다섯 가지였다.

1. **`d` 뒤에 무엇을 받는가.** `dd` `dw` 만 받을 수도 있고, 이미 있는 이동 키를 전부 받을 수도 있다
2. **지운 내용을 어디에 두는가.** 붙여넣기(`p`) 가 아직 없다
3. **숫자를 어디까지 받는가.** `3dd` `d3w` `3d2w` 가 각각 다른 문법이다
4. **범위를 어떻게 얻는가.** motion 마다 "어디까지" 를 다시 짜면 이동 키와 두 벌이 된다
5. **`dw` 의 줄끝 예외.** vim 은 줄의 마지막 단어에서 `dw` 를 쳐도 다음 줄을 끌어올리지 않는다

## 결정

**operator-pending 을 상태 하나(`normalOperator`) 로 두고, motion 쪽 키는 그 안의 상태가
처음부터 다시 먹는다.** `normalOperator` 는 `op` 와 앞에 붙은 숫자, 그리고 `inner normalState` 를
들고 있다. `d` 뒤의 키는 `inner`(처음에는 `normalStart`) 에 그대로 넘어가고, 거기서 명령이
완성되면 `d w` 처럼 operator 를 앞에 붙여 이름 하나로 잇는다. 접두 키와 같은 모양이라
실행하는 쪽은 평평한 이름으로 받는다(`d g g`).

**`d` 는 이미 있는 이동 키를 전부 motion 으로 받는다.** `w W e E b B h l ← → 0 ^ $ j k gg G` 와
`dd` 다. 검색 계열(`n` `N` `*` `#` `/` `?`) 과 `↑` `↓` 는 받지 않는다.

**지울 범위는 motion 을 실제로 실행해서 얻는다.** `Buffer` 를 값으로 복사한 뒤 그 위에서
`moveWordForward` 같은 이동 함수를 그대로 부르고, 커서가 간 자리를 범위의 끝으로 쓴다.
`e` `E` 만 커서가 선 글자를 범위에 넣는다(vim 의 inclusive motion).

**`dd` `dj` `dk` `dgg` `dG` 는 줄 단위다.** 커서 칸과 상관없이 줄 전체가 사라지고, 커서는
그 자리를 메운 줄의 첫 비공백에 선다.

**숫자는 operator 앞뒤에 각각 붙고 곱해진다.** `3d2w` 는 여섯 단어다. vim 과 같다. 둘 다 없으면
0 을 그대로 넘긴다 — `dG` 처럼 숫자가 되풀이가 아니라 줄 번호인 motion 이 "숫자 없음" 을
알아야 한다. `x` 도 숫자를 받는다(`3x`).

**`dw` 의 마지막 한 걸음은 줄을 넘지 않는다.** vim 과 같다. 중간 걸음은 넘는다 — `2dw` 는 다음
줄의 단어까지 지운다. 빈 줄에서는 그 줄 자체가 지울 것이라 다음 줄 시작까지 간다.

**`x` 는 `dl` 이다.** 같은 함수를 부른다.

**지운 내용은 `editor.register` 에 담는다.** 무명 register 하나뿐이고 줄 단위였는지를 같이
들고 있다. 아직 읽는 곳은 없다.

**지우기 한 번이 되돌리기 한 구간이다.** 앞의 편집 구간을 먼저 닫고 시작한다.

## 근거

### 범위를 이동으로 얻는다

**두 벌이 되면 갈린다.** `dw` 가 지우는 끝은 `w` 가 가는 자리와 같아야 한다. 그 규칙은
`buffer-word.go` 에 이미 있고 부류 넷(공백/단어/CJK/문장부호) 으로 끊는 판정까지 들어 있다.
`d` 쪽에서 다시 쓰면 한쪽만 고쳐지는 날이 온다. 실행해서 얻으면 그럴 수가 없다.

**복사가 싸다.** `Buffer` 는 slice header 뭉치이고 이동 함수는 `lines` 를 건드리지 않는다.
값으로 복사해서 움직이고 좌표만 꺼내면 된다. 이동 함수를 "커서를 옮기는 것" 과
"어디로 가는지 계산하는 것" 으로 쪼개는 리팩터링을 하지 않아도 된다.

**이동 키를 넣으면 motion 이 딸려 온다.** `f`/`t` 나 `{`/`}` 를 넣으면 `charMotionTarget` 에
case 한 줄이다.

### 이동 키를 전부 받는다

**받지 않는 쪽이 더 비싸다.** 이름을 몇 개만 허용하려면 목록을 손으로 들고 있어야 하는데,
이동 키가 늘 때마다 그 목록을 같이 고쳐야 한다. 범위 계산이 이동에서 나오는 이상 전부 받는
편이 코드가 적다.

**손이 이미 안다.** `d$` `d0` `dG` 는 vim 에서 매일 치는 것이라, `dd`/`dw` 만 되고 나머지가
조용히 안 되면 그것대로 사고다.

### 검색 motion 과 `↑` `↓` 는 뺐다

**`d/foo` 는 mode 를 넘나든다.** operator 를 들고 검색 mode 로 들어갔다가 `Enter` 에 돌아와야
해서 `viewEditorSearch` 가 operator 를 들고 다녀야 한다. 지우는 키를 넣는 김에 할 일이 아니다.

**`↑` `↓` 는 화면 행 단위다.** 이 편집기에서 `↓` 는 `j` 와 달리 wrap 된 줄 안에서 한 행만
내려간다(ADR-0006). `d↓` 가 줄 단위면 이동과 어긋나고, 화면 행 단위면 wrap 된 줄에서 무엇이
지워질지 눈으로 잡히지 않는다. 어느 쪽도 좋지 않아서 `←` `→` 만 받는다.

### 숫자를 곱한다

**vim 의 정식 문법이다.** `3d2w` 를 치는 사람은 여섯 단어를 뜻한다. 상태가 이미 operator 앞
숫자를 들고 있어서 뒤 숫자와 합치는 것은 함수 하나다.

**`x` 에도 숫자를 붙였다.** ADR-0006 은 "count 는 이동 키에만" 이었는데, 그 근거는 "뜻이
정해지지 않은 키에 숫자를 붙이면 안 된다" 였다. `3x` 와 `3dd` 는 뜻이 분명하다.

### `dw` 의 줄끝 예외

**vim 이 하는 동작이고, 근거가 있다.** `dw` 는 단어 하나를 지우려고 치는 키다. 줄의 마지막
단어에서 다음 줄이 끌려 올라오면 지우려던 것보다 큰 일이 일어난다. 줄을 없애는 키는 `dd` 다.

**vim 의 구현도 이 자리에 있다.** operator 와 함께 쓰인 `w` 는 `fwd_word(..., eol=TRUE)` 로
불려서 줄 끝에서 멈춘다. 예외를 `d` 쪽에 두지 않고 motion 쪽에 두는 것이라 `dw` 하나만
다르게 동작한다.

### register

**지금 담아두는 것이 싸다.** `p` 를 넣을 때 지우는 쪽을 다시 열지 않아도 된다. 지운 내용은
이미 손에 들려 있어서 필드에 넣는 것이 전부다.

**`editor` 에 둔다.** vim 의 register 도 buffer 밖이다. tab 을 옮겨 붙여넣는 것이 되어야 한다.
`search` 를 여기 둔 것과 같은 이유다(ADR-0010).

## 결과

좋은 점

- `dd` `dw` `x` 와 `d` + 이동 키 조합이 동작한다. `3dd` `d3w` `3d2w` 도 vim 과 같다.
- 기대값을 vim 9.1 에서 직접 쳐서 확인하고 표로 옮겼다(`delete_test.go`). 빈 줄, 줄 끝 단어,
  줄이 모자란 `2dj`, 파일의 마지막 글자처럼 헷갈리는 자리가 전부 실제 vim 결과다.
- `c`(고치기) 와 `y`(복사) 는 `normalOperator{op: "c"}` 를 열고 범위 계산을 같이 쓰면 된다.
- 이동 키가 늘면 motion 도 같이 는다.

감수하는 것

- **한글 상태의 음절 하나가 편집이 될 수 있다.** `어` 는 `d` `j` 라 `dj`(두 줄 지우기) 가 된다.
  전에는 `d` 가 없는 명령이라 `j` 만 남았다. 두벌식 자리로 되돌려 받는 이상(ADR-0008) 편집기가
  가릴 수 있는 것이 아니다. `u` 로 되돌아온다.
- **vim 의 exclusive 보정 규칙을 옮기지 않았다.** vim 은 "글자 단위 motion 의 끝이 1 칸에
  걸리면 앞 줄 끝으로 당기고, 시작이 첫 비공백 앞이면 줄 단위가 된다" 는 규칙을 더 가지고 있다.
  자주 만나는 자리(`dw` 의 줄끝, 빈 줄) 는 motion 쪽에서 이미 맞고, 나머지(빈 줄이 낀 `2dw` 등)
  에서는 지워지는 범위가 vim 과 다를 수 있다. `docs/tasks.md` 에 남겼다.
- **`d` 가 `ctrl+c` 를 삼킨다.** 접두 키와 같다(ADR-0006). 잘못 누른 `d` 를 무르는 값이다.
- **`run` 이 이름 하나로 받는 평평한 switch 가 아니게 됐다.** `d ` 로 시작하는 이름은 switch
  앞에서 갈라진다. 이름이 둘로 된 명령이라 평평한 표에 담을 수 없다.

## 대안

**`dd` `dw` 만 특별한 이름으로 받기** — 파서에 상태를 늘리지 않고 `normalPending` 에 `d` 를
더하면 끝이다. `d$` `dG` 가 조용히 안 되는 것이 문제이고, `c`/`y` 를 넣을 때 어차피 다시 짠다.

**motion 마다 지울 범위를 직접 계산하기** — 이동 함수를 `Buffer` 복사 없이 부를 수 있고
"어디까지 지우는가" 가 코드에 그대로 적힌다. 규칙이 두 벌이 되는 값을 치른다. 부류 판정과
wrap 계산이 걸린 `w`/`e`/`b` 에서 특히 비싸다.

**operator 를 type 으로 두고 표로 갈라놓기(`operator{name, apply}`)** — `c` 와 `y` 가 들어오면
셋의 공통점이 "범위를 잡는다" 하나뿐이라 표가 될 만하다. 지금은 `d` 뿐이라 이름 하나를
`strings.CutPrefix` 로 떼는 것으로 끝난다. `config 는 compile 됨` 의 형태를 정할 때 같이 본다
(ADR-0006 의 대안과 같은 자리다).

**register 를 지금 두지 않기** — 읽는 곳이 없는 필드가 남는 것이 싫다면 이 쪽이다. `p` 를
넣을 때 `deleteText`/`deleteLines` 의 돌려주는 값을 다시 손대야 한다.

## 이 ADR 이 정하지 않는 것

- `p`/`P`(붙여넣기) 와 이름 있는 register(`"a`)
- `c`(고치기) `y`(복사) `D` `C` `s` `S` `X`
- `.`(되풀이) 와 그것이 필요한 count 문법(`3i`)
- `d/foo` 처럼 검색을 motion 으로 쓰는 것
- `f`/`t`(줄 안에서 글자 찾기) 와 `di(`(text object)
- visual mode 에서 고른 범위를 지우는 것
