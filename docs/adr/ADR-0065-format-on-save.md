# ADR-0065 저장할 때 바깥 포매터에 통과시킨다

- 상태: 채택
- 날짜: 2026-08-24

## 맥락

Go 는 포맷이 정해져 있는 언어라 손으로 맞추는 자리가 아니다. 지금까지 zn 에서 그 일은
「밖에서 포매터를 돌리고 `:e` 로 다시 읽기」였다. `Reload` 주석이 그 길을 적어 두고 있었다.

저장할 때 맞추는 자리는 이미 있다. `.editorconfig` 의 저장 동작(ADR-0052) 이 「맞추는 것이
쓰기보다 먼저다」와 「바깥 변경 검사가 맞추기보다 먼저다」를 못 박아 두었고, 이 결정은 그 줄
옆에 포매터를 하나 세우는 일이다(`docs/tasks.md` 의 「저장할떄의 hook 실행」).

## 1. 파일이 아니라 buffer 를 통과시킨다

명령에 stdin 으로 흘려 넣고 stdout 으로 받는다. `prettier --write` 처럼 **파일만 고치는 도구는
못 쓴다.** 그 대가를 받아들인다.

파일을 먼저 쓰고 포매터를 돌리면 ADR-0052 의 두 규칙이 동시에 깨진다. 화면과 파일이 갈리는
순간이 생기고(포맷된 파일 · 안 된 buffer), 저장이 막히는 길에서 파일만 바뀐다. 아직 쓰지 않은
글을 넘기면 그 두 가지가 애초에 생기지 않는다.

그래서 순서가 **바깥 변경 검사 → 포매터 → `.editorconfig` → 쓰기** 다. 포매터가 `.editorconfig`
보다 앞인 것은 **적어 둔 사람의 뜻이 마지막에 서야** 하기 때문이다. gofmt 계열은 줄끝을 LF 로,
마지막 줄바꿈을 있는 것으로 내는데, 그 파일에 `end_of_line`·`insert_final_newline` 이 적혀
있으면 그쪽이 이겨야 한다.

마지막 줄바꿈은 포매터가 정하지 않는다. buffer 는 그것을 내용이 아니라 사실로 들고 있어서
(`finalLineEnding`), 넘길 때 붙이고 받을 때 뗀다. 넣고 빼는 것은 `.editorconfig` 의 몫이다.

## 2. 표는 코드 안의 switch 하나다

`.go` 한 칸이고 `saveHookFor` 의 switch 가 그 표다. 확장자 하나에 map 리터럴을 두면 칸만 늘고
값은 한 줄에 있다. `isGoFile` 이 syntax 의 언어 표를 빌려 오지 않은 것과 같은 자리다(ADR-0051).

**설정 파일을 만들지 않았다.** 지금 이 저장소에 설정 파일이 하나도 없고, 그 판을 여는 것은
tip 을 끄는 설정·`:set` 계열과 같이 볼 일이다(ADR-0061). 둘째 언어가 생기면 case 가 하나 는다.

## 3. goimports 를 찾는 순서는 「그 저장소가 tool 로 선언한 것 → PATH → `go install` 자리」다

`gofmt` 가 아니라 `goimports` 다. 하는 일이 gofmt 의 상위집합이고(포맷 + import 정리),
`go install` 로 깔 수 있어서 없을 때 묻는 길이 있다. gofmt 는 Go 툴체인에 딸려 오는 것이라
없으면 깔 것이 없다.

go.mod 에 `tool` 로 적어 둔 저장소는 판을 고정해 둔 것이라 그 뜻이 PATH 에 깔린 것보다 앞선다
(go 1.24 의 tool 지시자). 재 보면 값이 이렇다(macOS, 워밍 후).

| 방법 | 저장 한 번 | 조건 |
|---|---|---|
| `go tool goimports` | 0.13–0.15s | 그 모듈이 `tool` 로 선언했을 때만 |
| PATH 의 바이너리 | 그보다 짧다 | 깔려 있으면 |
| `go run …@latest` | 0.55–0.98s | 어디서나. 첫 회 5.6s |

**`go tool` 은 지금 모듈의 go.mod 에 적힌 tool 만 찾는다.** 선언 없는 모듈에서도 모듈 밖에서도
`go: no such tool "goimports"` 다. 그래서 이것 하나로는 편집기가 설 수 없다. zn 은 남의
저장소를 여는 물건이다. `go run …@latest` 는 어디서나 되지만 저장마다 0.5초라 자리가 아니다.

찾는 일은 **폴더마다 한 번** 하고 담아 둔다(`saveHooks`). 「아직 안 찾아봤다」와 「찾아봤는데
없다」가 갈려야 저장마다 다시 뒤지지 않는다. 담아 둔 것은 편집기가 도는 동안 그대로다.
도중에 go.mod 에 tool 을 적었으면 다시 띄워야 보이고, 이것은 gopls 가 한 번 실패하면 다시
걸지 않는 것과 같은 태도다.

찾는 것은 `go tool` 에게 물어서 한다. tool 지시자의 문법과 이름 줄이는 규칙은 go 가 아는
것이고, 그것을 go.mod 파서로 옮겨 적으면 판이 바뀔 때 어긋난다.

**PATH 만 보지 않는다.** `go install` 은 `$GOBIN` 또는 `$GOPATH/bin` 에 넣고 그 자리가 PATH 에
없는 기계가 흔하다. gopls 를 찾는 자리가 같은 일을 먼저 겪었고(ADR-0051), 이 기능을 만든
기계에서도 goimports 가 거기 깔려 있는데 「설치되어 있지 않습니다」가 떴다.

그 자리도 **`go env GOBIN GOPATH` 로 go 에게 묻는다.** 「GOBIN 이 비면 GOPATH/bin」이라는
규칙이 go 의 것이라 옮겨 적으면 어긋나기 때문이고, 위에서 `go tool` 에게 물은 것과 같은
태도다. 다만 **GOBIN 이 비면 첫 줄이 빈 줄로 온다.** 답을 통째로 다듬고 줄을 가르면 그 줄이
사라져 GOPATH 를 GOBIN 으로 읽는다. 실제로 그렇게 어긋났고 검사를 두었다.

## 4. 저장이 기다린다

백그라운드 job 으로 돌리지 않는다. 먼저 쓰고 나중에 buffer 를 갈아끼우면 **돌리는 동안 친
글자**와 그 사이의 다시 저장이 새 문제로 오고, 그것들은 전부 「화면·dirty·undo 가 어긋나는」
갈래다. 저장 한 번이 한 가지 일이면 그 자리가 아예 없다.

대가는 그만큼 화면이 멈추는 것이다. 130ms 이고 사람이 `:w` 를 친 직후라 받아들인다.
한계는 2 초다. 잰 값의 열 배가 넘고, 거기까지 갔으면 그 판이 무언가 잘못된 것이라 기다리는
것보다 저장을 끝내는 것이 낫다.

## 5. 실패는 저장을 막지 않는다

**돌아가다 실패하면(문법 오류) buffer 를 건드리지 않고 까닭만 아래 줄에 적는다. 파일은 쓴다.**
편집 중의 Go 는 거의 언제나 문법이 깨져 있다. 여기서 저장을 막으면 고치다 만 파일을 둘 곳이
없어진다. 그것은 편집기가 할 일이 아니다. 적는 것은 stderr 첫 줄이다(`<standard input>:5:1: …`).

**깔려 있지 않으면 저장을 끝낸 뒤 한 번 묻는다.** 그 「없다」는 nil 이 아니라 센티널
(`errHookNotInstalled`) 로 온다. nil 하나로는 「이 파일에는 돌릴 것이 없다」(`.txt`) 와
「돌릴 것이 있는데 깔려 있지 않다」(`.go`) 가 갈리지 않고, 묻는 것은 뒤쪽에서만 하기 때문이다.
갈라 두면 묻는 자리가 확장자를 다시 보지 않아도 되어 표가 한 자리에 남는다.

창은 gopls 설치 확인창과 같은 모양이고 **따로 산다**(`view-goimports-install-confirm.go`).

하나로 묶어 물음과 설치를 값으로 받게 하는 길을 보았다가 접었다. 창 하나에 부르는 쪽 둘이
매달리는데 **그 둘은 뜨는 까닭도 거절의 뜻도 다르다.** 이쪽은 저장에 딸려 와서 거절을 적어
두어야 하고, 저쪽은 사용자가 친 키에서만 온다. 같아 보이는 것을 묶는 값보다 각자 고쳐지는
값이 크다고 보았다(`CLAUDE.md` 의 「과도한 추상화를 하지 않는다」).

- **거절을 적어 둔다**(`goimportsDeclined`). gopls 는 `\gd` 를 친 그 자리에서만 물어서 적어 둘
  것이 없지만, 이것은 저장이라는 가장 잦은 동작에 딸려 온다. 적어 두지 않으면 저장할 때마다
  창이 뜨고, 그러면 그것이 곧 방해다.
- **나가는 길(`:wq`·`:x`) 에서는 묻지 않는다.** tab 을 닫는 것과 창이 겹친다. 거절로도 세지
  않으므로 다음 `:w` 가 묻는다.
- 깔고 나면 담아 둔 것을 버린다. 다음 저장이 다시 찾아서 방금 깐 것을 만난다.

## 6. 되돌리기는 한 덩어리다

포매터가 고친 것은 한 동작이라 `u` 한 번에 통째로 돌아간다(`replaceAll`). 앞의 타이핑 구간에
섞이면 `u` 한 번에 남의 편집까지 딸려오므로 구간을 먼저 끊는다. `trimTrailingSpace` 가 이미
그 자리다(ADR-0052).

커서는 줄 번호를 지킨다. 포매터는 들여쓰기를 고치고 import 를 옮기지 줄을 뒤섞지 않아서 보던
자리가 대개 그 자리에 있다. 파일이 짧아졌으면 범위 안으로 끌어온다. 다시 읽기가 커서를
이어받는 것과 같은 태도다.

**무엇을 했는지 반드시 적는다**(`goimports: 6 줄 맞춤, 2 줄 늘어남`). 손대지 않은 줄이 바뀌는
일이라 그렇다(ADR-0052). 세는 것은 자리로 맞댄 눈짐작이지 참 diff 가 아니다. 정확한 자리는
화면이 이미 보여주고 있다.

## 이 ADR 이 정하지 않는 것

- **끄는 설정과 사용자가 명령을 적는 자리.** 설정 파일을 열 때 같이 본다(ADR-0061 과 같은 건이다)
- 다른 언어. 표에 case 가 늘 자리는 있다
- gopls 의 `textDocument/formatting` 을 쓸지. 이미 이어져 있는 길이지만 Go 전용이라 표와 갈린다
- 저장이 아닌 때(`=` 처럼 손으로 부르는 포맷) 에 같은 명령을 쓸지
- 파일만 고치는 도구(`prettier --write`) 를 받을지. 받으려면 쓰고 다시 읽는 길이 새로 생긴다
