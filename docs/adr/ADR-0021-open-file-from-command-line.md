# ADR-0021 명령줄로 파일 열기

## Status

Accepted

## Context

편집 중에 파일을 열 길이 팔레트와 트리뿐이었다. `:e <파일>` 과 `:tabnew <파일>` 이 없어서
vim 에서 오는 손이 먼저 치는 것이 매번 「알 수 없는 명령」으로 튕겼다.

명령 parser 는 이미 `이름[!] [인자 ...]` 를 뜯어 놓고 있었고(`command{name, force, args}`),
`editor.openTab` 도 이미 있었다. 막고 있던 것은 `run()` 이 인자가 붙은 명령을 통째로 거절하는
한 줄뿐이었다. 그러니 정할 것은 배관이 아니라 의미다.

핵심은 이 편집기에 vim 의 window 가 없다는 것이다. tab 하나가 Buffer 하나이고 화면을 쪼개는
길이 없다. vim 에서 `:e` 는 "이 window 의 buffer 를 바꾼다" 이고 `:tabnew` 는 "tab 을 늘린다"
인데, window 가 없으면 `:e` 의 자리가 비어 버린다.

여기에 이미 정해 둔 규칙이 하나 걸린다 — **같은 파일을 두 tab 에 열지 않는다**. tab 마다
Buffer 가 독립이라 같은 파일이 둘이면 한쪽 저장이 다른 쪽 편집을 조용히 덮어쓴다. 나중 저장은
바깥 변경으로 잡혀 막히지만(ADR-0015) 갈라진 두 편집을 합칠 길은 없다. `openTab` 과 CLI 인자
정규화가 이미 이 규칙을 지키고 있다.

## Decision

### `:e <파일>` 은 활성 tab 을 갈아끼운다

tab 수는 그대로 두고 보고 있는 tab 의 Buffer 만 그 파일로 바꾼다. `:tabnew <파일>` 만 tab 을
늘린다. 둘을 같은 동작으로 합치는 길도 있었지만 그러면 이름이 둘인데 하는 일이 하나가 되고,
"지금 tab 에서 다른 파일로 갈아탄다" 를 표현할 명령이 사라진다.

vim 을 쓰던 손이 `:e` 에 기대하는 것도 이쪽이다.

### 이미 다른 tab 에 열려 있으면 갈아끼우지 않고 그 tab 으로 옮겨간다

갈아끼우기와 "같은 파일은 한 tab" 규칙이 부딪히는 자리다. 그대로 갈아끼우면 같은 파일에
Buffer 가 둘 생겨 규칙이 깨진다.

옮겨가는 쪽을 택했다. 오류로 막고 `gt` 로 직접 가게 하는 길도 있었지만, 사용자가 원한 것은
"그 파일을 보는 것" 이고 결과가 정확히 그것이다. `:tabnew <파일>` 이 이미 같은 규칙으로
움직이고 있어서 두 명령의 예외가 하나로 맞는다.

옮겨가기만 하는 길이라 지금 tab 의 저장하지 않은 편집도 그대로 남는다. 그래서 **이 경우에는
dirty 여도 묻지 않는다** — 잃을 것이 없는데 묻는 확인창은 손만 늦춘다.

### 인자 없는 `:e` 는 다시 읽기다

ADR-0016 에서 「파일 다시 읽기」를 팔레트에만 두고 `:e!` 를 미뤘던 이유가 "명령줄이 인자를
못 받아서 `:e <파일>` 없이 반쪽만 넣으면 이름이 거짓말이 된다" 였다. 이제 나머지 반쪽이
들어왔으므로 같이 넣는다. `:e` 는 팔레트 항목과 같은 길을 타고, 팔레트의 「파일 다시 읽기」에
`:e` 를 짝 명령으로 붙였다.

### `!` 는 어느 쪽이든 "묻지 말라" 다

| 명령 | 하는 일 |
|------|---------|
| `:e` | 다시 읽는다. 저장하지 않은 변경이 있으면 확인창 |
| `:e!` | 묻지 않고 다시 읽는다 |
| `:e <파일>` | 활성 tab 을 갈아끼운다. 잃을 것이 있으면 확인창 |
| `:e! <파일>` | 묻지 않고 갈아끼운다 |

`!` 의 뜻을 인자 유무에 따라 나누지 않았다. `!` 는 어느 명령에나 같은 뜻으로 붙는 표시라는
것이 명령 문법의 전제다(ADR-0003 이후 parser 가 `!` 를 이름에서 뗀 이유가 이것이다).

### 파일 이름은 하나만 받는다

`:e a b` 는 「파일은 하나만 쓸 수 있습니다」다. vim 의 E172 와 같다. 파일 여럿을 tab 여럿으로
여는 것은 CLI 인자의 몫이다. 인자를 받지 않는 나머지 명령(`:w`, `:q` …)은 인자가 붙으면 그대로
「알 수 없는 명령」이다 — 조용히 버리면 `:w foo` 가 foo 에 저장한 것처럼 보인다.

## Consequences

- `:e` 와 `:tabnew` 가 파일을 받으면서 팔레트·트리 말고도 편집 중에 파일을 여는 길이 생겼다.
  세 길 모두 "같은 파일은 한 tab" 을 지킨다.
- `editor.replaceTab` 이 `openTab` 과 나란히 생겼다. 앞부분(이미 열린 tab 찾아 옮기기) 이 겹치지만
  뒷부분이 갈린다 — 하나는 끼우고 하나는 바꾼다. 합치면 flag 로 갈리는 함수가 되므로 두었다.
- `:e` 로 갈아끼운 tab 의 undo 이력은 사라진다. 다시 읽기와 같다(ADR-0016) — 갈아끼운다는 것이
  곧 그 파일을 새로 연 것이다.
- 디렉터리를 주면(`:e docs/`) 읽기 오류가 그대로 아래 줄에 뜬다. vim 처럼 트리를 여는 것은
  하지 않았다 — sidebar 가 이미 그 일을 한다.
- `:e` 가 tab 을 갈아끼우므로, 열려 있던 파일이 tabline 에서 사라진다. 방금까지 보던 파일로
  돌아가는 길(vim 의 alternate file, `:e#` / `Ctrl+^`) 은 아직 없다.
