# ADR-0162 트리 메뉴의 「브라우저로 열기」는 셸 없이 OS 의 opener 에 경로를 넘긴다

- 상태: 채택
- 날짜: 2026-11-10
- 관련: ADR-0146(트리 우클릭 메뉴), ADR-0114(`%` 는 지금 파일), ADR-0138(background 셸), ADR-0080(언어는 표의 한 줄), ADR-0075(작업의 이름과 인자)

## 맥락

html 을 고치다 결과를 보려면 `:!& open %` 를 쳐야 했다. 트리에서 그 파일을 우클릭해 곧바로 브라우저로 넘기는 문이 필요했다.

정할 것은 넷이다.

1. 어느 파일에 항목을 세우는가
2. 항목 이름을 무엇으로 하는가
3. 무엇으로 실행하는가
4. 끝나는 것을 어떻게 다루는가

## 1. 강조가 html 로 읽는 파일에 세운다

확장자를 따로 적지 않고 `syntax.LanguageFor(path).Is("html")` 로 가른다. 그러면 `.html`·`.htm` 이 같이 들고, 대문자 확장자도 강조와 같은 답이 나온다. html 로 읽는 이름이 늘면 메뉴도 같이 따라간다.

이를 위해 `Language` 에 `Is(alias)` 를 더했다. 언어를 알아보는 자리가 표 하나라는 규칙(ADR-0080) 을 지키려면 메뉴가 확장자 목록을 따로 들면 안 된다. `PairsTags()` 는 지금 html 에만 참이지만 뜻이 다른 칸이라 빌려 쓰지 않았다.

디렉터리는 이름이 `.html` 로 끝나도 세우지 않는다.

## 2. 이름은 「브라우저로 열기」다

「열기」만 두면 트리를 왼쪽 클릭했을 때 zn 안에서 여는 것과 이름이 겹친다. html 에만 서는 항목이라 무엇이 뜨는지를 이름에 적었다. 「기본 앱으로 열기」도 있었지만 html 의 기본 앱은 사실상 브라우저라 덜 직접적이다. 다른 확장자로 넓힐 때 다시 본다.

항목은 메뉴 맨 위다. 아래 넷(새 파일·새 이름·복제·지우기) 은 파일을 고치는 일이고 이것은 바깥에 보여 주는 일이라 갈래가 다르다.

## 3. 셸을 거치지 않고 opener 를 바로 띄운다

macOS 는 `open`, 나머지 unix 는 `xdg-open` 에 경로를 인자 하나로 넘긴다.

- `:!& open %` 로 셸 줄을 만들면 공백이나 따옴표가 든 경로를 막아야 한다. `%` 는 일부러 감싸지 않는다(ADR-0114)
- 경로를 인자 하나로 넘기면 막을 것이 없다
- windows 는 보지 않는다. background 셸이 이미 unix 전용이다(ADR-0138)

## 4. 작업으로 돌리되 ctx 에 매지 않는다

이름이 `브라우저로 열기` 이고 인자가 경로인 작업이다(ADR-0075). 실패는 `finishJob` 이 늘 하던 대로 아래 줄에 알리고, 이유는 출력의 마지막 줄이다. `open` 은 왜 못 열었는지를 stderr 에 적는다. 성공은 알리지 않는다. 브라우저가 뜨는 것이 알림이다.

**편집기를 끝내도 띄운 것을 죽이지 않는다.** `xdg-open` 은 브라우저가 처음 뜰 때 그 브라우저가 닫힐 때까지 돌아오지 않기도 한다. 작업 ctx 에 매면 zn 을 닫는 순간 브라우저가 같이 죽는다.

- 세션은 가른다(`Setsid`). `ctrl+z` 가 그룹 전체를 멈출 때 브라우저까지 멈추지 않게 한다
- 띄운 브라우저가 출력 pipe 를 물려받으면 `Wait` 가 돌아오지 않는다. background 셸과 같이 `WaitDelay` 를 두고 그것으로 끝난 것은 성공으로 친다

## 결과

- html 파일 우클릭 메뉴가 다섯 줄이 된다
- `xdg-open` 이 브라우저를 붙들고 있는 동안 `:jobs` 에 그 작업이 「도는 중」으로 남고, 같은 파일을 다시 골라도 새로 띄우지 않는다
