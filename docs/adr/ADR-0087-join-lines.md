# ADR-0087 `J` 는 줄을 잇고, 이은 자리의 공백 규칙은 문장부호에서만 vim 과 갈린다

- 상태: 채택
- 날짜: 2026-08-27
- 관련: ADR-0083(대소문자 키와 operator 갈래를 미룬 자리), ADR-0037(visual mode), ADR-0013(지우기 operator), ADR-0058(register), ADR-0001(줄 배열 buffer), ADR-0008(한글 상태의 키), ADR-0081(count 를 받는 동작)

## 맥락

`docs/tasks.md` 에 「`J` 로 줄 이어 붙이는 기능」 한 줄로 남아 있던 건이다. 지우기·바꾸기·복사·들여쓰기·대소문자까지 normal 의 편집 키가 갖춰진 뒤에도 **줄을 합치는 길이 없었다.** 두 줄을 한 줄로 만들려면 줄 끝으로 가서 `i`·`Delete`·공백을 손으로 치는 수밖에 없었고, 그 손은 들여쓰기가 붙은 줄에서는 더 길어진다.

정할 것은 둘로 갈린다. **이은 자리에 공백을 어떻게 넣는가**와 **어느 문(`J`·`gJ`·visual·`:join`)까지 낼 것인가**다.

## 0. 먼저 vim 을 쟀다

vim 9.1(`-u NONE`, 즉 vimrc 없이 공장 기본값) 로 잰 값이다. 잰 것을 그대로 시험 파일(`buffer-join_test.go`) 의 기대값으로 옮겼다.

| 경우 | `J` 결과 | 커서 |
| --- | --- | --- |
| `foo` + `    bar` | `foo bar` | 넣은 공백 |
| `foo   ` + `    bar` | `foo   bar` (공백 안 넣음) | 올라온 첫 글자 |
| `foo\t` + `bar` | `foo\tbar` (공백 안 넣음) | 올라온 첫 글자 |
| `foo` + `    )bar` | `foo)bar` | - |
| `foo` + `    ]bar` | `foo ]bar` (`]` 는 예외가 아니다) | - |
| `End.` + `Next` | `End.  Next` (**공백 둘**) | 첫 공백 |
| `foo` + 빈 줄 | `foo` | 줄 끝 |
| 빈 줄 + `bar` | `bar` | 줄 머리 |
| `foo` + `    `(공백뿐) | `foo` | 줄 끝 |
| 마지막 줄에서 | 아무 일도 없음 | 그대로 |
| `3J` / `2J` / `1J` | 세 줄 / 두 줄 / **두 줄** | 마지막으로 이은 자리 |
| `9J`(줄 3 개) | 세 줄. 오류가 아니다 | 같음 |
| `gJ` | `foo    bar` (들여쓰기도 공백도 그대로) | - |
| `Vjj` + `J` | 고른 세 줄 | - |

여기서 규칙 셋이 나온다.

**커서는 「마지막으로 이은 자리」다.** 붙기 전 줄의 길이가 그 자리다. `3J` 가 첫 이음이 아니라 셋째 줄이 붙은 자리에 서는 것이 그 증거다. 그 자리가 다음에 칠 것(`x` 로 공백 지우기, `i` 로 손보기) 이 놓이는 자리다.

**count 는 「이을 줄 수」다.** 「몇 번 잇는가」가 아니다. `1J` 가 두 줄인 것이 그것을 말한다. 남은 줄이 모자라면 있는 만큼 잇고 오류를 내지 않는다.

**`]` 는 예외가 아니다.** 예외는 `)` 하나다. 규격이 아니라 관습이라 재지 않으면 알 수 없는 자리였다.

## 1. 공백 규칙은 vim 그대로 두고 문장부호에서만 갈린다

**공백 하나를 넣는 것이 기본이고 넣지 않는 경우가 넷이다.** 앞이 비었을 때, 걷고 난 뒤가 비었을 때, 앞이 이미 공백이나 tab 으로 끝났을 때, 뒤가 `)` 로 시작할 때다. 앞 셋은 「없는 곳에 공백을 만들지 않는다」 는 한 뜻이고, 마지막은 `foo(` 와 `)` 를 이으면 `foo()` 여야 한다는 것이다.

**문장부호(`.` `?` `!`) 뒤에도 하나다.** vim 은 기본값이 `joinspaces` 켜짐이라 둘을 넣는다(§0). 그것은 영문 타이프라이터 관습이고, 이 편집기가 여는 글의 대부분(한국어 산문과 코드) 에서는 **이은 자리에만 공백이 둘인 줄**이 남는다. 문장을 나누는 규칙을 지켜 쓰는 이 저장소의 문서에서도 그렇다. neovim 이 기본값을 끈 것과 같은 판단이다.

**설정으로 고를 수 있게 하지 않는다.** 설정 파일이 아직 없고(ADR-0061 이 같은 자리에서 미뤄 두었다), 그것을 이 키 하나 때문에 만들지 않는다. 둘을 원하는 사람에게는 이은 자리에서 공백 하나를 더 치는 길이 있다.

**vim 과 갈린 자리를 시험이 적어 둔다.** `TestJoinSingleSpaceAfterSentenceEnd` 가 그것이고, 시험 머리글에 「vim 은 둘, 우리는 하나」 라고 적었다. 잰 표를 옮긴 시험들 사이에서 이 하나만 다르므로, 적어 두지 않으면 나중에 「재다 틀린 것」으로 읽힌다.

## 2. `J` 하나만 낸다

`gJ`·visual 의 `J`·`:[range]join` 셋을 두지 않았다. 셋 다 값이 없는 것이 아니라 **`J` 와 겹친다.**

**`gJ`(공백을 손대지 않는 이어붙이기).** 넣는 값은 `prefixAction("g", …)` 에 한 줄이라 ADR-0083 이 `gu`·`gU` 를 미룰 때 걸렸던 operator 기계가 필요하지 않다. 그래도 두지 않은 것은 **이은 자리의 공백 규칙을 하나로 남기기 위해서다.** 키가 둘이면 「어느 쪽이 공백을 넣는가」를 매번 기억해야 하고, 규칙을 고칠 때 두 곳을 같이 봐야 한다. 들여쓰기를 살려 이어야 하는 자리는 `J` 뒤에 `x` 를 치거나 `i` 로 손보는 길이 있다.

**visual 의 `J`.** ADR-0037 이 visual 의 키 면적을 일부러 좁게 두었고, ADR-0083 은 반대로 「범위 일은 visual 로 보낸다」 고 적었다. 대소문자는 **normal 에 범위를 대는 길이 아예 없어서**(한 글자짜리 `~` 뿐) visual 이 그 몫을 받아야 했는데, `J` 는 count 가 이미 범위다. `3J` 와 `Vjj J` 가 같은 곳을 잇는다.

**`:[range]join`.** `:d`·`:y`·`:s` 가 이미 범위를 받으므로(ADR-0046) 자리는 있다. 다만 멀리 있는 줄을 보지 않고 잇는 일은 드물고, 명령 하나를 더하면 `spec.md` 의 표 둘과 팔레트와 도움말이 같이 넘어간다.

셋 다 **미룬 것이지 안 하기로 한 것이 아니다.** `docs/tasks.md` 에 남겼다. 그날에도 §1 의 공백 규칙은 한 함수(`joinSeparator`) 이므로 나눠 쓰면 된다.

## 3. 지우기 경로를 쓰지 않고 잇는 함수를 따로 둔다

`J` 를 「줄 끝의 줄바꿈과 다음 줄 들여쓰기를 지우고 공백 하나를 넣는 것」으로 보면 지우기·넣기로 흉내 낼 수 있다. 그러지 않았다.

**공백 규칙이 지우는 범위 계산 안으로 들어가기 때문이다.** 넣을지 말지가 앞 줄의 끝 글자와 뒷 줄의 첫 글자에 달려 있어서(§1), 지우기로 짜면 그 판정이 「어디까지 지우는가」와 섞인다. `buffer-join.go` 한 파일에 잇는 일만 두면 판정이 `joinSeparator` 하나에 모인다.

**register 에 담지 않는다.** 담기는 것은 지운 것인데 여기서 사라지는 것은 줄바꿈과 들여쓰기뿐이고, 그것을 `p` 로 되붙일 자리가 없다. vim 도 담지 않는다(ADR-0058).

**이은 것 전부가 되돌리기 한 구간이다.** `3J` 를 `u` 한 번으로 되돌린다. 친 것이 하나였으니 무르는 것도 하나다. 앞의 타이핑 구간과는 갈라 둔다(`endEdit` 을 먼저 부른다). `~`·`r` 이 같은 자리에서 하는 것이고, 섞이면 `u` 한 번에 남의 편집까지 딸려온다.

**줄 수가 줄어든 것을 `growEdit` 으로 알린다.** 구간이 든 `count` 는 「편집 **후** 그 자리를 차지하는 줄 수」라, 이것을 빼먹으면 `u` 가 없는 줄을 되돌리려다 죽는다. 만들면서 실제로 그렇게 죽었고, `replaceAll` 이 같은 자리에서 같은 호출을 하고 있었다.

## 4. 한글 상태에서 낼 수 없는 키가 다섯째가 된다

`J` 는 두벌식에서 `ㅓ` 자리이고 shift 자리에 다른 글자가 없어서, `shift+ㅓ` 와 `ㅓ` 가 같은 글자로 온다. 앱 안에서 가를 방법이 없다(ADR-0008).

`G` `B` `V` `U` 에 이어 다섯째다. **우회로를 만들지 않는다.** ADR-0083 §5 가 그 까닭을 이미 적었고 여기서 달라지는 것이 없다. 한글 상태로 normal 에 와 있는 것 자체가 사고이고, 그 상태에서 모든 키를 낼 수 있게 만드는 것은 이 편집기가 부탁받은 일이 아니다.

## 결과

- `J`·`3J` 로 줄을 잇는다. 읽기 전용 파일에서는 거절한다(다른 편집 동작과 같은 문이다)
- 이은 자리의 공백 규칙이 `joinSeparator` 한 함수에 있다. 넣지 않는 경우 넷이 거기 다 있다
- 늘어난 상태가 없다. 새 mode 도 새 명령도 register 자리도 늘지 않았다
- 잰 표가 시험이 되었다. vim 과 갈린 한 칸(문장부호) 도 시험에 적혀 있다

**대가**

- **문장부호 뒤 공백이 vim 과 다르다.** vim 을 오래 쓴 손에는 한 칸이 빈다(§1)
- **`gJ` 가 없다.** 들여쓰기를 살려 이으려면 `J` 뒤에 손이 한 번 더 간다
- **visual 에서 `J` 를 치면 아무 일도 없다.** 조용히 아무 일도 없는 키가 하나 늘었다
- **`J` 를 한글 상태에서 낼 수 없다.** 다섯째다(§4)
- **`)` 만 예외다.** `]` `}` 앞에는 공백이 들어간다. vim 과 같지만 코드에서는 눈에 걸린다

## 대안

- **지우기 경로로 흉내 내기**
	- 새 파일이 없고, 이미 잘 도는 범위 계산을 그대로 쓴다.
	- 공백을 넣을지 말지가 「어디까지 지우는가」와 섞인다(§3).
	- register 에 담지 않는 예외를 지우기 쪽에 만들어야 한다.
- **`gJ` 를 같이 내기**
	- vim 과 짝이 맞고, 값이 한 줄이다.
	- 이은 자리의 공백 규칙이 둘로 갈린다(§2).
- **visual 의 `J` 를 같이 내기**
	- 고른 줄을 눈으로 보면서 잇는다.
	- `3J` 가 같은 일을 한다. ADR-0037 이 좁게 둔 키 면적이 넓어진다.
- **vim 기본값(`joinspaces`) 을 그대로 따르기**
	- 「vim 과 같다」를 설명 없이 말할 수 있다.
	- 한국어 산문과 코드에서 이은 자리에만 공백 둘인 줄이 남는다(§1).
- **설정으로 고르게 하기**
	- 양쪽을 다 준다.
	- 설정 파일이 없다. 키 하나 때문에 만들 것이 아니다(§1).
- **`J` 를 count 없이 두 줄 전용으로 두기**
	- 규칙이 한 줄로 끝난다.
	- 세는 것이 이미 파서에 있고(ADR-0081), 다섯 줄을 이으려면 `J` 를 네 번 쳐야 한다.

## 이 ADR 이 정하지 않는 것

- **`gJ`.** 미뤘다. `joinSeparator` 를 지나지 않는 길로 들어온다 (§2)
- **visual 의 `J`.** 미뤘다 (ADR-0037, §2)
- **`:[range]join`.** 미뤘다 (ADR-0046, §2)
- **`joinspaces` 같은 설정.** 설정 파일 자체가 없다 (ADR-0061)
- **주석 표시를 알아보고 잇는 것**(vim 의 `formatoptions` 의 `j`). `// foo` 와 `// bar` 를 이으면 지금은 `// foo // bar` 다
- **`gq`(줄 너비에 맞춰 다시 채우기).** 잇기의 반대 방향이고 그 자체로 결정거리다
