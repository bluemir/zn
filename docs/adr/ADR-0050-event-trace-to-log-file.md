# ADR-0050: 들어오는 이벤트를 로그로 남기고, 적을 파일이 없으면 버린다

- 상태: 채택
- 날짜: 2026-08-22

## 맥락

한글 입력기가 얽힌 버그가 쌓여 있는데 **재현 경로를 모르는 것들이 있다.** `docs/tasks.md` 의
「`하나 둘` 입력후 `둘` 이 사라진다」를 파고들었더니 가설이 셋으로 갈렸고, 셋 다 그럴듯한데
**편집기 안에서는 어느 것인지 가릴 수가 없었다.**

1. 조합 중인 글자는 커밋될 때까지 pty 로 오지 않는다(ADR-0008). 그러면 그 글자는 편집기의
   buffer 에 없고 터미널이 화면에만 그려 준다. 그 사이에 다시 그리면 지워진다.
2. 입력기가 이미 보낸 글자를 되돌리려고 backspace 를 보낸다.
3. 조합이 mode 가 바뀐 뒤에 도착해서 글자가 아니라 키로 먹힌다.

셋을 가르려면 **터미널이 무엇을 언제 보내는지**를 봐야 한다. 그것은 편집기 밖의 일이라
추론으로는 좁혀지지 않는다. 그런데 볼 자리가 없었다. `internal/core` 에는 로그를 내는 코드가
한 줄도 없었다.

낼 수 없었던 이유가 있다. 편집기는 대체 화면으로 터미널을 통째로 차지하고, **그 터미널이 곧
stderr 다.** 로그 한 줄이 나가면 화면 한가운데에 찍혀 그림이 깨진다. 기본 level 이 `Warn` 이라
여태 아무것도 안 나갔을 뿐이고, `--log-file` 은 플래그만 있고 **읽는 자리가 없었다**
(`cmd/main.go` 에 TODO 로 적혀 있었다).

## 결정

**적을 파일이 없으면 로그를 버린다.** `--log-file` 이 비면 `io.Discard` 다. stderr 로 내리지
않는다.

새로 짜낸 규칙이 아니다. 그 플래그 옆의 TODO 가 이미 「지정 하지 않으면 log 가 남지 않는다」고
적어 두었다. 뜻은 정해져 있었고 구현만 없었다. 그대로 이었다.

`tea.LogToFile` 을 쓰지 않는다. 그것은 stdlib `log` 를 걸어 주는데 이 저장소는 logrus 를 쓴다.
쓰지도 않는 로거가 설정되면 읽는 사람이 헷갈린다.

**들어오는 이벤트를 `tea.WithFilter` 한 자리에서 남긴다.** `tea.NewProgram` 을 만드는 자리가
`core.Run` 하나뿐이라 여기 한 줄로 모든 mode 의 키가 모인다. mode 마다 손대면 빠뜨린 mode 에서
고리가 끊긴다. tick 에서 이미 겪은 일이다(ADR-0038).

**받은 msg 를 언제나 그대로 돌려준다.** `nil` 을 돌려주면 그 msg 가 사라진다. 로그를 켜고 끄는
것이 편집기의 동작을 바꾸면 안 된다. 이것이 깨지면 `-vv` 로 띄운 편집기가 키를 하나도 안 먹는다.

**꺼져 있으면 문자열을 짓지 않는다.** 키마다 도는 자리라 `IsLevelEnabled` 로 첫 줄에서 끊는다.

**사람이 친 것과, 사람이 아무것도 안 쳤는데 화면을 다시 그리게 하는 것만 적는다.**
키·붙여넣기·키보드 확장이 앞엣것이고, tick 두 개(git·파일)·작업 진행·창 크기·포커스가
뒤엣것이다. 뒤엣것이 없으면 **가설 1 을 로그에서 확인할 길이 없다.** 「손을 안 댔는데 글자가
사라졌다」가 바로 그것이다. 나머지(마우스 움직임 따위) 는 적지 않는다. 다 적으면 봐야 할 것이
잡음에 묻힌다.

**키는 들고 온 것을 전부 적는다.** `Text`·`Code`·`ShiftedCode`·`BaseCode`·`Mod` 와
`String()`·`Keystroke()` 다. 코드포인트를 같이 적는다. 눈으로는 같은 글자가 다른 값일 수 있다
(호환 자모 `ㅁ` U+3141, 음절 자모 `ᄆ` U+1106).

`String()` 은 `Text` 를 앞세우고 `Keystroke()` 는 `BaseCode` 를 쓴다(ADR-0014). **둘이 갈리는
순간이 곧 입력기가 끼어든 순간이라** 나란히 적는다.

## 근거

**mode 이름은 type 으로 가르고 공통 메서드를 두지 않는다.** ADR-0002 가 「밖에서 지금 어느
mode 냐를 묻기 어렵다」를 일부러 그렇게 두었다. 진단 하나 때문에 그 설계를 뒤집을 일이 아니다.
빠뜨린 type 은 `%T` 로 그대로 드러나서 조용히 사라지지 않는다.

**`BaseCode` 는 이미 켜져 있다.** `newView` 가 `ReportAlternateKeys` 를 걸어 둔다(ADR-0014).
다만 escape code 로 오는 키에만 붙어서 평범한 글자 키에는 없다. `ctrl+ㅔ` 에는 `p` 가 붙고
`ㅁ` 에는 없다. **비어 있다는 것도 적어야 알 수 있어서** 그대로 적는다.

## 감수하는 것

- **`internal/core` 가 logrus 를 알게 됐다.** 여태 이 패키지는 로그를 몰랐다. 대신 나가는 곳이
  한 자리(`traceEvent`) 뿐이고 꺼져 있으면 첫 줄에서 빠져나온다.
- **`--log-file` 없이 `-v` 를 켜면 아무 로그도 안 남는다.** 놀랄 수 있어서 플래그 도움말에 적었다.
- **로그 파일은 이어 쓰고 저절로 지워지지 않는다.** 여러 번 재현해서 견주는 일이 있어서 띄울
  때마다 지우면 방금 잡은 것을 잃는다. 지우는 것은 쓰는 사람 몫이다.
- **`SetReportCaller` 가 켜져 있어서 줄마다 `trace.go:36` 이 붙는다.** 진단 줄에는 쓸모가 없는데
  끄면 다른 로그까지 같이 꺼진다. 그대로 두었다.
- **평범한 글자 키의 물리 키는 여전히 모른다.** `ReportAllKeysAsEscapeCodes` 를 켜면 알 수
  있지만 키 처리 전체가 바뀐다. 이 로그로 값이 있는지부터 잰다(`docs/tasks.md`).

## 대안

- **mode 마다 로그를 넣기**
	- 빠뜨린 mode 에서 고리가 끊긴다. ADR-0038 이 겪은 그대로다.
- **stderr 로 내보내고 사용자가 리다이렉트하게 하기**
	- 편집기가 stdin/stdout/stderr 를 다 쥐고 있어서 리다이렉트해도 대체 화면과 섞인다.
	- 파일을 받는 편이 확실하다.
- **따로 `--trace` 플래그를 두기**
	- level 이 이미 있고, 진단을 켜는 손짓이 둘이 될 이유가 없다.
