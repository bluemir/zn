# ADR-0024 다른 파일에 쓰기

## Status

Accepted

## Context

`:tabnew` 로 만든 tab 은 저장할 방법이 없었다. 이름이 없어서 `:w` 가 「파일 이름이 없습니다」로
끝나고, 이름을 주는 명령이 없었다. 임시 메모장으로만 쓸 수 있는 tab 이었다.

명령줄은 ADR-0021 에서 이미 인자를 받게 되었고 `:e` 와 `:tabnew` 가 파일 이름을 쓰고 있다.
`:w <파일>` 을 막고 있던 것은 인자가 붙은 `:w` 를 「알 수 없는 명령」으로 튕기는 한 줄뿐이었다.
그러니 정할 것은 배관이 아니라 의미다.

vim 에는 이 자리에 명령이 둘 있다. `:w {file}` 은 그 파일에 내용을 쓰지만 buffer 는 원래 파일에
계속 붙어 있고(사본 쓰기), `:saveas {file}` 은 buffer 의 이름까지 그 파일로 옮긴다. 다만
이름 없는 buffer 에서는 `:w {file}` 이 이름까지 준다. 붙어 있을 원래 파일이 없기 때문이다.

vim 9.1 로 실제로 확인한 값이다.

| 해 본 것 | vim 9.1 |
|---------|---------|
| 이름 없는 buffer 에 `:w a_new.txt` | `bufname=a_new.txt`, `modified=0`. 이름을 받는다 |
| `b.txt`(변경 있음) 에서 `:w b_copy.txt` | `bufname=b.txt`, `modified=1`, `b.txt` 무손상. 사본이다 |
| 있는 파일에 `:w c.txt` | 쓰지 않는다(E13). `:w!` 는 덮어쓴다 |
| `b.txt` 에서 `:w ./b.txt` | 그냥 쓴다. `modified=0`. 제자리 저장이다 |
| `b.txt` 에서 `:wq e_out.txt` | 사본을 쓰고 닫는다. `b.txt` 의 편집은 사라진다 |
| `:e b.txt` 뒤 `:tabnew b.txt` | buffer 1 개, tab 2 개. 같은 파일은 buffer 를 공유한다 |

여기에 이미 정해 둔 규칙 둘이 걸린다.

- **모르고 덮어쓰지 않는다**(ADR-0015). 저장 직전에 파일을 다시 읽어 읽은 시점의 해시와 맞춰
  본다. 그런데 다른 파일은 읽은 적이 없어서 맞춰 볼 기준이 아예 없다.
- **같은 파일을 두 tab 에 열지 않는다**(ADR-0021). tab 마다 Buffer 가 독립이라 같은 파일이
  둘이면 한쪽 저장이 다른 쪽 편집을 조용히 덮어쓴다.

## Decision

### `:w <파일>` 은 사본을 쓴다

이름 있는 buffer 에서 `:w <파일>` 은 그 파일에 내용을 쓰기만 한다. 보고 있는 파일도 tab 이름도
dirty 표시도 그대로라, 이어지는 `:w` 는 여전히 원래 파일에 쓴다. vim 과 같다.

이름을 갈아치우는 쪽(`:saveas`) 으로 합치는 길도 있었다. 명령 하나로 두 뜻을 겸하면 손이
덜 가지만, "지금 파일은 손대지 않고 이 내용을 저기에도 남긴다" 를 표현할 길이 사라진다.
그리고 이름이 조용히 옮겨가는 것은 되돌릴 명령이 없어서 잘못 쳤을 때 손해가 크다.

`:saveas` 는 두지 않았다. 필요해지면 그때 이름으로 넣는다. 두 뜻이 두 이름으로 갈려 있는
쪽이 나중에 늘리기도 쉽다.

### 이름 없는 buffer 만 이 저장으로 이름을 받는다

붙어 있을 원래 파일이 없으므로 사본이라는 말이 성립하지 않는다. `:tabnew` 로 만든 tab 은 이
저장으로 그 파일의 buffer 가 되고, dirty 가 꺼지고, 방금 쓴 내용이 이후 바깥 변경 검사의
기준이 된다. vim 과 같은 나눔이다.

아래 줄 문구도 갈라 둔다. 이름을 받은 쪽은 「저장함: <파일>」이고 사본 쪽은
「사본을 씀: <파일>」이다. 같은 문구를 쓰면 tabline 의 이름이 그대로인 것이 실패로 읽힌다.

### 이미 있는 파일이면 쓰지 않는다. `:w!` 가 덮어쓴다

ADR-0015 의 해시 비교를 여기에 쓸 수 없으니 있는지 없는지만 본다. vim 의 E13 과 같다.

그냥 덮어쓰는 길도 있었다(셸의 `>` 처럼). 하지만 ADR-0015 가 막으려던 것이 "무엇을 지우는지
모르고 쓰는 것" 이고, 남의 파일에 쓰는 이쪽이 오히려 잃는 것이 크다. 자기 파일은 undo 이력이
손에 있지만 남의 파일에는 그것이 없다.

`!` 의 뜻은 인자 유무에 따라 갈린다. 인자가 없으면 "밖에서 바뀐 파일도 덮어쓴다"(ADR-0015),
있으면 "이미 있는 파일도 덮어쓴다" 다. 둘 다 "묻지 말고 해라" 의 같은 얼굴이라 ADR-0021 의
「`!` 는 어느 쪽이든 묻지 말라」와 어긋나지 않는다.

### `:w <보고 있는 파일>` 은 그냥 `:w` 다

쓸 곳이 보고 있는 파일과 같으면 사본이 아니라 제자리 저장이다. 사본 쪽으로 보내면 자기 파일에
「이미 있습니다」로 막히고, `!` 를 붙여 통과시켜도 dirty 가 남아 저장한 것으로 보이지 않는다.

같은 파일인지는 경로를 정규화해서 본다(`samePath`). `:w ./a.txt` 도 제자리 저장이다.

### 이름을 붙이려는 파일이 다른 tab 에 열려 있으면 막는다

이름을 받는 경우에만 걸리는 규칙이다. 이름이 붙는 순간 같은 파일에 Buffer 가 둘이 되어
ADR-0021 이 막아 둔 자리로 들어간다. 그래서 쓰지도 않고 「그 파일은 이미 다른 tab 에 열려
있습니다」로 끝낸다.

**vim 에는 이 상황 자체가 없다.** vim 은 같은 파일을 두 tab 에 열어도 buffer 하나를 둘이
나눠 쓴다(위 표). buffer 를 tab 마다 독립으로 둔 것이(ADR-0001) 여기서 값을 치르는 자리라,
이 규칙은 vim 을 따른 것이 아니라 그 구조에서 나온 것이다.

`:e`·`:tabnew` 처럼 그 tab 으로 옮겨가는 길은 여기서 쓸 수 없다. 그쪽은 사용자가 원한 것이
"그 파일을 보는 것" 이라 옮겨가면 목적이 이뤄지지만, 이쪽이 원한 것은 "지금 손에 든 내용을
저장하는 것" 이고 옮겨가면 그 내용이 어디에도 남지 않는다.

사본을 쓰는 경우는 걸리지 않는다. Buffer 가 늘지 않기 때문이다. 그 tab 이 들고 있는 내용이
파일과 어긋나게 되지만, 그것은 바깥에서 파일이 바뀐 것과 같은 상태이고 이미 ADR-0015 가
다루고 있다. 그 tab 에서 저장하려 하면 막히고 `:e` 로 가져온다.

### `:wq <파일>` 과 `:x <파일>` 은 받지 않는다

인자가 붙으면 그대로 「알 수 없는 명령」이다. `:w` 만 받는다.

**vim 은 받는다.** 여기는 일부러 따르지 않았다. vim 에서 `:wq e_out.txt` 를 해 보면 사본을
쓰고 창을 닫는데 원래 파일의 편집은 그대로 사라진다(위 표). 한 명령이 인자에 따라 "잃는다" 와
"잃지 않는다" 로 갈리는 것이고, 하필 잃는 쪽이 `:w` 를 쳤으니 저장됐으리라 믿는 자리다.

이름을 받은 경우에만 저장하고 닫는 것으로 좁힐 수도 있지만, 그러면 같은 명령이 tab 에
이름이 있는지에 따라 갈린다. 필요해지면 그때 다시 본다.

## Consequences

- `:tabnew` 로 만든 tab 을 저장할 길이 생겼다. 이름 없는 tab 이 임시 메모장에서 벗어났다.
- `Buffer.write` 에서 내용을 만드는 부분이 `contents()` 로 갈라져 나왔다. 쓸 곳이 두 군데가
  되었기 때문이다. `write` 는 `buf.path` 에, `saveTo` 는 받은 경로에 쓴다.
- `Save`/`SaveForce` 와 나란히 `SaveTo`/`SaveToForce` 가 생겼다. 검사만 다르고 쓰는 것은 같아서
  `Save(force bool)` 로 합칠 수도 있지만, 이미 있는 짝의 모양을 따랐다.
- `tabOf` 가 쓰던 경로 정규화가 `samePath` 로 나왔다. `:w <보고 있는 파일>` 판정이 같은 기준을
  써야 해서다.
- `:w` 마다 `git status --porcelain` 이 도는 것은 사본을 써도 마찬가지다. 저장소가 dirty 가
  되는 것은 어느 쪽이든 같다(ADR-0009).
- 사본은 밖에서 바뀌었는지 추적하지 않는다. `:w copy.txt` 를 두 번 치면 두 번째는
  「이미 있습니다」다. 첫 번째로 자기가 쓴 것이어도 그렇다. 사본은 buffer 가 기억하는 파일이
  아니라서 구분할 길이 없다.
- 이름을 받은 뒤에도 undo 이력은 그대로다. 파일을 새로 연 것이 아니라 지금 내용을 어딘가에
  둔 것이라 `:e` 의 갈아끼우기와 다르다(ADR-0021).
