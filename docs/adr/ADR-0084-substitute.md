# ADR-0084 치환은 `:s` 하나이고 문법은 vim 것을 쓴다

- 상태: 채택
- 날짜: 2026-08-26
- 관련: ADR-0010(`/` 검색의 패턴 문법), ADR-0046(명령줄의 줄 범위), ADR-0077(`:grep` 이 뒤를 통째로 받는 자리), ADR-0017(복사 알림), ADR-0008(한글 입력 상태의 키)

## 맥락

`docs/tasks.md` 의 v1.1 첫 줄이 「`:%s/a/b/g` 치환을 넣는다. 패턴 문법은 검색과 같다.
범위를 받는 자리는 이미 있다」였다. **빌려 쓸 것 둘이 이미 서 있다** — 패턴은
`parseSearchPattern` 이 정한 RE2 이고(ADR-0010) 범위는 `cmd.lines.resolve` 가 준다(ADR-0046).

그래서 이 결정이 새로 정할 것은 다섯이다. 구분자, 바꿀 글의 문법, flag, 한 자리씩 물어보는
`c`, 그리고 **이름 뒤가 공백으로 갈리지 않는다는 사실을 명령줄 파서가 어떻게 아느냐**다.
마지막 것은 고를 여지가 없는 일거리이고, 나머지 넷이 갈림이다.

## 1. 구분자는 아무 글자나 쓴다

`:%s/a/b/g` 가 보통이지만 **첫 글자가 곧 구분자다.** vim 과 같다.

값은 경로를 바꿀 때 나온다. `:%s#internal/core#internal/ui#` 를 `/` 로만 쓰면
`:%s/internal\/core/internal\/ui/` 가 되고, 이것은 눈으로 읽어 옳은지 확인할 수 있는 줄이
아니다. 이 저장소에서 치환이 가장 자주 쓰일 자리가 경로와 import 라 그 자리를 막을 값이 없다.

**구분자가 될 수 없는 글자가 넷 있다.** 영문자·숫자는 이름을 이어갈 수 있어서(`:substitute`
의 가운데 글자들이 그 자리다) 안 되고, 공백은 `:s /a/b/` 처럼 띄어 쓴 것을 받아야 해서 뺀다.
`\` 는 막는 글자, `"` 는 명령줄의 따옴표라 뺀다. vim 도 이 넷을 뺀다. ASCII 만 받는다 —
한글이 구분자가 되는 자리를 만들 값이 없다.

**`!` 는 여기서 강제가 아니라 구분자다.** `:s!a!b!` 는 vim 에서 쓰는 형태이고, `:s` 에는
강제할 것이 애초에 없다(`:q!` 의 `!` 는 「잃을 것이 있어도」인데 치환에는 그런 물음이 없다).

## 2. 파서는 「이름 다음 글자」로 이름의 끝을 안다

지금 tokenizer 는 이름을 **공백에서** 끊는다. `:%s/a/b/g` 는 공백이 없어서 `s/a/b/g` 가
통째로 이름 토큰이 되고, 도중의 `\` 는 `tokenEscaped` 를 지나며 뒤 글자 하나를 뜻 없이
먹는다 — `:%s/a\/b/c/` 가 `:%s/a/b/c/` 로 바뀌어 **정규식이 조용히 다른 뜻이 된다.**

ADR-0077 이 `:grep` 에서 겪은 것과 같은 자리다. 그때는 「이 이름은 뒤를 통째로 받는다」
(`takesRawArgument`) 를 공백에 걸어 풀었는데, `:s` 는 공백조차 없으므로 한 겹이 더 든다.

**`takesDelimitedArgument` 가 그 겹이다.** 모으던 이름이 `s`·`substitute` 이고 다음 글자가
구분자면 거기서 이름 토큰을 내고 나머지를 `tokenRest` 로 넘긴다. 뒤쪽 상태 기계는 달라지지
않는다 — 이름 토큰 하나와 뜯지 않은 한 줄 하나가 오는 것은 `:grep` 과 똑같은 모양이다.

**`:s /a/b/` 도 받는다.** 그쪽은 공백에서 끊기므로 `takesRawArgument` 에 이름을 더하는 것으로
끝난다. 그래서 표가 둘이 되었고, 둘이 답하는 물음이 다르다 — 하나는 「인자를 뜯을 것인가」,
다른 하나는 「이름이 여기서 끝났는가」다.

`takesRawArgument` 는 여태 `grep` 하나뿐이라 표가 아니라 등식 하나였다. 둘째가 와서 표가
됐다 — 그 주석이 예고한 그대로다.

## 3. 바꿀 글은 vim 의 `&`·`\1` 이다

Go 정규식은 `${1}` 로 잡은 것을 쓴다. 그대로 열면 번역기가 없어서 제일 작은데, **`$` 가
코드에 흔한 글자다.** 셸 변수(`$PATH`), 정규식의 줄 끝(`$`), jQuery 와 템플릿이 다 `$` 를
쓴다. 바꿀 글에 `$1` 을 쳤을 때 그것이 글자가 아니라 잡은 것이 되는 것은 사고가 난 뒤에야
안다 — 치환은 파일 전체를 한 번에 고치는 명령이라 사고의 값이 크다.

vim 문법을 받고 옮긴다. 옮기는 자리는 `parseReplacement` 하나다.

| 친 것 | 뜻 | Go 로 |
|---|---|---|
| `&` | 잡은 것 전체 | `${0}` |
| `\0` … `\9` | 잡은 것 | `${0}` … `${9}` |
| `\&` | `&` 한 글자 | `&` |
| `\t` | tab | tab |
| `\x` | 그 밖의 글자는 그대로 | `x` |
| `$` | 사람이 친 `$` 는 글자다 | `$$` |

**`\t` 가 표에서 유일하게 규칙을 벗어난다.** 「`\` 뒤는 그 글자」로 두면 `\t` 가 `t` 가
되는데, **명령줄에서 tab 글자를 낼 다른 길이 없다** — tab 키는 글자를 주지 않는다. 넣을 수
없는 것을 넣는 길이라 예외를 둔다.

**줄을 가르는 것(vim 의 `\r`) 은 넣지 않는다.** 줄 수가 바뀌면 되돌리기 구간의 범위와
`growEdit` 이 따라 들어오고, 물어보며 바꾸는 쪽은 「범위의 끝 줄이 시작할 때 정한 그 줄」
이라는 전제를 잃는다. 값에 비해 짐이 크다.

## 4. flag 는 `g`·`i`·`c` 셋이다

`g` 는 한 줄의 모든 자리, `c` 는 한 자리씩 물어보기, `i` 는 대소문자 무시다.

**`i` 를 `:s` 가 스스로 처리하지 않는다.** `g`·`c` 를 걷어낸 나머지를 `compilePattern` 에
넘기고, 그것이 `(?i)` 를 앞에 붙이거나 「모르는 flag」로 거절한다. 이 함수는 `/` 검색의
`parseSearchPattern` 몸통을 떼어낸 것이라 **모르는 flag 를 거절하는 자리가 저장소에 하나로
남는다** — 둘로 나뉘면 `/pat/z` 와 `:s/a/b/z` 가 다른 말을 하게 된다.

**`/` 검색의 「뒤에 붙은 `/flag`」 문법은 `:s` 에 없다.** flag 자리가 셋째 구분자 뒤로 이미
정해져 있어서다. 이것을 그대로 두면 구분자가 `#` 일 때 `:%s#abc/i#x#` 의 패턴에서 `/i` 를
flag 로 떼어 가 **찾는 것이 조용히 달라진다** — 그래서 `:s` 는 `parseSearchPattern` 을
부르지 않고 `compilePattern` 을 직접 부른다.

**`n`(세기만) 과 `e`(오류 내지 않기) 는 넣지 않았다.** `n` 은 「바꾸기 전에 몇 곳인지 본다」인데
그 일은 `/` 로 찾아 놓고 `:s//` 를... 도 아직 없으니 지금은 `:grep` 이 답한다. `e` 는 스크립트를
위한 것인데 스크립트가 없다.

## 5. `c` 는 편집 화면 그대로에서 묻는다

새 화면을 만들지 않았다. **커서를 지금 물어보는 자리에 세우고 아래 줄이 묻는다.**

**칠하는 것을 따로 만들지 않았다.** `:s` 는 찾은 패턴을 마지막 검색으로 굳히는데(vim 과
같다) 그러면 화면의 매칭이 저절로 칠해지고, ADR-0010 이 「커서가 선 매칭만 색이 다르다」로
둔 규칙이 **지금 물어보는 한 자리**를 정확히 가리킨다. 이 일을 위해 만들어 둔 것이 아닌데
그대로 맞았다.

패턴을 굳히는 것은 물어보지 않을 때도 한다. `n` 으로 남은 자리를 훑을 수 있다.

키는 넷이다.

| 키 | 하는 일 |
|---|---|
| `y` | 바꾸고 다음으로 |
| `n` | 두고 다음으로 |
| `a` | 남은 것 전부 |
| `q` `esc` | 그만 |

**vim 의 `l`(이것만 하고 그만) 은 두지 않았다.** `y` 다음 `q` 로 같은 일을 하고, 마지막
하나에서만 키가 하나 더 드는 것이 새 키 하나의 값보다 싸다.

넷 다 두벌식 자리에 있어서 한글 입력 상태에서도 낸다(`ㅛ` `ㅜ` `ㅁ` `ㅂ`). 키가 곧 답인
자리라 확인창들과 같이 `expandHangul` 을 지난다(ADR-0008).

**답하는 사이에 buffer 가 갈아끼워질 수 있다.** 바깥 파일 검사는 mode 를 보지 않고 `dirty`
하나로 판정하는데(ADR-0044), 아직 `y` 를 한 번도 안 쳤으면 dirty 가 서 있지 않아서 밖에서
바뀐 파일을 그 자리에서 읽어 들인다. 그러면 시작할 때 정한 끝 줄도 찾아 둔 자리도 남의 글을
가리킨다 — 키를 받는 문 앞에서 알아채고 **그 자리에서 멈춘다**(`stale`). 하나라도 바꿨으면
dirty 가 서 있어서 그 길이 막혀 있으므로, 멈출 때 닫을 되돌리기 구간도 없다.

검사 쪽을 고치지 않았다. 「mode 를 보지 않는다」가 ADR-0044 의 결정이고, 그것을 뒤집으면
mode 가 늘 때마다 그 판정에 줄이 하나씩 는다 — 알아채는 쪽이 한 자리인 편이 싸다.

**답하는 동안에는 작업 결과가 mode 를 바꾸지 못하게 막았다.** 여기는 되돌리기 구간을 연 채
서 있는 자리라, 언어 서버의 답(`\gd` 의 고르는 화면) 이 사람을 끌어내면 그 구간이 열린 채
남아서 **다음 편집이 이 치환에 딸려 들어간다.** 진행도와 tick 은 그대로 받는다 — 흘려보내면
다음 조각을 받을 Cmd 를 아무도 발행하지 않아 작업이 멈춘다.

## 6. 되돌리기는 한 번 친 것마다 하나다

`:%s/a/b/g` 가 백 줄을 고쳐도 `u` 한 번에 다 돌아온다. `:1,5d` 가 지운 줄들을 한 묶음으로
되돌리는 것과 같은 자리다(ADR-0046).

물어보며 바꾼 것도 마찬가지다 — **한 판이 한 구간이다.** `y` 를 열 번 쳤어도 그것은 한 번
부른 명령이다. 구간은 **처음 `y` 를 칠 때** 열고 판이 끝날 때 닫는다.

**하나도 안 바뀌면 구간을 열지 않는다.** `beginEdit` 는 dirty 를 세우고 되돌아갈 앞날(redo)
을 버리므로, 못 찾은 `:s` 가 파일을 건드린 것이 된다. `~` 가 한글 위에서 파일을 그대로 두는
것과 같은 까닭이다(ADR-0083).

## 7. 짧게 치는 길은 마지막 구분자 하나만 연다

`:%s/a/b` 는 `:%s/a/b/` 와 같다. 그 뒤에 올 것이 flag 뿐이라 **없는 것과 비어 있는 것이 같다.**

나머지 생략은 열지 않았다.

- **빈 패턴이 마지막 검색이 되지 않는다.** vim 은 `/foo` 로 찾아 놓고 `:%s//bar/g` 를
  치는 길을 주는데, 눈에 보이지 않는 상태가 무엇을 바꿀지를 정하게 된다. 파일 전체를 한 번에
  고치는 명령에서 그 상태는 화면에 있어야 한다
- **`:s` 만 쳐서 마지막 치환을 되풀이하지 않는다.** 기억할 상태가 하나 더 생기고, 그것을
  볼 자리(`:registers` 같은 것) 가 없다. `:!!`(마지막 셸 명령) 과 한 건이고 까닭도 같다
  (ADR-0045). **영영 닫는 것이 아니라 필요해지면 그때 다시 본다** — 그때는 「명령줄 이력」과
  한 건일 것이다. 보이는 목록에서 고르는 것이면 「무엇을 되풀이하는지가 화면에 없다」는 이
  까닭이 없어진다
- **`:%s/a` 는 오류다.** 바꿀 글을 대지 않은 것이고, vim 처럼 「빈 글로 바꾼다」로 읽으면
  손이 미끄러져 끊긴 명령이 조용히 지우는 명령이 된다

## 결과

좋은 점

- `:%s/a/b/g`·`:1,5s/a/b/`·`:s/a/b/` 가 vim 그대로 먹는다. 범위 문법은 `:d`·`:y` 와 같은 것이다
- 경로를 바꿀 때 escape 가 없다 — `:%s#internal/core#internal/ui#`
- 잡은 것을 되쓴다 — `:%s/(\w+)Buffer/\1Screen/g`
- `c` 가 편집 화면에서 물어서, 무엇을 바꾸는지가 **문맥과 함께** 보인다
- 한 번의 `u` 로 전부 돌아온다. 물어보며 고른 것들도 하나다
- 못 찾으면 파일도 되돌리기 이력도 그대로다
- 모르는 flag 를 거절하는 자리가 `/` 검색과 하나다

감수하는 것

- **패턴이 vim 문법이 아니다.** `\(` `\|` `\<` 가 안 먹는다. `/` 검색이 이미 진 값이고
  둘이 같은 것이 다른 것보다 낫다(ADR-0010)
- **바꿀 글만 vim 문법이다.** 찾는 쪽은 RE2 인데 바꾸는 쪽은 `\1` 이라 한 줄 안에서 `\` 의
  뜻이 두 번 갈린다. `$1` 이 글자로 남는 값이 그보다 크다고 봤다
- **줄을 넘는 치환이 없다.** 검색이 줄 단위인 것과 같은 자리다
- **바꿀 글로 줄을 가를 수 없다.** vim 의 `\r` 이다
- **`:s` 만 쳐서 되풀이할 수 없다.** 같은 것을 또 하려면 다시 친다
- **여러 파일 치환은 아직 없다.** `:grep` 이 여는 길이고 그쪽에서 같이 본다
- **`:s///c` 로 답하는 동안 언어 서버의 답이 화면을 열지 않는다.** 목록에는 남는다

## 대안

**`$1` 을 그대로 열기** — 번역기가 없다. 코드에 흔한 `$` 가 조용히 다른 뜻이 되고, 그것을
알아채는 것은 파일 전체가 바뀐 뒤다.

**잡은 것을 아예 안 받기(`ReplaceAllLiteral`)** — 제일 작다. 치환을 쓰는 절반이 「이름의 일부만
바꾸기」라 그 절반이 빠진다.

**구분자를 `/` 로만 두기** — 규칙이 하나다. 경로를 바꿀 때마다 `\/` 를 손으로 넣게 되고,
그 줄은 눈으로 읽어 옳은지 확인할 수 없다.

**`c` 를 새 화면(drawer) 으로 만들기** — `:grep` 과 같은 손이 된다. 물어보는 것은 목록이
아니라 한 자리라 둘러볼 것이 없고, 편집 화면이 그대로 보이는 것이 그 자리에 필요한 전부다.

**`c` 를 안 넣기** — 이번 일이 절반이 된다. 파일 전체를 한 번에 고치는 명령에서 「보고
고르기」가 빠지면, 넓게 걸리는 패턴은 `u` 로 되돌리고 패턴을 좁히는 것을 되풀이하게 된다.

**`:s` 를 팔레트에 얹기** — 다른 명령들처럼 이름으로 찾을 수 있다. 팔레트의 명령들은 인자
없이 서거나 박스를 여는 것들인데, 치환은 받을 것이 패턴·바꿀 글·flag 셋이라 그 박스가
명령줄과 같은 것이 된다.

## 이 ADR 이 정하지 않는 것

- **여러 파일 치환.** `:grep` 이 여는 길이고 작업(job)·되돌리기·저장이 다 다른 물음이다
- **`:'<,'>`(visual 로 고른 범위) 와 마크 주소.** visual 을 나갈 때 확정된 범위를 남기는 것이
