# ADR-0049: sticky 머리줄은 본문 위에 덮어쓰고, 커서를 그 아래로 밀어낸다

## 상태

받아들임

## 배경

문서를 읽다 보면 화면 위로 올라가 버린 제목이 무엇이었는지 잊는다. VSCode 의 sticky scroll 이
감싸는 제목·정의를 화면 맨 위에 붙여 두어 「지금 보는 곳이 어디인가」를 늘 보여준다.
`docs/tasks.md` 가 markdown 과 golang 에 각각 적어 두었던 것이다.

ADR-0047 이 자리를 미리 깔아 두었다. `codeBytes` 를 만들면서 「sticky header 와 autoindent 가
같은 토큰을 쓸 수 있다」고 적었고, autoindent 가 먼저 그 길을 썼다.

## 결정

### 자리를 떼지 않고 덮어쓴다

`editorView` 가 만든 `textRows` 의 앞 몇 개를 머리줄로 갈아끼운다. **행 수가 그대로다.**

자리를 떼려면 `textHeight()` 를 줄여야 하는데, 붙는 줄 수가 스크롤에 따라 바뀌므로 화면
높이가 스크롤마다 흔들린다. `sidebarHeight() = tablineHeight + textHeight()` 라서 sidebar
까지 같이 늘었다 줄었다 한다. 덮어쓰면 `textHeight`·`sidebarHeight`·`visibleRows`·
`positionAt`·`cursorScreenPos`·`regionAt` 이 하나도 바뀌지 않는다.

### 합성기를 쓰지 않는다

붙이는 것이 폭 전체를 쓰는 행이라 문자열을 통째로 갈아끼우면 된다. ADR-0011 의 셀 버퍼
비용(화면 문자열이 통째로 다시 쓰인다) 이 아예 없고, 머리줄이 없는 화면은 이 기능을 넣기 전과
**한 글자도 다르지 않다.** 기존 테스트가 한 줄도 바뀌지 않은 것이 그 증거다.

### 머리줄 수와 top 은 서로를 보므로 되풀이로 맞춘다

붙는 줄 수는 `top` 에서 나오고, 커서가 덮이지 않으려면 `top` 이 그 줄 수만큼 더 올라가야 한다.
한 번 셈으로는 안 맞고, **단순히 대입하면 진동한다.** 감싸는 줄 수가 줄 번호에 대해 단조가
아니라서 `top` 이 두 값을 오간다.

`top` 이 **위로만 가는 갈래만** 두어 끝낸다. 한 바퀴마다 `top` 이 최소 한 행 올라가고 `top` 이
0 이면 감싸는 것이 없다. 바퀴 수도 못 박는다. 판정이 틀려도 편집기가 멈추지 않게 하는 자물쇠다.

`scrollTo` **안에** 둔다. 여백을 인자로 빼면 `action.go` 의 스무 곳 중 하나가 빠뜨리는 순간
커서가 머리줄 밑에 조용히 숨는다. 인자를 안 늘려서 기존 부름도 그대로다.

### 뼈대는 언어가 안다. `Outline` 은 표의 세 번째 칸이다

`State`·`Indent` 와 나란한 세 번째 언어별 값이다. `Depth(line, tokens) int` 와
`Heads(line, tokens) bool` 둘뿐이고, 깊이를 화면에 어떻게 보일지는 core 가 정한다.

여섯 언어(go js css python shell html) 가 `blockOutline` 하나를 나눠 쓰며 들여쓰기 규칙에
「이 줄이 블록을 여는가」를 되묻는다. **나머지 셋은 그럴 수 없다:**

- `makeIndent.Next` 는 대상 줄에 단계가 아니라 tab prefix 를 낸다(단계가 0 이다). 그대로
  쓰면 makefile 에 머리줄이 하나도 없다.
- `dockerIndent.Next` 는 `\` 로 이어지는 줄에 단계 1 을 낸다. 이어짐은 거느림이 아니다.
- markdown 의 제목은 들여쓰기와 무관하다.

markdown 은 **토큰으로** 제목을 가린다. `mdFence.Lex` 가 `KindHeading` 을 내보내지 않으므로
코드펜스 안의 `# 주석` 이 제목이 되지 않는다(ADR-0040). 원문을 `#` 로 훑으면 이것이 깨진다.

### 지나는 줄마다 한계를 낮춘다

위로 훑으며 「지금까지 본 것보다 얕은 줄」만 거둔다. **머리줄만 보고 낮추면 이미 닫힌 블록이
되살아난다:**

```go
func alpha() {
    if a {
        x()
    }
    s := "text" +
        "more"      // 여기서 위를 보면 닫힌 `if a {` 가 붙는다
```

지나는 줄마다 낮추면 닫는 줄(`}`) 이 그 블록과 같은 깊이라 여는 줄이 저절로 걸러진다.
**파일 전체의 괄호를 세지 않고 닫힘을 아는 것이 이 규칙 하나다.**

그러려면 「깊이를 말할 수 없는 줄」이 있어야 한다(`OutlineDeep`). 빈 줄과 여러 줄에 걸친
문자열·주석 안의 줄이다. 이것이 없으면 raw string 안에 왼쪽 끝으로 붙여 쓴 SQL 한 줄이 그
위의 함수를 통째로 가리고, 함수 안의 빈 줄 하나가 훑기를 거기서 끝낸다.

### 늘 켜져 있고, 화면 절반이 상한이다

이 편집기에는 설정이 없다(README). 강조하지 않는 파일에서는 뼈대 규칙도 없어서 저절로 없다.

깊게 중첩된 코드에서 화면이 통째로 머리줄이 되지 않게 `textHeight/2` 를 넘지 않는다. 넘치면
**바깥쪽부터 버린다.** 가장 안쪽이 방금 사라진 것이라 잃으면 가장 아깝다. 40 행 화면에서
20 겹이 필요하므로 정책이 아니라 자물쇠다.

### 본문과 색으로 가르지 않는다

새 색도 구분선도 넣지 않는다. 줄번호 칸이 그대로 있어서 번호가 뚝 끊기는 것(`3` 다음 `47`)
으로 머리줄임이 읽힌다. 상대번호는 그 줄까지 가는 실제 `k` 수다.

그 때문에 딸려 온 고침이 하나 있다. 상대번호 칸은 화면 높이까지만 잡는데(`lineNumberDigits`)
머리줄은 화면 밖에서 온다. `%*d` 의 폭은 **최소**라 넘치면 그대로 늘어나고, 한 칸이라도
넘치면 행이 편집 영역보다 넓어져 터미널이 접는다. 그 아래가 통째로 밀리고 sidebar 칸까지
어긋난다. 넘치면 그 칸을 비운다.

### 머리줄을 누르면 그 줄로 간다

VSCode 와 같다. **무시하는 선택지가 없다.** 그대로 두면 `positionAt` 이 덮인 줄을 돌려주어
눌러서 보이는 글자와 커서가 어긋난다.

## 감수하는 것

- **본문 몇 줄이 가려진다.** 화면 기하가 하나도 안 바뀌는 값이다.
- **닫힌 블록이 잠깐 붙어 보일 수 있다.** 머리줄은 `top` 을 감싸는 것인데 `top` 부터 몇 줄이
  그 머리줄에 덮이므로, `top` 이 블록 끝자락일 때 화면에 보이는 본문은 이미 그 블록 밖이다.
  맞는 답이지만 눈에는 어긋나 보인다. 보이는 첫 줄로 기준을 옮기면 그 값이 다시 자기를
  참조해서 같은 진동을 부른다. 지금은 두지 않는다.
- **`k` 로 올라갈 때 화면이 커서보다 먼저 움직인다.** vim 의 `scrolloff` 를 위에만 둔 느낌이다.
- **`scrollTo` 가 순수한 화면 함수가 아니게 됐다.** 되풀이를 돌고 문법 캐시를 본다.
- **머리줄에는 검색·선택 색이 없다.** 화면 밖 줄이라 여기서만 강조하면 어느 쪽이 지금
  자리인지 흐려진다.
- **긴 머리줄은 잘리고 잘렸다는 표시가 없다.** 자르는 자리는 `wrapOffsets` 가 준다.
- **들여쓰기를 깊이로 삼는 것은 어림이다.** 관례대로 쓴 코드에서는 정확하고, tab 과 space 를
  섞은 파일에서는 어긋난다. `switch` 가 `case` 에 가리고 `} else {` 는 머리줄이 아니다.
  전부 머리줄이 **덜** 붙는 쪽으로 틀린다. 없는 것을 붙이지는 않는다.
- **깊이 0 인 줄이 위에 없는 파일에서는 훑기가 파일 처음까지 간다.** 거슬리면 `syntaxLine` 에
  깊이 칸을 더한다.

## 대안

- **자리를 떼기(reserve).** 본문이 안 가려지지만 화면 높이가 스크롤마다 흔들리고 sidebar 까지
  따라 흔들린다. 그리고 되풀이 문제가 사라지지 않는다. 오히려 여섯 함수에 높이 인자가 는다.
- **`lipgloss` 합성기로 겹치기.** ADR-0011 이 이미 길을 냈지만, 셀 버퍼를 지나면 화면 문자열이
  통째로 다시 쓰여서 머리줄이 없는 화면까지 바뀐다.
- **파일 전체의 괄호를 세어 정확한 깊이 얻기.** 키 하나마다 파일 크기에 비례한 일이 된다.
