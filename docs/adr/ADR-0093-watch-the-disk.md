# ADR-0093 감시기를 안에 들고 간다. 이벤트는 판정이 아니라 앞잡이다

- 상태: 채택
- 날짜: 2026-08-28
- 관련: ADR-0092(gopls 에 디스크 변경 알리기), ADR-0044(파일 검사를 작업으로), ADR-0038(밖에서 바뀐 파일), ADR-0015(해시로 판정), ADR-0043(cooldown), ADR-0030(백그라운드 작업), ADR-0075(작업의 신원)

## 맥락

ADR-0092 가 「다른 도구가 고친 것은 이번에 안 잡는다」로 긋고 나온 자리다. 그때 잰 것이 이것이었다.

| | 능력 선언 | 감시 | 별도 설치 없이 되는가 |
| --- | --- | --- | --- |
| VS Code(`golang.go` 0.56.0) | 한다 | `createFileSystemWatcher`(에디터 내장) | **된다** |
| vim + coc.nvim | 한다 | watchman(외부 프로그램) | **안 된다.** 조용히 실패 |
| zn(ADR-0092) | 안 한다 | HEAD 가 움직일 때 git 목록 | git 동작만 된다 |

**VS Code 가 이기는 자리는 「능력을 알렸다」가 아니라 감시기를 에디터가 들고 있다는 점이다.** zn 은 Go 프로그램이라 그 자리에 설 수 있다. 이 ADR 이 서는 일이다.

구멍이 둘이었다.

- **주기 검사가 활성 buffer 하나만 본다**(ADR-0044). 보고 있지 않은 tab 의 파일이 밖에서 바뀌면 그 낡은 내용이 tab 을 옮길 때까지 남고, `syncGopls` 가 tick 마다 그 낡은 overlay 를 서버에 덮어씌운다. ADR-0092 가 「알리지 않는 것보다 나쁜 자리」로 적어 둔 것이다.
- **gopls 에 알리는 것이 HEAD 가 움직일 때뿐이다**(ADR-0092). 다른 창의 편집기, AI, `git stash`·`git restore` 가 전부 빠진다.

## 0. 잰 값

읽어서 확인한 것과 이 기계에서 잰 것을 먼저 적는다. 결정이 전부 여기에 매달려 있다.

### fsnotify 자체

| 잰 것 | 값 |
| --- | --- |
| 의존성 | `golang.org/x/sys` 하나. 이미 우리 것이다 |
| 우리 모듈 그래프에 이미 있는가 | 있었다. `v1.6.0 // indirect`, `tool github.com/bluemir/watcher` 경유 |
| 고른 판 | `v1.10.1`. kqueue 의 fd 누수(#740) 와 dangling symlink 하나가 `Add` 를 통째로 깨뜨리던 것(#748) 이 여기서 고쳐졌다. **둘 다 우리가 밟는 자리다** |
| 재귀 감시 | **없다.** 디렉터리마다 `Add` 해야 한다(README FAQ) |
| 파일 하나를 감시하는 것 | **하면 안 된다.** 원자적 저장(임시 파일 + rename) 이 inode 를 바꿔서 감시가 끊긴다(README FAQ) |
| macOS 의 fd 값 | `Add(디렉터리)` 가 **그 안의 항목마다 fd 를 연다**(`backend_kqueue.go:582` `watchDirectoryFiles`) |
| Chmod | Spotlight·백업·백신이 많이 낸다. 버리라고 문서가 권한다 |

### 감시를 붙이는 값

이 기계(macOS, `kern.maxfilesperproc` 122880) 에서 실제로 붙여 보고 쟀다.

| 뿌리 | 감시할 디렉터리 | 걸린 시간 | 늘어난 fd |
| --- | --- | --- | --- |
| zn 저장소 | 32 개 | 34ms | **469 개** |
| Go 툴체인 트리(파일 약 1 만 개) | 1046 개 | 543ms | **10336 개** |

**fd 수가 「디렉터리 + 파일」이다.** 소스에서 읽은 것이 실제로 그렇게 나온다. 파일 10 만 개짜리 저장소면 fd 10 만 개이고 붙이는 데 5 초쯤이다.

`.git` 을 거르는 것이 여기서 가장 큰 한 수다. 이 저장소만 해도 감시할 디렉터리가 32 개인데 `.git` 을 세면 313 개다.

### 원자적 저장이 어떻게 오는가

**시험을 쓰다 잡았다.** macOS 에서 임시 파일에 쓰고 `rename` 으로 덮으면 그 파일이 `Remove` 로 온다. 감시하던 inode 가 정말로 사라지기 때문이다.

**이대로 gopls 에 넘기면 서버가 살아 있는 파일을 지운 것으로 알고 자기 view 에서 뺀다.** 편집기와 포매터가 이 방식으로 쓰므로 흔하게 밟는다. Linux 에서는 같은 일이 `Create` 로 온다.

## 1. 감시기를 안에 들고, 뿌리 전체를 본다

`fsnotify` 를 직접 의존으로 올린다. 외부 프로그램에 맡기지 않는다. coc 가 watchman 이 없는 손에서 조용히 실패하는 자리가 그것이고, 우리는 Go 프로그램이라 안에 들고 갈 수 있다.

**뿌리는 cwd 다.** 트리·팔레트 뿌리와 같고 gopls 에게 준 뿌리와도 같다. 저장소 뿌리를 쓰면 하위 디렉터리에서 zn 을 열었을 때 위쪽 전체를 감시하게 된다. 그 대신 cwd 위의 변경은 못 잡는다.

**디렉터리를 감시한다. 파일이 아니다.** 원자적 저장이 파일 감시를 끊는다(§0). 이것은 선택이 아니라 fsnotify 가 정한 것이다.

**무시 규칙을 그대로 쓴다.** `.git` 과 `.gitignore` 에 적힌 것에 들어가지 않는다. `walkGitDir` 이 이미 하는 일이라 디렉터리를 주는 형제(`walkGitDirs`) 하나만 두었다. 합치지 않은 것은, 하나로 만들면 `visit` 이 「디렉터리인가」를 인자로 받아야 하고 지금 부르는 셋 중 둘이 그 값을 버리기 때문이다.

**상한을 두지 않는다.** 대신 둘을 한다.

- `Add` 가 막히면 **알림으로 알린다.** 몇 개까지 붙였는지 같이 적는다. 조용히 실패하지 않는 것이 이 ADR 의 절반이다
- **주기 검사가 그대로 남는다.** 감시가 반쯤 붙어도 정확성은 유지되고 반응만 느려진다

상한이 필요하다고 드러나면 그때 값을 정한다. 지금은 그 값을 정할 근거가 없고, 근거 없는 상수 하나가 「왜 이 숫자인가」를 영영 달고 다닌다.

## 2. 이벤트는 판정이 아니라 앞잡이다

**buffer 쪽은 이벤트를 믿지 않는다.** 이벤트를 받으면 cooldown 을 기다리지 않고 그 파일의 검사를 시작할 뿐이고, 「바뀌었나」는 그대로 sha256 이 답한다(ADR-0015).

까닭이 둘이다.

- **이벤트는 내용을 말하지 않는다.** 되쓰기·`touch`·권한 변경이 전부 이벤트를 내는데 내용은 그대로일 수 있다. ADR-0015 가 mtime 판정을 기각한 그 까닭 그대로다
- **판정 경로가 둘이 되면 안 된다.** 이미 stat 앞잡이 + 해시 판정이라는 길이 있고(ADR-0044), 감시는 그 길의 방아쇠를 하나 더 다는 것이다. 새 길을 내면 두 길이 어긋나는 날이 온다

**주기 검사는 그대로 둔다.** cooldown 도 5 초 그대로다. 감시가 놓치는 자리가 있다.

- 네트워크 파일 시스템(NFS·SMB·FUSE). fsnotify 문서가 「받침이 없다」고 적어 두었다
- 감시 개수 상한에 걸린 뒷부분
- 새 디렉터리를 감시에 올리는 사이에 그 안에서 생긴 파일

**gopls 쪽은 반대다. 이벤트를 그대로 넘긴다.** 서버는 우리 판정을 받지 않고 알림을 받으면 자기가 디스크를 다시 읽는다(ADR-0092 §0). 우리가 「내용이 같더라」고 걸러 주면 서버가 알아야 할 것을 우리가 대신 판단하는 셈이 된다.

**딱 한 자리만 이벤트를 고친다.** 지웠다고 온 것이 아직 디스크에 있으면 바뀐 것으로 되돌린다(§0 의 원자적 저장). 반대 방향(만들었다는데 없는 것) 은 보지 않는다. 그러려면 쓰기마다 `Lstat` 을 해야 하는데 그 자리는 쓰기마다 지나고, 없는 파일을 알린 서버는 읽어 보고 없으면 그대로 끝낸다.

## 3. 검사 대상을 열린 tab 전부로 넓힌다

ADR-0044 가 활성 buffer 하나로 두었던 것을 여기서 푼다. 감시가 그 파일들을 이미 보고 있어서 「누가 바뀌었나」는 공짜로 오는데, 검사가 활성 tab 만 보면 그 앎을 쓸 자리가 없다.

값은 앞잡이가 답한다. 유휴 상태의 검사 하나는 `Lstat` 하나라(ADR-0044) tab 이 열 개여도 tick 마다 `Lstat` 열 번이다.

**주기 검사는 인자 없는 작업 하나가 전부를 본다.** 파일마다 따로 시작하면, 그것들이 「이미 도는 중」이라 건너뛰어질 때 `jobDoneMsg` 가 하나도 오지 않고 **cooldown 고리가 조용히 멈춘다.** tab 이 없어도 작업이 도는 것과 같은 까닭이다. 시작하지 않으면 끝나지도 않는다.

**감시가 부르는 검사는 같은 이름에 인자로 갈린다**(ADR-0075). 같은 이름이라 그 작업이 끝나는 것도 cooldown 을 잇는 자리를 그대로 지나고, 인자가 달라서 주기 검사와 서로를 막지 않는다. 같은 파일에 이벤트가 잇달아 와도 신원이 같아 두 번 돌지 않는다.

## 4. tea 로 들이는 배선은 이미 있는 것을 쓴다

`tea.Program.Send` 를 쓰지 않는다. Program 핸들을 들고 있지도 않다. 채널을 기다리는 Cmd 를 받을 때마다 다시 발행하는 고리가 이미 둘 있고(`waitJob`·`waitDiagnostics`) 그것을 그대로 쓴다.

**진단이 오는 길을 베꼈다.** 다른 점은 진단이 「상태」라 종만 울리면 되는 데 비해 이쪽은 「사건」이라 담을 자리가 필요하다는 것뿐이다.

**debounce 는 `Sleep` 한 줄이다.** 종을 받고 250ms 자고 나서 msg 를 낸다. 그 사이에 온 것은 모여서 한 번에 나온다. Cmd 는 goroutine 에서 도니 화면은 멈추지 않고, **편집기에 상태가 하나도 늘지 않는다.** 예약 bool 을 넷째로 늘리지 않는 것이 이 선택의 값이다(`gitTickScheduled`·`fileTickScheduled`·`lspTickScheduled` 로 이미 셋이다).

**끝을 알리는 데 종을 닫지 않는다.** 별도 `done` 채널을 닫는다. 종을 닫으면 울리는 자리와 닫는 자리가 겨루고, 지는 쪽은 닫힌 채널에 보내다가 죽는다. 지금은 울리는 자리가 하나뿐이라 실제로 겨루지 않지만, 그 안전이 「부르는 자리가 하나뿐이다」라는 논증에 기대게 된다. 채널 하나를 더 두면 그 논증이 필요 없다. 시험을 쓰다 race 로 드러난 자리다.

## 5. 능력은 여전히 알리지 않는다

규격은 `workspace.didChangeWatchedFiles` 능력을 알리고 `client/registerCapability` 로 서버가 감시 규칙(glob) 을 등록하게 되어 있다.

**ADR-0092 §1 의 판단을 그대로 지킨다.** 재보니 gopls 는 알리지 않아도 이 알림을 받고, 알리면 서버가 되묻는 문이 열린다. 그 문을 열면 glob 패턴을 해석해 매칭하는 겹이 하나 생기는데, 우리가 지금 감시하는 것은 「무시되지 않은 것 전부」라 그 패턴이 좁혀 줄 것도 없다.

이 자리는 VS Code 와 갈리는 유일한 점이고, 값을 내는 쪽이 감시기라는 것은 §0 이 이미 보여 주었다.

## 결과

좋은 점

- **다른 창의 편집기나 AI 가 고친 파일을 gopls 가 안다.** ADR-0092 가 감수한 것 중 가장 큰 것이 없어졌다
- `git stash`·`git restore` 처럼 HEAD 가 안 움직이는 git 동작도 잡힌다
- **보고 있지 않은 tab 도 밖의 변경을 따라간다.** 낡은 overlay 가 서버를 틀린 내용에 못 박던 자리가 없어졌다
- 밖에서 바뀐 파일이 5 초를 기다리지 않고 다시 읽힌다. 재보니 0.7 초 안이다(§6)
- 원자적 저장으로 고친 것도 잡는다. 파일이 아니라 디렉터리를 보기 때문이다
- 붙이지 못하면 알린다. coc 처럼 조용히 실패하지 않는다
- 새 의존성이 실질적으로 없다. fsnotify 는 이미 모듈 그래프에 있었고 그 의존성은 `golang.org/x/sys` 하나다

감수하는 것

- **파일 수만큼 fd 를 연다(macOS).** 잰 값으로 파일 1 만 개에 fd 1 만 개다(§0). 상한을 두지 않기로 했으므로 큰 저장소에서는 상한에 걸릴 수 있고, 그때 알리고 주기 검사로 돈다
- **Linux 는 `fs.inotify.max_user_watches` 에 걸린다.** 배포판 기본이 8192 인 곳이 있다. 같은 길로 알린다
- **cwd 위의 변경은 못 잡는다.** 하위 디렉터리에서 열었으면 그 위는 감시 밖이다(§1)
- **네트워크 파일 시스템에서는 이벤트가 오지 않는다.** 주기 검사만 남는다
- **새 디렉터리를 붙이는 사이가 비어 있다.** 그 짬에 그 안에서 만들어진 파일은 이벤트를 잃는다. 주기 검사가 그물인데, 그 파일이 열려 있지 않으면 그물에도 안 걸린다
- **디렉터리를 붙이는 것을 감시 goroutine 이 직접 한다.** 갓 생긴 디렉터리는 거의 비어 있어서 값이 없지만, 큰 트리가 통째로 옮겨져 오면 그동안 이벤트를 받지 못한다
- **저장할 때마다 헛검사가 한 번 돈다.** 우리가 쓴 것도 이벤트로 돌아온다. 걸러내려면 「방금 내가 쓴 경로와 해시」를 들어야 하고, 판정이 곧바로 「그대로」로 끝나므로 값이 파일 하나 읽기다
- **`go.mod`·`go.sum`·`go.work` 는 여전히 안 보낸다.** `.go` 만이다(ADR-0092 §3 그대로)
- **감시 goroutine 이 하나 는다.** 편집기 수명 내내 살고 나가는 길이 하나다(`stopWatch`)
- **mode 마다 두는 공용 case 25 곳에 이름이 하나 늘었다.** ADR-0002 가 「늘어나면 공용 처리로 뺀다」고 해 둔 값이 또 한 번 늘었다

## 대안

- **주기로 모듈 전체를 훑어 mtime 을 견주기**
	- git 도 다른 도구도 다 잡고, fd 를 하나도 안 쓴다.
	- dirty 판정 walk 은 첫 차이에서 곧바로 나오게 짜여 있어서 공짜로 얹히지 않는다. 전부 훑게 만들면 성질이 바뀌고 사내 monorepo 에서 tick 마다 120ms 다(ADR-0092 §4).
	- **바뀐 순간을 모른다.** 최대 5 초 늦는데, 감시는 250ms 다.

- **감시 개수에 상한을 두고 넘으면 물러나기**
	- 큰 저장소에서 fd 가 터지지 않는다.
	- **그 값을 정할 근거가 없다.** 이 기계의 상한이 122880 이고 다른 기계는 다르다. 근거 없는 상수 하나가 영영 「왜 이 숫자인가」를 달고 다닌다.
	- 막히면 알리고 주기 검사로 도는 지금 길이 그 자리를 덮는다. 실제로 걸리는 것을 보고 정한다.

- **열린 tab 의 부모 디렉터리만 감시하기**
	- fd 가 몇 개로 끝난다.
	- **이 ADR 의 목적을 이루지 못한다.** 열지 않은 파일이 밖에서 바뀌는 것을 잡는 것이 시작점이었다.

- **macOS 에서 FSEvents 를 쓰기**
	- 재귀 감시가 싸다. fd 를 파일마다 열지 않는다.
	- fsnotify 는 FSEvents 를 쓰지 않고 kqueue 로 간다. 쓰려면 별도 패키지(`fsnotify/fsevents`) 를 붙이고 플랫폼별로 코드가 갈린다. 「os 를 가리지 않는 하나」를 버리는 값이다.

- **watchman 에 맡기기**
	- coc 가 가는 길이다. 우리가 감시 코드를 안 써도 된다.
	- **안 깔린 손에서 조용히 실패한다.** §0 의 표가 그것을 보여 주는 표다. 이 ADR 이 서려는 자리의 정확한 반대편이다.

- **이벤트를 판정으로 쓰고 주기 검사를 걷기**
	- 읽기와 해시가 없어진다.
	- ADR-0015 가 기각한 자리로 돌아간다. 되쓰기·`touch` 에 헛경고가 나고, 놓친 이벤트를 메울 길이 없어진다.

- **능력을 알리고 `registerCapability` 에 답하기**
	- 규격이 정한 순서고 VS Code 가 가는 길이다.
	- 서버가 되묻는 문이 열리고 glob 매칭 겹이 하나 생긴다. 우리가 감시하는 것이 「무시되지 않은 것 전부」라 그 패턴이 좁혀 줄 것이 없다(§5).

## 6. 손으로 재현한 것

임시 git 저장소를 만들어 zn 을 띄우고 밖에서 고쳐 보았다. 전부 이 변경 전에는 되지 않던 것이다.

| 한 것 | 본 것 |
| --- | --- |
| 열어 둔 파일을 밖에서 고치기 | **0.7 초 안**에 다시 읽혔다(0.2 초 간격으로 화면을 떠서 잰 값이라 그 안에 debounce 250ms 가 들어 있다) |
| **보고 있지 않은 tab** 의 파일을 밖에서 고치기 | tab 을 옮기기 전에 이미 새 내용이었다. 활성 tab 은 건드려지지 않았다 |
| 열지 **않은** `b.go` 를 밖에서 만들어 `Foo()` 를 쓰게 하고 `\gr` | **사용처가 1 개에서 3 개로 늘었다.** ADR-0092 §0 이 「0 개」로 쟀던 그 자리다 |
| 그 `b.go` 를 밖에서 없애고 다시 `\gr` | 1 개로 돌아왔다. 지웠다는 알림도 서버가 듣는다 |
| `git stash -u`(HEAD 가 안 움직인다) | 되돌아간 두 파일이 다 다시 읽혔다. ADR-0092 가 못 잡던 자리다 |
| 임시 파일에 쓰고 `mv` 로 덮기 | 다시 읽혔다. `Remove` 로 오는 것을 되돌린 것(§0) 이 실제로 먹힌다 |
| `:jobs` | `파일 감시  끝남  폴더 1 개` 로 보인다 |
| `:messages` | 실패 알림이 하나도 없다 |

## 이 ADR 이 정하지 않는 것

- **감시 개수 상한.** 실제로 걸리는 것을 보고 정한다(§1)
- **`go.mod`·`go.sum`·`go.work` 를 같이 알릴지.** 지금은 `.go` 만이다
- **cwd 위의 변경을 볼지.** 뿌리를 저장소 뿌리로 올리는 일이다(§1)
- **cooldown 값.** 감시가 붙어도 5 초 그대로다. 늘릴지는 감시가 실제로 얼마나 잡는지 본 뒤에 정한다
- **우리가 쓴 것을 걸러낼지.** 지금은 헛검사 한 번으로 지나간다
- **예약 상태를 이름→cooldown 표로 모을지.** 이 건은 예약을 늘리지 않았다(§4)
