# ADR-0099 명령줄의 `tab` 은 디렉터리를 읽어 경로를 채운다

- 상태: 채택
- 날짜: 2026-08-28
- 관련: ADR-0011(팔레트가 저장소 안을 흐릿하게 찾는다), ADR-0066(insert 의 자동완성 창), ADR-0088(`~` 를 푸는 자리), ADR-0002(mode 를 model 로 나눈 것)

## 맥락

`:tabnew` 로 파일을 열려면 경로를 끝까지 손으로 쳐야 했다. 명령줄의 `tab` 은 아무 일도 하지 않고 글자도 들어가지 않아서 자리가 비어 있었다.

정할 것이 셋이다. **후보를 어디서 가져오는가**, **`tab` 이 무엇을 하는가**, **후보를 어디에 그리는가**다. 첫째가 나머지를 정한다.

## 1. 후보는 그때그때 디렉터리를 읽어 만든다

팔레트가 쓰는 파일 목록(`e.files`) 이 이미 있다. `.gitignore` 가 따라오고 흐릿한 매칭까지 되니 그것을 쓰는 것이 짧아 보인다. **그런데 두 가지가 걸린다.**

- **팔레트를 한 번이라도 열어야 채워진다.** 인덱싱을 시작하는 자리가 팔레트를 여는 곳 하나다(view-palette.go). 안 열었으면 후보가 없고, `:tabnew` 가 그것을 시작하게 만들면 파일 하나 여는 데 저장소 전체를 훑는다
- **저장소 안만 담긴다.** `~/…`·절대 경로·저장소 밖은 목록에 없다. 그런데 명령줄에서 경로를 치는 까닭의 상당수가 그쪽이다

그래서 **읽는다.** 친 조각의 마지막 `/` 앞까지를 디렉터리로 보고 그 자리를 `os.ReadDir` 한다. 인덱싱에 기대지 않아 언제나 되고, 값은 디렉터리 하나 읽기다.

**갈래가 팔레트와 나뉜 것이기도 하다.** 저장소 안을 흐릿하게 찾는 것(`icedit` 으로 `internal/core/edit.go`) 은 팔레트가 하고, 경로를 또박또박 짚어 가는 것은 명령줄이 한다. 둘이 같은 일을 두 손으로 하지 않는다.

**`~` 는 읽을 때만 푼다.** 명령줄에 남는 글자는 친 그대로 `~/` 다 — 풀어서 되돌려 주면 사람이 친 것과 화면의 글자가 달라진다. 푸는 것은 실제로 여는 자리의 몫이다(ADR-0088).

## 2. 공통 앞부분까지 채우고, 여럿이면 보여준다

셸과 vim 의 기본값이다. 하나면 통째로 채우고, 여럿이면 **공통된 데까지만** 채운 뒤 후보를 늘어놓는다.

후보를 차례로 넣는 손(vim 의 `wildmenu`) 도 있다. 몇 번 치면 닿는다는 것이 분명해서 좋지만, **어디까지 왔는지가 상태로 남는다** — 그 상태를 어느 키가 무르는지, 글자를 치면 어떻게 되는지가 새로 정할 것이 되고, 무엇보다 사람이 이미 아는 손이 아니다. 채우다 만 자리에서 글자를 더 치는 것이 익은 손이다.

**디렉터리에는 `/` 를 붙인다.** 채운 뒤 곧바로 이어 칠 수 있고, 목록만 보고도 더 들어갈 수 있는지가 갈린다.

**숨김 파일은 앞글자가 `.` 일 때만 낸다.** 셸과 같다. 안 그러면 `:e ` 뒤에 `tab` 을 친 순간 `.git` 이 목록 맨 앞에 선다.

## 3. 붙이는 명령은 경로를 받는 셋이다

`:tabnew`·`:e`·`:w` 다. **`~` 를 푸는 자리가 이미 그 셋을 한 눈금으로 묶어 두었다**(view-editor-command.go). 같은 자를 쓰면 「어느 명령에서 되고 어느 명령에서 안 되는지」를 세는 자리가 새로 생기지 않는다.

`:w` 도 넣었다. 쓰는 자리라 있는 파일을 완성해 주는 것이 덮어쓰기를 권하는 꼴로 보일 수 있는데, **덮어쓰기를 막는 것은 완성이 아니라 `:w` 자신이다** — 이미 있는 파일이면 쓰지 않고 알린다(ADR-0024). 완성이 그 자리를 대신 지킬 이유가 없고, 오히려 「이미 있다」를 치기 전에 알게 된다.

**이름 자리는 완성하지 않는다.** 명령을 고르는 자리는 팔레트다(ADR-0011).

**따옴표가 든 줄은 건드리지 않는다.** 완성한 글에 빈 칸이 들면 따옴표를 새로 지어야 하는데, 이미 친 따옴표와 겹치는 자리를 만들지 않는다. 그때는 손으로 친다.

## 4. 후보 창은 insert 의 자동완성 창과 같은 손이다

후보를 늘어놓는 그림이 이미 있고(render-completion.go, ADR-0066) 자리를 잡는 `popupPos` 가 「아래에 못 넣으면 위로 뒤집고 statusBar 는 덮지 않는다」를 이미 한다. 명령줄은 화면 맨 아래라 창은 늘 위로 뒤집힌다.

**statusBar 윗줄을 쓰지 않았다.** vim 의 `wildmenu` 가 서는 자리인데, 그 줄을 명령줄이 갈아끼우려면 `editorView` 에 인자가 하나 늘고 그것을 부르는 스무 곳이 전부 뜻 없는 값을 넘기게 된다.

**고르는 화면이 아니다.** 반전으로 짚어 둔 줄이 없고 키도 받지 않는다. 무엇이 있는지만 보이고 고르는 것은 이어 치는 글자다. 그래서 mode 를 만들지 않았고, 후보는 명령줄 model 이 든다 — 다른 mode 가 이 필드를 이고 다니지 않는다(ADR-0002).

**다음 키에 사라진다.** 글자를 하나 더 치면 조각이 달라지므로, 남겨 두면 화면이 지금 조각과 어긋난 목록을 들고 있게 된다.

## 밖에 둔 것

- **흐릿한 매칭.** §1 대로 팔레트의 몫이다
- **후보를 차례로 넣기.** §2 대로 상태가 하나 는다. 써 보고 손이 아쉬우면 다시 본다
- **`:grep`·`:s`·`:replace` 의 인자.** 경로가 아니라 정규식이다(ADR-0077, ADR-0084)
- **빈 칸이 든 파일 이름.** §3 대로 따옴표를 지어야 해서 미뤘다
