# ADR-0051 정의로 가기는 gopls 에게 묻는다

- 상태: 채택
- 날짜: 2026-08-22

## 맥락

Go 파일에서 커서 자리의 정의로 뛰는 기능이 필요했다(`docs/tasks.md` 의 「golang → go to definition」).
뒤이어 rename 도 같은 자리를 쓴다.

정의를 아는 방법이 셋이었다.

- **표준 라이브러리 파서 + 휴리스틱.** `go/parser` 로 파일을 떠서 `func Name`·`type Name` 을 찾는다.
  의존성이 0 이고 즉시 돈다. syntax highlight 를 `go/scanner` 로 직접 감싼 것(ADR-0039) 과 같은 결이다.
  대신 같은 이름이 여러 패키지에 있으면 가리지 못하고, `x.Foo()` 에서 `x` 의 타입을 모른다.
- **`golang.org/x/tools/go/packages` 로 타입체크.** 외부 프로세스 없이 정확하다. 대신 첫 로드에
  `go list` + 컴파일 비용이 붙고, 편집 중의 소스는 거의 언제나 문법이 깨져 있다.
- **gopls 를 자식 프로세스로 띄우고 LSP 로 묻기.** 정확도가 가장 높고 표준 라이브러리·의존 모듈까지
  따라간다. rename·진단·자동완성이 같은 길로 온다. 대신 LSP client 겹이 새로 생기고 gopls 설치를 요구한다.

## 잰 것

주장 대신 재고 골랐다. gopls v0.23.0, 이 저장소, Apple silicon.

| 잰 것 | 값 |
|---|---|
| `initialize` | 300~360ms |
| 첫 `definition`(모듈 인덱싱 포함) | 0.6~1.3초 |
| 그 뒤의 `definition` | 0~15ms |
| 응답 모양 | `Location` **배열** |
| 위치 인코딩 | **UTF-16**. `general.positionEncodings: ["utf-8"]` 를 보내도 빈 값으로 답한다(= 규격 기본값) |
| byte 열로 물으면 | `column is beyond end of line` 오류 |
| 저장하지 않은 글 | 전문·증분 **둘 다** 먹는다. 끼운 줄만큼 정의 위치도 밀렸다 |
| 전문 보내기 | 34.6KB 파일 100 번에 75ms (한 번당 750µs) |
| 표준 라이브러리·의존 모듈 파일 | module cache 라 `r--r--r--` |

후보 개수는 두 번 재야 했다. 식별자(패키지 안 함수·상수·method, 다른 패키지, 표준 라이브러리,
의존 모듈) 위에서는 **늘 하나**였다. 그런데 **import 경로나 패키지 이름 위에서는 그 패키지의
파일 수만큼 온다.** `path/filepath` 에서 5 개, `charm.land/bubbletea/v2` 에서 28 개다.
파일마다 있는 `package` 절이 모두 후보이기 때문이다. 처음 잰 것이 식별자뿐이어서 「늘 하나」로 잘못
읽었고, 실제 편집기에서 눌러 보고서야 나왔다.

## 결정

### gopls 에게 묻는다

정확도가 이 기능의 존재 이유다. 휴리스틱으로 「대개 맞는」 정의는 뛰어 놓고 매번 의심해야 해서
안 쓰는 기능이 된다. rename 이 뒤따라 오는 것도 같은 무게다. 그것은 휴리스틱으로 할 수 없다.

`internal/lsp` 를 새 패키지로 둔다. 서버와 주고받는 것만 알고 편집기도 화면도 모른다.
서버를 고르는 interface 는 두지 않았다. 상대가 하나뿐이라, 둘째가 생길 때 무엇이 갈리는지 보고 가른다.

실행 파일은 **PATH 만 보지 않는다.** `go install` 은 `$GOBIN`/`$GOPATH/bin` 에 넣고 그 자리가
PATH 에 없는 기계가 흔하다. 이 기능을 만든 기계가 그랬다. `LookPath` → `$GOBIN` → `$GOPATH/bin`
→ `~/go/bin` 순으로 찾는다.

한 번 실패하면 다시 걸지 않는다. 까닭이 대개 「깔려 있지 않다」 라서, 파일을 열 때마다 다시
시도해도 나아지지 않고 그때마다 오류 문구가 화면 아래를 차지한다.

### Go 파일을 열 때 미리 띄운다

첫 요청이 1 초 남짓 걸리는 것은 서버가 모듈을 훑기 때문이다. 파일을 여는 자리에서 시작해 두면
그 기다림이 `\gd` 앞으로 옮겨간다. Go 파일이 없는 저장소에서는 아예 실행되지 않는다.

띄우는 것도 묻는 것도 `Cmd` 안에서 한다. 화면을 그리는 goroutine 이 남의 프로세스를 기다리면
그동안 편집기가 멈춘다.

### 평소는 증분, 묻기 직전에는 전문

- 마지막 키에서 250ms 조용해지면 **바뀐 줄만** 보낸다.
- `\gd` 를 치는 순간 그 파일 **전문**을 한 번 보내고 묻는다.

주기적으로(1~5분) 전문을 다시 보내는 것도 검토했지만 뺐다. 어긋난 사본을 낫게 하려는 것인데,
어긋남이 눈에 보이는 순간은 정확히 무언가를 묻는 순간이다. 그 자리에서 맞추면 틀린 답이 나올 창이
아예 없고, 타이머는 그 사이에 조용히 틀린 답을 준 뒤 언제 나았는지도 알려주지 않는다.

### 증분은 편집 기록이 아니라 **두 사본의 차이**에서 만든다

이것이 이 결정의 핵심이다.

편집하는 자리마다 「무엇을 바꿨다」 를 적어 보내는 것이 LSP 의 보통 방식이다. 그러면 적는 자리가
하나라도 틀릴 때 서버의 사본이 **조용히** 어긋난 채 남고, 증상은 「정의가 엉뚱한 데로 뛴다」 라서
남의 프로그램 탓처럼 보인다. zn 의 편집은 `deleteText`·`changeLines`·`indent-range`·`paste` 등
여러 `Buffer` 메서드에 흩어져 있어 적을 자리가 여럿이다.

그래서 `internal/lsp` 가 **마지막으로 보낸 줄들의 사본**을 들고, 보낼 때 앞뒤로 같은 줄을 깎아
달라진 구간만 보낸다. 보낼 것이 누적이 아니라 파생이라 어긋날 자리가 없고, 편집 입구에는 갈고리가
하나도 없다. 열고 닫는 것도 같은 손이다. 열려 있는 tab 목록과 서버가 아는 목록을 견주어
새것은 알리고 없는 것은 닫는다(`core/gopls.go` 의 `syncGopls`).

### 동기화는 줄 단위로만 보낸다

범위의 열이 늘 줄 머리라서 UTF-16 으로 세는 자리가 **묻는 자리와 답을 받는 자리** 둘로 줄어든다.
zn 은 줄 안의 자리를 byte 로 세므로(`Buffer.cursorCol`) 이 변환이 없으면 한글이 든 줄에서
gopls 가 요청을 거절한다. 변환은 `lsp/position.go` 의 두 함수뿐이다.

파일 끝까지 바뀐 경우만 줄 끝 자리를 써야 해서, UTF-16 을 세는 세 번째 자리가 `diff` 안에 하나 있다.

### 하나면 뛰고, 여럿이면 고르는 화면을 연다

하나면 새 tab 으로 뛴다. 이미 열려 있는 파일이면 그 tab 으로 옮겨가 커서만 움직인다
(`openTab` 이 이미 그렇게 한다).

여럿이면 `viewLocations` 를 연다. **처음에는 「첫 번째로 뛰고 개수를 알린다」 로 두려 했다.**
잰 것이 「식별자 위에서는 늘 하나」였기 때문인데, 실제로 눌러 보니 import 경로 위에서 28 개가
왔고 알파벳순 첫 파일(`clipboard.go`) 로 뛰었다. 아무도 원하지 않는 자리다. 그래서 넣었다.

**팔레트에 얹지 않았다.** 팔레트는 「입력 맨 앞 글자가 갈래를 정하고, 그 글자를 지우면 파일
찾기로 돌아온다」 가 중심 규칙이다(ADR-0011 의 `paletteKind`). 프로그램이 띄우는 목록은 그
규칙에 들어갈 자리가 없다. 갈래를 정할 글자가 없고, 지웠을 때 돌아갈 곳도 파일 찾기가 아니다.
`:jobs` 와 같은 자리에 둔다(ADR-0027).

> **나중에 뒤집혔다.** 사용처로 가기가 붙으면서 이 목록은 화면 전체가 아니라 **하단 drawer**
> 가 되었다. 훑는 목록은 간 자리가 같이 보여야 하고, `enter` 로 뛰어도 닫히지 않는다
> (ADR-0069). 팔레트에 얹지 않는다는 위의 판단은 그대로다.

줄 내용은 아직 붙이지 않는다. 붙이려면 그 파일을 읽어야 하는데 여기 오는 것은 대개 열려 있지
않은 파일이라, 「디스크에서 읽은 글」과 「tab 에서 고치던 글」이 갈리는 셈이 새로 생긴다.
여러 파일 검색이 이 화면을 쓸 때 같이 정한다(`docs/tasks.md`).

경로가 화면보다 길면 **왼쪽부터** 접는다. 오른쪽부터 자르면 고르는 데 쓰는 파일 이름과 줄
번호가 먼저 사라지고, 남는 것이 줄마다 똑같은 앞머리뿐이다.

### 작업 결과가 mode 를 바꿀 수 있게 넓혔다

`handleJob` 이 `tea.Cmd` 만 돌려주어서 백그라운드 결과로 화면을 바꿀 길이 없었다. 지금까지는
그럴 결과가 없었다. git 표시·파일 검사·인덱싱은 전부 editor 를 고치고 끝난다.

정의 후보 목록이 첫 예외다. `(tea.Model, tea.Cmd)` 로 넓히고 **바꾸지 않으면 nil** 로 둔다.
동작(`action.run`) 이 이미 쓰는 규칙과 같아서 부르는 쪽이 새로 배울 것이 없다(ADR-0026).

### 되돌아오기(jumplist) 는 이번에 넣지 않았다

`ctrl+o`/`ctrl+i` 는 검색·`G`·`gg` 와 함께 정할 건이라 `docs/tasks.md` 에 남겼다.
지금은 `gT` 와 tab 닫기로 돌아온다.

### 읽기 전용 파일을 알아본다

표준 라이브러리·의존 모듈로 뛰면 module cache 의 `r--r--r--` 파일이 열린다. 그대로 두면 한참
고친 뒤 저장할 때에야 막힌다. 그래서 `Buffer.readOnly` 를 열 때 정하고, 고치는 동작이 첫 줄에서
거절하며 statusBar 에 `[읽기 전용]` 이 붙는다.

검사를 줄 갈아끼우는 한 자리(`replaceLines`) 에 두지 않은 것은, 거절했다는 것을 사람이 알아야
하기 때문이다. 거기서 막으면 아무 일도 일어나지 않는 것처럼 보여서 키가 먹지 않는 편집기가 된다.

권한 비트만 본다. 소유자·ACL 까지 따지려면 실제로 쓰기로 열어봐야 하고, 여기서 놓치는 경우는
저장할 때 오류로 잡힌다. 그 자리에는 이미 문구가 있다.

### 키는 `\gd`

`\` 는 vim 의 `<Leader>` 기본값이라 vim 이 비워 둔 자리다. `gd` 하나로 두지 않은 것은 vim 의
`gd`(현재 함수 안의 지역 선언) 와 뜻이 달라서다.

접두 키가 두 키를 넘는 첫 자리라 `normalPending` 이 접두 키를 쌓게 넓혔다(ADR-0006, ADR-0013).
`\g` 까지만 자라고 짝이 없는 `\x` 는 그 자리에서 끝난다. 잘못 짚은 접두 키가 다음 키를 삼키지 않는다.

**한글 자판의 원화 기호(`₩`) 도 같은 leader 다.** 그 자리의 키가 한글 입력 상태에서 `\` 가 아니라
`₩` 를 낸다. `ctrl` 조합은 터미널에게 PC-101 자리를 물어서 풀었지만(ADR-0014) 이것은 modifier 가
없어서 그 길이 없으므로 글자를 보고 안다. 받는 자리에서 곧바로 `\` 로 맞춰 두어서, 접두 키를 쌓는
자리와 showcmd 는 어느 글자로 들어왔는지 몰라도 된다.

팔레트에도 「정의로 가기」로 둔다(ADR-0011). 하는 일은 같은 자리로 간다.

## 결과

- `\gd`(한글 상태에서는 `₩gd`) 와 팔레트로 정의로 뛴다. 저장하지 않은 편집도 기준이 된다.
- 후보가 여럿이면 `GOTO` 목록에서 고른다. 여러 파일 검색이 쓸 화면이 이것으로 하나 생겼다.
- 표준 라이브러리·의존 모듈까지 따라가고, 그 파일은 읽기 전용으로 열린다.
- gopls 가 없으면 그 자리에서 알리고 나머지 기능은 그대로 돈다.
- rename(`docs/tasks.md`) 이 이 연결을 그대로 쓴다. `textDocument/rename` 은 편집을 되돌려
  받는 것이라 되돌리기 구간(ADR-0033) 과 어떻게 묶을지가 그때의 결정이다.
- 진단(오류 밑줄) 은 서버가 이미 보내오고 있고 우리가 버리고 있다. 화면에 자리를 정하면 받는다.

## 함께 본 것

- ADR-0006 normal mode 키 상태 기계: 접두 키가 두 키를 넘는 첫 자리다
- ADR-0011 command palette: 「정의로 가기」가 그 표에 한 줄이다. 후보 목록을 여기 얹지 않은 이유도 그 ADR 의 규칙에서 나왔다
- ADR-0014 한글 상태의 ctrl 조합: leader 가 자판에 따라 다른 글자로 오는 것이 같은 결의 문제다
- ADR-0025·0027 백그라운드 작업: 띄우고 묻는 것이 화면 밖에서 도는 규칙, 그리고 목록을 화면 전체로 두는 손이 여기서 왔다(그 손은 ADR-0069 에서 하단 drawer 로 바뀌었다)
- ADR-0026 editor 를 포인터로: 「바꾸지 않으면 nil」 규칙을 handleJob 에도 그대로 썼다
- ADR-0039 문법 강조: Go 를 `go/scanner` 로 직접 다룬 결정. 정확도가 필요한 자리에서는 갈렸다
- ADR-0043 갱신 cooldown: 예약을 하나로 묶는 손을 debounce 에 그대로 썼다
- ADR-0050 이벤트 로그: 키가 어떻게 들어오는지 보는 자리
