# ADR-0064 tab 이 없으면 빈 화면이고, 그 화면의 `:q` 는 종료다

- 상태: 채택
- 날짜: 2026-08-24

## 맥락

편집기는 지금까지 **tab 이 최소 하나** 라는 불변식 위에 서 있었다. 세 곳이 그것을 지켰다. 인자 없이 실행하면 `openBuffers` 가 이름 없는 빈 buffer 하나를 끼워 넣었고, `closeTabAt` 은 `len(buffers) < 2` 면 삭제를 거부했고, `:q` 는 그 거부를 종료로 번역했다.

그래서 `zn` 을 열면 늘 `[No Name]` tab 이 하나 있었다. **아직 아무 파일도 열지 않았다는 것이 「이름 없는 파일을 편집하는 중」 으로 보인다.** tabline 과 statusBar 가 그것을 tab 으로 적어야 하기 때문에, 화면에서 「빈 상태」 와 「빈 tab 하나」 를 가릴 방법이 없다.

곁가지로 막다른 길도 하나 있었다. 트리에서 열린 파일을 지우려 하면 「tab 에 열려 있습니다. 먼저 닫아 주세요」(ADR-0054) 인데, 마지막 tab 이면 닫는 순간 편집기가 끝난다. **안내를 따르면 편집기가 사라진다.**

`docs/tasks.md` 에 「처음 시작 할떄 빈 화면으로 시작 / 마지막 tab 을 닫으면 다시 해당 화면표시」 가 열려 있었다. 정할 것이 여섯이다.

## 1. tab 이 하나도 없는 상태를 둔다. `len(buffers) == 0` 이 그 상태다

이름 없는 tab 하나로 흉내내지 않는다. 그러면 tabline·statusBar 가 없는 tab 을 적게 되고, 「빈 화면」 과 「빈 tab」 이 사람이 보는 곳에서 같은 글자가 된다. **상태가 갈리지 않으면 화면도 갈릴 수 없다.**

활성 자리는 `active = -1` 이다. tab 을 여는 길이 활성 tab **바로 뒤**에 끼우는 것이라 (`openTab`, `newTab` 의 `slices.Insert(buffers, active+1, …)`) -1 이라야 첫 tab 이 0 번에 생긴다. 0 으로 두면 없는 tab 뒤를 가리켜서 여는 길마다 갈래가 생긴다. 마지막 tab 을 닫을 때도 `closeTabAt` 의 `min(active, len-1)` 이 저절로 -1 을 만든다.

감수하는 것: `activeBuffer()` 를 불러서는 안 되는 상태가 생겼고, 컴파일러가 그것을 막아주지 않는다.

## 2. `activeBuffer()` 는 tab 이 없으면 그대로 터지게 둔다

`nil` 을 돌려주면 부르는 곳 일흔이 다 nil 검사를 달아야 하고, **빠뜨린 한 곳은 터지는 대신 조용히 틀린다.** 터지는 쪽을 남기고, tab 이 없는 동안 편집 동작이 그 자리에 오지 않는 것으로 지킨다. 판을 갈아끼우는 것이 mode 라는 것(ADR-0002) 이 그 보증을 준다.

mode 를 가리지 않고 오는 공용 코드만 `hasTab()` 을 먼저 본다. 어느 mode 에서 왔는지로는 tab 이 있는지 알 수 없는 곳들이다. `scrollToCursor`(창 크기가 바뀌는 모든 길), `activePath`· `renderTabline`·`renderStatusBar`·`lineNumberWidth`(매 프레임), `regionAt`(mouse), `startOutsideCheck`(주기 검사), `traceBuffer`(`-vv` 로그).

`startOutsideCheck` 은 **nil 을 주지 않는다.** 시작하지 않으면 끝나지도 않아서 cooldown 고리가 그 자리에서 멈추고(ADR-0044), 그러면 빈 화면에서 파일을 열어도 바깥 변경을 다시 보지 않는다. 빈 경로로 작업을 돌려 이름 없는 buffer 와 같은 길로 보낸다.

`traceBuffer` 는 `interface{ activeBuffer() *Buffer }` 로 model 을 가렸는데, 빈 화면 model 도 editor 를 embed 해서 **그 interface 를 만족해 버린다.** 판별에 `hasTab()` 을 같이 넣었다. `-vv` 와 `--log-file` 이 둘 다 있을 때만 나던 종류의 패닉이라 검사로 잠갔다.

## 3. 화면은 본문만 갈아끼우고, 가르는 곳은 `editorView` 하나다

tabline 은 줄만 남기고 비운다. 줄까지 없애면 tab 을 여닫을 때마다 편집 영역이 한 행 튀고, 남는 칸을 반전으로 채우면 아무것도 안 적힌 막대가 떠서 고장 난 tab 으로 읽힌다. sidebar 와 statusBar 는 그대로다.

`:jobs` 처럼 화면을 통째로 쓰지 않았다(ADR-0027). 여기서 치는 키는 그 판의 키가 아니라 편집기 키이고, 트리도 그대로 쓸 수 있어야 한다.

**그래서 그림은 mode 안이 아니라 공용 코드에 있다.** `ctrl+w ctrl+w` 로 tab 없이 트리에 포커스를 둘 수 있고 그때 그리는 것은 `viewSidebar` 다. command·search·팔레트도 같은 곳을 지난다. 빈 화면 model 의 `View` 에 두면 그 상태들이 비거나 터진다.

로고는 글이라 `internal/assets` 에 데이터로 둔다(ADR-0061 의 경계). 박스·블록 문자는 East Asian Width 가 Ambiguous 라 두 벌이고, 한 칸으로 확인된 터미널에서만 unicode 를 쓴다(ADR-0028).

**자르지 않고 버린다.** 원소 칸이 폭이나 높이에 안 들어가면 `zn` 한 줄로 내리고, 그래도 자리가 없으면 버전 줄만 남긴다. 반쯤 잘린 아스키 아트는 로고로 읽히지 않으면서 자리는 다 차지한다. tip 을 자르지 않고 고르는 것과 같은 태도다(ADR-0061).

## 4. mode 이름은 `NORMAL` 이다. 새 mode 가 아니다

model 은 따로 둔다(`viewEditorEmpty`). normal 이 `activeBuffer` 를 전제로 한 코드에 통째로 매달려 있어서, 거기에 갈래를 넣으면 파서와 동작 전체에 「buffer 가 없을 때」 가 번진다.

그러나 statusBar 에는 `NORMAL` 을 적는다. 사람에게는 mode 가 바뀐 것이 아니라 편집할 것이 없는 것이다. 새 이름을 지으면 spec 의 mode 목록이 늘고 「그 mode 에서 무슨 키가 되나」 를 표로 또 적어야 하는데, 답은 「되는 것이 거의 없다」 다.

**키 파서는 normal 것을 그대로 쓰고 실행할 동작만 거른다.** 숫자 접두와 `g`·`ctrl+w` 접두, 한글 되돌림(ADR-0008), showcmd 가 그 안에 있어서, 키 문자열 목록을 따로 두면 그 규칙을 두 벌로 적게 되고 한쪽만 고치는 날이 온다. 남기는 동작은 다섯이다. `ctrl+c`, `ctrl+z`, `:`, `ctrl+p`, `ctrl+w w` 다.

거른 것은 **조용히** 버린다. `g` 뒤에 짝이 없는 키가 조용한 것과 같다(ADR-0003). 반면 이름을 대고 부른 것(`:w`, 팔레트 항목) 은 「열린 파일이 없습니다」 로 물러난다. 키는 눌러 본 것이지만 그쪽은 골라서 부른 것이라, 아무 일도 안 나면 편집기가 먹지 않는 것으로 읽힌다(`refuseNoBuffer`, `refuseReadOnly` 와 같은 꼴).

하단 drawer 를 쓰는 둘(`:registers`, 특수문자 넣기) 도 그렇게 막는다. drawer 는 편집 맥락에 딸린 것이고(ADR-0056, ADR-0058) 특수문자는 넣을 커서가 없다.

## 5. `:q` 는 tab 을 닫는다. 닫을 tab 이 없을 때만 종료다

마지막 tab 을 닫으면 빈 화면이 남는다. **그 화면에서 다시 `:q` 를 치면 종료다.** 닫을 tab 이 없다는 것이 화면에 이미 드러나 있는데 `:q` 를 친 것은 닫으라는 것이 아니라 나가겠다는 뜻이다.

이 갈래를 고른 이유는 셋이다.

- 규칙이 「`:q` 는 tab 을 닫는다, 단 마지막이면 종료다」 에서 「`:q` 는 tab 을 닫는다. 닫을 것이 없으면 나간다」 가 되었다. 같은 여섯 글자가 상황에 따라 다른 일을 하는 것이 아니라, 두 상황이 화면으로 갈라져 있다.
- **`:q` 를 두 번 치면 편집기가 끝난다.** vim 에서 오는 손버릇이 그대로 살고, 종료의 길이 `ctrl+c`·`:qa` 둘로 줄어드는 것도 아니다.
- 확인창의 범위가 예외 없이 성립한다. 예전에는 마지막 tab 의 `:q` 가 `quitAll` 로 들어가 `anyDirty()` 를 보았다. 이제 `:q` 가 `anyDirty()` 를 보는 곳이 하나도 없다. 「묻는 범위는 각자 잃는 것에 맞춘다」(ADR-0003) 가 분기 없이 참이다.

`:q!`·`:wq`·`:x` 도 같은 규칙이다. `:wq` 에만 종료를 남기지 않았다. 그러면 방금 없앤 「같은 이름이 상황에 따라 다른 일」 을 이름 사이로 옮겨 놓는 것이다. 빈 화면에서 `:wq` 는 저장할 파일이 없어서 물러난다.

곁따라 `:wq` 쪽 주석 하나가 거짓이 되었다. `.editorconfig` 를 따라 맞춘 것을 알리는 곳에 「마지막 tab 이었으면 편집기가 여기서 끝나므로 보이지 않는다」 가 있었는데, 이제 빈 화면 아래 줄에 보인다(ADR-0052).

## 6. 마지막 tab 의 우클릭도 닫는다. ADR-0060 §3 을 뒤집는다

그 결정이 마지막 tab 을 거부한 근거는 하나였다. 「한 번 잘못 누른 것으로 편집기가 통째로 닫히면 안 된다」. 편집기가 닫히지 않게 되면 남는 것이 없다. 슬쩍 눌러 잃는 것은 그 tab 의 커서와 스크롤과 undo 이력인데, **그것은 오늘 남의 tab 을 우클릭할 때 이미 잃는 것**이다. 마지막 tab 만 다르게 대할 이유가 없다.

## 결과

좋은 점

- 아무 파일도 열지 않은 상태가 화면에 그대로 보인다. 무엇을 할 수 있는지도 그 자리에서 알린다.
- 트리 삭제의 막다른 길이 없어졌다. 「먼저 닫아 주세요」 가 실행 가능한 안내가 되었다.
- `:e`·우클릭·`:q` 가 마지막 tab 에서 갈라지지 않는다.

감수하는 것

- 화면이 하나 늘어서 좁고 낮은 터미널에서 접히는 규칙을 또 하나 챙긴다.
- `activeBuffer()` 를 부를 수 없는 상태가 생겼다. 앞으로 편집 기능을 붙일 때마다 이것을 생각해야 하고, 그 안전망은 편집 키를 하나씩 먹여 보는 검사 하나다.
- 로고를 두 벌 든다. 고칠 때 줄 수와 폭을 맞춰야 한다.
- vim 은 마지막 창을 닫으면 끝난다. 첫 `:q` 에서 갈리고 두 번째에서 다시 만난다.

## 대안

- **이름 없는 tab 하나로 시작하고 마지막 tab 은 못 닫게 한다.** 지금까지의 동작이다. 「마지막 tab 을 닫으면 다시 그 화면」 을 이루지 못한다.
- **`:q` 는 언제나 종료로 남기고 빈 화면은 시작 화면으로만 둔다.** 화면 하나가 편집기 수명의 첫 프레임에만 있고 두 번 다시 볼 수 없다. 상태가 아니라 스플래시다. 게다가 `len(buffers) == 0` 은 시작 직후에 이미 존재하므로 방어 비용은 거의 그대로다.
- **빈 화면에서도 `:q` 는 tab 만 닫는다(아무 일도 없다).** 종료의 길이 `ctrl+c`·`:qa` 뿐이 되고, `:q` 를 두 번 치는 손버릇이 죽는다. 조용히 두면 편집기가 멈춘 줄로 읽혀서 알림을 하나 더 두어야 한다.
- **전용 mode 이름을 짓는다(`EMPTY`).** 되는 키가 거의 없는 mode 를 spec 의 목록에 하나 더 얹는다. 사람이 보는 것은 mode 가 바뀐 것이 아니라 편집할 것이 없는 것이다.

## 이 ADR 이 정하지 않는 것

- 로고의 모양과 색, tip 목록의 내용. 여기는 「그 자리에 무엇이 오는가」 만 정한다.
- 빈 화면에서 키 하나로 tab 을 만드는 길(`i`·`o` 가 `:tabnew` 를 겸하는 것). 조용히 tab 이 생기는 것이 나은지 따로 본다.
- 최근에 본 파일을 빈 화면에 적을지. 자리는 있지만 어디에 남길지가 따로 결정이다.
- 팔레트의 「모든 tab 닫기」. 「오른쪽 tab 모두 닫기」 와 같이 정할 건이다(ADR-0060).
- 빈 화면을 끄는 설정. 설정 파일 자체가 없다(ADR-0061 과 같은 건이다).
- 세션 복원.
