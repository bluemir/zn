# ADR-0016: 다시 읽기는 팔레트 항목 하나로 넣고, 저장하지 않은 변경이 있으면 확인창으로 묻는다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

ADR-0015 로 "밖에서 바뀐 파일을 모르고 덮어쓰지 않는" 안전망은 깔렸다. 그런데 그 경고를 받은
사용자가 할 수 있는 것은 두 가지뿐이었다. `:w!` 로 남이 쓴 것을 덮어쓰거나, 포기하는 것이다.
**바깥 내용을 편집기 안으로 가져올 길이 없었다.** ADR-0015 가 "이 ADR 이 정하지 않는 것" 으로
남겨둔 첫 항목이다.

가져와야 하는 자리는 저장이 막힐 때만이 아니다.

- 다른 터미널에서 `git pull`·`git checkout`·포매터를 돌린 뒤 그 결과를 보고 싶을 때
- 파일을 열어둔 채 밖에서 고친 것을 편집기 쪽으로 맞출 때
- 잘못 편집한 것을 저장 전에 파일 내용으로 되돌리고 싶을 때 (`u` 를 여러 번 누르는 것 대신)

셋 다 지금은 편집기를 나갔다 다시 들어와야 한다.

## 결정

**`Buffer.Reload` 를 넣는다.** 파일을 다시 읽어 `newBuffer` 로 만든 것을 그대로 갈아끼운다.
`Save`/`SaveForce` 와 나란한 세 번째 파일 입출력 지점이다.

**진입은 command palette 의 「파일 다시 읽기」 하나다.** `>` 목록에 한 줄이 늘고, 영문 `reload
file` 로도 찾힌다. `:e!` 는 넣지 않는다.

**저장하지 않은 변경이 있으면 확인창으로 묻는다.** 기존 확인창(`viewQuitConfirm` → 이름을
`viewConfirmDiscard` 로 바꿨다) 을 그대로 쓴다. Yes 면 다시 읽고, No·`Esc` 면 팔레트가 아니라
normal 로 돌아간다. 변경이 없으면 묻지 않는다.

**다시 읽기는 "이 파일을 새로 연 것" 이다.** undo·redo 이력을 버리고 `dirty` 를 끈다.
방금 읽은 내용이 새 `diskHash` 기준이 되므로 이어지는 `:w` 는 막히지 않는다.

**커서는 줄 번호와 화면 칸을 유지한다.** 파일이 짧아졌으면 범위 안으로 끌어온다. 화면(`top`) 도
보고 있던 자리를 이어받는다.

**밖에서 지워진 파일은 다시 읽지 않는다.** `파일이 없습니다: <경로>` 로 알리고 buffer 는
그대로 둔다. 이름 없는 buffer(`:tabnew`) 도 읽을 곳이 없으므로 묻기 전에 알리고 끝낸다.

## 근거

### 왜 팔레트인가

`:e!` 가 아니라 팔레트에 넣는다.

**`:e` 는 반쪽으로 넣을 수 없는 이름이다.** vim 의 `:e` 는 본래 "파일을 연다" 이고 인자 없는
`:e!` 는 그것의 특수한 경우다. 지금 명령줄 parser 는 인자 있는 명령을 받지 못해서
(`docs/tasks.md` 의 `:e <파일>` 항목) `:e!` 만 먼저 넣으면 `:e foo.go` 는 "알 수 없는 명령"
이 된다. vim 을 아는 손에게는 그쪽이 더 헷갈린다.

**목록에서 눈으로 읽는 이름이 이 기능에 맞다.** 자주 쓰는 명령이 아니다. 하루에 몇 번 쓰는
것을 위해 두 글자 명령을 외우게 할 이유가 없고, 팔레트는 이미 그런 것을 담는 자리다(ADR-0011).

**팔레트 항목은 되돌릴 수 없는 일을 담은 첫 항목이다.** 「줄 끝 공백 지우기」는 `u` 로 돌아오고
「파일 트리 열기/닫기」는 아무것도 잃지 않는다. 다시 읽기는 편집을 지운다. 그래서 확인창이 붙는다.

### 왜 확인창인가

팔레트 항목에는 `!` 를 붙일 자리가 없다.

ADR-0015 는 `:w`/`:w!` 로 갈랐다. **팔레트 목록에는 그 `!` 를 붙일 자리가 없다.** 항목 이름을
「파일 다시 읽기(강제)」로 둘로 늘리는 것은 목록을 읽는 사람에게 두 줄의 차이를 설명해야 하는
일이고, `!` 를 아는 사람만 고를 수 있는 항목이 목록에 있는 것도 이상하다.

**확인창은 이미 있다.** 종료와 tab 닫기가 쓰던 것을 그대로 쓴다. `y`/`n` 이 손에 익어 있고
한글 입력 상태의 키 되돌림(ADR-0008) 도 이미 붙어 있다. mode 를 새로 만들지 않는다.

**얻는 것이 `:w!` 때와 다르다.** 저장 충돌은 "지금 저장하면 안 된다" 는 **경고**여서 한 번
실패하고 다시 치는 흐름이 자연스럽다. 다시 읽기는 사용자가 이미 시킨 일이라, 실패로 끝내고
"다른 방법으로 다시 하라" 고 할 수 있는 두 번째 방법이 없다.

### undo 이력을 버리는 이유

**이력은 lines 의 자리(index) 로 기록된다.** 파일이 밖에서 바뀌면 그 자리는 다른 줄을 가리킨다.
남겨두면 `u` 가 엉뚱한 줄을 엉뚱한 내용으로 갈아끼운다. 자리를 옮겨 붙이는 것은 세 방향 병합에
가까운 일이고 이 편집기가 할 일인지부터 정해야 한다(ADR-0015 도 같은 것을 미뤘다).

**"다시 읽기 한 번을 `u` 로 되돌리기" 는 매력적이지만 값이 비싸다.** `edit` 이 파일 전체를
담아야 하고, `dirty` 판정과 `diskHash` 기준이 서로 어긋난다. 되돌린 뒤의 내용은 파일과 다른데
`diskHash` 는 방금 읽은 파일의 것이다. 확인창이 이미 실수 한 번을 막고 있으므로 여기서
그 복잡도를 내지 않는다.

### 커서를 유지하는 이유

**밖에서 포매터를 돌린 뒤가 가장 흔한 자리다.** 내용은 거의 그대로이고 보고 있던 곳도 그대로다.
맨 위로 올라가 버리면 그 자리를 다시 찾아가야 한다.

**칸은 byte offset 이 아니라 화면 칸으로 옮긴다.** 새 내용에서 같은 offset 이 두 칸 글자의
중간일 수 있다. 화면 칸은 `statusBar` 가 `줄:칸` 으로 보여주는 값이라, 유지되는 것이 눈에
보이는 값과 같다.

### 없는 파일을 빈 buffer 로 만들지 않는 이유

`OpenBuffer` 는 없는 파일을 빈 buffer 로 연다. 새 파일을 만드는 길이다. **다시 읽기는 반대다.**
밖에서 지워졌다면 편집기가 든 것이 마지막 사본이고, 그것을 지우는 명령이 되어서는 안 된다.
ADR-0015 가 사라진 파일에 대한 저장을 막은 것과 같은 태도다.

## 결과

좋은 점

- 저장이 충돌로 막혔을 때 편집기 안에서 바깥 내용을 가져올 수 있다. ADR-0015 가 남긴 구멍이 막힌다.
- 잘못 편집한 것을 파일 내용으로 되돌리는 길도 같이 생긴다(vim 에서 `:e!` 를 쓰는 흔한 용도다).
- 확인창을 재사용해서 새 mode 가 늘지 않았다. 늘어난 것은 팔레트 항목 한 줄과 `Buffer.Reload` 다.

감수하는 것

- **`:e!` 가 없다.** vim 에서 오는 손은 `:e!` 를 먼저 친다. `:e <파일>` 을 넣을 때 같이 본다.
- **undo 로 다시 읽기 전으로 돌아갈 수 없다.** 확인창의 Yes 가 마지막 방어선이다.
- **여전히 저장할 때까지 바깥 변경을 모른다.** 알림을 먼저 받는 것(`checktime`) 은 ADR-0015 가
  미룬 그대로다. 다시 읽을 길이 생겼으니 그 알림에 "다시 읽을까요" 를 붙일 수 있게 되었다.
- **커서 자리는 유지하지만 그 자리의 내용은 다를 수 있다.** 줄이 밀린 파일에서는 다른 내용 위에
  선다. 어디를 보고 있었는지를 유지하는 것과 무엇을 보고 있었는지를 유지하는 것은 다르다.

## 대안

- **`:e!` 명령**
	- vim 과 같은 이름이라 배울 것이 없다.
	- `:e <파일>` 없이 반쪽만 넣으면 이름이 거짓말이 된다.
	- 명령줄 parser 가 인자를 받게 될 때 팔레트 항목과 같이 두는 것이 자연스럽다.
- **전용 키(`R` 같은 것)**
	- 가장 빠르다.
	- 자주 쓰지 않는 것에 normal mode 의 한 글자를 내주는 것은 이르다.
	  키맵 전체를 정하는 결정(`docs/tasks.md`) 뒤로 미룬다.
- **묻지 않고 바로 다시 읽기**
	- 가장 단순하다.
	- 실수로 한 번 고르면 편집이 사라지고 되돌릴 길이 없다.
	  목록에서 화살표로 고르는 자리라 오조작이 명령줄보다 쉽다.
- **다시 읽기를 undo 한 항목으로 기록**
	- 실수를 되돌릴 수 있다.
	- `edit` 이 파일 전체를 담고 `dirty`·`diskHash` 판정이 꼬인다. 위의 근거에 적었다.
- **바깥 내용과 지금 내용을 나란히 보여주기(diff·세 방향 병합)**
	- 편집을 잃지 않고 합칠 수 있는 유일한 길이다.
	- 이 편집기가 할 일인지부터 정해야 한다. ADR-0015 도 같은 것을 미뤘다.

## 이 ADR 이 정하지 않는 것

- `:e <파일>` 과 그때 `:e!` 를 별칭으로 둘지
- 포커스가 돌아올 때 검사(`checktime`) 와 그 알림에 다시 읽기를 붙이는 형태
- 여러 tab 을 한 번에 다시 읽는 것(`:checktime` 에 해당하는 일괄 처리)
- 다시 읽은 뒤 검색 강조를 유지할지. 지금은 `search` 가 editor 에 있어서 그대로 남는다
- 세 방향 병합이나 diff 표시. ADR-0015 와 같이 미룬다
