# ADR-0007: 줄번호는 절대·상대를 왼쪽에 나란히 두고 상대만 흐린 색으로 그린다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

`hjkl` 과 숫자 접두를 넣고 나니(ADR-0006) `10j` 를 치려면 열 줄을 눈으로 세야 했다.
상대 줄번호가 있으면 세지 않고 읽는다. `docs/tasks.md` 에 "상대 줄번호와 절대 줄번호 동시 표시의
렌더 형태를 정하고 구현한다" 가 열려 있었는데, 정할 것이 렌더 형태였다.

vim 은 `number` 와 `relativenumber` 를 같이 켜면 한 칸에 몰아 넣는다 — 커서 줄만 절대번호이고
나머지는 상대번호다. 칸을 아끼는 대신 두 번호를 동시에 볼 수 없다. 오류 메시지의 줄 번호를 찾을
때는 절대번호가, 이동할 때는 상대번호가 필요한데 vim 방식은 커서를 옮겨가며 봐야 한다.

## 결정

**절대번호와 상대번호를 편집 영역 왼쪽에 `절대 상대` 순서로 나란히 그린다.**
상대번호가 본문에 붙는 쪽이다. 커서 줄의 상대번호는 `0` 이다.

**상대번호만 흐린 색이다.** 256색 244 로, sidebar 의 gitignore 색과 같은 값이다(ADR-0005).
절대번호와 본문에는 색이 없다.

**wrap 되어 이어지는 화면 행은 번호 칸이 빈 칸이다.** vim 과 같다.

**항상 그린다.** 여닫는 명령을 두지 않는다. 번호 칸을 떼고 나면 본문이 `minTextWidth`(20칸)
아래로 떨어지는 좁은 화면에서는 sidebar 와 같은 규칙으로 그리지 않는다.

**폭 계산을 둘로 나눈다.** `textWidth` 는 편집 영역 너비(tabline·statusBar 가 쓴다) 이고
`contentWidth` 는 거기서 번호 칸을 뺀 본문 너비다. 줄바꿈·스크롤·커서 계산은 전부 후자를 쓴다.

## 근거

### 둘을 나란히

**둘 다 동시에 필요하다.** 지금 몇 번째 줄인지(오류 메시지, `:42`, git diff) 와 몇 줄 떨어져
있는지(`10j`, 앞으로 들어올 `d5j`) 는 다른 질문이다. vim 방식은 둘 중 하나를 커서 자리에서만
답해준다. 칸 일곱은 80칸 화면의 9% 이고, 이 편집기는 sidebar 32칸을 이미 쓰고 있다.

**상대번호를 본문 쪽에 둔다.** 이동 거리를 셀 때 눈이 본문과 번호 사이를 오간다. 그 왕복이
짧아야 한다. 절대번호는 찾을 때만 보므로 바깥쪽이어도 된다.

**양쪽으로 나누지 않는다.** 오른쪽 끝에 상대번호를 두는 안도 봤다. 본문이 양쪽에서 좁아져
긴 줄이 더 일찍 접히고, 무엇보다 이동 거리를 보려고 눈을 화면 끝까지 보내야 한다.

**커서 줄은 `0` 이다.** vim 은 그 자리에 절대번호를 넣는데, 여기서는 절대번호가 바로 옆 칸에
이미 있다. `0` 이 찍혀 있으면 커서 줄이 한눈에 드러나고, 위아래 숫자가 `0` 에서 멀어지는 모양이
그대로 거리다.

### 색

**흐린 색이 본문과 번호를 가른다.** 번호 칸이 일곱 칸이라 그냥 두면 들여쓰기와 섞여 읽힌다.
상대번호는 이동할 때만 보는 것이라 평소에는 배경으로 가라앉아 있어야 하고, 절대번호는 본문과
같은 색이어서 둘이 색으로도 갈린다.

**ADR-0004(반전만 쓴다) 에서 또 벗어난다.** ADR-0005 가 sidebar 에서 이미 256색 고정값을
쓰기 시작했고, 여기서 값을 새로 만들지 않고 그 회색(244) 을 그대로 쓴다. 팔레트를 정하는
결정은 여전히 열려 있고, 그때 이 값도 같이 본다(`docs/tasks.md`).

### 여닫지 않는다

**`:tree` 가 기본으로 열려 있는 것과 같은 결정이다.** 개인용이라 늘 쓰는 상태를 기본으로 둔다.
명령을 두면 명령 하나와 상태 하나가 늘고, 그 상태는 tab 별인지 전역인지도 정해야 한다.
복사·붙여넣기 때문에 끄고 싶어지면 그때 `:number` 를 넣는다 — `docs/tasks.md` 에 남겼다.

**좁은 화면 규칙은 sidebar 를 따른다.** 폭을 떼는 것이 둘 다 같은 일이라 규칙이 다르면
어느 화면 크기에서 무엇이 사라지는지 설명할 수 없게 된다.

### 폭 계산을 나눈 것

**`textWidth` 하나가 두 뜻으로 쓰이고 있었다.** tabline·statusBar 는 편집 영역 전체를 쓰고
줄바꿈은 본문만 쓰는데, 번호 칸이 생기기 전에는 두 값이 같아서 드러나지 않았다.
`contentWidth` 를 만들어 buffer 를 만지는 모든 호출을 그쪽으로 옮겼다.
한 군데라도 놓치면 줄이 화면 오른쪽으로 삐져나가거나 커서가 본문과 어긋난다.

## 결과

좋은 점

- `10j`, `d5j`(앞으로) 를 세지 않고 읽는다. 절대번호도 같이 보여서 오류 메시지를 따라가기 쉽다.
- 커서 줄이 `0` 으로 드러난다. 반전을 칠하지 않고도 지금 줄이 어디인지 보인다.
- `textWidth`/`contentWidth` 가 갈려서 "편집 영역" 과 "본문" 이 코드에서 구분된다.

감수하는 것

- **본문이 일곱 칸 좁아진다.** sidebar 까지 열면 80칸 화면에서 본문이 41칸이다.
  긴 줄이 더 일찍 접힌다.
- **번호 칸 폭이 파일마다 다르다.** 1000 줄이 넘는 파일로 tab 을 옮기면 본문 시작 칸이 한 칸
  밀린다. 자릿수를 고정하면 짧은 파일에서 칸이 남고, 최소 3 칸을 둬서 흔한 경우는 안 흔들린다.
- **고정 색값이 하나 늘었다.** 밝은 테마에서 244 가 잘 안 보이는 문제를 sidebar 와 같이 안는다.
- **화면 문자열에 색이 섞였다.** 편집 영역 행을 글자 그대로 비교하던 테스트가 번호 칸을
  떼어내야 한다. `textOf`/`gutterOf` 로 나눴다.

## 대안

**vim 처럼 한 칸에(커서 줄만 절대)** — 칸을 가장 아낀다. 두 번호를 동시에 볼 수 없고,
절대번호를 알려면 커서를 그 줄로 옮겨야 한다. 이 결정의 출발점이 "둘 다 보고 싶다" 였다.

**상대번호만** — 이동에는 이것으로 충분하고 칸도 적게 든다. 오류 메시지나 리뷰 코멘트의 줄
번호를 찾을 방법이 statusBar 의 `줄:칸` 하나만 남는다.

**절대번호를 흐리게, 상대번호를 진하게** — 자주 보는 쪽을 진하게 하는 것이 맞아 보이지만,
그러면 본문 바로 옆의 진한 숫자가 들여쓰기와 섞여 읽힌다. 본문에 붙는 쪽이 가라앉아 있어야
경계가 산다.

**`~` 로 파일 끝 표시(vim)** — 번호 칸을 넣는 김에 같이 볼 수 있었다. 지금은 파일 끝 아래가
빈 줄이라 편집 가능한 줄과 구분되지 않는데, 이번 결정과 묶을 이유가 없어서 미뤘다.

## 이 ADR 이 정하지 않는 것

- 팔레트. 244 를 새로 만들지 않고 sidebar 값을 빌렸을 뿐이다
- `:number` 로 여닫는 것. 필요해지면 그때 넣는다
- 커서 줄 전체를 강조하는 것(vim 의 `cursorline`)
- 파일 끝 아래를 `~` 로 표시하는 것
- git 변경 표시나 접기(fold) 표시처럼 번호 칸 옆에 붙을 것들
