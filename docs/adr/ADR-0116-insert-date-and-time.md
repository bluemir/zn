# ADR-0116: 오늘 날짜와 시각은 RFC3339 로 넣는다

## 맥락

글을 쓰다 오늘 날짜를 적는 일이 잦다. 문서의 머리말, 메모의 항목, 로그에 남기는 시각이 그렇다. 지금은 손으로 치거나 다른 창에서 옮겨 와야 한다.

정할 것은 셋이다. 어떤 서식으로 넣을지, 명령을 몇 개 둘지, 커서의 어느 쪽에 넣을지다.

## 결정

### 서식은 RFC3339 다

`2026-09-01T19:27:19+09:00` 이다. Go 의 `time.RFC3339` 를 그대로 쓴다.

날짜와 시각 사이를 공백으로 두는 길도 있었다. RFC3339 §5.6 의 NOTE 가 사람이 읽는 용도로 그것을 허용하고, 눈으로 읽기에는 그쪽이 낫다. 그래도 `T` 를 골랐다. 넣은 글이 다시 기계에 들어가는 자리(스크립트의 인자, 로그, `git` 의 날짜 인자) 가 있고, 그때 통하는 것은 엄격한 쪽 하나뿐이다. 눈으로 읽기 어려운 것은 한 글자 차이인데, 다시 파싱되지 않는 것은 고칠 수 없다.

시간대는 편집기가 도는 곳의 오프셋이다. UTC 에서는 `Z` 가 된다. 초까지 찍고 소수부는 붙이지 않는다.

### 명령은 둘이다

「오늘 날짜 넣기」(`2026-09-01`) 와 「오늘 날짜와 시각 넣기」(RFC3339 전체) 다. 문서에 날짜만 적는 일이 시각까지 적는 일만큼 잦아서, 넣은 뒤 뒤를 지우게 하지 않는다.

날짜만 넣는 쪽은 RFC3339 의 날짜 부분(full-date) 이다. 두 서식이 앞머리를 나눠 갖는 것이라 날짜를 넣은 뒤 뒤에 시각을 이어 붙여도 같은 글이 된다.

시각만 넣는 셋째는 두지 않았다. 시각 홀로는 며칠 뒤에 읽으면 뜻이 없고, 필요한 자리가 떠오르지 않았다. 필요해지면 그때 한 줄이 는다.

### 팔레트에만 둔다

짝이 되는 `:` 명령을 두지 않았다. `:` 는 이름을 대고 치는 자리라 짧은 것이 미덕인데, 이 명령은 하루에 몇 번 부르는 것이고 팔레트에서 `date` 로 찾으면 두 줄이 함께 선다. 필요해지면 `:date` 를 여는 자리는 남아 있다.

### 커서 뒤에 넣는다

normal 의 `a` 와 같은 자리다. 특수문자 drawer 도 같은 손이고(ADR-0056), insert 에서 팔레트를 연 경우 그쪽이 커서를 normal 자리로 맞춰 놓고 넘기므로 치던 자리에 그대로 들어간다(ADR-0011).

넣고 나면 normal 로 돌아간다. drawer 를 열어 잇달아 넣는 특수문자와 달리 이것은 한 번에 끝나는 일이라 열어 둘 판이 없다. 커서는 넣은 마지막 글자 위에 서고, 넣은 것은 한 번의 `u` 로 통째로 돌아온다.

### 시각은 부르는 자리에서 뜬다

`time.Now()` 를 run 함수 안에서 부른다. 시계를 밖에서 넣지 않는다 — 저장소의 다른 자리도 그렇게 하고 있고(`job.go`·`notice.go`), 시험할 것은 「지금」이 아니라 서식이다.

## 결과

- 팔레트에서 `date` 로 두 명령이 함께 선다. 한글 이름을 몰라도 `insert date` 로 찾힌다.
- 읽기 전용 파일과 파일이 없는 화면에서는 목록에 뜨지 않는다(`whenWritable`). 고치는 명령의 조건 그대로다.
- 두 명령의 몸통은 하나다(`paletteInsertText`). 갈리는 것이 서식 하나라 두 벌로 두지 않았다. 대소문자 맞추기 둘이 `paletteChangeCase` 를 나눠 쓰는 것과 같다.
- 넣는 글이 커서 자리에 그대로 들어가므로, 이 몸통은 날짜가 아닌 다른 글을 넣는 명령이 생기면 그대로 쓸 수 있다.
