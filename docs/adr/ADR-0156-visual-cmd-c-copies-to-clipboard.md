# ADR-0156 visual 의 cmd+c 는 `"+y` 다. mac 만 본다

- 상태: 채택
- 날짜: 2026-10-15
- 관련: ADR-0037(visual mode), ADR-0058(register), ADR-0148(시스템 클립보드)

## 맥락

visual 로 고른 것을 시스템 클립보드로 보내는 길은 `"+y` 와 팔레트의 「선택 영역 클립보드로 복사」 둘이다. mac 에서 손이 먼저 가는 것은 cmd+c 인데, 그 키는 터미널이 먼저 먹어서 편집기에 오지 않았다.

정할 것은 셋이다.

1. 어느 키를 받는가
2. 터미널이 그 키를 어떻게 넘기게 하는가
3. 앞에 댄 이름(`"a`) 과 어떻게 만나는가

## 1. `super+c` 하나, visual 에서만

kitty 키보드 프로토콜은 mac 의 cmd 를 `super` 로 보낸다. 편집기는 이미 그 프로토콜을 켜 두었다(`editor.go` 의 `KeyboardEnhancements`). 그래서 `super+c` 를 받는 줄 하나면 된다.

**visual 에서만이다.** 보낼 것이 고른 범위라 normal 에서는 보낼 것이 없다. normal 에서 줄을 보내는 것은 `"+yy` 다.

**mac 만 본다.** Linux 의 Super 키도 같은 `super` 로 오므로 그쪽에서도 되긴 한다. 다만 Linux 에서 손에 붙은 복사 키는 그것이 아니라 `ctrl+shift+c` 나 `ctrl+insert` 이고, 그 둘은 대개 터미널이나 데스크톱이 먼저 가져간다. 어느 것을 열지는 Linux 에서 실제로 쓸 때 정한다(docs/tasks.md).

`ctrl+shift+c` 를 같이 받지 않은 까닭도 그것이다. Linux 터미널 대부분이 그 키를 자기 복사에 쓰므로 cmd+c 와 같은 설정 문제를 하나 더 안는다.

## 2. Ghostty 는 `performable:` 로 넘긴다

Ghostty 1.3.1 의 기본값은 `super+c=copy_to_clipboard` 다. 이것을 그냥 풀면(`unbind`) 마우스로 긁은 터미널 글자를 cmd+c 로 복사하는 손이 사라진다.

그래서 설정에 이 줄을 둔다.

```
keybind = performable:super+c=copy_to_clipboard
```

Ghostty 문서에 따르면 `performable:` 은 「할 수 있을 때만 키를 먹는다」이고, `copy_to_clipboard` 는 터미널 쪽 선택이 있을 때만 할 수 있다. 선택이 없으면 그 키 설정이 없는 것처럼 앱에 넘긴다. 마우스로 긁은 것은 Ghostty 가, visual 로 고른 것은 편집기가 복사한다. 문서에는 그렇게 적혀 있지만 아직 손으로 재 보지는 않았다.

**편집기가 이 설정을 대신 해 주지 않는다.** 남의 설정 파일이고, 키가 오지 않으면 아무 일도 없을 뿐 해가 없다. spec 과 도움말에 그 줄을 적는다.

## 3. 앞에 댄 이름은 덮지 않고 버린다

`"acmd+c` 는 아무것도 하지 않는다. cmd+c 는 이름이 이미 `+` 로 정해진 키다. 뒤에서 댄 이름이 이기게 하면 `a` 에 담기고, 클립보드로 보낸 줄 알고 다른 창에 붙인 손이 빈손이 된다. 앞에서 댄 이름이 이기게 하면 cmd+c 의 뜻이 「이름을 댄 `y`」로 흐려진다. 둘 다 아니게 둔다. 이름을 받지 않는 동작에 이름을 대면 버려지는 것과 같은 자리다(ADR-0058).

## 기각한 것

- **`unbind` 로 늘 넘기기.** 터미널의 드래그 복사가 cmd+c 를 잃는다
- **normal 에서 줄 보내기.** `yy` 와 뜻이 겹치고, mac 앱에서 cmd+c 는 고른 것이 없으면 아무것도 아니다
- **cmd+v 로 붙이기.** 터미널이 cmd+v 를 bracketed paste 로 이미 넣어 준다. 편집기가 받을 일이 없다

## 결과

- visual 에서 cmd+c 가 `"+y` 와 같다. 무명에도 담기고 「(클립보드)」를 알리며 커서는 범위의 시작으로 간다
- super 를 넘기지 않는 터미널(Terminal.app) 에서는 키가 오지 않는다. tmux 안도 아마 그렇다(재 보지 않았다). 그때는 `"+y` 와 팔레트가 그대로 길이다
- Linux 의 키는 정하지 않았다
