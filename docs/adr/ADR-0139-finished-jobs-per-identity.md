# ADR-0139: 끝난 작업은 신원당 하나로 남기고 상한을 둘 둔다

- 상태: 채택
- 날짜: 2026-09-07
- 관련: ADR-0030(이름당 하나), ADR-0075(이름과 인자), ADR-0077(상한을 두는 첫 목록), ADR-0138(`:!&`)

## 맥락

`:jobs` 의 끝난 목록은 **이름당 마지막 결과 하나**였다. 그 까닭이 ADR-0030 에 적혀 있다.

> 끝난 순서대로 쌓으면 주기적으로 도는 git 갱신이 목록을 자기 이름으로 뒤덮어서, 조용히 실패한 다른 작업을 찾으라고 남겨둔 자리가 그것으로 다 찬다.

상한을 두지 않아도 됐던 것은 「이름은 코드에 있는 종류만큼만 있다」였기 때문이다. ADR-0075 가 신원을 (이름, 인자) 로 가른 뒤에도 **끝난 목록을 미는 기준은 이름으로 남겨** 두었다.

`:!&`(ADR-0138) 가 그 가정을 깬다. **셸 명령은 이름이 하나인데 인자가 사람이 치는 만큼 다르다.** `make build` 를 돌려 놓고 결과를 보려는 사이 `go test` 가 끝나면 앞의 것이 목록에서 사라진다. 둘 다 방금 내가 시킨 것인데 하나만 남는다.

## 결정

### 1. 미는 기준을 이름에서 신원으로 바꾼다

```go
kept := slices.DeleteFunc(e.finished, func(old job) bool {
	return old.is(name, args)   // 예전에는 old.name == name
})
```

**ADR-0030 이 막은 자리는 되돌아오지 않는다.** git 갱신과 파일 검사는 인자가 없어서 신원이 곧 이름이라 지금도 하나로 모인다. 5 초마다 도는 것이 목록을 뒤덮는 일은 그대로 막혀 있다. 인자가 있는 것만 신원마다 한 줄이 되고, `:jobs` 는 그것을 이름 줄 아래로 접으므로(ADR-0075) 화면에는 `디렉터리 읽기 (30)` 한 줄로 보인다.

### 2. 상한을 개수와 시간 둘 다 둔다

**둘이 서로 다른 것을 막는다.** 개수는 빠르게 끝나는 것이 쏟아지는 것을, 시간은 오래 켜 둔 판에 옛것이 앉아 있는 것을 막는다.

- `finishedJobsMax = 50` — 넘으면 오래된 것부터 버린다
- `finishedJobsTTL = 30분` — 그보다 오래 끝나 있던 것을 버린다

**값의 근거는 이 목록에서 무엇을 잃는지다.** 실패는 알림 목록(`:messages`) 에 상한 없이 남으므로(ADR-0053) 여기서 밀려나며 사라지는 것은 「언제 끝났는지」뿐이다. 그래서 스크롤로 훑어 찾을 수 있는 범위면 넉넉하고, 몇 시간 전 빌드의 결과는 아무 물음에도 답하지 않는다.

**근거 없는 상수를 막아 둔 ADR-0093 을 지나는 자리다.** 그 문서가 「근거 없는 상수 하나가 「왜 이 숫자인가」를 영영 달고 다닌다」로 상한을 물렸는데, 여기는 **사람이 치는 만큼 자라는 목록**이 되었으므로 저절로 멈추지 않는다. 여러 파일 검색이 「상한을 두는 첫 목록」이 된 것과 같은 모양이다(ADR-0077 §7).

### 3. 자르는 자리는 넣을 때 하나뿐이다

`finishJob` 에서만 자른다. **그리는 자리에서 자르면 보는 중에 줄이 사라진다.** 목록이 바뀌는 것은 무언가 끝났을 때뿐이어야 한다.

## 감수하는 것

**상한 상수가 둘 늘었다.** ADR-0093 이 경계한 그 종류이고, 위 2 번의 근거가 그 값을 지킨다. 값이 맞지 않으면 옮길 자리다.

**오래 켜 두면 방금 끝난 것 말고는 남지 않는다.** 30 분이 그 경계다. 그보다 옛것을 찾아야 하면 `:messages` 다 — 실패는 거기 다 있다.

**끝난 디렉터리 읽기가 한 줄씩 쌓인다.** ADR-0075 가 이름으로 밀어 없앤 그 줄들이 다시 생긴다. 이름 줄 아래로 접히므로 화면에서는 한 줄이고, 개수 상한이 그 수를 묶는다.

## 대안

- **개수 상한만** — 오래 켜 두면 몇 시간 전에 끝난 것이 자리를 잡고 앉아 지금 보려는 것을 밀어낸다
- **시간 상한만** — 빠르게 끝나는 것이 쏟아지면 30 분 안에 수백 줄이 쌓인다
- **셸만 예외로 여러 개 남기기** — 「끝난 목록의 규칙」이 작업 갈래마다 달라진다. `:jobs` 를 읽는 사람이 갈래별 규칙을 알아야 하게 된다
- **그대로 두기(이름당 하나)** — `:!&` 를 두 번 돌리면 앞의 결과를 볼 길이 없다. 이 ADR 이 생긴 까닭이다

## 결과

- `:!& make build` 와 `:!& go test` 의 결과가 나란히 남는다
- 주기 갱신은 여전히 한 줄이다
- 시험은 `TestFinishedJobsKeepLastPerIdentity`·`TestFinishedJobsCollapsePeriodicRefresh`·`TestFinishedJobsDropOldestOverMax`·`TestFinishedJobsDropStale` 다
