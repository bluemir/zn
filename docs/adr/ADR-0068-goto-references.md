# ADR-0068 사용처로 가기는 정의로 가기의 짝이고, 선언은 목록에서 뺀다

- 상태: 채택
- 날짜: 2026-08-24

## 맥락

`\gd`(ADR-0051)·자동완성(ADR-0066)·이름 바꾸기(ADR-0067) 가 gopls 연결을 다 놓아 두어서, `docs/tasks.md` 에 남아 있던 「사용처로 이동」에 붙일 것은 요청 하나뿐이었다.

**정의로 가기의 거울이다.** 그쪽은 「이 이름은 어디서 왔나」이고 이쪽은 「이 이름을 누가 쓰나」다. 묻는 요청(`textDocument/references`) 만 다르고 **답의 모양이 같다.** 정의와 똑같이 `Location` 목록이라 응답을 읽는 함수(`parseLocations`) 도 그것을 보이는 화면(`viewLocations`) 도 그대로 쓴다. 새로 쓴 것은 `internal/lsp/references.go` 와 `internal/core/references.go` 둘이고 나머지는 한 줄씩이다.

## 1. 선언한 곳은 목록에 넣지 않는다(`includeDeclaration: false`)

vim 의 LSP 클라이언트 다수가 선언을 같이 넣는다. 그렇게 하지 않은 까닭이 둘이다.

- **정의로 가기가 따로 있다.** 선언으로 가고 싶으면 `\gd` 다. 한 목록에 「정의 하나 + 사용처 여럿」이 섞이면 고르는 사람이 줄마다 어느 갈래인지 눈으로 갈라야 하는데, 목록에 적히는 것은 `경로:줄` 뿐이라 갈라 볼 단서가 없다.
- **0 개가 뜻을 갖는다.** 선언을 빼면 「사용처를 찾지 못했습니다」가 곧 **아무도 이 이름을 쓰지 않는다**는 말이다. 선언이 들어 있으면 안 쓰이는 이름이 1 개로 오고, 그 1 개는 「곧바로 뛴다」(2 절) 규칙에 걸려 **제자리로 뛴다.** 아무 일도 안 난 것처럼 보인다.

**gopls 가 이 값을 실제로 지키는지 재고 넣었다.** 남의 프로세스의 약속이라 규격만 믿지 않는다. `openBuffers` 의 선언한 곳에서 물어 5 개를 받았고 그중에 선언 줄은 없었다 (`TestGoplsReferencesExcludesDeclaration`).

## 2. 하나면 곧바로 뛰고, 여럿이면 목록을 연다

정의로 가기와 같은 규칙이다(`finishDefinition`). 한 줄짜리 목록을 띄우고 `enter` 를 또 받는 것은 손이 하나 더 드는 일이고, 그 화면이 알려 주는 것은 이미 뛴 뒤에도 보인다.

「사용처가 몇 개인가」를 늘 보고 싶다는 쪽도 있었는데, 그것 때문에 **자주 있는 쪽(하나)** 에 손을 하나 더 얹을 만하지는 않다고 보았다.

## 3. 커서를 선언에 둘지 사용처에 둘지 사용자가 고민하지 않아도 된다

재 보니 **어느 곳에서 물어도 같은 목록이 온다**(`TestGoplsReferencesFromUseSite`). 그래서 「선언 위에서 쳐야 합니다」 같은 안내를 두지 않았다.

## 4. 부르는 문은 `\gr` 과 팔레트 둘이다

`\g` 접두는 이미 「간다」 갈래다(`\gd`). `r` 은 references 이고, `\rn`(rename) 과는 접두가 갈라서 부딪히지 않는다. 한글 자판에서는 `₩ㅎㄱ` 로 들어오는데 leader 와 자모 되돌리기가 이미 그 일을 맡고 있다(ADR-0008, ADR-0014).

**`:` 명령은 만들지 않았다.** `:rename` 이 있는 것은 `:rename <새 이름>` 처럼 인자를 받아 창을 건너뛸 수 있어서인데(ADR-0067), 사용처 찾기는 받을 인자가 없다. 정의로 가기도 같은 까닭으로 `:` 명령이 없다.

## 5. 문 앞의 검사를 정의 쪽과 하나로 묶지 않았다

`gotoReferences` 가 보는 것(볼 파일이 있나 → Go 파일인가 → 서버가 떴나 → 없으면 설치를 묻는다) 은 `gotoDefinition` 과 순서까지 같다. 그래도 묶지 않은 것은 **알리는 문구가 「무엇을 찾는 중인가」로 갈리기 때문**이다. 묶으면 그 문구가 인자가 되고, 인자로 문장을 만드는 함수는 여기 있는 대여섯 줄보다 읽기 어렵다. `startRename` 도 자기 검사를 따로 든다 (ADR-0067). 검사가 늘어나는 것은 「무엇을 묻는가」가 아니라 「무엇을 고치는가」 쪽인데 (rename 의 읽기 전용·뿌리 밖), 묻기만 하는 둘은 그 자리에서 갈릴 일이 없다.

## 무엇이 걸리는가

첫 요청이 **935ms** 다. 서버가 저장소 전체를 훑는 일이라 정의 찾기(15ms) 가 아니라 rename(664ms) 쪽이다. 그 뒤로는 **2ms** 다. 그래서 답을 기다리지 않고 Cmd 로 내는 것이 정의 쪽보다 더 필요하다. 기다리면 편집기가 1 초 멈춘다.

## 이 ADR 이 정하지 않는 것

- 목록에 줄 내용을 같이 보이는 것. 여기 오는 파일은 정의 후보와 달리 대개 **저장소 안**이라 「디스크에서 읽은 글」과 「tab 에서 고치던 글」이 갈리는 문제가 더 잘 드러난다. 여러 파일 검색이 이 화면을 쓸 때 같이 정한다(ADR-0051)
- 「구현으로 가기」(`textDocument/implementation`). interface 를 쓰지 않는 저장소라 물을 일이 잘 없다(README 의 「정의/구현으로 이동」)
- 사용처 목록에서 곧바로 이름을 바꾸는 길. 미리보기 화면과 같은 건이다(ADR-0067)
- Go 밖의 언어. 언어 서버가 gopls 하나다
