# ADR-0115: 커밋 기록을 화면 둘로 보인다

- 상태: 채택
- 날짜: 2026-09-01

## 맥락

`docs/tasks.md` 에 「`git log`, `git graph` 의 결과를 볼 수 있는 기능」이 열려 있었고 「무엇을 어떻게 보일지가 남은 일이다」라고 적혀 있었다. ADR-0042 가 go-git 을 들여 놓아서 커밋을 훑는 것은 이미 라이브러리가 해준다. 없던 것은 화면이다.

지금까지 편집기 안에서 기록을 보려면 `:!git graph` 로 셸에 내보내야 했다. 출력이 터미널에 흘러가고 남지 않으며(ADR-0045) 편집기 안에서 훑을 수 없다.

바탕이 되는 그림은 이미 있었다. 사용자의 `git graph` alias 다.

```
log --graph --abbrev-commit --decorate --all
    --format='%h - %aD (%ar)%d%n          %s - %an'
```

`--all` 이고, 커밋 하나가 두 줄이며, 색이 `%h` 파랑·`%aD` 청록·`%ar` 초록·`%d` 노랑·`%an` 흐린 회색이다. 새로 정할 것이 아니라 옮겨올 것이 있었다.

## 1. 화면을 통째로 쓰는 판 둘이다

목록이 `GRAPH`, 상세가 `COMMIT` 이다. `:jobs`·`:messages` 와 같은 갈래이고 `renderTitle` + 목록 + 키 안내 + statusBar 로 짜였다.

**팔레트처럼 얹지 않는다.** 커밋 하나가 두 줄이라 상자에 담으면 다섯 개 남짓밖에 안 보인다. 기록은 훑는 것이라 그 수로는 쓸 수 없다.

**하단 drawer 로 내리지도 않는다.** 판을 내리는 근거는 늘 「편집 화면이 같이 보여야 고를 수 있다」였다(ADR-0069, ADR-0078). 검색 결과는 위아래 문맥을 봐야 고를 수 있고 정의 후보도 그렇다. **커밋은 그렇지 않다.** 지금 보고 있는 파일과 무관한 것을 고르는 자리라 편집 화면이 보일 값이 없고, 오히려 두 줄짜리 항목이 열여섯 줄 안에서 여덟 개로 줄어든다.

**상세도 화면을 통째로 덮는다.** 목록을 위아래로 갈라 아래에 전문을 두는 길도 있었는데, 그러면 목록이 대여섯 커밋으로 줄고 전문도 열 줄로 줄어서 **둘 다 쓸 수 없게 된다.** 훑을 때는 목록이 넓어야 하고 읽을 때는 전문이 넓어야 하는데 그 둘은 동시에 일어나지 않는다.

**상세는 목록 model 을 그대로 들고 있다가 `q` 에 돌려준다.** 고른 자리와 스크롤이 저절로 남는다. 확인창이 부모를 드는 것과 같은 손이다(view-quit-confirm.go, ADR-0110).

## 2. 범위는 `--all` 이다

local branch·tag·remote branch 의 끝을 모두 씨앗으로 삼는다. HEAD 에서 닿는 것만 담는 길도 있었지만, **기록을 여는 까닭의 절반이 「저쪽은 어디까지 갔나」다.** 방금 만든 branch 도 `git fetch` 로 받은 것도 HEAD 범위에서는 보이지 않는다.

alias 가 이미 `--all` 이라 옆 터미널과 같은 그림이 되는 것도 값이다.

**차례는 커밋한 때 내림차순이다.** git 의 기본과 같다. 큐는 heap 이 아니라 넣을 때 자리를 찾아 꽂는 배열이다 — 담기는 것이 「지금 갈래들의 끝」이라 저장소가 아무리 커도 branch 수만큼이다. 같은 순간이면 해시 순으로 갈라서, 커밋을 몰아서 만든 저장소에서도 차례가 실행마다 달라지지 않는다.

## 3. 커밋은 필요한 만큼만 조금씩 읽는다

한 번에 1,000 개다. 고른 자리가 담긴 것의 끝에서 100 개 안으로 들어오면 다음 조각을 읽는다.

**자리를 보고 읽는 것이 요점이다.** 조각이 도착할 때마다 다음 것을 이어 걸면 여는 순간부터 저장소를 통째로 읽게 되어, 조금씩 읽기로 한 뜻이 사라진다.

**훑는 자리(`graphWalk`) 를 job 에게 넘겼다 돌려받는다.** 시작하는 쪽이 `editor` 에서 떼어 goroutine 에 실어 보내고(그 사이 `editor` 쪽은 nil 이다) 끝나면 `apply` 가 되돌려 놓는다. 두 곳에서 동시에 만지는 자리가 없어서 잠금이 필요 없다 — job.go 가 `apply` 를 Update 안에서 부르는 약속을 그대로 쓴 것이다(ADR-0025, ADR-0027).

**끊겨도 읽은 것과 훑는 자리를 돌려준다.** 버리면 「읽는 중」이 선 채로 굳어서 그 화면이 다시는 읽지 못한다.

**저장소를 여는 것은 작업이 아니다.** ref 를 읽는 것뿐이라 값이 없고, 「저장소가 아닙니다」를 친 자리에서 바로 돌려줄 수 있다. 비싼 것은 커밋을 훑는 쪽이고 그것만 나간다.

**`G` 는 지금 담긴 것의 끝이다.** 저장소의 첫 커밋이 어디인지는 다 읽어야 알 수 있고, 그것을 기다리게 하지 않는다. 거기서 다음 조각이 이어 붙는다.

## 4. 판을 열 때마다 처음부터 읽는다

앞서 본 것을 두지 않는다. 팔레트 파일 목록과 같은 태도다(ADR-0011) — 바깥에서 `commit`·`fetch` 를 하고 돌아왔을 때 묵은 기록을 보이면, 그 사이의 커밋이 빠진 채로 「기록」이라고 말하게 된다.

값은 첫 조각 하나뿐이다. 이 저장소에서 196 개를 읽는 데 눈에 띄는 시간이 들지 않는다.

## 5. 레인은 열 배열 하나로 잡는다

`lanes []plumbing.Hash` 가 열마다 「그 열이 기다리는 커밋」을 든다. 커밋을 내보낼 때 자기 열을 찾고(없으면 왼쪽부터 빈 열), 같은 커밋을 기다리던 다른 열을 그리로 모으고, 자기 열을 첫 부모로 갈아 끼운다. 나머지 부모는 빈 열을 얻는다.

**빈 열을 왼쪽부터 찾는다.** 그래야 갈래가 끝난 자리를 다음 갈래가 물려받아 그래프가 오른쪽으로만 자라지 않는다. git 도 같다.

**그리는 법은 훑기가 모른다.** 줄마다 `before`(그리기 전 열) 와 `after`(그린 뒤 열) 를 남기고, 어느 글자로 그릴지는 그리는 쪽이 정한다 — 터미널에 따라 갈리는 판단이라(ADR-0028) 훑기가 들 것이 아니다.

**대각선을 쓰지 않고 모서리를 쓴다.** git 은 `|\`·`|/` 인데 우리는 `│─┐`·`●─┘` 다. `╲`·`╱` 를 새로 들이면 `boxSet` 에 글자가 둘 늘고 ASCII 로 물러설 때 `\`·`/` 를 또 정해야 하는데, **모서리는 이미 넷 다 있다.** 뜻도 같다 — 세로에서 가로로 꺾이는 자리다.

**점(`●`) 은 `boxSet` 에 새로 들였다.** 박스 그리기 문자는 아니지만 `●` 도 East Asian Ambiguous 라 두 칸으로 그리는 터미널에서는 열이 통째로 밀린다. 이 화면은 열 맞춤이 전부라 선과 점이 같은 판단을 타야 한다(ADR-0028, ADR-0072). ASCII 로 물러서면 `*` 이고 그것이 git 이 쓰는 글자다.

**그래프 칸의 폭은 커밋마다 잰다.** 화면 전체로 한 번 재면 저 아래 갈래 하나 때문에 위쪽 커밋이 통째로 오른쪽으로 밀리고, 훑어 내려갈 때마다 본문이 좌우로 흔들린다. git 의 `--graph` 도 줄마다 따로 잰다.

## 6. 색은 alias 에서 옮겨 온다

해시 파랑(ANSI 12), 날짜 청록(14), 얼마나 전인지 초록(10), ref 이름 노랑(11) 이다. 제목은 기본색이고 글쓴이는 흐린 회색(`styleDetail`) 이다.

256 색 고정값이 아니라 ANSI 밝은 색인 것은 git 마커·진단과 같은 자리다(ADR-0007, ADR-0041, ADR-0094) — 여기서 필요한 것은 특정 파랑이 아니라 **그 테마가 부르는 파랑**이다.

**그래프 선과 점에는 색을 두지 않는다.** 갈래를 가르는 것은 자리이지 색이 아니고, 색을 넣으면 그 색이 뜻하는 바를 또 익혀야 한다.

**고른 줄에는 색을 얹지 않는다.** 색을 켜고 끄는 escape 가 안에 있으면 그 자리에서 반전이 끊겨 줄이 얼룩덜룩해진다. 고른 줄이 무엇인지는 반전 하나로 이미 다 말한다.

**고른 커밋은 두 행을 다 반전한다.** 한 항목이 두 행이라 한 행만 칠하면 어디까지가 한 커밋인지가 갈리지 않는다. 첫 행에 `▸` 도 붙는다.

## 7. 상세는 `git show --format=fuller` 를 따른다

`commit`·(`Merge:`)·`Author:`·`Date:`·(`Commit:`·`CommitDate:`)·메시지·파일 목록 차례다.

`Merge:` 는 부모가 둘 이상일 때만, `Commit:`·`CommitDate:` 는 커밋한 사람이 쓴 사람과 다를 때만 선다. 늘 적으면 같은 값이 두 번 적히는 줄이 커밋마다 둘씩 는다.

**파일 목록은 `--name-status` 자리다.** 줄 수(`+12 -3`) 는 내지 않는다. blob 을 전부 풀어 diff 를 돌려야 나오는 값이고, 그 값이 필요해지는 것은 diff 화면과 함께다.

**merge 는 첫 부모와 견준다.** `git log --name-status` 는 merge 에서 아무것도 보여주지 않는데(`-m` 을 줘야 나온다) 그것보다는 「이 merge 로 무엇이 들어왔나」가 쓸모 있다. 갈래에서 이미 본 파일이 다시 서지만 아무것도 안 서는 것보다 낫다.

**옮긴 파일을 찾는다.** git 도 2.9 부터 `--name-status` 에서 기본으로 찾는다. go-git 에서는 `DefaultDiffTreeOptions` 를 그대로 넘겨야 한다 — `DiffTreeOptions{DetectRenames: true}` 만 주면 닮은 정도의 문턱이 0 이 되어 **지운 파일과 새로 만든 파일이 무엇이든 짝지어진다.** 내용이 전혀 다른 둘도 「옮긴 것」이 되고, 시험이 그것을 잡았다.

**읽기는 작업이 아니라 msg 를 돌려주는 Cmd 다.** 작업은 결과를 `editor` 에 놓는 틀인데(`apply func(*editor)`) 이것은 지금 보고 있는 화면 하나의 것이라 `editor` 에 남길 값이 없다. 정의를 묻고 답을 받는 자리와 같은 손이다(ADR-0051). 늦게 온 답은 해시를 견줘 버린다.

## 8. `d`(diff) 는 넣지 않는다

그릴 화면이 아직 없다. 줄 단위 diff 는 이미 내고 있지만(ADR-0094) 그것을 나란히 보여주는 화면이 없고, 그것은 diff mode 와 같은 건이다(`docs/tasks.md`).

**안내 줄에도 적지 않는다.** 먹지 않는 키를 권하지 않는다.

상세의 파일 목록이 그리로 가는 문이 된다 — diff 가 생기면 그 줄에서 열면 된다.

## 결과

좋은 점

- `:!git graph` 로 셸에 내보내지 않고 편집기 안에서 기록을 훑는다. `q` 로 나오면 보던 파일 그대로다.
- 옆 터미널의 `git graph` 와 같은 그림이다. 형식도 색도 alias 에서 옮겼다.
- 수만 커밋 저장소에서도 여는 순간 뜬다. 훑는 것은 뒤에서 이어진다.
- `git` 바이너리가 없어도 된다. ADR-0042 가 깔아 놓은 자리를 그대로 쓴다.
- 차례가 진짜 `git log --all` 과 같은지를 시험이 견준다. 파일 목록도 `git show --name-status` 와 견준다.

감수하는 것

- **닫았다 다시 열면 처음부터 읽는다.** 만 번째 커밋까지 훑어 내려갔다가 나가면 그 자리를 잃는다.
- **범위를 바꾸는 길이 없다.** `--all` 고정이라 갈래가 많은 저장소에서는 열이 넓어진다.
- **`origin/HEAD` 가 이름표에 서지 않는다.** 상징 참조를 씨앗에서 건너뛰는데, git 의 `--decorate` 는 그것도 적는다.
- **merge 의 파일 목록이 첫 부모 기준이다.** git 과 다른 답이고, 갈래에서 이미 본 파일이 다시 선다.
- **가로선이 살아 있는 열을 지날 때 한 칸 끊긴다.** 지나가는 갈래를 지우면 그 갈래가 사라진 것처럼 보여서, 그 자리는 세로선이 이긴다. 갈래 셋 이상이 한 자리에서 모일 때만 보인다.
- **얕은 복제(shallow) 의 잘린 자리를 표시하지 않는다.** 읽히지 않는 부모는 없는 것으로 다뤄서, 거기가 끝인지 잘린 것인지가 화면에 드러나지 않는다. git 은 `grafted` 라고 적는다.
- **해 단위 상대 시각이 git 보다 거칠다.** git 은 `1 year, 4 months ago` 인데 우리는 `1 년 전` 이다.
- **`bareStatusBar` 가 넷째 사본이다.** `:jobs`·`:messages` 가 같은 것을 자기 안에 하나씩 들고 있고, 이번에 그 둘을 데려오지는 않았다(`docs/tasks.md`).

## 대안

- **하단 drawer 에 목록을 담는다**
	- `drawer` 틀(ADR-0101) 을 그대로 쓸 수 있고 편집 화면이 같이 보인다.
	- 두 줄짜리 항목이 열여섯 줄 안에서 여덟 개가 된다. 그리고 이 화면은 지금 보고 있는 파일에 딸린 것이 아니라 편집 화면이 보일 값도 없다.
- **커밋 하나를 한 줄로 그린다**
	- 한 화면에 두 배가 들어가고 `j`/`k` 가 커밋 하나씩 지난다.
	- 좁은 화면에서 제목이 잘린다. 그리고 alias 와 다른 그림이 되어 옆 터미널과 견줄 수 없다.
- **범위를 HEAD 에서 닿는 것으로 한다**
	- 열이 하나로 좁고 지금 branch 의 이야기만 보인다.
	- 다른 branch 의 끝이 안 보이는데, 기록을 여는 까닭의 절반이 그것이다. alias 도 `--all` 이다.
- **커밋을 전부 미리 읽는다**
	- 「몇 개」를 처음부터 말할 수 있고 `G` 가 진짜 끝으로 간다.
	- 수만 커밋 저장소에서 여는 데 시간이 들고, 훑지도 않을 것을 다 들고 있게 된다.
- **`Worktree.Log` 나 `object.NewCommitIterCTime` 을 쓴다**
	- 큐를 우리가 짜지 않아도 된다.
	- 씨앗을 하나만 받아서 `--all` 이 안 된다. 여러 ref 에서 시작하려면 어차피 밖에서 합쳐야 한다.
- **대각선(`╲`·`╱`) 으로 그린다**
	- git 의 `|\`·`|/` 와 더 닮는다.
	- `boxSet` 에 글자가 둘 늘고 ASCII 대체도 따로 정해야 한다. 모서리 넷은 이미 있고 뜻도 같다.

## 이 ADR 이 정하지 않는 것

- 커밋의 diff 를 보이는 법. diff 화면과 같은 건이다(`docs/tasks.md`)
- 닫았다 다시 열 때 자리를 기억할지
- 범위를 `--all` 과 HEAD 사이에서 오갈지
- 파일 하나의 기록(`git log -- <path>`) 을 볼지
- 커밋에서 그 자리로 뛰거나 해시를 register 에 담을지
- branch 를 옮기거나 만드는 것. 읽기만 하는 화면이다
