# ADR-0003: tab 전환은 `gt`/`gT`, `:q` 는 tab 을 닫고 `Ctrl+C` 는 전체를 끝낸다

- 상태: 채택
- 날짜: 2026-08-12

## 맥락

CLI 인자로 받은 파일들은 이미 전부 `editor.buffers` 에 실려 있었다(`cmd/main.go` 의 인자 주석도 "tab 으로 열린다" 라고 적혀 있었다). `Buffer` 가 커서와 스크롤을 직접 들고 있는 것도 "tab 을 오갈 때 파일별로 유지되어야 하므로" 였다. 그런데 `buffers[0]` 말고는 갈 방법이 없었다.

두 가지를 정해야 tab 이 동작한다.

1. **전환 키.** normal mode 에는 지금 한 글자 키만 있다(`i`, `a`, `u`, `:`). vim 의 `gt`/`gT` 는 `g` 뒤에 키가 하나 더 붙는 조합이라, 없던 "다음 키를 기다리는 상태" 가 필요해진다.
2. **`:q` 의 범위.** tab 이 하나뿐일 때는 "닫기" 와 "종료" 가 같은 말이라 구분할 필요가 없었다. ADR 없이 `:q` 와 `Ctrl+C` 를 아예 같은 `quit` 경로로 묶어 뒀다(`docs/spec.md` 에도 "`:q` 와 `Ctrl+C` 는 같은 경로다" 라고 적혀 있다). tab 이 여럿이면 둘이 갈라진다.

## 결정

**전환 키는 `gt` / `gT` 다.** `g` 를 접두 키로 받고, 이어지는 키가 `t` 면 다음 tab, `T` 면 이전 tab 이다. 양끝에서 둘러 간다. 접두 키를 기다리는 상태(`pending`) 는 `editor` 가 아니라 `viewEditorNormal` 이 들고 있다. 별개 model 로 빼지 않았다.

**`:q` 는 지금 보고 있는 tab 만 닫는다.** 마지막 tab 이면 닫을 것이 없으므로 종료가 된다.

> ADR-0064 가 이 한 문장을 뒤집었다. tab 이 하나도 없는 상태를 두었으므로 마지막 tab 도 닫히고 그 자리에 빈 화면이 남는다. 종료가 되는 것은 **닫을 tab 이 없는 그 화면에서 다시 쳤을 때**다. `:q` 를 두 번 치면 끝난다는 점은 그대로다.

`Ctrl+C` 는 전체 종료이고 `:qa` 와 같은 경로다. 확인창은 각자 잃는 것만 본다. `:q` 는 활성 tab 의 변경만 보고, `Ctrl+C`/`:qa` 는 어느 tab 이든 변경이 남아 있는지를 본다.

## 근거

### `gt` / `gT`

**vim 그대로다.** `docs/tasks.md` 에는 "vim 대비 무엇을 개선하는지" 를 정하기 전에는 키맵을 짜지 않는다는 항목이 아직 열려 있다. tab 전환은 그 결정을 기다릴 이유가 없다. 개선할 것이 있어서가 아니라 손가락이 이미 알고 있어서 고른다. 결정이 필요한 키(`hjkl`, `Esc` 의 커서 이동) 는 계속 미뤄 둔다.

**단일 키를 쓰지 않은 이유.** `Ctrl+N`/`Ctrl+P` 나 `Alt+숫자` 는 접두 키 없이 끝나서 코드가 두 줄 늘고 마는 선택지였다. 하지만 `Ctrl+N` 은 vim 에서 자동완성이고, `Alt` 는 터미널·OS 에 따라 안 잡히는 경우가 있다. 손에 익은 것을 버리고 얻는 것이 없다.

**접두 키는 어차피 필요해진다.** `dd`, `cw`, `3j`, `gg` 가 전부 같은 모양이다. `gt` 가 그중 처음 들어오는 것일 뿐이라, 여기서 접두 키를 피해 봐야 미루는 것이지 없애는 것이 아니다.

**별개 model 로 빼지 않은 이유.** ADR-0002 는 mode 별 상태를 그 mode 에 두라고 하고, "operator-pending 을 별개 model 로 둘지" 는 열어 뒀다. 지금 필요한 것은 문자열 필드 하나이고 `g` 하나뿐이다. type 을 하나 더 만들면 전환 함수와 `WindowSizeMsg` 껍데기가 같이 따라온다. operator(`d`, `c`) 가 들어와서 "무엇을 기다리는가" 가 진짜 상태가 되면 그때 다시 본다.

**짝이 없는 조합은 버린다.** `g` 뒤에 아무 키나 오면 아무 일도 일어나지 않는다. `esc` 와 `Ctrl+C` 도 여기로 와서 버려진다. vim 처럼 잘못 누른 접두 키를 무르는 것이고, 덕분에 `g` 뒤에 손이 미끄러져서 편집기가 꺼지는 일도 없다.

### `:q` 는 tab, `Ctrl+C` 는 전체

**둘을 같은 경로로 묶었던 이유가 사라졌다.** 원래 묶은 이유는 "`Ctrl+C` 가 미저장 상태를 몰라서 `:q` 와 다르게 동작하는 것" 을 고치기 위해서였다(`docs/tasks.md`). 그때 맞추려던 것은 **확인을 하느냐** 였지 **무엇을 닫느냐** 가 아니다. 확인 규칙은 여전히 같다. 잃을 것이 있을 때만 묻는다. 범위만 갈라진다.

**vim 과 같다.** `:q` 는 창을 닫고 `:qa` 는 전부 닫는다. 위에서 `gt`/`gT` 를 고른 것과 같은 이유다.

**`Ctrl+C` 를 tab 닫기로 두면 위험하다.** 한 키로 tab 이 하나씩 사라지는데, 마지막 하나에서는 그 키가 곧 종료다. "닫기" 를 반복하다 편집기 전체를 날리는 모양이 된다. 편집기를 끝내는 것은 누를 때 그렇게 하려던 것이어야 한다.

**확인창이 잃는 것만 묻는다.** `:q` 로 dirty 인 tab 을 닫을 때 다른 tab 의 변경까지 들먹이면 겁만 주고 정보는 틀리다. 반대로 `Ctrl+C` 는 보고 있지 않은 tab 의 변경도 같이 잃으므로 활성 buffer 만 봐서는 안 된다. 그래서 `anyDirty()` 가 따로 있다.

## 결과

좋은 점

- 이미 실려 있던 `buffers` 가 실제로 쓰인다. 커서·스크롤은 `Buffer` 에 있어서 전환이 공짜다.
- 잃는 것의 범위와 묻는 범위가 맞는다.
- 접두 키 자리가 생겨서 `gg`, `dd` 를 넣을 때 둘 자리가 이미 있다.

감수하는 것

- **`g` 를 누른 동안 화면에 아무 표시가 없다.** vim 도 그렇지만, vim 은 `showcmd` 로 오른쪽 아래에 보여준다. statusBar 에 넣을 자리가 있는데 아직 넣지 않았다.
- **`docs/spec.md` 의 "`:q` 와 `Ctrl+C` 는 같은 경로다" 를 뒤집는다.** 문서를 같이 고쳤다.
- **tabline 이 화면 너비를 넘으면 잘린다.** 활성 tab 이 오른쪽 끝에 있으면 안 보인다. 파일을 몇 개나 여느냐에 달린 문제라 실제로 겪은 뒤에 고치기로 하고 `docs/tasks.md` 에 남겼다.
- **tabline 이 편집 영역을 한 줄 먹는다.** tab 이 하나여도 그렇다. vim 은 기본값이 "2 개 이상일 때만" 인데, 열린 파일이 하나뿐이라는 것도 보고 있으면 알아야 할 정보라 항상 그리기로 했다. 화면이 계속 흔들리지 않는 이점도 있다.

## 대안

- **`:bn`/`:bp` 명령만 두기**
	- 접두 키가 필요 없어서 기존 `run()` 의 switch 에 case 만 늘리면 끝난다.
	- tab 전환은 편집 중에 수시로 하는 동작이라 매번 `:` 를 치고 `Enter` 를 누르는 것은 비싸다.
	- 명령은 나중에 곁들일 수는 있어도 이것만 두는 것은 답이 아니다.
- **`Alt+1`~`Alt+9` 로 직접 선택**
	- 번호로 바로 간다. 터미널·OS 에 따라 `Alt` 가 안 잡히는 것이 알려진 문제라, 개인용 단일 바이너리라도 환경을 옮기면 깨진다.
	- tabline 에 번호를 찍어 뒀으니 나중에 곁들일 수는 있다.
- **`Ctrl+Tab`**
	- 다른 편집기와 같다. 터미널이 `Tab` 과 구분해서 보내주지 않는 경우가 많다.

## 이 ADR 이 정하지 않는 것

- 편집 중에 파일을 여는 방법(`:e <파일>`, `:tabnew`). 인자 있는 명령 파싱이 필요해서 미뤘다
- tab 을 닫는 것 말고 tab 순서를 바꾸거나 옮기는 동작
- operator-pending(`d`, `c`) 을 별개 model 로 둘지. 여기서는 `g` 하나라 필드로 뒀을 뿐이다
- tabline 의 색. statusBar 색 결정과 같이 본다
