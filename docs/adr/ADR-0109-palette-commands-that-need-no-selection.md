# ADR-0109 고른 범위가 필요 없는 팔레트 명령 다섯을 넣는다

- 상태: 채택
- 날짜: 2026-08-31
- 관련: ADR-0011(팔레트와 `>` 명령 표), ADR-0016(확인창), ADR-0037(visual mode), ADR-0064(빈 화면), ADR-0065(저장 hook), ADR-0106(markdown 표 맞추기)

## 맥락

`docs/tasks.md` 가 세 자리에 「command palette 에 추가할 명령」을 적어 두었고 여덟 항목이 남아 있었다.

close right tabs, close all tabs, 새파일 만들기, transfer to upper, transfer to lower, format selection, sort line ascending, remove duplicated white space.

세어 보니 **여덟이 한 갈래가 아니었다.** 셋은 고른 범위를 받아야 하고, 셋은 없는 기능을 새로 만드는 일이고, 둘은 tab 조작이다.

## 1. 고른 범위가 필요한 셋은 넣지 않는다

`view-palette.go` 가 명령을 돌리기 직전에 고른 범위를 놓는다.

```go
// **여기서부터는 반드시 팔레트를 떠난다. 고른 범위를 놓는 자리다.**
if m.hasTab() {
	m.activeBuffer().clearSelection()
}
```

놓는 근거가 그 자리에 적혀 있다. 놓지 않으면 커서를 옮기며 둘러보는 판에서 강조가 커서를 따라 널뛰고, 특수문자 판은 고른 것이 칠해진 채 글자를 넣으며, 다른 파일을 열면 원래 tab 에 유령 강조가 남는다.

그래서 대소문자 바꾸기와 `format selection` 은 **팔레트에 둘 자리가 아직 없다.** 「팔레트가 고른 범위를 어떻게 넘겨주는가」를 먼저 정해야 하고, 그것은 `docs/tasks.md` 가 markdown 표 쪽에서 이미 미결로 남긴 물음이다(ADR-0106 과 같이 볼 건이다). 지금 그 몫은 visual 의 `u`·`U`·`~`·`\mt` 가 맡는다.

**대신 넣지 않았다는 사실을 tasks.md 에 근거째 남겼다.** 세 항목을 한 줄로 모으고 무엇을 먼저 정해야 하는지 적었다.

## 2. 줄을 다루는 둘은 파일 전부를 대상으로 한다

「줄 끝 공백 지우기」·「표 맞추기」가 이미 그렇다. 같은 손을 쓰면 팔레트가 범위를 넘겨주는 문제를 지나가지 않아도 되고, `u` 한 번에 통째로 돌아간다.

### 줄 정렬은 byte 순이고 오름차순뿐이다

사전 순(locale) 을 쓰지 않는다. **판마다 다른 답을 내기 때문**이고, 「설정 없이 컴파일된다」는 이 편집기의 태도와도 맞지 않는다. byte 순이라 대문자가 소문자보다 앞에 서고, UTF-8 의 byte 순이 코드포인트 순과 같아서 한글 음절은 가나다 순으로 선다(음절이 유니코드에서 이어져 있다).

안정 정렬이다. 같은 줄끼리 자리를 바꾸지 않으므로 두 번 돌려도 결과가 같고, 두 번째는 「이미 정렬되어 있습니다」로 끝난다.

내림차순과 중복 줄 지우기는 두지 않았다. 이름을 하나 더 늘리는 일이고, 오름차순을 써 보고 정할 일이다.

### 중복 공백 지우기는 들여쓰기와 줄 끝을 건드리지 않는다

**들여쓰기는 이 편집기가 뜻으로 다루는 공백이다.** `.editorconfig` 가 그 폭을 정하고 autoindent 가 그것을 잇고 마커가 그것을 그린다. 줄이면 코드가 깨진다.

**줄 끝은 「줄 끝 공백 지우기」의 몫이다.** 한 명령이 두 가지를 하면 무엇이 내 줄을 고쳤는지 알기 어려워진다(ADR-0011 의 「한 기능에 진입점 하나」와 같은 태도다). 둘을 이어 쓰면 둘 다 사라지고, 그 조합을 시험이 덮는다.

그래서 이 명령이 보는 것은 **들여쓰기 뒤부터 줄 끝 앞까지**다. 그 사이의 이어진 공백·tab 을 빈 칸 하나로 줄인다.

## 3. tab 을 닫는 둘은 「다른 tab 모두 닫기」와 같은 손이다

잃을 것이 있으면 확인창을 띄운다. 팔레트 항목에는 `:q!` 의 `!` 처럼 강제를 붙일 자리가 없어서다(ADR-0016).

**무엇을 보고 묻는지가 둘에서 갈린다.**

- 오른쪽만 닫는 것은 활성 buffer 와 그 왼쪽을 건드리지 않으므로 오른쪽만 본다(`rightDirty`)
- 모두 닫는 것은 활성 tab 의 변경까지 잃으므로 전부 본다(`anyDirty`)

**「모든 tab 닫기」는 편집기를 끝내지 않는다.** 빈 화면이 남고, 거기서 `:q` 를 치면 그때 끝난다. 마지막 tab 을 닫는 것이 이미 그렇게 동작하므로 새 규칙이 아니다(ADR-0064). 활성 자리는 -1 로 둔다. `closeTabAt` 이 마지막 하나를 닫을 때 남기는 값과 같다.

오른쪽 끝 tab 에서는 「오른쪽 tab 모두 닫기」가 **목록에 아예 뜨지 않는다**(`whenRightTabs`). 골라 놓고 거절하는 것보다 고를 수 없는 편이 낫다는 ADR-0011 의 규칙 그대로다.

## 4. 「새 파일」은 빈 tab 이다. 디스크에 만들지 않는다

인자 없는 `:tabnew` 와 같은 것이라 `alias` 에 그것을 적었다.

디스크에 파일을 만드는 것은 트리의 `mc` 가 이미 한다. 팔레트에서 경로를 받으려면 입력 화면이 하나 더 생기고, 그것은 이 항목이 요구한 일보다 크다. tasks.md 에 후속으로 남겼다.

**`when` 을 두지 않은 유일한 새 명령이다.** 볼 파일이 없는 빈 화면에서도 떠야 한다 — 거기서 편집을 시작하는 길이기 때문이다. 재보니 빈 화면의 목록이 다섯에서 여섯이 되었다.

## 결과

팔레트 명령이 17 개에서 22 개가 되었다.

`docs/spec.md` 의 명령 표에 다섯 줄을 더하고, **낡아 있던 개수도 같이 고쳤다.** 「열여섯 중 다섯만 남고」로 적혀 있었는데 표는 이미 17 개였다. 두 표가 낡는 것을 검사로 막을지는 tasks.md 가 이미 미결로 들고 있는 물음이다.

## 이 ADR 이 정하지 않는 것

- **팔레트가 고른 범위를 넘겨주는 길.** §1 의 셋이 그것을 기다린다
- **정렬의 내림차순·중복 줄 지우기·사전 순.** 오름차순을 써 보고 정한다
- **`:` 표에 짝을 만들지.** ADR-0011 이 「이유가 생기기 전까지 한 기능에 진입점 하나」로 정해 둔 자리다
- **목록이 길어지는 것.** 22 개가 한 화면에 다 보이지 않는데, 거르면 대개 몇 줄로 줄어서 지금은 값이 드러나지 않는다
