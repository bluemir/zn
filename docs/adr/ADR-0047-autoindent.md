# ADR-0047: 새 줄의 들여쓰기는 언어별 규칙이 정하고, 규칙은 lexer 옆에 둔다

- 상태: 채택
- 날짜: 2026-08-22
- 이후: 같은 규칙 위에 `=` `>` `<`(이미 있는 줄 다시 들여쓰기) 를 얹으면서 `Close` 의 계약이
  「방금 친 것이 닫는 표시가 되었는가」에서 **「줄 앞에 이것이 있으면 나온 줄인가」**로 넓어졌다.
  치는 도중에 줄을 옮길지는 부르는 쪽이 정한다. 글자 하나가 그 답을 0 에서 1 로 바꾼 순간에만
  움직인다. `Reindents()` 가 늘어서 markdown 이 `=` 에서 비켜난다
- 이후: **「한 단계」가 들여쓰기를 움직이는 모든 키의 공통 기준이 되었다.** `tab` 은 tab 글자를
  넣는 키가 아니라 한 단계 들여쓰는 키이고, `shift+tab`(내어쓰기) 과 들여쓰기 안의
  `backspace` 도 같은 값을 쓴다. 세는 단위는 byte 가 아니라 화면 칸이다. `TabIndentsLine()` 이
  늘어서 markdown 목록에서는 tab 이 줄 전체를 옮긴다

## 맥락

`o` `O` 와 insert 의 Enter 는 언제나 빈 줄을 만들었다. `edit.go` 의 주석이 그것을
「vim 의 `noautoindent`」라고 못 박아 두었다. 들여쓴 Go 코드를 쓰면 줄마다 tab 을 다시 친다.

같은 저장소에 `cc` 는 이미 첫 줄의 들여쓰기를 남긴다(ADR-0033). 손에는 둘 다 「새로 칠 줄」인데
한쪽만 들여쓰기를 준다. `docs/tasks.md` 가 그 어긋남을 열어 두고 autoindent 를 정할 때 같이
보라고 적어 두었다.

넣는다면 어디까지인지가 갈렸다. vim 의 `autoindent` 는 앞 줄의 공백을 그대로 복사하는 것이
전부라 언어를 모른다. `{` 뒤에서 한 단계 더 들어가려면 그 줄이 무엇인지 알아야 한다.
그것을 알 자리는 이미 있었다. 문법 강조가 줄마다 토큰을 담아 두고(ADR-0039) 파일 이름으로
언어를 고른다. `docs/tasks.md` 가 「sticky header 와 autoindent 가 이제 같은 토큰을 쓸 수
있다」고 적어 둔 것이 이 자리다.

## 결정

**언어를 보고 정한다.** 아홉 언어에 규칙을 둔다. golang·js·css 는 중괄호, python 은 줄 끝의
`:`, shell 은 `then`·`do`, html 은 닫히지 않은 tag, makefile 은 대상 줄 뒤의 조리법 tab,
dockerfile 은 `\` 로 이어지는 줄, markdown 은 목록 표시다. 언어를 모르는 파일은 앞 줄의
공백을 그대로 잇는다. vim 의 `autoindent` 와 같다.

**규칙은 `internal/syntax` 안, 언어별 lexer 파일 옆에 둔다.** `languageRule` 표에 칸이 하나
늘고 `Detect` 와 짝인 `IndentFor` 가 는다. 규칙은 `Indent` interface 이고 `State` 와 나란한
두 번째 언어별 값이다.

```go
type Indent interface {
	Next(line []byte, tokens []Token) (level int, prefix []byte)
	Close(head []byte) int
	Unit() []byte
}
```

**단계로만 답한다.** 한 단계가 tab 인지 space 몇 칸인지는 파일마다 다르고 그것을 정하는 자리는
core 다(ADR-0048). `Unit` 만 예외로 공백을 아는데, 그것은 「이 파일이 무엇을 쓰는가」가 아니라
「이 언어가 관례로 무엇을 쓰는가」(gofmt 는 tab, PEP 8 은 space 넷) 라 언어 지식이 맞다.

**한 번에 한 단계뿐이다.** 한 줄에서 두 겹을 열어도(`foo({`) 한 단계다.

**닫는 표시를 치는 순간 그 줄이 당겨진다.** 커서 앞이 들여쓰기와 닫는 표시뿐일 때만이다.
`Close` 가 **방금 친 글자를 담은** head 를 받고, Enter 는 `\n` 이라는 마침 글자로 흘러간다.
그래서 「치다가 닫았다」와 「닫고 줄을 떠난다」가 규칙 하나로 걸린다.

**붙여넣기에는 걸지 않는다.** 걸어붙이는 자리를 `insert` 안이 아니라 부르는 쪽에 둔다.

**자동으로 넣은 들여쓰기는 지우지 않는다.** 아무것도 치지 않고 그 줄을 떠나도 공백이 남는다.

## 근거

**토큰이 이미 있어서 언어별 규칙이 싸졌다.** 문자열·주석 안의 괄호를 세지 않는 것이 이 일의
가장 성가신 부분인데, 줄마다의 토큰이 그 자리를 이미 가리키고 있다. `codeBytes` 하나가
그 자리를 공백으로 지우고 나면 아홉 규칙이 전부 평범한 byte 비교다. 손으로 lexer 를 다시
쓰지 않아도 되는 값이 규칙을 lexer 옆에 두는 이유다.

**`Close` 가 방금 친 글자를 받는 것이 낱말로 닫는 언어를 살린다.** shell 의 `fi` 를 두 글자만
보고 당기면 `file=x` 를 칠 때 세 번째 글자에서 이미 줄이 튄 뒤다. 마침 글자를 기다리면
`fi` 와 `file` 이 갈린다. Enter 를 마침 글자로 흘려보내는 것은 덤이 아니라 이 설계의 값이다.
`fi` 를 치고 바로 Enter 를 치는 것이 가장 흔한 손인데, 그것이 특별한 길을 타지 않는다.

**한 단계로 묶은 것은 어긋났을 때의 값 때문이다.** 겹을 세면 `foo({` 에서 두 단계가 되는데,
그것이 맞는 경우와 gofmt 가 한 단계만 주는 경우가 섞인다. 한 단계는 틀려도 tab 한 번이지만
두 단계가 틀리면 손으로 되돌리는 것이 더 번거롭다.

**붙여넣기를 뺀 것은 겹치면 계단이 되기 때문이다.** `insert` 는 타이핑·Enter·Tab·붙여넣기가
모두 지나는 단 하나의 경로다. 안에 넣으면 여러 줄 붙여넣기에서 원래 들여쓰기 위에 자동
들여쓰기가 얹혀 줄마다 오른쪽으로 밀린다. vim 이 `:set paste` 를 두는 이유가 이것인데,
설정을 두지 않기로 한 이상 걸어붙이는 자리를 옮기는 것이 답이다.

**빈 줄의 공백을 남기는 것은 상태를 늘리지 않으려는 것이다.** 지우려면 「이 공백은 자동으로
넣은 것」을 buffer 가 기억해야 하고, 그 기억은 커서가 움직이거나 되돌리기가 지나갈 때마다
맞춰야 한다. 남는 것은 줄 끝 공백인데 그것을 지우는 팔레트 명령이 이미 있다.

## 결과

- `o` `O` `r<Enter>` 와 insert 의 Enter 가 모두 들여쓰기를 받는다. `cc` 와 손이 같아졌다
- 화면에 이미 있는 글자가 움직이는 자리가 하나 생겼다. 닫는 표시를 치는 순간이다.
  좁게 잡았지만 zn 에서 처음 있는 갈래의 동작이다
- 되돌리기는 손대지 않았다. `insert` 가 여러 줄을 이미 한 구간으로 다루므로 Enter 와
  들여쓰기가 `u` 한 번에 같이 사라진다
- 언어를 더할 때 손댈 칸이 하나 늘었다. 빠뜨리면 그 언어만 조용히 앞 줄 잇기로 내려가서,
  `TestIndentForEveryLanguage` 가 그것을 막는다
- 코드펜스 안과 `<script>`·`<style>` 안은 바깥 언어의 규칙을 받는다. 규칙을 파일 이름으로
  고르기 때문이다. 강조는 이미 안쪽 언어로 넘기고 있어서(ADR-0040) 색과 들여쓰기가 갈린다
- **같은 규칙이 `=` `>` `<` 를 그대로 떠받쳤다.** operator 표에 키 셋을 더한 것이 전부라
  motion·숫자·겹치기(`>>` `3>>`)와 visual 쪽이 딸려 왔다(ADR-0013, ADR-0037). 세 자리에서
  갈렸다. 글자 단위 범위(`>w`) 여도 걸친 **줄 전체**가 움직이고(들여쓰기는 줄의 성질이다),
  `>` `<` 는 언어를 보지 않으며(손으로 미는 것이라 규칙이 끼어들 자리가 없다), markdown 은
  `=` 가 비켜 간다. `>` `<` 가 **얼마나 떼는지**를 세는 단위는 화면 칸이 아니라 byte 라
  tab 과 space 가 섞인 파일에서 어긋난다. `docs/tasks.md` 에 열어 두었다. 자르는 **자리**는
  들여쓰기 안을 벗어나지 않으므로 글자가 깨지는 갈래의 문제는 아니다

## 대안

**앞 줄의 공백만 복사한다(vim 의 `autoindent`).** 규칙이 하나라 언어를 몰라도 되고 틀릴 일이
거의 없다. 뺀 이유는 이 저장소가 Go 로 쓰였고 `{` 뒤에서 tab 을 한 번 더 치는 것이 남는
일의 대부분이기 때문이다. 그리고 이것은 언어별 규칙의 밑바닥으로 그대로 남아 있다.
언어를 모르는 파일이 받는 것이 정확히 이것이다.

**규칙을 새 `internal/indent` 패키지에 둔다.** `syntax` 의 「줄을 훑어 갈래를 말한다」는 계약이
그대로 남는다. 뺀 이유는 언어를 알아보는 표가 둘로 갈리기 때문이다. 언어를 더할 때 손대는
자리가 둘이 되고, 한쪽만 고치면 강조는 되는데 들여쓰기는 안 되는 언어가 생긴다. 그리고
토큰을 받으려면 어차피 `syntax` 를 import 해야 한다.

**규칙을 `internal/core` 에 모은다.** Buffer 와 바로 닿아 있어 가장 적게 움직인다. 뺀 이유는
`.go` 가 무엇인지 아는 자리가 두 군데가 되기 때문이다. 위와 같은 값을 반대쪽에서 치른다.

**진짜 파서로 정한다.** `go/parser` 는 이미 표준 라이브러리에 있다. 뺀 이유는 편집 중의 소스가
거의 언제나 문법이 깨져 있기 때문이다. 줄을 새로 만드는 그 순간이 특히 그렇다.

## 「한 단계」를 재는 법

**byte 가 아니라 화면 칸이다.** byte 로 세면 tab 파일에 섞인 space 줄에서 `<` 가 한 단계가
아니라 공백 한 칸만 뗀다. 「한 단계」가 키마다 다른 뜻이 되면 기준이 아니다.

**재는 자리는 화면이다.** tab 을 `.editorconfig` 의 `tab_width` 가 아니라 zn 이 실제로 그리는
폭(`tabWidth = 4`) 으로 센다. 눈에 보이는 것과 움직이는 것이 어긋나면 안 되고, 화면 폭은
ADR-0020 이 정한 것이라 그쪽을 열지 않고서는 바꿀 수 없다. `tab_width = 8` 이라고 적힌
저장소에서 이 둘이 갈리는데, 갈리는 자리가 「tab 하나가 몇 칸인가」뿐이라 `docs/tasks.md` 에
열어 두었다.

**칸 수만 맞추고 그 줄이 쓰던 글자는 둔다.** vim 은 `<<` 를 칠 때 들여쓰기를 `expandtab` 에
맞춰 다시 짓는데, 그러면 tab 파일에 섞인 space 줄이 `>` 한 번에 tab 으로 바뀐다. 미는 것과
글자를 갈아치우는 것은 다른 일이라 나눴다. 갈아치우는 것은 `=` 가 할 일이다.

## 이 ADR 이 정하지 않는 것

- **저장할 때 정렬기를 돌리는 것**(`gofmt` hook). README roadmap 에 따로 있다
- **코드펜스와 `<script>` 안을 안쪽 언어의 규칙으로 넘기는 것.** 넘기려면 규칙을 파일 이름이
  아니라 그 줄을 시작한 문맥(`syntax.State`) 으로 골라야 하는데, 그러면 상태 스무 남짓이
  전부 규칙을 들어야 한다
- **한 단계를 무엇으로 볼지.** ADR-0048 이 정한다
