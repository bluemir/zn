# ADR-0152 트리에서 파일과 디렉터리를 복제한다. `mc` 는 복제, 만들기는 `ma`

- 상태: 채택
- 날짜: 2026-10-06
- 관련: ADR-0054(트리에서 만들고 지우고 이름 바꾸기), ADR-0146(트리 우클릭 메뉴), ADR-0005(트리는 symlink 를 따라가지 않는다), ADR-0032(트리를 나눠 읽기)

## 맥락

트리에서 만들고 지우고 이름을 바꿀 수는 있는데 복제가 없었다. 옆에 비슷한 파일을 두려면 셸로 내려가 `cp` 를 쳐야 했다. ADR-0054 는 「넣을 때는 이름을 받는 화면과 '이미 있으면 거절' 판정을 이름 바꾸기 쪽에서 가져온다」고만 남겼다.

정할 것은 여섯이다.

1. 키를 무엇으로 둘지
2. 디렉터리를 어디까지 복제할지
3. symlink 를 따라갈지
4. tab 에서 고치고 저장하지 않은 파일은 무엇을 복제할지
5. 중간에 실패하면 무엇을 남길지
6. 끝난 뒤 어디에 설지

## 1. `mc` 를 복제로 넘기고 만들기는 `ma` 하나로 둔다

NERDTree 의 파일 메뉴는 `a`(add)·`m`(move)·`d`(delete)·`c`(copy) 다. ADR-0054 가 그 메뉴를 `m` 접두 자리에 두었으면서 `c` 를 만들기에 썼고, NERDTree 손버릇을 위해 `ma` 를 별칭으로 붙였다. 복제가 들어오면 `c` 자리가 둘에게 걸린다.

**`c` 는 복제에게 준다.** 그러면 `ma`·`mm`·`md`·`mc` 넷이 NERDTree 와 같은 글자가 된다. 별칭이 필요 없어지고 만들기는 `ma` 하나로 남는다.

전에 `mc` 로 만들던 손은 이제 복제 화면을 연다. 잃는 것은 없다. 화면이 `복제: 지금 경로` 로 열려 무엇이 다른지 곧바로 보이고, 그대로 `enter` 를 누르면 「이미 있습니다」로 아무것도 하지 않는다.

아래 줄 안내도 `a 새 파일  c 복제  d 지우기  m 새 이름` 으로 바뀐다.

## 2. 디렉터리는 통째로, 그 자리에서 돌린다

디렉터리를 고르면 안의 것까지 다 복제한다. 파일만 받으면 디렉터리를 고른 손이 거절당하고, 그 거절을 피할 길이 셸뿐이다.

**job 으로 돌리지 않는다.** `enter` 를 누른 자리에서 끝낸다.

- 트리에서 복제하는 것은 대개 작은 것이다. 순간에 끝난다
- job 으로 돌리면 끝났을 때 트리를 다시 읽고 고른 자리를 옮기는 일을 따로 이어야 한다. 그 사이에 사람이 트리를 움직였으면 어디에 설지도 다시 정해야 한다
- 큰 것(`node_modules` 같은 것) 을 고르면 그동안 화면이 멈춘다. 감수한다

## 3. symlink 는 링크로 복제한다

안에 있는 것이든 고른 것 자체든 링크는 링크로 만든다. 가리키는 것도 그대로 옮긴다. `cp -R` 의 기본과 같다.

따라가면 링크가 가리키는 뿌리 밖의 것이나 자기 위층이 통째로 딸려 올 수 있다. 트리도 링크를 따라가지 않는다(ADR-0005). 트리에서 보이지 않던 것이 복제본에서 갑자기 생기면 안 된다.

FIFO·소켓·장치 파일을 만나면 거절하고 멈춘다. FIFO 는 열면 쓰는 쪽이 나타날 때까지 돌아오지 않아 편집기가 통째로 멈춘다.

## 4. 디스크에 있는 것을 복제한다

tab 에서 고치고 저장하지 않았어도 고친 것은 따라가지 않는다. `cp` 와 같은 결과다. 트리는 디스크를 보여주는 자리이고(ADR-0134), 트리에서 한 일이 화면 밖 buffer 상태에 따라 갈리면 결과를 맞춰 볼 길이 없다.

## 5. 중간에 실패하면 만든 것을 지운다

권한이나 디스크 자리 때문에 디렉터리 복제가 중간에 멈추면 새 자리를 통째로 지운다. 새 자리는 방금 만든 것이라 지워도 잃는 것이 없다. 반쯤 찬 복제본이 남으면 원본과 같은 것처럼 보인다.

**맨 처음 만드는 것이 실패했으면 지우지 않는다.** 앞에서 없는 것을 보았어도 그 사이에 누가 같은 이름을 만들었을 수 있고, 그것은 우리 것이 아니다. 그래서 파일은 `O_EXCL`, 디렉터리는 `Mkdir`, 링크는 `Symlink` 로 만든다. 셋 다 이미 있으면 실패한다.

권한은 원본 그대로다. 실행 파일은 실행 파일로 남는다. 디렉터리에만 주인 쓰기 권한을 늘 붙인다. 읽기 전용 디렉터리를 그 권한 그대로 만들면 그 안에 아무것도 복제해 넣을 수 없다.

## 6. 트리에 머물고 새 것을 고른다

이름 바꾸기와 같다. 새 자리를 다시 읽고 reveal 로 고른 자리를 새 것에 둔다. 복제한 뒤에는 대개 그것을 고치러 가므로 고른 자리가 거기 있어야 한다.

다시 읽는 자리는 **트리가 아는 가장 깊은 위층**이다. `cmd/zn/main.go` 처럼 없는 중간 디렉터리까지 만들었으면 `cmd/zn/` 은 트리에 없고, 새로 생긴 `cmd/` 를 들고 있어야 할 자리는 뿌리다.

## 그 밖

- **칸에는 지금 경로가 채워져 있다.** 이름 바꾸기와 같다. 복제는 대개 옆에 이름만 조금 다른 것을 두는 일이다(`main.go` → `main_test.go`). 앞을 고치면 다른 디렉터리에 복제한다
- **이름 바꾸기와 화면을 나눠 쓰지 않는다.** `viewSidebarCopy` 를 따로 둔다. 같은 것은 칸의 모양뿐이고 `enter` 에 하는 일과 거절하는 까닭이 다르다. 합치면 그 둘이 「어느 쪽이냐」를 묻는 flag 가 된다(ADR-0054 §1 과 같은 까닭)
- **대소문자만 바꾼 이름도 막는다.** 이름 바꾸기는 같은 파일이면 지나가게 했는데, 복제에서는 대소문자를 가리지 않는 파일 시스템에서 그것이 자기 자신이라 열어서 쓰는 순간 원본이 비워진다
- **뿌리는 복제할 수 없다.** 뿌리 안의 어느 자리든 뿌리 자기 안이다
- **메뉴 항목은 「복제」이고 「새 이름」 다음에 선다.** 경로를 받는 둘이 이웃하고 지우기는 맨 아래에 남는다. 「복사」가 아닌 것은 나중에 들어올 「경로 복사」(클립보드) 와 말이 겹치지 않게 하려는 것이다

## 기각한 것

- **`mc` 를 만들기로 두고 복제를 `mp` 에 두기.** ADR-0054 가 적어 둔 자리다. 지금 손버릇은 지키지만 NERDTree 와 한 글자가 어긋난 채 별칭까지 둘을 들고 간다
- **빈 칸에서 시작하기.** 만들기처럼 고른 디렉터리 기준으로 이름만 받는다. 복제본은 대개 원본 옆에 원본과 비슷한 이름이라 지금 이름을 다시 치게 된다
- **job 으로 돌리기.** §2
- **symlink 를 따라가 내용을 복제하기.** 순환 링크를 따로 막아야 하고 뿌리 밖의 것이 딸려 온다
- **저장하지 않은 buffer 내용을 복제하기.** §4. 트리의 다른 동작은 모두 디스크를 본다

## 결과

- 트리에서 `mc` 와 우클릭 메뉴의 「복제」로 파일과 디렉터리를 복제한다
- `mc` 로 만들던 손버릇은 `ma` 로 옮겨야 한다
- 큰 디렉터리를 복제하는 동안 화면이 멈춘다. 취소할 길이 없다
- 트리에 포커스를 두는 mode 가 하나 더 늘었다(`viewSidebarCopy`)
