# ADR-0053 알림을 기록하고 `:messages` 로 본다

- 상태: 채택
- 날짜: 2026-08-23

## 맥락

statusBar 아래 줄의 알림은 다음 키를 누르면 사라지고 어디에도 남지 않았다.

**사람이 키를 누르지 않았는데 도착하는 알림이 넷 있다.** 바깥 파일이 바뀐 것(ADR-0031),
백그라운드 작업 실패(ADR-0027), gopls 기동 실패(ADR-0051) 다. 이것들은 도착한 직후 아무 키나
누르면 사라져서 **일이 일어났다는 사실 자체를 놓친다.** `job.go` 의 주석이 그 취지를 이미
적어 두었다 — "목록을 열어 보기 전에는 아무 일도 없던 것처럼 보인다".

`:jobs` 는 이 일을 대신하지 못한다. 끝난 작업을 **이름당 마지막 결과 하나**만 남기기 때문이다.
그것은 5 초마다 도는 git 갱신이 목록을 자기 이름으로 뒤덮지 않게 한 결정이고(ADR-0030),
알림 기록에는 정반대로 맞지 않는다 — 같은 알림이 되풀이된 것 자체가 정보다.

알림을 내는 자리가 쉰넷이었다. `editor.message` 에 직접 대입하는 자리 스물,
`normalModeMessage` 를 지나는 자리 서른넷. **기록을 붙일 한 자리가 없었다.**

## 결정

### 아래 줄에 뜬 알림을 전부 기록한다

예외를 두지 않는다. 「…하는 중입니다」 같은 진행 알림도 남긴다 — 예외를 하나 두면 앞으로
알림을 낼 때마다 「이건 남길 것인가」를 사람이 판정해야 하고, 그 판정은 바로 아래에서
없애기로 한 그것이다. 매달린 「찾는 중」 줄은 잡음이 아니라 **답이 오지 않았다는 정확한 기록**이다.

### 알림을 내는 길을 넷으로 모은다

`internal/core/notice.go` 의 `notify`·`notifyError`·`notifyFailure`·`clearNotice` 다.
`normalModeMessage` 도 `notify` 를 부르므로 쉰넷이 전부 이 파일을 지난다.

`editor.message` 를 `notice` 로 **이름을 바꾼 것이 이 작업의 절반**이다. 값을 넣는 자리
스물여덟이 전부 컴파일 오류가 되어 한 번씩 손이 갔다. 이름을 그대로 두었으면 어느 자리를
빠뜨렸는지 알 길이 없다 — 빠뜨린 알림은 화면에는 뜨고 기록에만 없어서, 없다는 것을 나중에
알아차릴 방법도 없다.

이름 바꾸기는 **한 번의 그물**이고 앞으로를 막지는 못한다. 그래서 필드 주석에 「쓰는 자리는
notice.go 넷뿐」이라고 적어 두었다.

### 갈래는 사람이 아니라 type 이 가른다

`error` 값에서 왔으면 실패, 아니면 그 밖이다. 오류 알림 스물하나가 전부 `error` 를 손에 들고
있어서 **갈래가 이미 type 으로 있다.** 사람이 쉰넷을 훑어 표를 만들면 그 표는 다음 사람이
다시 훑어야 유지되고, 알림이 늘 때마다 「이건 오류인가 거절인가」를 물어야 한다.

갈래가 둘뿐인 것은 이 규칙의 값이자 한계다. `읽기 전용 파일입니다`·`알 수 없는 명령` 같은
거절은 「그 밖」으로 간다 — 선이 「사람이 거절당했는가」가 아니라 **「코드가 `error` 를 만들
만큼 예상 밖이었는가」**에 그어진다.

### 오류 깔때기를 모든 mode 로 올린다

`fail` 은 command mode 의 메서드여서 팔레트·트리·검색이 쓸 수 없었고, 그쪽은
`normalModeMessage(e, errors.Cause(err).Error())` 를 손으로 되풀이했다. 그러면 깔때기에 닿기
전에 이미 문자열이라 위의 type 규칙이 그것을 보지 못한다.

`normalModeError(e, err)` 로 올리고 `fail` 은 걷어냈다. `errors.Cause` 를 벗기는 자리도
`notifyError` 하나가 되었다 — 예전에는 벗기는 자리와 안 벗기는 자리가 섞여 있었다.

### 오류가 글자가 되는 자리는 하나다 — 센티넬로 표시하고 보여 주는 곳에서 짓는다

`errors.Cause` 를 한 자리에서 벗기기로 하니 곧바로 걸리는 것이 나왔다. `:tabnew /etc` 가
`is a directory` 만 띄운다 — 감싼 말(`cannot read /etc`) 에 든 경로가 벗겨지는데 그 파일은
열리지도 않아 statusBar 에도 없다(이 결정 이전부터 그랬다).

처음에는 **여는 쪽이 문구를 짓게** 고쳤다. `errors.Newf("열 수 없습니다: %s: %v", path, cause)` 다.
그것이 틀렸다 — error 값이 들고 있던 구조를 글자로 부순 뒤 그 글자를 다시 error 에 담는
것이고, 부순 뒤에는 어느 부분이 경로이고 어느 부분이 까닭인지 아무도 알 수 없다.

그래서 이렇게 한다.

- **하려던 일**은 실패를 내는 자리가 **센티넬로 표시**한다 — `errors.Mark(err, errOpenFile)`.
  `Mark` 는 `errors.Is` 가 맞도록 표시만 붙이고 원래 error 를 그대로 둔다. 감싸기와 다른 점이다.
- **경로와 까닭**은 우리가 만들지 않는다. `os.ReadFile`·`os.WriteFile` 이 `*os.PathError` 로
  둘 다 들고 온다.
- **한 줄로 잇는 것은 `noticeText` 하나**다(`notice.go`). 센티넬을 `switch` 로 골라 앞말을 얻고,
  `errors.As` 로 `*os.PathError` 를 꺼내 경로와 까닭을 붙인다.

```
열 수 없습니다: /etc: is a directory
쓸 수 없습니다: /etc/zntest: permission denied
permission denied                          ← 표시가 없으면 까닭만
```

**`*os.PathError` 의 `Op` 은 쓰지 않는다.** 그것은 syscall 이지 우리 뜻이 아니다 — 재 보면
쓰기가 권한으로 막혀도 `Op` 이 `open` 이라, 그것으로 동사를 고르면 `:w` 실패가
「열 수 없습니다」가 된다. 하려던 일은 센티넬만 안다.

센티넬은 지금 셋이다. `errOpenFile`·`errWriteFile`·`errNoWorkingDir` 이고, 각자 자기 문구를
들고 있어서 `switch` 는 고르기만 한다. 새 갈래는 변수 하나와 `case` 하나가 는다.

남은 `errors.Wrap` 들(`cannot check %s` 따위) 은 그대로 둔다. 영어 개발자 맥락이고 화면에
가지 않는다 — 그 안의 `*os.PathError` 가 경로와 까닭을 주므로 표시에는 모자람이 없다.
검색의 `잘못된 패턴` 만 `errors.Wrap` 에서 `errors.Newf` 로 옮겼다. 그것은 앞말이 아니라
**문구 전체가 사람에게 보일 것**이라 센티넬이 아니라 지어야 하는 자리이고, 한 줄 위의
`모르는 flag` 가 이미 그렇게 하고 있었다.

### 지우는 것은 기록하지 않는다

`clearNotice` 를 따로 둔다. 「알림이 사라졌다」는 알림이 아니다. 지우는 자리 여덟이 전부
「다음 키를 누르면 사라진다」를 실행하는 곳이라, 남기면 목록이 빈 줄로 반쯤 찬다.

### 상한을 두지 않고 접지도 않는다

알림 하나가 백 바이트 남짓이라 만 개라도 1 MB 이고, 편집기가 여는 파일 하나보다 작다.
알림은 사람 속도로만 는다 — 키를 누르거나 백그라운드 일이 끝나야 난다.

같은 문구를 접지도 않는다. 되풀이된 횟수가 정보이기 때문이다. 다만 5 초마다 도는 갱신이
계속 실패하면 그 줄이 쌓인다 — 접기는 그것이 실제로 거슬릴 때 본다(`docs/tasks.md`).

### `:jobs` 를 그대로 두고 새 화면을 만든다

작업 목록은 「무엇이 돌고 있나」이고 알림 기록은 「무슨 말을 들었나」다. 세는 단위가 다르고,
한쪽은 취소하는 화면이고 한쪽은 읽는 화면이다.

작업의 **실패**는 그 자체가 알림이라 저절로 기록에 들어온다. 성공은 들어오지 않는다 —
그것을 알리는 자리가 없고, 알리게 하면 git 갱신이 5 초마다 목록을 채운다.

### 목록은 오래된 것이 위, 열 때 맨 아래를 고른다

`:jobs` 의 끝난 목록은 새것이 위인데 여기는 반대다. **뒤에만 붙어야 이미 있는 줄의 자리가
밀리지 않고**, 그래야 목록을 보는 동안 새 알림이 도착해도 고른 줄이 다른 알림으로 바뀌지 않는다.
작업 목록이 앞에 끼워 넣으면서도 「고른 자리는 유지한다」고 한 것은 앞에 끼는 일이 드물어서
통하는 근사치인데, 알림 기록은 앞에 끼는 것이 유일한 변화라 그 근사치가 맞지 않는다.

열 때는 맨 아래를 고른다 — 찾는 것이 대개 방금 지나간 것이다. 맨 아래를 보고 있는 동안
새 알림이 오면 따라 내려간다. 「지금 오는 것을 보는 중」이라는 뜻이라서다.

### 갈래를 색으로만 나타내지 않는다

실패한 줄에 `!` 를 찍고 색도 준다. 화면을 글자로 떠서 보는 길이 있고
(`.claude/skills/run-zn` 의 `capture-pane`) 색으로만 갈리면 그 길에서 갈래가 사라진다.

색은 256 색 고정값이 아니라 ANSI 1 이다. 절대 줄번호가 ANSI 3 을 쓰는 것과 같은 자리다
(ADR-0007) — 여기서 필요한 것은 특정 빨강이 아니라 **그 터미널 테마가 실패라고 부르는 색**이고,
새 고정값을 들이면 어두운 배경 대비 규칙(ADR-0041) 을 표 전체에서 다시 재야 한다.

### 절대 시각을 화면에 찍는 첫 자리다

`15:04:05`, 스물네 시간, 날짜 없음. 지금까지 이 저장소가 화면에 찍은 시간은 경과를 재는
`분:초`(`formatElapsed`) 뿐이었다. 초까지 찍는 것은 알림이 초 단위로 몰려 오기 때문이다 —
저장하면 곧바로 git 갱신이 따라온다.

시각은 **기록할 때 굳는다.** `:jobs` 가 프레임마다 `time.Now()` 를 뜨는 것과 다르다 —
저쪽은 「지금」이 필요하고 이쪽은 「그때」가 필요하다.

### 알림은 오른쪽부터 접는다

정의 후보 목록이 경로를 왼쪽부터 접는 것(ADR-0051) 과 반대다. 경로는 뒤쪽의 파일 이름과 줄
번호가 고르는 데 쓰이지만, 알림은 앞머리가 무엇이 일어났는지다.

### 목록 화면의 공용 조각은 이번에 빼지 않았다

`:jobs`·`GOTO`·`MESSAGES` 셋이 `scrollTo`·`move`·`View` 뼈대·`renderBareStatusBar` 를 복사해
가지고 있다. 세 번째가 되어 rule of three 이지만 이번에는 두지 않았다 — 기능이 깨진 것과
추출이 깨뜨린 것을 가르려면 다른 커밋이어야 한다. `docs/tasks.md` 에 남겼고, 재 보니
`selected`·`top` 을 embed 로 빼면 Go 의 필드 승격 덕에 참조 마흔다섯 곳이 그대로 컴파일된다.

## 결과

- `:messages`(`:mes`) 와 팔레트의 「알림 목록」으로 지나간 알림을 본다.
- 놓치던 넷(바깥 변경·작업 실패·서버 기동 실패)이 남는다. 목록을 열어 둔 채로 도착하는 것도 보인다.
- 알림을 새로 만드는 사람은 `e.message = …` 를 쓸 수 없다. 넷 중 하나를 골라야 하고,
  고르는 순간 기록과 갈래가 따라온다.
- **오류가 글자가 되는 자리가 하나가 되었다.** 실패를 내는 자리는 무엇을 하려 했는지만
  표시하고, 경로와 까닭은 error 가 들고 온 채로 화면까지 간다.

## 함께 본 것

- ADR-0002 mode 를 model 로 — 목록 화면이 mode 하나인 이유
- ADR-0027 작업 관리자 — `:jobs` 와 화면 문법을 나눠 쓰고, 「이름당 하나」 규칙이 여기서는 뒤집힌다
- ADR-0030 주기 갱신 — 그 규칙이 필요했던 까닭이자 여기서 뒤집는 까닭
- ADR-0031 바깥 변경 알림 · ADR-0051 정의로 가기 — 키 없이 도착해 놓치던 알림들
- ADR-0041 어두운 배경 팔레트 · ADR-0007 줄번호 색 — 실패 색을 ANSI 로 고른 근거
- ADR-0050 이벤트 로그 — mode 이름을 등록하는 자리. `GOTO` 가 빠져 있던 것을 여기서 같이 채웠다
