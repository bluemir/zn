# ADR-0132: `%` 는 짝으로 간다. 괄호 셋과 html 의 tag 쌍이다

- 상태: 채택
- 날짜: 2026-09-03
- 관련: ADR-0013(`d` 와 motion), ADR-0034(키에서 동작을 만드는 상태 기계), ADR-0037(visual mode), ADR-0082(멀리 뛰는 이동을 이력에 담는다), ADR-0091(text object), ADR-0114(명령줄의 `%`), ADR-0080(언어는 표의 한 줄)

## 맥락

`%` 가 normal mode 에서 비어 있었다. 괄호가 어디서 닫히는지 보려면 눈으로 세거나 `]c` 처럼 다른 것에 기대야 했다. 명령줄의 `%`(지금 파일 경로, ADR-0114) 는 다른 mode 라 부딪히지 않는다.

html 도 같은 물음이다. `<div>` 가 어디서 닫히는지는 괄호보다 세기 어렵다. vim 은 이것을 기본으로 하지 않고 `matchit` 플러그인이 한다.

**tag 를 읽는 코드는 이미 있다.** `internal/syntax/html.go` 의 `htmlTagNameAt`(이름·닫는 tag 여부), `htmlVoidTags`(`<br>` 처럼 짝이 없는 것), `htmlTagDepth`(깊이 증감) 가 강조와 들여쓰기를 위해 살고 있었다. 새로 오는 것은 **여러 줄에 걸쳐 겹을 세는 일**뿐이다.

정할 것은 여덟이다. 무엇을 짝으로 보는가, 숫자, 어느 mode 에서 쓰는가, 문자열·주석, 커서가 짝 위가 아닐 때, tag 를 잡는 자리, 커서가 서는 자리, 못 찾았을 때.

## 결정

### 1. 괄호 셋과 html 의 tag 쌍이다

`()` `[]` `{}` 는 vim 의 `matchpairs` 기본값 그대로다.

`<`·`>` 는 넣지 않는다. go 의 제네릭이나 C++ 템플릿에 쓸모가 있지만 `a < b` 의 비교 연산자와 구별할 수 없다. **짝이 아닌 자리로 데려가는 이동**은 아무 데도 안 가는 것보다 나쁘다.

tag 쌍은 `<div>` ↔ `</div>` 다. 이름이 같은 tag 만 세므로 `<div><p>a</p></div>` 에서 `<div>` 의 짝은 `</div>` 다. void tag 와 스스로 닫은 tag(`<img />`) 는 짝이 없어서 아무 일도 하지 않는다.

**어느 언어가 tag 쌍을 갖는지는 언어 표가 안다.** `syntax.Language` 에 `pairsTags` 칸이 하나 늘었고 html 줄만 참이다. 언어를 더할 때 손대는 자리를 하나로 두는 규칙 그대로다(ADR-0080).

인터페이스로 열지 않았다. tag 를 읽는 법이 `HTMLTagAt` 하나뿐이라 규칙으로 담을 것이 없다. 둘째 언어가 오면 그때 이 칸이 규칙으로 자란다.

### 2. 숫자를 버린다

vim 의 `50%` 는 「파일의 50% 자리로」다. 짝 찾기와 아예 다른 일이다.

따르지 않는다. 한 키가 숫자 유무로 그렇게 갈리면 눌러 보고 아는 키가 된다. `3%` 는 `%` 와 같다.

파일 안에서 비율로 뛰는 손은 `G` 와 `ctrl+d` 가 이미 받고 있어서, 버리는 자리에 갈 곳 없는 손짓이 남지 않는다.

### 3. 이동·operator·visual 셋 다 받는다

`motionFor` 에 한 줄을 더하면 셋이 한꺼번에 붙는다. normal 의 이동, operator 여섯(`d%` `y%` `c%` `>%` `<%` `=%`), visual 의 범위 늘리기다. visual 이 `motionFor` 를 나눠 쓰기 때문이다(ADR-0037).

operator 가 잡는 범위는 **양쪽을 다 담는다**. `d%` 가 여는 괄호와 닫는 괄호를 함께 지운다. vim 의 inclusive motion 이다.

**visual 이 값을 내는 자리다.** 지우기 전에 무엇이 사라지는지 눈으로 보고 지우는 손이 `v%d` 다.

다만 visual 은 **커서가 선 자리부터** 고른다. `%` 는 커서만 옮기고 시작 자리를 옮기지 않는다. 괄호는 커서가 곧 그 괄호라 `v%d` 가 `d%` 와 같은 것을 지우지만, tag 는 `<` 가 아닌 자리에서 시작하면 앞이 잘린다 — `<p|>` 에서 시작한 `v%d` 는 `<` 를 남긴다. 시작 자리를 tag 앞으로 끌어오는 것은 `%` 가 아니라 text object(`vat`) 의 일이라, 그쪽을 넣을 때 같이 본다.

### 4. 문자열·주석 안의 괄호도 센다

`x := "{"` 의 `{` 가 짝으로 잡힌다. vim 의 기본과 같다.

거르려면 커서에서 짝까지의 **모든 줄**을 문법으로 훑어야 한다. 지금 문법 훑기는 화면까지만 게으르게 하는데(`LexSyntaxTo`), 짝 찾기가 그것을 파일 끝까지 끌고 가면 `%` 한 번이 파일 전체를 훑는 일이 된다.

들여쓰기 규칙은 토큰으로 거른다(`buffer-indent.go`). 그쪽은 **한 줄**만 보므로 값이 다르다.

tag 도 같다. `<!-- <div> -->` 의 tag 가 겹으로 잡힌다. 어느 자리가 주석 안인지는 파일 처음부터 훑어야 알아서, 괄호와 같은 자리에 선다.

### 5. 커서가 짝 글자 위에 있을 때만 일한다

vim 은 커서가 괄호 위가 아니면 **그 줄에서 오른쪽으로 첫 괄호를 찾아** 그 짝으로 간다.

따르지 않는다. 그러면 `%` 가 어디로 갈지 알려면 커서 오른쪽 줄 끝까지를 눈으로 훑어야 한다. 짝을 보려고 치는 키가 짝을 먼저 찾게 만든다.

### 6. tag 는 `<` 부터 `>` 까지 안 아무 곳에서 잡는다

괄호와 규칙이 다르다. 괄호는 글자 하나이고 tag 는 낱말이다. `<di|v class="a">` 에서도 `</div>` 로 간다.

tag 를 치는 손은 이름을 보고 있다. 양끝 글자 위에 서 있으라고 하면 손이 한 번 더 움직인다.

**커서가 선 글자 자체가 괄호면 괄호가 이긴다.** `<div onclick="f()">` 의 `(` 위에서는 그 괄호를 본다 — 커서가 선 글자가 짝이면 그것을 제쳐 두고 둘레를 볼 이유가 없다.

### 7. 커서는 짝의 **먼 쪽 끝**에 선다

앞으로 가면 마지막 글자, 뒤로 가면 첫 글자다. 괄호는 한 글자라 둘이 같고 **tag 에서만 갈린다** — `<p>` 에서 `%` 를 치면 `</p>` 의 `>` 에 선다.

matchit 은 `<` 에 세운다. 그러면 `v%` 가 닫는 tag 를 반만 잡아서 `/p>` 가 남는다. 고른 범위는 커서가 선 글자까지이기 때문이다.

먼 쪽 끝에 세우면 괄호에서든 tag 에서든 `v%d` 와 `d%` 가 같은 것을 지운다. §3 이 visual 을 넣은 까닭이 그것이라, 이 자리에서 matchit 과 갈린다.

되돌아가는 것은 그대로다. `>` 에 서서 `%` 를 다시 치면 그 자리가 `</p>` 안이라 `<p>` 의 `<` 로 간다.

### 8. 못 찾으면 알린다

「짝을 찾지 못했습니다」가 아래 줄에 뜬다. 커서는 그대로다.

vim 은 조용하다. 우리 쪽이 알리는 것은 §5 때문이다 — 커서가 짝 위에 있는지, 그 짝이 닫혔는지가 **눈으로 훑어야 아는 것**이라, 아무 일도 안 나면 키가 안 먹은 것으로 읽힌다. 마커가 하나도 없을 때 알리는 것과 같은 자리다(`jumpToMarkerLines`, ADR-0095).

**알리는 것은 이동 키를 그냥 쳤을 때뿐이다.** `d%` 는 짝이 없으면 조용히 아무 일도 하지 않는다. 다른 operator 가 잡을 것이 없을 때와 같다.

### 9. 되돌아오기 이력에 담는다

vim 이 `%` 를 jump motion 으로 본다(`:help jump-motions`). 긴 함수의 끝으로 뛰었다가 `ctrl+o` 로 돌아온다. `jumpMotion` 에 한 줄이다(ADR-0082).

## 결과

- `%` 가 normal 의 이동, operator 여섯, visual 에서 짝 사이를 오간다
- 새로 오는 파일은 하나다. `internal/textarea/match-pair.go` 가 짝을 찾고, core 는 motion 하나(`motionMatchPair`) 로 그것을 부른다
- `internal/syntax` 는 셋이 바뀌었다. `htmlTagNameAt` → `HTMLTagAt`, `HTMLVoidTag` 를 열고, 언어 표에 `pairsTags` 칸이 늘었다

감수하는 것

- **문자열·주석 안의 괄호와 tag 를 센다.** `f(")")` 의 `%` 는 문자열 안의 `)` 로 간다(§4)
- **커서가 짝 위가 아니면 아무 데도 안 간다.** vim 은 줄에서 찾아 준다(§5)
- **`<`·`>` 는 짝이 아니다.** go 의 제네릭에서 쓸 수 없다(§1)
- **`50%` 가 vim 과 다르다.** 파일의 절반이 아니라 짝 찾기다(§2)
- **tag 에서 커서가 matchit 과 다른 자리에 선다.** `</p>` 의 `<` 가 아니라 `>` 다(§7)
- **`<script>` 안의 글에서 tag 를 센다.** js 문자열 안의 `</div>` 가 겹으로 잡힌다. §4 와 같은 자리다
- **닫히지 않은 괄호에서 파일 끝까지 훑는다.** 짝이 없다는 것은 다 보고서야 안다. vim 도 그렇다
- **`v%` 는 커서가 선 자리부터다.** tag 를 통째로 고르려면 `<` 에서 시작해야 한다(§3)

## 대안

- **`%` 를 홀로 서는 동작으로 두기**
	- 못 찾았을 때 알리는 자리가 그 동작 안에 있어서 `actionMove` 를 건드리지 않는다.
	- 키가 표 셋(`motionFor`·`standaloneAction`·`visualAction`) 에 흩어지고, operator 를 받으려면 결국 motion 이 하나 더 필요하다. 같은 키가 두 갈래로 산다.

- **tag 를 나중에 별건으로 넣기**
	- 이 결정이 괄호만 보게 되어 짧아진다.
	- tag 를 읽는 코드가 이미 있어서 새로 오는 것이 「겹을 세는 일」 하나였다. 그 일은 괄호 쪽과 같은 모양이라 같이 오는 편이 값싸다(맥락).

- **문법 토큰으로 문자열·주석을 거르기**
	- 답이 더 맞다. `x := "{"` 에 걸리지 않는다.
	- `%` 한 번이 파일 전체를 문법으로 훑는 일이 된다. 게으른 훑기(ADR-0039) 를 세워 둔 값이 그 자리에서 사라진다(§4).

- **커서를 matchit 처럼 `<` 에 세우기**
	- vim 을 쓰던 손이 어긋나지 않는다.
	- `v%` 가 닫는 tag 를 반만 잡는다. visual 을 넣은 까닭이 「지우기 전에 눈으로 보는 것」이라 그 자리에서 값이 사라진다(§7).

- **`{count}%` 를 vim 처럼 파일 비율로 받기**
	- vim 과 같아진다.
	- 한 키가 숫자 유무로 아예 다른 일을 한다. 그쪽 손짓은 `G` 가 이미 받는다(§2).

## 이 ADR 이 정하지 않는 것

- **짝 text object(`i(` `a(` `it` `at`).** ADR-0091 이 backlog 로 내려 둔 것이고, 이 결정의 짝 찾기 위에 설 수 있다
- **화면에서 짝을 칠하는 것.** vim 의 `matchparen` 이다. 그리는 자리의 물음이라 여기서 정하지 않는다
- **`matchpairs` 를 설정으로 여는 것.** 설정 파일이 아직 없다
