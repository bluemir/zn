# ADR-0010: 검색은 Go 정규식으로 하고 flag 는 패턴 뒤에 `/i` 로 붙인다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

`docs/tasks.md` 에 "검색 기능(`/`, `?`)" 이 열려 있었다. 편집기에서 자리를 찾는 가장 기본이 되는
이동이고, `w` `b` `gg` `G` 같은 이동 키가 이미 들어와 있어서(ADR-0006) 다음 순서였다.

정할 것이 넷이다.

1. **패턴을 무엇으로 읽는가** — 평문인가 정규식인가. 정규식이면 어느 문법인가
2. **대소문자를 어떻게 가리는가** — vim 은 `ignorecase`·`smartcase` 라는 설정 두 개로 정하는데
   이 편집기에는 런타임 설정이 없다(`config 는 compile 됨`)
3. **찾은 자리를 화면에 어떻게 보이는가** — 지금 본문에는 색이 하나도 없고, 반전은 statusBar 와
   tabline 이 이미 쓰고 있다(ADR-0004)
4. **검색 상태를 누가 들고 있는가** — `n` 은 검색이 끝나고 한참 뒤에 눌린다

## 결정

**패턴은 Go 의 정규식(RE2) 이다.** `regexp.Compile` 에 그대로 넘긴다. vim 의 magic 규칙
(`\(` 이 그룹, `(` 이 글자) 으로 옮기는 변환기를 두지 않는다.

**flag 는 패턴 뒤에 `/글자들` 로 붙인다.** `/abcd/i` 는 대소문자를 무시하고 `abcd` 를 찾는다.
지금 있는 flag 는 `i` 하나다. 모르는 flag 는 오류다.

**마지막 `/` 뒤가 비어 있거나 ASCII 영문자가 아닌 것이 섞여 있으면 flag 가 아니라 패턴의 일부다.**
`/http://` 는 그대로 `http://` 를 찾는다. flag 로 읽힐 `/` 를 패턴에 넣어야 하면 `\/` 로 막는다.
그 `\/` 는 Go 정규식에서도 `/` 한 글자를 뜻하므로 떼지 않고 그대로 넘긴다.

**`?` 로 위를 찾을 때도 구분자는 `/` 다.** `?abcd/i` 다.

**flag 를 붙이지 않으면 대소문자를 구분한다.** smartcase 를 두지 않는다.

**찾은 자리는 모두 칠하고, 커서가 선 자리만 다른 색이다.** 나머지는 노랑(256색 220) 바탕,
커서가 선 것은 주황(208) 바탕에 검은 글자다. 검색할 때마다 켜지고 `:noh` 로 끈다.

**치는 동안 첫 매칭으로 커서와 화면이 따라간다(incsearch).** 항상 검색을 시작한 자리에서 다시
찾는다. `Esc` 로 나가면 커서·화면·직전 검색이 모두 시작 상태로 돌아간다.

**파일 끝에 닿으면 반대쪽 끝에서 이어 보고, 감쌌으면 아래 줄에 알린다.**

**마지막 검색은 `editor` 가 들고 있다.** Buffer 가 아니다. `gt` 로 tab 을 옮겨도 `n` 은 같은
것을 찾는다.

**`*` `#` 는 커서 아래 단어를 찾는다.** 커서를 그 단어 앞으로 옮긴 뒤 거기서 찾기 시작한다.
단어 경계는 `w` 와 같은 부류 나누기를 쓰고(ADR-0006), 양끝이 ASCII 단어 글자일 때만 `\b` 를 붙인다.

**mode 는 model 을 갈아끼워 나타낸다(ADR-0002).** `viewEditorSearch` 가 command mode 와 같은
자리(statusBar 아래 줄) 를 쓴다.

## 근거

### Go 정규식

**표준 라이브러리라 옮기는 코드가 없다.** vim 문법을 받으려면 `\(`→`(`, `(`→`\(`, `\|`→`|`,
`\{n,m}`→`{n,m}`, `\<`→`\b` 처럼 뒤집힌 규칙을 문자 단위 상태 기계로 구현해야 한다. 명령줄
tokenizer 하나가 겨우 100 줄인데(`command-parser.go`) 검색 하나에 그만한 변환기를 두는 것은
"과도한 추상화를 하지 않는다" 와 정면으로 어긋난다.

**RE2 는 최악의 경우에도 선형이다.** 화면을 그릴 때마다 보이는 줄에 정규식을 돌리는데(강조),
backtracking 엔진이면 어떤 패턴에서 편집기가 멈춘다. 그런 패턴을 사용자가 막아야 하는 구조는
개인용 편집기에 맞지 않다.

**평문 검색은 정규식의 부분집합이다.** 나중에 필요해지면 `regexp.QuoteMeta` 로 flag 하나를
더하면 된다 — 반대 방향(평문으로 시작해 정규식을 얹기) 은 문법을 새로 정해야 한다.

**대가는 근육기억이다.** vim 에서 `\(...\)` 를 치던 손이 여기서는 `(...)` 다. 다만 이 편집기는
"vim 대비 무엇을 개선하는가" 를 아직 정하는 중이고(`docs/tasks.md`), grep·ripgrep·대부분의
언어가 쓰는 문법이 vim 쪽이 아니라 이쪽이다.

### 뒤에 붙는 flag

**Go 에는 `(?i)` 가 이미 있다.** 그런데 패턴 **앞** 이라, 다 치고 나서 대소문자를 무시하고
싶어지면 커서를 맨 앞으로 되돌려야 한다. 치는 순서와 생각하는 순서가 어긋난다.

**smartcase 는 규칙이 조용하다.** 소문자로만 치면 무시, 대문자가 섞이면 구분이라는 규칙은
"왜 이건 안 찾히지" 를 만든다. `/i` 는 화면에 글자로 남아 있어서 왜 그렇게 동작하는지가 보인다.
런타임 설정이 없는 편집기에서는 설정 두 개(`ignorecase`+`smartcase`) 의 조합보다 패턴에 붙는
글자 하나가 정직하다.

**구분자 규칙은 "안 쓰는 사람은 몰라도 되는" 쪽으로 골랐다.** flag 를 안 쓰면 마지막 `/` 뒤가
늘 비어 있거나 경로의 일부라 규칙이 발동하지 않는다. `/http://`, `/foo/bar/`, `/a/b c` 가 전부
친 그대로다. 실제로 걸리는 것은 `/a/b` 처럼 짧은 경로 조각인데, 그때는 조용히 다르게 동작하는
대신 "모르는 flag: b" 라고 말한다 — 안다고 넘겨짚는 것보다 낫다.

**알려진 flag 일 때만 떼는 방식은 채택하지 않았다.** `/a/i` 가 `a` 인지 `a/i` 인지가 지원 flag
목록에 따라 달라진다. flag 를 하나 더 넣는 순간 옛날에 치던 패턴의 뜻이 바뀐다.

**`?` 도 `/` 로 닫는 것은 규칙을 하나로 두기 위해서다.** 여는 글자로 닫는 방식(`?abcd?i`) 은
vim 의 offset 문법과 같지만, 그러려면 "구분자는 방향에 따라 다르다" 를 외워야 한다. `/` 는
방향과 상관없이 flag 를 여는 글자 하나다.

### 강조

**반전은 이미 뜻이 있다.** statusBar 와 tabline 이 반전이다(ADR-0004). 본문 안에서 반전을 쓰면
같은 모양이 두 가지 뜻을 갖는다. 그래서 여기만 256색 고정값을 쓴다 — sidebar 의 파일 종류
색(ADR-0005), 상대 줄번호의 회색(ADR-0007) 과 같은 방식이고, 팔레트를 정하는 일에 딸린 빚도 같다.

**커서가 선 매칭을 따로 칠하는 것은 `n` 때문이다.** 매칭이 다 같은 색이면 `n` 을 눌렀을 때 화면이
바뀌지 않는 것처럼 보인다(같은 화면 안의 다음 매칭으로 옮겼을 때). 색이 하나 늘지만, 이동했다는
사실을 보여주는 것이 검색의 절반이다.

**"커서가 선 매칭" 은 커서 자리에서 시작하는 매칭이다.** 검색 직후에는 늘 그런 자리에 서 있고,
다른 키로 커서를 옮기면 자연히 사라진다. 검색이 "지금 몇 번째" 라는 상태를 따로 들고 있지 않아도
된다.

### incsearch

**시작 자리에서 다시 찾는 것이 핵심이다.** 옮긴 자리에서 이어 찾으면 글자를 지웠을 때 커서가
앞으로 돌아오지 못해서, 같은 글자를 쳤는데 다른 곳에 서 있게 된다.

**되돌릴 것에 화면 위치(`top`, `topRow`) 가 들어간다.** 커서만 되돌리면 `scrollTo` 가 이미 옮겨둔
화면이 그대로 남아서, 커서는 제자리인데 보이는 곳이 달라진다.

**치는 도중에는 오류를 띄우지 않는다.** `(` 까지 친 순간은 늘 잘못된 정규식이다. 오류는 Enter 때
낸다.

### 검색 상태의 자리

**`n` 은 검색이 끝나고 한참 뒤에 눌린다.** mode model 안에 두면 mode 가 바뀌는 순간 사라진다.
그래서 mode 를 넘어 사는 것들이 모여 있는 `editor` 에 둔다(ADR-0002).

**tab 마다 따로 두지 않는다.** 같은 이름을 여러 파일에서 훑는 것이 검색을 쓰는 흔한 흐름이다.
tab 을 옮겼다고 패턴을 다시 쳐야 하면 그 흐름이 끊긴다. vim 도 검색은 전역이다.

### `*` `#`

**커서를 단어 앞으로 옮기고 찾는다.** 옮기지 않으면 커서 오른쪽에 있던 그 단어 자체가 첫 매칭이
되어, `*` 를 눌렀는데 한 칸 옆으로 가는 것으로 끝난다.

**한글 단어에는 `\b` 를 붙이지 않는다.** Go 의 `\b` 는 ASCII 단어 글자 기준이라 `\b한글\b` 는
앞뒤에 ASCII 단어 글자가 있어야 한다는 뜻이 되어 아무것도 찾지 못한다. 양끝 글자를 보고 붙일지
정한다 — 한글 단어는 경계 없이 찾으므로 `한글자` 안의 `한글` 에도 걸린다. 이 편집기가 한글
문서를 다루는 이상 "못 찾는 것" 보다 "더 찾는 것" 이 낫다.

## 결과

좋은 점

- 정규식이 그대로 먹는다. `func.*Buffer` 를 vim 처럼 `\(` 로 escape 하지 않고 친다
- 치면서 화면이 따라가고, `Esc` 로 아무 일도 없던 것처럼 돌아온다
- 화면 안의 같은 것이 모두 칠해져서 몇 개가 있는지가 눈에 들어온다
- 검색은 tab 을 넘어 남는다. 여러 파일에서 같은 이름을 훑는 흐름이 끊기지 않는다
- 검색 상태와 강조 규칙이 한 곳(`search.go`) 에 모여 있어서 나중에 `:%s` 나 fzf 가 같은 것을 쓴다

감수하는 것

- **vim 근육기억과 어긋난다.** `\(` `\|` `\<` 를 치면 찾지 못한다. 특히 `\<word\>` 대신 `\bword\b` 다
- **`/a/b` 가 오류다.** 짧은 경로 조각을 찾을 때 `\/` 를 쓰거나 flag 없는 형태로 바꿔야 한다
- **화면을 그릴 때마다 보이는 줄에 정규식을 돌린다.** 줄 하나가 여러 행으로 wrap 되면 줄이
  바뀔 때만 다시 찾도록 줄였지만, 강조를 켠 채로 아주 긴 줄이 화면을 채우면 그리는 값이 붙는다
- **색 고정값이 둘 늘었다.** 밝은 테마에서 220/208 이 어떻게 보이는지는 팔레트를 정할 때 같이 본다
- **한글 단어의 `*` 는 단어 경계를 보지 않는다.** `한글` 을 찾으면 `한글자` 도 걸린다
- **검색은 줄 단위다.** 줄바꿈을 건너뛰는 패턴(`func\s*\n`) 은 맞지 않는다

## 대안

**평문 검색** — `bytes.Index` 한 줄이면 끝나고 `.` 이나 `*` 를 escape 없이 찾는다. 코드에서
기호를 찾을 때 편하지만, `func.*Buffer` 같은 것을 못 찾는다. 나중에 flag 로 열어줄 수 있는
방향이라 잃는 것이 없다.

**vim magic 문법 흉내** — 근육기억이 그대로 먹는다. 뒤집힌 escape 규칙을 문자 단위로 옮기는
변환기가 필요하고, 그 변환기의 버그는 "왜 이 패턴만 안 되지" 로 나타난다. 개인용 편집기가
질 부담이 아니다.

**smartcase** — 치는 글자가 줄어든다. 규칙이 화면에 보이지 않아서 왜 그렇게 동작하는지 알 수
없고, 런타임 설정이 없는 이 편집기에서는 켜고 끌 방법도 없다.

**`(?i)` 만 쓰기(flag 문법 없음)** — 규칙이 하나도 늘지 않는다. 다 치고 나서 앞으로 되돌아가야
하고, `/` 구분자 규칙을 피한 대가로 매번 네 글자를 앞에 친다.

**강조 없음** — 렌더를 건드리지 않아 이번 변경이 절반이 된다. 화면에 같은 것이 몇 개나 있는지
보이지 않아서 `n` 을 눌러보기 전에는 알 수 없다.

**전부 같은 색으로 강조** — 색이 하나만 는다. 화면 안에서 `n` 을 눌렀을 때 무엇이 달라졌는지
보이지 않는다.

**검색 상태를 Buffer 에 두기** — 파일마다 다른 것을 찾는 흐름에 맞다. tab 을 옮길 때마다 패턴을
다시 쳐야 하고, vim 과도 다르다.

## 이 ADR 이 정하지 않는 것

- 검색 이력(명령줄에서 위·아래로 이전 검색어 꺼내기). `:` 명령 이력과 같은 구조라 같이 정한다
- `:%s/a/b/g` 같은 치환. 이 ADR 이 정한 패턴 문법을 그대로 쓸 자리다
- `f` `t` `;` `,`(줄 안에서 글자 찾기). 검색과 별개의 이동 키다
- 여러 파일 검색(grep, fzf). `docs/tasks.md` 의 fzf·command palette 항목이다
- `i` 밖의 flag. 필요해질 때 하나씩 더한다
- 강조 색의 고정값. 팔레트를 정할 때 다른 색과 같이 본다
- 검색으로 옮기기 전 자리로 돌아가는 것(vim 의 jump list, `` `` ``)
