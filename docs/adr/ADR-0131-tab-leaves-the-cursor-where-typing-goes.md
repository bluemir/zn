# ADR-0131: 목록을 들여쓴 뒤 커서는 글이 시작하는 자리에 선다

## 맥락

ADR-0047 이 markdown 목록 줄에서 `tab` 을 「줄 전체를 한 단계 깊게」로 정했다. 줄이 통째로 움직이므로 커서를 어디에 세울지도 그때 같이 정해졌는데, 그것이 `shiftLines` 가 `>` 를 위해 쓰던 자리를 그대로 물려받은 것이었다. **들여쓰기 다음**, 곧 목록 표시 **앞**이다.

`>` 에는 그것이 맞다. normal mode 에서 줄을 미는 손은 그 줄의 첫 글자를 보려는 손이다. insert mode 에서 `tab` 을 치는 손은 다르다.

```
o        →  - |          항목을 하나 더 낸다(mdIndent.Next 가 표시를 이어 준다)
tab      →    |-         「이건 하위 항목이다」
셋째     →    셋째-      표시 앞에 글이 들어간다
```

목록을 쓰는 내내 `tab` 마다 커서를 손으로 되돌려야 했다. 내용이 있는 항목 가운데에서 쳐도 치던 자리를 잃었다.

정할 것은 셋이다.

1. 내용이 있는 항목 가운데에서 쳤을 때 커서를 어디에 두는가
2. 커서가 표시 앞에 있었을 때 어디까지 내보내는가
3. 그 자리를 아는 것은 누구인가

## 결정

### 1. 치던 자리를 지킨다

들여쓰기가 늘어난 만큼만 오른쪽으로 옮긴다. `shift+tab`(`outdentLine`) 이 이미 그렇게 하고 있었고, 두 키가 서로를 되돌리는 짝이라 답이 같아야 한다.

```
- 첫|째   →  tab  →    - 첫|째
```

### 2. 표시 앞이었으면 글이 시작하는 자리까지 나온다

`0` 이나 `I` 로 줄 앞에 서서 `tab` 을 치는 손도 곧 그 항목을 쓸 손이다. 지킬 자리가 애초에 없으므로 표시를 지나 내보낸다.

```
|- 첫째   →  tab  →    - |첫째
- |       →  tab  →    - |        (빈 항목은 그 자리가 줄 끝이다)
```

**checklist 의 `[ ] ` 도 표시로 본다.** `- [ ] ` 에서 글이 시작하는 자리는 칸 뒤다.

```
|- [ ] 할일   →  tab  →    - [ ] |할일
```

칸으로 보는 것은 `[ ] `·`[x] `·`[X] ` 셋이고, 뒤에 빈 칸이 와야 한다. `- [열] 할일` 은 그냥 글이라 표시까지만 지난다.

### 3. 자리를 아는 것은 언어 규칙이다

`syntax.Indent` interface 의 `TabIndentsLine` 이 자리를 같이 낸다.

```go
TabIndentsLine(line []byte) (content int, indents bool)
```

ADR-0126 이 세운 가름을 그대로 따른다.

| | 언어별 규칙이 어디 있나 | 부르는 쪽 코드 안에 언어가 있나 |
|---|---|---|
| `reindentLines` | `syntax.Indent` interface | 없다 |
| `formatTables` | `syntax.MarkdownTableCells` 함수 | 있었다 |
| **`indentWholeLine`** | **interface** | **없다** |

「이 줄에서 `tab` 이 무엇을 하는가」는 이미 interface 의 물음이다. 커서 자리를 `syntax.MarkdownListContentStart` 같은 함수로 내면 `viewport-indent.go` 가 markdown 을 알게 되는데, 지금 그 파일은 규칙에 묻고 받은 것을 쓸 뿐이라 언어 이름이 한 번도 나오지 않는다. 답이 markdown 에서만 0 이 아닌 것과, 묻는 쪽이 markdown 을 아는 것은 다른 일이다.

열한 언어 중 열이 `(0, false)` 다. 목록이 아닌 줄에서 `tab` 은 커서 자리에 드는 글자이고, 그때 커서를 옮길 일이 없어서 낼 자리도 없다.

### 4. checklist 를 표시로 보는 것은 이 자리에만 넣는다

`mdParseListMark` 는 손대지 않고 `mdCheckboxSize` 를 따로 두었다. 칸을 표시에 넣으면 `- [ ] ` 만 있는 줄이 **빈 항목**이 되어 Enter 로 목록을 잇는 답(`mdIndent.Next`) 까지 바뀐다. 지금은 `- [ ] ` 에서 Enter 를 치면 `- ` 가 나오는데, 그것을 `- [ ] ` 로 낼지와 빈 checklist 항목에서 목록을 끝낼지는 이 건과 따로 정할 일이다.

## 남는 것

- `shift+tab` 은 표시 앞에 서 있었을 때 그대로 줄 맨 앞에 둔다. 치던 자리를 지키는 쪽은 이미 같고, 나머지 한 갈래를 맞출지는 그 키를 손볼 때 같이 본다.
- Enter 로 checklist 항목을 이을 때 `- [ ] ` 를 낼지 (위 §4).
