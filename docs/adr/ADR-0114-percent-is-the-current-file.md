# ADR-0114: 명령줄의 `%` 는 지금 보고 있는 파일이다

## 맥락

`:!` 는 뒤를 뜯지 않고 셸에 통째로 넘긴다(ADR-0045). 그래서 `:!git add` 뒤에 파일 이름을 손으로 다시 쳐야 했다. 지금 보고 있는 파일인데도 그렇다.

vim 은 그 자리에 `%` 를 둔다. 우리도 그렇게 하기로 했다. 정할 것은 「어디서 어떻게 펴는가」다.

명령줄에는 이미 `%` 가 산다. **이름 앞의 `%` 는 줄 범위**로, 파일 전체를 뜻한다(`:%s/a/b/g`, `:%d`). 그것을 건드리면 안 된다.

## 결정

### 자리가 뜻을 가른다

이름 **앞**의 `%` 는 범위, 이름 **뒤**의 `%` 는 지금 파일이다. `!` 가 이미 그렇게 갈린다 — 이름 자리의 `!` 는 셸이고 그 밖의 `!` 는 글자다(ADR-0045). 같은 규칙을 하나 더 얹는 것이라 새 개념이 늘지 않는다.

범위를 뜯는 상태(`tokenRange`) 가 이미 맨 앞에서만 돌고 있어서, 그 뒤를 지나는 상태에서만 펴면 저절로 갈린다.

### 펴는 자리는 둘이다

- **파일 이름 자리** — 글자를 끊는 기계(`tokenPlain`·`tokenQuoted`) 안에서 편다.
- **`:!` 의 셸 줄** — `runShell` 안에서 편다.

한 자리로 모으지 못한 까닭이 각각 있다.

셸 줄은 뜯지 않은 한 덩어리라 끊는 기계가 손댈 것이 없고, 팔레트의 `!` 는 그 기계를 아예 지나지 않고 `runShell` 로 곧장 온다. 둘이 만나는 곳이 `runShell` 하나다.

파일 이름 자리는 반대로 끊는 기계 **안**이어야 한다. 밖에서 펴면 `\%` 를 살릴 수 없다 — `tokenEscaped` 가 `\` 를 먼저 먹어서 `\%` 와 `%` 가 같은 글자로 나온다. 안에서 펴면 「`\` 뒤의 한 글자는 뜻이 없다」는 이미 있는 규칙에 `\%` 가 저절로 들어간다.

### 통째로 받는 정규식에서는 펴지 않는다

`:grep`·`:s`·`:replace` 의 인자는 찾을 글자이지 파일 이름이 아니다. `:%s/50%/60%/` 의 `%` 가 경로로 펴지면 안 된다. vim 도 그렇다(9.1 로 확인).

끊는 기계에서 이 갈림은 **경로를 주지 않는 것**으로 표시한다. 상태가 경로를 들고 있으면 펴고, 없으면 글자로 둔다. 「펴지 않는다」를 따로 적은 flag 가 없다.

### 셸 줄에서는 자리를 가리지 않고 다 편다

vim 과 같다. `:!cp % %.bak` 이 되는 값으로 `:!df | grep 100%` 가 깨지는 것을 받는다. 낱말로 홀로 선 `%` 만 펴면 뒤엣것이 안전해지지만 앞엣것이 안 된다. 놀랄 자리를 하나 두더라도 vim 을 아는 손이 그대로 통하는 쪽을 골랐고, 깨지는 쪽에는 `\%` 라는 길이 있다.

### 감싸지 않는다

공백이 든 이름은 셸에서 두 토큰이 된다. 우리가 감싸면 `:!cat "%"` 로 친 사람의 따옴표와 겹치고, 같은 명령이 파일 이름에 따라 다르게 도는 자리도 생긴다. 감싸는 것은 친 사람의 몫이다. vim 과 같다.

### 늘 상대 경로다

`buffers[active].path` 는 연 길에 따라 상대이기도 절대이기도 하다(CLI 냐 트리냐). 그대로 펴면 같은 파일이 어느 날은 `main.go` 이고 어느 날은 `/Users/…/main.go` 다.

화면이 경로를 줄여 보일 때 쓰는 규칙(`shortenPath`) 을 그대로 쓴다. cwd 아래면 상대, 홈 아래면 `~`, 아니면 절대다. 보이는 것과 펴지는 것이 어긋나지 않는다. `~` 는 셸이 펴고, 파일 이름 자리는 `expandHome` 이 편다(ADR-0088).

### 펼 것이 없으면 명령을 세운다

이름 없는 tab 이나 tab 이 없는 자리에서 `%` 를 치면 실행하지 않고 아래 줄에 알린다. 빈 문자열로 조용히 펴면 `:!rm %` 가 `rm ` 이 되어 뒤엣것을 지운다. vim 도 여기서 세운다(E499).

끊는 기계에는 이 오류를 낼 자리가 없었다. `consume` 이 상태만 돌려주기 때문이다. 토큰 단위 기계의 `commandFailed` 와 같은 결로 `tokenFailed` 를 두었다 — 막힌 뒤의 글자를 먹고 끝에서 오류를 낸다.

## 결과

- `:!git add %`·`:!cat %`·`:e %.bak` 이 된다.
- `%` 라는 이름의 파일은 `\%` 로 가리킨다. 어느 자리에서나 같다.
- 끊는 기계의 상태들이 경로를 하나씩 더 들고 다닌다. 넘기는 자리를 빠뜨리면 그 자리에서 `%` 가 안 펴진다 — 눈에 보이는 실패라 조용히 어긋나지는 않는다.
- 수식어(`%:h`·`%:t`) 는 넣지 않았다. 디렉터리가 필요하면 `:!dirname %` 처럼 셸에 시킨다. 필요해지면 그때 여는 자리다.
- `#`(직전 파일) 도 넣지 않았다. 직전 파일을 가리키는 개념이 아직 없다.
