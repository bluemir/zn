# ADR-0095 마커 사이를 `]c`·`[c` 와 `]d`·`[d` 로 뛴다. 감아 돈다

- 상태: 채택
- 날짜: 2026-08-28
- 관련: ADR-0094(git 마커), ADR-0086(진단 마커), ADR-0070(되돌아오기), ADR-0074(방문 기록), ADR-0010(검색), ADR-0013(operator 와 motion), ADR-0059(숫자 접두)

## 맥락

줄 앞 마커 칸에 이제 둘이 선다. 진단(`✖`·`⚠`, ADR-0086) 과 git 변경(`+`·`~`·`_`, ADR-0094) 이다. 둘 다 「저기에 뭔가 있다」를 말하는데 **거기로 가는 길이 눈으로 찾아 내려가는 것뿐**이었다. 두 ADR 이 각각 「뛰는 키는 뛸 목록이 생긴 뒤에 본다」로 미뤄 둔 것이 이 건이다.

## 0. 먼저 vim 을 확인했다

키 이름을 정하기 전에 로컬 vim 9.1 의 도움말을 직접 읽었다.

| 확인한 것 | 결과 |
| --- | --- |
| `]c`·`[c` 가 vim 에 있는가 | **있다.** `diff.txt` 의 「3. Jumping to diffs」이고 count 를 받는다 |
| 그 키가 언제 뜻이 있는가 | **diff mode 안에서만.** 평범한 buffer 에서 눌러 보면 오류도 없고 커서도 안 움직인다 |
| `]d`·`[d` 가 vim 에 있는가 | **있다. 다른 뜻이다.** `index.txt` 에 `show first #define found in current and included files` 로 적혀 있다 |
| 그 둘이 vim 의 jump 목록에 드는가 | **안 든다.** `motion.txt` 의 jump 목록은 `'` `` ` `` `G` `/` `?` `n` `N` `%` `(` `)` `[[` `]]` `{` `}` `:s` `:tag` `L` `M` `H` 다 |

이 표가 아래 셋을 정한다.

## 1. `]c`·`[c` 는 비어 있는 자리를 같은 뜻으로 쓴다

우리에게는 diff mode 가 없다. 그래서 이 키가 가리킬 「변경」이 vim 에서는 나란히 연 두 buffer 사이의 차이인데 우리에게는 HEAD 와의 차이다. **뜻은 그대로이고 무엇과 견주는지만 다르다.**

vim-gitgutter 가 이미 같은 자리를 같은 손으로 쓴다. 그 계보를 잇는 셈이라 새 규칙을 외울 것이 없다.

## 2. `]d`·`[d` 는 vim 의 뜻을 덮는다

vim 에서 그 키는 `#define` 을 찾는 `[`/`]` 계열이다. **우리는 그 기능이 없고 앞으로도 넣을 일이 없다** — 문법 강조는 있어도 include 를 따라가는 장치가 없고, 심볼을 찾는 일은 gopls 가 `\gd`·`\gr` 로 답한다(ADR-0051, ADR-0068).

Neovim 이 진단으로 덮어 쓴 뜻을 따른다. 「`]` 는 다음, `[` 는 이전, 뒤 글자가 무엇 사이인지」라는 한 규칙으로 넷이 묶이는 것이 값이다.

**빈자리를 쓰는 것과 덮는 것을 갈라 적어 둔다.** 나중에 vim 과 다른 자리를 찾을 때 이 둘은 성격이 다르다.

## 3. 감아 돈다. 검색과 같다

vim 의 `]c` 는 끝에서 오류를 낸다. **우리는 감아 돌고 감았으면 아래 줄에 알린다** — `n`·`N` 이 하는 그대로이고 글자도 같다(「아래에서 처음으로 돌아옴」).

- 이 키를 쓰는 손이 「바뀐 것을 하나씩 짚어 나가는」 것이다. 마지막 다음이 처음인 편이 그 손에 맞고, 끝에 닿았는지는 알림이 말한다.
- 편집기 안에 이미 감아 도는 것이 있다(검색). 같은 성격의 이동이 하나는 감고 하나는 멈추면 규칙이 둘이 된다.
- Neovim 의 진단 뛰기도 기본이 감아 돌기다.

**하나도 없으면 커서를 두고 알리기만 한다**(「바뀐 자리가 없습니다」·「진단이 없습니다」). 마커가 있는지 없는지는 화면 왼쪽 칸을 훑어야 아는 것이라, 아무 일도 안 나면 키가 안 먹은 것으로 읽힌다. 못 찾은 검색이 알리기만 하는 것과 같은 자리다.

## 4. 잇달아 붙은 줄은 한 자리다. 진단은 아니다

git 쪽은 **잇달아 마커가 선 줄을 한 덩이로 보고 그 첫 줄로 간다.** 열 줄을 고쳤으면 `~` 가 열 개 서는데 뛰는 쪽에서 그것은 열 곳이 아니라 한 곳이다. vim 이 `]c` 를 「변경의 **시작**으로」라고 적어 둔 것과 같다.

진단 쪽은 **묶지 않는다.** 잇달아 선 오류는 저마다 다른 오류이고, 한 줄씩 짚어 가며 고치는 것이 이 키를 쓰는 손이다.

## 5. motion 이 아니라 홀로 서는 동작이다

`d]c` 는 아무 일도 하지 않는다.

vim 의 `]c` 는 cursor movement command 라 operator 뒤에 설 수 있는데, 우리 쪽에서 그것을 받으려면 **지울 범위가 줄 단위인지 글자 단위인지**를 먼저 정해야 한다. hunk 는 줄 뭉치라 줄 단위가 자연스러운데, 그러면 같은 `]` 키가 홀로 칠 때와 operator 뒤에서 가리키는 것이 갈린다. `d↑`·`d home` 을 미뤄 둔 것과 같은 자리다(ADR-0013, ADR-0076).

**숫자 접두는 받는다**(`3]c`). vim 도 count 를 받고, 파서가 접두 키 뒤로 숫자를 이미 들고 다닌다. 이 건에 `prefixAction` 이 count 를 받게 되었다 — 그전에는 파서가 들고 온 숫자를 그 문에서 버리고 있었다.

## 6. 뛰기 전 자리는 이력에 담는다

vim 은 이 키를 jump 로 세지 않는다(§0). **우리는 담는다.**

- 우리에게 이 키는 파일을 가로질러 뛴다. 500 줄짜리 파일에서 3 번 줄과 480 번 줄 사이를 오가는 것이 흔한 쓰임이고, 그것을 담지 않으면 `ctrl+o` 가 돌려주지 못한다.
- 검색이 지나는 자리를 그대로 지난다(`recordJump` → 이동 → `arrive`). 닿은 자리가 방문 기록에도 남는 것까지 같다(ADR-0070, ADR-0074).
- **닿을 자리를 확인한 뒤에 담는다.** 못 가면 커서가 그대로라 담을 것도 없다.

## 결과

- `]c`·`[c` 로 git 으로 바뀐 자리를, `]d`·`[d` 로 진단을 짚어 나간다. `3]c` 처럼 숫자를 받는다
- 끝에 닿으면 감아 돌고 아래 줄이 그것을 알린다. 하나도 없으면 알리기만 한다
- `ctrl+o` 로 뛰기 전 자리로 돌아온다. `:jumps`·`:jumplogs` 에도 남는다
- `[`·`]` 가 접두 키가 되었다. showcmd 에 `3]` 처럼 보인다
- `prefixAction` 이 숫자를 받는다. `gt`·`gT` 는 여전히 버린다(그쪽은 별건이다)

**대가**

- **operator 뒤에 오지 않는다**(§5)
- **vim 과 두 자리가 다르다.** 감아 도는 것(§3) 과 jump 이력에 담는 것(§6) 이다
- **`]d` 는 vim 의 `#define` 찾기를 덮는다**(§2)
- **git 쪽은 열려 있는 파일 안에서만 뛴다.** 다른 파일의 변경으로 건너가지 않는다 — 그것은 파일 목록(`:changes`) 이 할 일이다(ADR-0094)
- **마커가 낡아 있는 250ms 동안은 뛰는 자리도 낡아 있다.** 마커를 그대로 읽으므로 어긋남도 그대로다

## 대안

- **끝에서 멈추고 오류를 내기(vim 과 같게)**
	- 파일 끝에 닿았다는 것이 분명하다.
	- 우리 편집기의 같은 성격 이동(검색) 이 감아 돈다. 규칙이 둘로 갈린다(§3).
- **`]h`·`[h`(hunk) 로 이름 짓기**
	- 「hunk」라는 말과 곧바로 이어진다.
	- vim 에 이미 있는 자리를 비워 두고 새 자리를 만드는 것이다. gitgutter 도 `]c` 를 기본으로 두고 `]h` 는 예시로 적어 둔다.
- **`]e`·`[e`(error) 로 진단 뛰기**
	- vim 의 `#define` 을 덮지 않는다.
	- 경고도 같은 키로 뛰므로 이름이 좁다. Neovim 과 갈리는 값이 그것을 넘지 못한다.
- **motion 으로 만들어 `d]c` 를 받기**
	- vim 의 갈래와 같아진다.
	- 지울 범위가 줄 단위인지 글자 단위인지 먼저 정해야 한다(§5).
- **파일을 넘어 다음 변경으로 가기**
	- 저장소 전체의 변경을 한 손으로 훑는다.
	- 열지 않은 파일을 열며 뛰는 일이라 tab 이 저절로 늘어난다. 그것은 목록에서 골라 여는 일이다(ADR-0094 의 `:changes`).

## 이 ADR 이 정하지 않는 것

- **hunk 미리보기·되돌리기.** ADR-0094 가 열어 둔 그대로다
- **`:changes` 목록에서 파일을 넘어 뛰는 것**
- **`]]`·`[[`(구역 사이 이동) 처럼 `[`/`]` 계열의 다른 키.** 자리는 이제 열려 있다
- **visual 에서의 `]c`.** 지금은 normal 에서만 받는다. 고른 범위를 hunk 까지 늘리는 것은 범위 규칙이 따로 필요하다
