# ADR-0017: 붙여넣기는 무명 register 하나로 하고, `y` 는 `d` 의 범위 계산을 그대로 쓴다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

ADR-0013 으로 `d`·`x` 가 들어오면서 지운 내용이 `editor.register` 에 쌓이기 시작했다. 그런데
**읽는 곳이 없었다.** 지운 것을 다시 꺼낼 길은 `u` 뿐이고, 그것은 되돌리기이지 옮겨 붙이는 것이
아니다. 줄 하나를 아래로 옮기려면 지우고 → 커서를 옮기고 → 손으로 다시 치는 수밖에 없었다.

`p`/`P` 만 넣으면 반쪽이 된다. register 를 채우는 길이 "지우기" 뿐이라, **지우지 않고 복사만
하는 것이 불가능**하다. 옮기기는 되고 베끼기는 안 되는 편집기가 된다. 그래서 `y` 를 같이 넣는다.

ADR-0013 이 "이 ADR 이 정하지 않는 것" 으로 남긴 것 중 세 개가 여기 걸린다 — `p`/`P`,
이름 있는 register(`"a`), `y`.

정할 것이 넷이었다.

1. **register 를 몇 개 둘 것인가.** 무명 하나인가, 이름 있는 것(`"a`) 까지인가
2. **`y` 의 범위를 어떻게 얻는가.** `d` 와 같이 쓸 것인가, 따로 짤 것인가
3. **붙인 뒤 커서를 어디에 둘 것인가.** 줄 단위와 글자 단위가 다르고, 여러 줄이면 또 다르다
4. **시스템 클립보드와 잇는가.**

## 결정

**register 는 무명 하나다.** `editor.register` 를 그대로 쓴다. 파서에 `"` 를 받는 상태를
더하지 않는다. 숫자 register(`"1`~`"9`) 도 없다.

**`y` 는 `d` 와 같은 범위 계산을 쓴다.** `deleteByMotion` 에서 범위를 잡는 부분을
`rangeByMotion` 으로 떼고 둘이 같이 부른다. 파서는 `normalStart`/`normalCount` 의 operator
자리에 `y` 를 한 글자 더한 것이 전부다 — `yy` `y3w` `3yy` `ygg` `y$` 가 `d` 와 똑같이 딸려 온다.
`w` 의 줄끝 예외(ADR-0013) 도 그대로 물려받아서 `y2w` 는 줄을 넘지 않는다.

**`y` 는 파일을 건드리지 않는다.** dirty 도 되돌리기도 없다. 뒤로 가는 motion 이었으면 커서가
범위의 시작으로 간다(`yb` `yk` `ygg`). 앞으로 가는 motion 은 제자리다(`yw` `yy` `y$` `yG`).

**커서가 가는 자리는 motion 이 커서를 둔 자리 그대로다.** 그래서 `yk` 는 칸을 지키고
`ygg` 는 첫 비공백으로 간다. vim 과 같다. 줄 단위 motion 도 이동 함수를 복사본 위에서 실제로
실행해서 그 자리를 얻는다 — `lineMotionTarget` 이 줄 번호를 셈으로 구하던 것을 이동 실행으로
바꿨다. ADR-0013 이 글자 단위에 쓴 방식을 줄 단위에도 쓴 것이다.

**`p`/`P` 의 뜻은 vim 과 같다.**

- 줄 단위 register: `p` 는 커서 줄 아래, `P` 는 위에 줄로 끼운다. 커서는 붙인 **첫 줄의 첫 비공백**이다
- 글자 단위 register: `p` 는 커서가 선 글자 뒤, `P` 는 커서 자리에 끼운다.
  한 줄이면 커서는 붙인 **마지막 글자** 위, 여러 줄이면 붙인 **첫 글자** 위다
- 숫자는 되풀이다. `3p` 는 세 번 붙인다

**빈 register 로 `p` 를 치면 아무 일도 하지 않는다.** 알림도 없고 dirty 도 서지 않는다.

**붙여넣기 한 번이 되돌리기 한 구간이다.** `3p` 도 `u` 한 번에 전부 사라진다. 앞의 타이핑
구간을 먼저 닫고 시작한다. 지우기와 같다.

**시스템 클립보드와 잇지 않는다.** 터미널 붙여넣기는 지금처럼 insert mode 의 `tea.PasteMsg`
뿐이다.

## 근거

### register 하나

**쓰는 사람이 한 명이고, 그 손이 `"a` 를 치지 않는다.** 이름 있는 register 는 매크로(`q`) 와
같이 쓸 때 값이 나오는데 매크로가 없다. 없는 것을 위해 파서에 상태를 늘리고 `register` 를
map 으로 바꾸는 것은 지금 치를 값이 아니다.

**나중에 붙일 자리는 열려 있다.** `editor.register` 필드 하나가 map 이 되고 `normalStart` 에
`"` case 가 하나 느는 것이라, 그때 가서 해도 지금 코드가 버려지지 않는다.

### `d` 와 범위를 같이 쓴다

**두 벌이 되면 갈린다.** ADR-0013 이 이동과 지우기를 갈라놓지 않은 것과 같은 이유다. `dw` 와
`yw` 가 서로 다른 자리에서 멈추는 편집기는 손이 못 믿는다. 실제로 `y2w` 가 줄 끝에서 멈추는
것은 `d` 쪽 예외를 그냥 물려받아 얻었다 — 코드를 한 줄도 더 쓰지 않았다.

**`c` 도 여기로 들어온다.** 남은 operator 하나는 "범위를 지우고 insert 로 들어가는 것" 이라
`rangeByMotion` 위에 얹힌다.

### 줄 단위 motion 도 이동을 실행해서 얻는다

**커서 칸이 필요해졌다.** 범위만 필요할 때는 줄 번호를 셈으로 구해도 됐다. 복사는 커서를
그 자리로 옮기므로 칸까지 알아야 하는데, `k` 는 칸을 지키고 `gg` 는 첫 비공백으로 가는 규칙이
이미 이동 함수 안에 있다. 다시 쓰면 두 벌이다.

**셈과 이동의 결과가 같은지는 기존 표가 지킨다.** `delete_test.go` 의 `dj` `dk` `dG` `dgg`
표가 그대로 통과한다.

### 커서 자리는 vim 그대로

**기대값을 vim 9.1 에서 직접 쳐서 확인했다.** ADR-0013 과 같은 방식이다. 세 규칙(한 줄이면
마지막 글자, 여러 줄이면 첫 글자, 줄 단위면 첫 비공백) 은 짐작으로는 맞힐 수 없는 것이라
`xp`(글자 뒤바꾸기) 같은 흔한 손버릇이 vim 과 다르게 동작할 뻔했다.

### 빈 register 는 조용하다

**모르는 motion 이 조용한 것과 같다.** `d` 뒤에 미끄러진 키가 아무 일도 하지 않는 것처럼,
아직 아무것도 지우거나 복사하지 않은 채로 친 `p` 도 아무 일도 하지 않는다. 알림을 띄우면
편집기를 켜자마자 `p` 를 눌러본 사람에게 오류처럼 읽힌다.

### 클립보드는 나중이다

**터미널마다 갈린다.** OSC 52 는 지원이 제각각이고, ssh 로 쓸 때와 로컬에서 쓸 때가 또 다르다.
편집기 안에서 옮겨 붙이는 것과 밖으로 내보내는 것은 별개의 결정이라 섞지 않는다.

**밖으로 내보내는 길은 이미 계획에 있다.** "화면을 cat 과 같은 형태로 보여주는 기능"
(`docs/tasks.md`) 이 터미널 자체의 복사를 쓰게 하는 길이다.

## 결과

좋은 점

- `p` `P` `3p` 와 `y` + 이동 키 조합이 동작한다. `yy` `yw` `y$` `3yy` `y3w` `ygg` 다.
- 기대값을 vim 9.1 에서 쳐서 확인하고 표로 옮겼다(`paste_test.go`). 빈 buffer 에 붙이기,
  마지막 줄 아래, 빈 줄, 여러 줄에 걸친 글자 단위처럼 헷갈리는 자리가 전부 실제 vim 결과다.
- tab 을 옮겨 붙는다. register 가 `editor` 에 있는 이유가 여기서 쓰인다.
- `insertLines` 가 생겨서 "줄을 끼우는" 편집이 되돌리기와 함께 한 곳에 모였다.

감수하는 것

- **`dy` 나 `yd` 는 아무 일도 하지 않고 키만 먹는다.** 뒤의 operator 가 operator 를 새로 열어서
  이름이 `d y w` 처럼 되고, 그것을 아는 곳이 없다. vim 은 `dy` 에서 바로 무르고 다음 키를
  동작으로 받는다. 잘못 친 자리라 실제로 걸리는 일은 드물다.
- **한글 상태의 `ㅛ` 가 `y` 다.** operator 가 하나 더 늘었으니 한글로 잘못 친 음절이 편집이 될
  자리도 늘었다. `y` 는 파일을 바꾸지 않아서 `d` 보다는 덜 아프다(ADR-0008).
- **`.`(되풀이) 가 없어서 `p` 를 반복하려면 다시 친다.** 숫자(`3p`) 로 대신한다.
- **register 가 buffer 의 줄을 그대로 가리킨다.** 줄은 제자리에서 바뀌지 않으므로(ADR-0001)
  안전하지만, 그 규칙이 깨지면 붙여넣기가 조용히 다른 내용을 내놓는다. 큰 파일에서 `yG` 를 하면
  파일 전체가 register 에 남는 것도 같은 이유다 — 복사하지 않으니 값은 slice header 뿐이다.

## 대안

**클립보드를 먼저 넣기** — `y` 가 OSC 52 로 터미널 클립보드에 쓰고 `p` 가 거기서 읽는다.
편집기 밖과 이어지는 것이 안에서 옮기는 것보다 자주 필요할 수 있다. 터미널마다 지원이 갈리고
읽기(paste)는 OSC 52 로 안 되는 터미널이 더 많아서, 편집기 안이 먼저다.

**이름 있는 register 를 같이 넣기** — `"ayy` `"ap` 다. 파서에 상태 하나와 map 이면 되지만,
쓰지 않을 것을 미리 넣는 것이라 뺐다.

**`p` 를 `insert` 로만 구현하기** — 줄 단위 붙여넣기도 "줄 끝으로 가서 `\n` + 내용을 넣는 것"
으로 쓸 수 있다. `openLineBelow` 가 그 방식이다. `p` 와 `P` 가 서로 다른 자리에서 줄을
갈라야 해서 조건이 갈리고, 마지막 줄과 첫 줄이 각각 예외가 된다. `insertLines` 로 줄을
통째로 끼우는 편이 읽힌다.

**register 를 `Buffer` 안에 두기** — tab 을 넘어 붙지 않게 된다. 옮겨 붙이는 것이 붙여넣기를
쓰는 가장 흔한 이유라 ADR-0013 에서 이미 `editor` 로 정했다.

## 이 ADR 이 정하지 않는 것

- 이름 있는 register(`"a`) 와 숫자 register(`"1`~`"9`), 매크로(`q`)
- 시스템 클립보드(OSC 52) 와 `"+`/`"*`
- `c`(고치기) `D` `C` `s` `S` `X`
- `gp`/`gP`(붙인 뒤로 커서 옮기기) 와 `]p`(들여쓰기를 맞춰 붙이기)
- `.`(되풀이)
- visual mode 에서 고른 범위를 복사하거나 그 위에 붙이는 것
