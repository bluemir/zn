# ADR-0091 text object 는 단어 넷으로 시작한다. 공백 위에서는 아무 일도 하지 않는다

- 상태: 채택
- 날짜: 2026-08-28
- 관련: ADR-0013(`d` 와 motion), ADR-0017(`y`), ADR-0033(`c`), ADR-0034(키에서 동작을 만드는 상태 기계), ADR-0008(한글 입력), ADR-0037(visual mode), ADR-0047(`>` `<` `=`)

## 맥락

`ciw` 가 아무 일도 하지 않는다. `normal-key-parser.go` 가 그 자리를 이렇게 적어 두었다.

> motion 이 아니면 홀로 서는 동작인데, 그것은 operator 뒤에 올 수 없다 — `di` 는 아무것도 아니다.

ADR-0033 이 `c` 를 넣으며 남긴 물음이 이것이다. 「`ciw` `ci"` 같은 text object. operator 뒤에 motion 이 아닌 것이 오는 첫 경우다.」

**이동이 아니라 범위만 주는 갈래는 이미 있다.** `dd` 의 「줄 전체」(`motionWholeLines`) 가 `move` 없이 `span` 만 갖는다(`motion.go`). text object 도 같은 갈래다. 새로 오는 것은 **키 둘로 범위 하나를 만드는 것**이다.

정할 것은 여섯이다. 무엇을 넣는가, `aw` 의 공백 규칙, count, 공백 위에서의 동작, 빈 줄, visual.

## 1. 단어 넷만 넣는다

`iw` `aw` `iW` `aW` 다.

vim 의 text object 는 열 남짓인데 **경계를 찾는 값이 갈래마다 다르다.**

| 갈래 | 무엇이 붙는가 |
| --- | --- |
| 단어 | `charClass` 로 곧바로 된다. 표가 이미 있다(word.go) |
| 따옴표(`i"` `i'`) | escape(`\"`) 를 볼지, 줄을 넘을지 |
| 짝괄호(`i(` `i{` `i[`) | **겹을 세야 한다.** 여러 줄에 걸치고 문자열 안의 괄호를 어떻게 볼지가 온다 |
| tag(`it`) | html 파서가 필요하다 |
| 문단(`ip`) | 빈 줄 경계. 문단 상태가 필요하다 |

단어만 `charClass` 위에 그대로 선다. 나머지는 각각 별건이고 `docs/tasks.md` 의 backlog 로 내렸다.

**단어 하나를 넣으면 operator 여섯에 한꺼번에 붙는다.** `diw` `yiw` `ciw` `>iw` `<iw` `=iw` 다. `operate` 가 범위 하나를 여섯으로 갈라 주기 때문이다(ADR-0013, ADR-0017, ADR-0033, ADR-0047).

## 2. 공백 위에서는 아무 일도 하지 않는다

**vim 과 갈리는 자리다.** vim 의 `diw` 는 커서가 공백 위에 있으면 **그 공백 덩어리**를 지운다.

따르지 않는다. `iw` 를 치는 손짓은 「이 단어를 바꾼다」이고, 그것이 커서 한 칸에 따라 「이 공백을 지운다」로 갈리면 무엇이 사라질지 미리 알 수 없다. **눌러 보고 알게 되는 키를 만들지 않는다.**

`~` 가 한글 위에서 파일을 그대로 두는 것과 같은 태도다(ADR-0083). 할 일이 없으면 dirty 도 세우지 않는다.

**빈 줄과 줄 끝도 여기서 같이 걸린다.** `classAt` 이 줄 끝을 공백으로 보기 때문이다(buffer-word.go). 따로 가른 자리가 없다.

## 3. `aw` 는 뒤 공백을 먹고, 없으면 앞 공백을 먹는다

vim 그대로다. `iw` 가 단어만이고 `aw` 가 그 둘레까지다.

이 규칙이 값을 내는 자리는 낱말을 지우는 손이다. 줄 가운데 낱말을 `daw` 로 지우면 공백이 하나만 남고, 줄 끝 낱말이면 앞 공백을 먹어서 줄 끝에 공백이 남지 않는다.

## 4. count 를 받지 않는다

vim 의 `d2iw` 는 「단어 둘」이 아니다. **단어와 공백을 번갈아 세서** `d2iw` 가 「단어와 그 뒤 공백」이다. `d3iw` 는 「단어, 공백, 단어」다.

이 규칙은 아는 사람에게만 뜻이 있고, 모르면 `d2iw` 가 단어 둘을 지울 것으로 읽힌다. **틀리게 읽히는 숫자를 받지 않는다.**

`3ciw` 는 숫자를 버리고 `ciw` 와 같다. `c3iw` 도 같게 둔다 — 숫자를 먹는 자리가 operator 앞뒤 둘이라(`operatorCount`) 한쪽만 막으면 같은 것을 쳐도 답이 갈린다.

## 5. `i`·`a` 는 operator 뒤에서만 text object 다

홀로 치면 insert mode 다. 그것을 빼앗지 않는다.

**갈라 두는 자리가 `building.op` 하나다.** operator 를 먹었으면 접두 키가 되고, 아니면 지금처럼 `standaloneAction` 으로 흘러간다.

`normalTextObject` 는 `r`(`normalReplace`)·`"`(`normalRegister`) 와 같은 모양이다 — 한 키를 더 기다렸다가 동작을 짓는다. **본이 이미 둘 있다.**

짝이 없는 조합(`ciz`) 은 아무 일도 하지 않는다. `dgt` 와 같다(ADR-0034).

## 6. visual 에는 넣지 않는다

vim 의 `viw` 는 고른 범위를 그 단어로 늘린다.

visual 이 받는 키는 지금 전부 한 개짜리다(`visual-key-parser.go`). 접두 키를 여는 것은 `\c` 하나뿐이고 그것도 두 키에서 끝난다(ADR-0085). **여기에 `i`·`a` 를 열면 visual 의 키 면적이 또 넓어진다** — ADR-0037 이 일부러 좁게 둔 자리다.

그리고 visual 에서 `i` 는 vim 에서도 다른 뜻이 없어서 나중에 넣어도 부딪히지 않는다. 급할 이유가 없다.

## 결과

- `iw` `aw` `iW` `aW` 가 operator 여섯에 붙는다. `diw` `yiw` `ciw` `>iw` `<iw` `=iw`
- 새로 오는 코드는 셋이다. 파서 상태 하나(`normalTextObject`), motion 하나(`motionWordObject`), 키 표 하나(`wordObjectKind`)
- `motionFor` 는 손대지 않는다. 그 함수는 키 하나 → motion 이고 text object 는 키 둘이다

감수하는 것

- **공백 위에서 아무 일도 하지 않는다.** vim 은 공백 덩어리를 지운다(§2)
- **count 를 버린다.** `3ciw` 가 `ciw` 다(§4)
- **줄을 넘지 않는다.** 단어는 줄 안의 것이고 `classAt` 이 줄 끝을 공백으로 보므로 저절로 멈춘다
- **따옴표·짝괄호·tag·문단이 없다.** `ci"` 는 아직 아무 일도 하지 않는다(§1)
- **visual 에 없다.** `viw` 에서 `i` 는 버려지고 `w` 가 이동 키로 먹혀서 고른 범위가 한 낱말 늘어난다. 원하던 것과 다른 답이라 넣을 때 이 자리를 같이 본다(§6)
- **`iw` 가 CJK 경계를 따른다.** `한글abc` 에서 `ciw` 는 `한글` 만 잡는다. `w` 가 그렇게 걷는 것과 같다(word.go)

## 대안

- **vim 처럼 공백 덩어리도 잡기**
	- vim 을 쓰던 손이 어긋나지 않는다.
	- 같은 키가 커서 한 칸에 따라 「단어를 바꾼다」와 「공백을 지운다」로 갈린다. 눌러 보고 아는 키가 된다(§2).

- **count 를 vim 규칙으로 받기**
	- `d2iw` 가 vim 과 같아진다.
	- 단어와 공백을 번갈아 세는 규칙은 모르면 틀리게 읽힌다. 얻는 것이 그 하나뿐이다(§4).

- **따옴표까지 같이 넣기**
	- `ci"` 가 실제로 많이 쓰인다.
	- escape 와 줄 넘기를 정해야 하고, 문법 강조가 이미 문자열을 아는데 그것을 쓸지도 물음이다. 단어와 값이 달라서 갈랐다(§1).

- **`motionFor` 를 두 키까지 받게 넓히기**
	- 표가 한 곳에 모인다.
	- 그 함수는 키 하나로 motion 을 짓는 자리이고, 여섯 operator 와 이동 키가 같이 쓴다. 두 키를 받게 하면 「아직 안 정해졌다」를 표현할 자리가 새로 생긴다. 상태 기계가 이미 그 일을 한다(ADR-0034).

- **`i`·`a` 를 operator 없이도 text object 로 쓰기**
	- 키 하나가 덜 필요하다.
	- insert mode 를 빼앗는다. 이것을 고를 수 없다(§5).

## 이 ADR 이 정하지 않는 것

- **따옴표(`i"` `i'`)·짝괄호(`i(` `i{` `i[`)·tag(`it`)·문단(`ip`).** backlog 에 있다 (§1)
- **visual 의 `viw`** (§6)
- **`ib`·`iB` 같은 vim 의 별칭.** 짝괄호가 올 때 같이 본다
- **문법 강조가 아는 문자열·주석을 text object 로 쓰는 것.** lexer 가 이미 그 경계를 아는데 쓰는 자리가 아직 없다 (ADR-0039)
