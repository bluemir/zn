# ADR-0022 트리에서 지금 보는 파일을 굵게

## Status

Accepted

## Context

트리에는 지금 무엇을 보고 있는지 나타내는 것이 **커서 하나뿐**이었다. 그런데 그 커서는
터미널 커서라서 포커스가 트리에 있을 때(`mode=TREE`) 만 그려진다. `viewSidebar.View` 가
커서를 트리 행에 놓고, 다른 mode 는 커서를 본문이나 명령줄에 놓기 때문이다.

`treeRow.cell` 은 파일 종류별 글자색만 입힌다. 고른 행을 따로 칠하는 코드가 없다.
그래서 **편집 중(`NORMAL`) 에는 트리에 지금 자리 표시가 아예 없었다.** ADR-0019 로 트리가
보는 파일을 따라 펼쳐지고 고르게 만들었지만, 그 결과가 눈에 보이는 것은 트리로 포커스를
옮긴 다음이었다.

여기에 `:e <파일>` 이 들어오면서(ADR-0021) 파일을 오가는 길이 더 늘었다. 트리를 보고
"지금 어디" 를 알 수 있어야 할 이유가 커졌다.

## Decision

### 굵은 글씨는 "지금 보고 있는 파일" 하나다

트리에서 활성 buffer 의 파일 행만 `Bold` 로 그린다. 종류별 색 위에 덧입힌다 —
색은 그 파일이 무엇인지, 굵기는 지금 보고 있는지다.

열려 있는 tab 을 **전부** 굵게 하는 길도 있었지만 택하지 않았다. tabline 이 이미 열린 tab
목록이고 그 중 활성 tab 도 반전으로 나타낸다. 트리까지 같은 정보를 실으면 표시만 늘고
읽을 것이 늘지 않는다. 트리가 못 하던 것은 "지금 어디" 쪽이므로 그것만 채운다.

### 디렉터리에서 굵기를 뗀다

`styleTreeDir` 이 파랑(117) + `Bold` 였다. 그대로 두면 굵기가 "디렉터리" 와 "지금 보는 파일"
두 뜻을 갖는다. 디렉터리는 tab 으로 열리지 않으니 실제로 헷갈릴 일은 드물지만, 화면에서
읽는 규칙은 한 표시에 한 뜻이라야 설명이 짧다.

디렉터리는 색(117) 과 `▸`/`▾` 펼침 표시와 `/` 접미로 이미 세 가지나 갈려 있어서 굵기를
빼도 잃는 것이 없다.

### 활성 경로는 editor 가 계산해서 넘긴다

`sidebar` 는 `buffers` 를 모른다. `sidebar.cells(height, activePath)` 로 받는다.
`editor.activePath()` 가 활성 buffer 의 경로를 절대 경로로 맞춰서 준다 — 트리 항목은 절대
경로이고 CLI 로 연 파일은 상대 경로라, `tabOf` 나 `reveal` 과 같은 이유로 정규화가 필요하다.

sidebar 에 "열린 파일 목록" 을 따로 들고 있게 하는 길도 있었지만, tab 이 열리고 닫히고
갈아끼워질 때마다 맞춰 줘야 하는 상태가 하나 더 생긴다. 그릴 때 받는 편이 어긋날 자리가 없다.
이름 없는 buffer 는 빈 문자열이라 어느 행과도 맞지 않는다.

## Consequences

- 편집 중에도 트리만 보고 지금 자리를 안다. ADR-0019 의 "트리가 따라간다" 가 비로소 눈에 보인다.
- 디렉터리가 덜 도드라진다. 트리 모양이 조금 바뀐다.
- 굵기를 흉내만 내고 밝은 색으로 바꾸는 터미널이 있다. 그런 곳에서는 종류별 색이 살짝 밝아지는
  것으로 보이는데, 어느 쪽이든 한 행만 달라지므로 구분은 된다.
- 열린 tab 전부를 트리에서 구분하는 것은 여전히 열려 있다. 하려면 색이 필요한데 색은 파일 종류가
  이미 쓰고 있다(ADR-0005). 팔레트 색 결정과 같이 본다.
- **CLI 로 시작한 직후에는 굵은 자리가 화면 밖일 수 있다.** 트리는 시작할 때 파일 자리를 펼치기만
  하고 스크롤은 하지 않는다 — `WindowSizeMsg` 가 오기 전이라 높이를 모르기 때문이다(`core.go`).
  `resize` 도 편집 buffer 만 맞추고 트리는 건드리지 않는다. 지금까지는 커서가 안 보여서 티가 나지
  않던 것이 굵기가 생기면서 드러난다. 따로 다룬다(`docs/tasks.md`).
