# ADR-0038: 저장하지 않은 변경이 없으면 바깥 변경을 자동으로 가져오고, 주기 tick 을 하나 더 둔다

- 상태: 채택 (검사하는 방식과 mode 조건은 ADR-0044 가 바꿨다 — 작업으로 내리고 `dirty` 만 본다)
- 날짜: 2026-08-20

## 맥락

바깥 변경을 다루는 결정이 셋 쌓였다.

- ADR-0015: 저장 직전에 내용 해시로 검사하고 `:w!` 로만 덮어쓴다
- ADR-0016: 가져오는 길은 팔레트의 「파일 다시 읽기」 하나이고, dirty 면 확인창으로 묻는다
- ADR-0031: 포커스가 돌아올 때 검사해서 statusBar 에 `[!]` 로 들고 있는다

세 결정이 모두 **사람이 시켜야 가져온다** 는 자리에 서 있다. 그래서 다른 창에서 `git pull`·
포매터·`git checkout` 을 돌리고 돌아오면, 편집기는 `[!]` 를 붙여 두고 사람이 팔레트를 열어
「파일 다시 읽기」를 고를 때까지 기다린다. **저장하지 않은 변경이 하나도 없을 때도 그렇다.**
그때 가져오는 것은 아무것도 잃지 않는데, 손은 매번 같은 두 걸음을 걷는다.

ADR-0031 은 이것을 대안으로 적어 두고 물렸다 — "발견하면 바로 다시 읽기(vim 의 `autoread`) …
저장하지 않은 변경이 있으면 그것을 버리게 되고, 없더라도 커서와 화면이 갑자기 움직인다".
앞의 이유는 `dirty` 를 보면 없어지고, 뒤의 이유는 ADR-0016 이 커서 줄·화면 칸·`top` 을
이어받게 만들어 두어서 이미 값이 작다. `docs/tasks.md` 에도 "파일이 변경 되었을때, zn 에서
변경 한게 없으면 자동으로 reload 한다" 로 열려 있었다.

검사 시점도 같이 걸린다. ADR-0031 은 포커스 복귀만 본다. 자동으로 가져오기로 하면 **보고 있는
채로 밖에서 바뀌는 파일**(로그·생성물, 옆 pane 에서 도는 `git pull`) 이 남는다. 포커스가 오간
적이 없어서 복귀만으로는 영원히 잡히지 않는다. `docs/tasks.md` 의 "변경 검사 시점이 포커스만으로
부족하면 주기 검사를 얹는다" 가 그 자리다.

## 결정

**`dirty` 가 아니고 내용이 달라졌으면(`outsideModified`) 그 자리에서 다시 읽는다.**
`Buffer.Reload` 를 그대로 쓴다 — ADR-0016 이 만든 길이고 커서와 화면을 이어받는 것도 그대로다.

**`dirty` 면 읽지 않고 지금처럼 `[!]` 마커만 붙인다.** 무엇을 남길지는 사람이 정할 일이고,
그것을 묻는 확인창은 ADR-0016 이 이미 「파일 다시 읽기」에 붙여 두었다.

**자동으로 읽는 것은 `outsideModified` 뿐이다.** 없던 파일이 생긴 것(`outsideCreated`) 은
`:tabnew foo.go` 로 새로 쓰려던 자리일 수 있어서 손으로 정한다. 사라진 것(`outsideRemoved`) 은
가져올 것이 없다.

**normal 과 트리에서만 읽는다.** insert 는 지금처럼 알리고 마커만 붙인다.

**포커스 복귀(`FocusMsg`·`ResumeMsg`) 와 5 초 주기 tick, 두 자리에서 본다.**

**주기 tick 은 git tick 과 나눈다.** `fileTickMsg` 를 새로 두고 주기는 `fileInterval`
(5 초) 이다. 판정은 ADR-0015 의 내용 해시 그대로다 — mtime 으로 거르지 않는다.

**자동으로 읽으면 한 번 알린다.** `파일이 밖에서 바뀌어 다시 읽었습니다` 다. 마커는 붙지 않는다 —
어긋난 것이 없다.

**tick 을 받는 자리와 주기를 잇는 자리를 가른다.** 보는 mode(normal·트리) 는 자기 case 에서
받고 스스로 다음 tick 을 예약한다. 나머지 mode 는 공용 처리(`handleJob`) 가 파일을 보지 않고
주기만 잇는다. 한 msg 를 한 자리가 받으므로 고리가 갈라지지 않는다.

## 근거

### 왜 `dirty` 만 보는가 — undo 이력까지 보지 않고

**`dirty` 는 "지금 파일과 다른 것을 손에 들고 있는가" 다.** 그것이 아니면 가져와서 잃는 내용이
없다. 이 기능이 서는 자리가 정확히 거기다.

**undo 이력까지 비어 있어야 한다고 하면 기능이 거의 동작하지 않는다.** 한 글자만 고쳐 `:w` 한
파일은 그 뒤로 영원히 자동 reload 가 걸리지 않는다. 편집기를 켜 두고 하루를 쓰는 흐름에서
그것은 "없는 기능" 과 같다.

**그래서 이력이 사라지는 것은 감수한다.** `Reload` 는 buffer 를 갈아끼우므로 `undo`·`redo` 를
버린다(ADR-0016 이 "이력은 lines 의 자리로 기록되어 밖에서 바뀌면 엉뚱한 줄을 가리킨다" 로
정한 값이다). 고치고 저장한 뒤 밖에서 파일이 바뀌면, 묻지 않고 그 이력이 사라진다.
**내용을 잃는 것과 이력을 잃는 것은 무게가 다르다** — 내용은 되찾을 길이 없고 이력은 편의다.
잃는 쪽을 이력으로 한정하는 것이 이 결정의 값이다.

**이력을 남긴 채 내용만 갈아끼우는 길은 물렸다.** ADR-0016 이 이미 "`u` 가 엉뚱한 줄을
엉뚱한 내용으로 갈아끼운다" 로 물린 것이고, 조용히 하는 자동 동작에서는 더 위험하다.

### 왜 normal·트리이고 insert 는 아닌가

**insert 는 커서가 글자 사이에 있다.** 치는 중에 줄이 밀리면 다음에 치는 글자가 다른 자리에
들어간다. `dirty` 가 아니어도(들어와서 아직 안 쳤어도) 다음 순간에는 칠 것이고, 그 사이에
내용이 갈아끼워지는 것은 손이 예상할 수 없다.

**normal 은 키 하나가 끝난 상태다.** 화면이 바뀌어도 다음 키는 새 내용 위에서 시작한다.

**트리는 편집 영역을 옆에 그린다.** 포커스가 트리에 있어도 오른쪽 화면이 파일과 어긋나 있으면
안 된다 — ADR-0031 이 트리를 검사 대상에 넣은 것과 같은 이유다.

**insert 에서 놓친 것은 `Esc` 뒤에 잡힌다.** normal 로 나오면 다음 tick 이 5 초 안에 본다.
그 사이에 치면 `dirty` 가 서고 마커 쪽 길로 간다 — 그것이 맞는 동작이다.

### 왜 주기를 얹는가 — 포커스만으로는 부족하다

**자동으로 가져오기로 하면 포커스가 오가지 않는 흐름이 남는다.** 옆 pane 에서 도는 빌드의
생성물, 흘러가는 로그, tmux 안에서 창을 옮기지 않고 돌린 `git pull`. ADR-0031 이 "바깥에서
파일을 고치는 흐름에는 포커스 이동이 딸려 온다" 고 쓴 것은 **알림** 이 목적이었을 때의 값이다.
가져오는 것이 목적이 되면 그 가정으로 덮이지 않는 자리가 눈에 띈다.

**주기 검사가 알림과 궁합이 안 맞던 이유도 줄어든다.** ADR-0031 은 "주기적으로 띄우면 타이핑
중에 떴다가 못 보고 지나간다" 를 들었다. 자동 reload 는 알림이 본체가 아니다 — 화면이 바뀌는
것 자체가 알림이고, 문구는 그 이유를 붙이는 것이다.

### 왜 git tick 에 얹지 않고 나누는가

**tick 은 무엇을 위한 것인지가 이름에 남아야 한다.** `gitTickMsg` 가 파일 검사까지 나르면
ADR-0030 이 정한 "5 초는 `git status` 프로세스가 분당 서른여섯 개로 그치는 자리" 라는 근거와
이 결정의 근거가 한 상수에 매달린다. 한쪽 주기를 바꾸려면 다른 쪽을 같이 봐야 한다.

**대신 mode 열 곳의 공용 case 에 `fileTickMsg` 를 더해야 한다.** 어느 mode 에서든 고리가
이어져야 하기 때문이다. `docs/tasks.md` 의 "`Update` 마다 공용 메시지 case 가 반복된다" 가
이것으로 한 번 더 늘었고, 사용자가 "주기적 동작을 위한 구조 만들기" 로 따로 적어 두었다.

### 왜 mtime 으로 거르지 않는가

**판정 기준이 갈리지 않게 한다.** 저장 직전(ADR-0015)·포커스 복귀(ADR-0031)·주기가 전부
`checkOutside` 하나를 부른다. mtime 앞잡이를 두면 buffer 에 상태(mtime·크기) 가 늘고
"어느 자리는 stat 으로 먼저 걸렀다" 는 예외가 생긴다.

**ADR-0015 가 그 절충을 "큰 파일이 실제로 문제가 되면 옮겨갈 자리" 로 남겨 두었다.**
지금 편집기가 다루는 파일은 통째로 메모리에 올려 두는 크기다(ADR-0001). 실제로 거슬리면
그때 `checkOutside` 안쪽만 바꾸면 되고, 부르는 자리는 그대로다.

### 왜 알리는가

**화면이 바뀐 이유를 말해 준다.** 아무 키도 누르지 않았는데 내용이 달라진 것은, 이유를 모르면
편집기가 무언가를 잃어버린 것처럼 보인다.

**한 번만 뜨고 다음 키에 사라진다.** `editor.message` 라 원래 그렇다. 밖에서 계속 바뀌는
파일에서는 뜨는 횟수가 실제로 바뀐 횟수와 같다 — 마커와 달리 같은 사실을 되풀이하는 것이 아니다.

## 결과

좋은 점

- 다른 창에서 `git pull`·포매터를 돌리고 돌아오면 편집기가 이미 새 내용을 보여준다. 손이 걷던
  두 걸음(팔레트 열기 → 「파일 다시 읽기」 고르기) 이 없어진다.
- 보고 있는 채로 바뀌는 파일도 따라온다. 주기 검사가 그것을 잡는다.
- `[!]` 마커의 뜻이 좁아져서 오히려 선명해졌다. 이제 마커가 붙는 것은 **양쪽에 잃을 것이 있는
  경우**(내 미저장 변경 + 남의 변경) 이거나 자동으로 가져오지 않는 경우(생김·사라짐) 다.
- 커서 줄·화면 칸이 유지되므로 보던 자리에서 이어 본다. ADR-0016 이 만들어 둔 값을 그대로 쓴다.

감수하는 것

- **undo 이력이 묻지 않고 사라진다.** 고치고 `:w` 한 뒤 밖에서 파일이 바뀌면 `u` 로 돌아갈
  것이 없어진다. 이 결정에서 가장 비싼 값이다.
- **유휴 상태에서 5 초마다 파일을 통째로 읽어 sha256 을 낸다.** git 갱신과 달리 프로세스는
  뜨지 않지만 공짜도 아니다. 큰 파일을 띄워두면 그만큼 읽는다.
- **주기 tick 이 하나 더 늘었다.** mode 열 곳의 공용 case 에 `fileTickMsg` 가 붙었고, 그 목록을
  빠뜨린 mode 가 새로 생기면 그 mode 에서 고리가 끊긴다.
- **화면이 저절로 움직인다.** 줄이 밀린 파일에서는 보고 있던 줄 번호에 다른 내용이 온다.
  "어디를 보고 있었는지" 는 유지되고 "무엇을 보고 있었는지" 는 아니다(ADR-0016 과 같다).
- **보고 있지 않은 tab 은 여전히 모른다.** 검사하는 것은 활성 buffer 하나다.
- **insert 에 머무는 동안은 가져오지 않는다.** mode 에 따라 동작이 갈리는 자리가 하나 생겼다.

## 대안

**지금처럼 손으로만 가져오기** — 아무것도 저절로 움직이지 않는다. 잃을 것이 없을 때도 같은 두
걸음을 매번 걷는다. 이 결정이 없애려는 것이 그것이다.

**dirty 와 undo 이력이 모두 비어 있을 때만** — 이력도 잃지 않는다. 한 번 고치고 저장한 파일은
그 뒤로 자동 reload 가 걸리지 않아서, 켜 두고 쓰는 흐름에서는 거의 동작하지 않는 기능이 된다.

**이력을 남긴 채 내용만 갈아끼우기** — 자동으로 읽어도 `u` 가 살아 있다. `u` 가 엉뚱한 줄을
엉뚱한 내용으로 갈아끼운다. ADR-0016 이 이미 물린 길이다.

**포커스 복귀만 보기(주기 없이)** — 유휴 상태에서 아무것도 하지 않는다. 보고 있는 채로 바뀌는
파일을 영원히 못 잡는다. 그 자리를 남겨두면 "어떤 파일은 따라오고 어떤 파일은 안 온다" 가 된다.

**git tick(5 초) 에 얹기** — 타이머가 하나고 mode 의 공용 case 를 건드리지 않는다. `gitTickMsg`
가 git 만의 것이 아니게 되고, 두 결정의 주기 근거가 한 상수에 매달린다.

**mtime 으로 거르고 다를 때만 해시** — 유휴 비용이 `os.Stat` 하나로 줄어든다. buffer 에 상태가
늘고 판정 자리가 갈린다. `checkOutside` 안쪽만 바꾸면 되는 일이라 필요할 때 옮긴다.

**fsnotify 로 파일을 감시** — 바뀌는 순간에만 읽어서 가장 정확하고 싸다. goroutine 을 tea.Msg
로 잇는 다리와 직접 의존성이 하나 늘고, 편집기가 파일을 여닫을 때마다 감시 대상을 옮겨야 한다.
ADR-0031 이 "따로 볼 문제" 로 미뤄둔 자리이고, 주기 검사가 실제로 거슬릴 때 옮겨갈 곳이다.

**insert 에서도 갈아끼우기** — mode 마다 갈리지 않아서 규칙이 하나다. 치는 중에 줄이 밀리면
다음 글자가 다른 자리에 들어간다.

**`outsideCreated` 도 자동으로 읽기** — "바깥 내용을 가져온다" 는 같은 일이다. `:tabnew foo.go`
로 새로 쓰려고 열어둔 빈 buffer 가 조용히 남의 내용으로 채워진다.

## 이 ADR 이 정하지 않는 것

- 주기적 동작을 담을 공용 구조. tick 이 둘이 되어 mode 의 공용 case 가 한 번 더 늘었다.
  `docs/tasks.md` 에 따로 열려 있다
- 여러 tab 을 한 번에 검사하거나 가져오는 것. 검사하는 것은 활성 buffer 하나다 (ADR-0031)
- fsnotify 로 옮길지, mtime 앞잡이를 둘지. 주기 검사가 실제로 거슬릴 때 정한다
- 자동으로 읽는 것을 끄는 길. config 는 compile 된다는 값(ADR-0006) 이라 켜고 끄는 형태는
  키맵·설정 결정과 같이 본다
- 밖에서 바뀐 내용과 손에 든 것의 차이를 보여주는 것(diff)·세 방향 병합. ADR-0015 부터 미뤄둔
  그대로다
