# ADR-0018: `r` 은 인자를 받는 상태를 따로 두고, 그 한 키만 한글 되돌림을 건너뛴다

- 상태: 채택
- 날짜: 2026-08-13

## 맥락

normal mode 에서 글자 하나를 바꾸려면 `x` 로 지우고 `i` 로 들어가 치고 `Esc` 로 나와야 했다.
vim 에서 그 자리에 있는 키가 `r` 이다. `docs/tasks.md` 의 milestone 항목이었다.

`r` 은 지금까지의 키와 다르다. **뒤에 오는 키가 동작이 아니라 파일에 들어갈 글자다.**
ADR-0006 은 이런 키를 "인자를 한 글자 더 받는 키(`f` `t`)" 로 예고하고 `normalPending` 이
그 자리라고만 적어두었다. 실제로 넣어보니 접두 키와 같은 자리에 둘 수 없었다.

이유는 ADR-0008 이다. normal mode 는 한글 입력 상태에서 온 키를 두벌식 자리의 영문으로
되돌린다. `ㅁ` 이 `a` 다. 이 되돌림을 `r` 뒤의 키에도 적용하면 `한` 이 `g` `k` `s` 세 키로
풀려서, 첫 키가 `g` 로 들어가고 나머지 둘이 동작이 된다. **한글로 바꿔 넣는 것이 아예 불가능해진다.**

정할 것이 셋이었다.

1. **`r` 뒤의 키를 한글 되돌림에 넣을 것인가**
2. **글자가 아닌 키(방향키, `ctrl` 조합) 가 오면 무엇을 할 것인가**
3. **`r<Enter>` 와 숫자(`3rx`) 를 받을 것인가**

## 결정

**상태를 하나 더 둔다(`normalReplace`).** `r` 을 먹으면 이 상태가 되고, 다음 키 하나로 이름이
완성된다(`r x`). 접두 키(`normalPending`) 와 모양은 같지만 type 이 다르다. 그 다름이 곧
"다음 키는 동작이 아니라 글자다" 라는 표시다.

**그 한 키만 한글 되돌림을 건너뛴다.** `viewEditorNormal.Update` 가 상태를 보고, `normalReplace`
를 기다리는 중이면 `hangulKeys` 를 지나지 않고 키를 그대로 넘긴다. `r한` 이 `한` 을 넣는다.
건너뛰는 것은 딱 그 한 키뿐이고, 다음 키부터는 다시 되돌린다.

**글자가 아닌 키는 무른다.** `esc` `ctrl+c` 방향키 `ctrl+w` 는 아무 일도 하지 않고 normal 로
돌아온다. 잘못 누른 `r` 을 되돌리는 길이다. vim 과 같다.

**빈 칸과 tab 은 이름으로 온다.** 터미널이 주는 키 이름은 글자면 글자 그대로지만
(`a` `한` `?`) 빈 칸은 `space`, tab 은 `tab` 이다. 이 둘만 글자로 되돌려 받고, 나머지 이름은
글자가 아닌 키로 본다. 글자인지는 grapheme cluster 하나인지로 가른다. `up` 은 두 글자라 걸린다.

**숫자와 `r<Enter>` 는 vim 과 같다.** `3rx` 는 세 글자를 바꾸고, 줄에 남은 글자가 count 보다
적으면 **아무것도 바꾸지 않는다**. `r<Enter>` 는 커서 글자를 지우고 그 자리에서 줄을 가르며,
`3r<Enter>` 는 세 글자를 지우고 한 번 가른다. 커서는 마지막으로 바꾼 글자 위, 줄을 갈랐으면
새 줄의 첫 칸이다.

**바꿔 넣기 한 번이 되돌리기 한 구간이다.** 앞의 편집 구간을 먼저 닫고 시작한다. 지우기·
붙여넣기와 같다.

## 근거

### 상태를 따로 둔다

**되돌림을 건너뛰려면 밖에서 상태를 알아봐야 한다.** 한글 되돌림은 파서보다 앞, `Update` 에서
일어난다. 파서 안에 "지금은 글자를 기다린다" 는 표시가 없으면 `Update` 가 알 길이 없다.
`normalPending` 에 `r` 을 얹고 `prefix == "r"` 을 보게 할 수도 있지만, 그것은 이름 하나를
조건으로 쓰는 것이라 `f`/`t` 가 들어오면 그 조건이 목록이 된다. type 으로 나누면 늘어나는 것이
`case` 하나다.

**ADR-0006 의 방식 그대로다.** "필드를 하나씩 늘리는 대신 상태를 하나씩 늘린다" 가 그 ADR 의
결정이고, 여기가 세 번째 상태다(숫자, 접두 키, operator 다음).

### 한글 되돌림을 건너뛴다

**보이는 글자가 그대로 들어가는 것이 맞다.** `r` 뒤의 키는 파일 내용이다. 화면에 `한` 이
보이는데 `g` 가 들어가면 그것은 되돌림이 아니라 고장이다.

**치르는 값은 반대쪽이다.** 한글 입력 상태에서 영문 `r` 로 바꿔 넣으려면 입력기를 영문으로
돌려야 한다. `ㄱ` 을 누르면 `ㄱ` 이 들어간다. 이것은 ADR-0008 이 이미 "편집기 밖의 문제" 로
정리한 자리이고, 무엇보다 **눈에 보이는 대로 들어간다** 는 점에서 헷갈리지 않는다.

**insert mode 와 결이 같아진다.** insert mode 는 되돌림을 적용하지 않는다(ADR-0008). `r` 뒤의
한 키는 그 mode 에 한 글자만 들어갔다 나오는 것과 같으니, 같은 규칙을 받는 것이 자연스럽다.

### 글자가 아닌 키는 무른다

**접두 키가 짝 없는 조합을 버리는 것과 같다.** `g x` 가 아무 일도 하지 않듯 `r ↑` 도 그렇다.
`esc` 를 따로 다루지 않아도 같은 길로 무마된다.

### 줄이 짧으면 아무것도 바꾸지 않는다

**`3r` 은 세 글자를 바꾸겠다는 뜻이다.** 두 글자만 바꿔주면 친 것과 다른 일이 일어난다.
vim 도 그렇다. 지우기에서 "지울 것이 없으면 dirty 도 세우지 않는다" 와 같은 규칙이다.

## 결과

좋은 점

- `r` `3r` `r<Enter>` `r한` 이 동작한다. 한글 한 글자가 통째로 바뀌고 한글로도 바꿔 넣는다.
- 기대값을 vim 9.1 에서 쳐서 확인하고 표로 옮겼다(`replace_test.go`). tab·빈 칸으로 바꾸기,
  줄이 짧을 때, `3r<Enter>` 처럼 헷갈리는 자리가 전부 실제 vim 결과다.
- `f`/`t` 가 들어올 자리가 생겼다. 인자를 한 글자 받는 상태가 이미 있고, 그쪽은 되돌림을
  **건너뛰지 않는다** 는 점만 다르다. 찾는 글자는 동작의 일부라 두벌식 자리가 맞다.

감수하는 것

- **파서가 키 이름(string) 만 받아서 빈 칸과 tab 을 이름으로 되돌려야 한다.** 터미널이 주는
  `Text` 를 파서까지 들고 가면 없을 일인데, 그러면 상태 기계 전체가 문자열이 아닌 type 을 받게 된다.
  지금은 이름 두 개를 되돌리는 것으로 끝난다.
- **한글 입력 상태에서 영문 한 글자로 바꾸려면 입력기를 돌려야 한다.** 위에 적은 값이다.
- **`R`(계속 바꿔 넣는 mode) 은 없다.** `r` 을 여러 번 치거나 `3r` 을 쓴다.

## 대안

- **`normalPending` 을 그대로 쓰기**
	- 상태를 늘리지 않는다.
	- `Update` 가 `prefix == "r"` 을 보고 되돌림을 건너뛰어야 하는데, 인자를 받는 키가 늘 때마다
	  그 조건이 같이 늘어난다.
	- 접두 키와 인자를 받는 키는 "다음 키를 무엇으로 보는가" 가 정반대라 한 type 에 담을 것이
	  아니다.
- **insert mode 를 한 글자만 열기**
	- `r` 이 mode 를 바꾸고 한 글자를 받으면 되돌림·글자 판정·결합 문자 처리를 insert mode 의
	  것으로 그대로 쓴다.
	- mode 가 "한 글자만 받고 나가는" 예외를 갖게 되고, 그 안에서 방향키·`Esc` 를 다시
	  갈라야 한다. 얻는 것보다 늘어나는 것이 많다.
- **`Text` 를 파서까지 넘기기**
	- `press(key string)` 을 `press(key tea.KeyPressMsg)` 로 바꾼다. 빈 칸과 tab 을 이름으로
	  되돌리는 자리가 사라지고, 한글 되돌림도 파서 안에서 정할 수 있다.
	- 상태 기계가 bubbletea type 에 묶이고 테스트가 무거워진다.
	- `config 는 compile 됨` 의 형태를 정할 때 같이 본다(ADR-0006 의 대안과 같은 자리다).

## 이 ADR 이 정하지 않는 것

- `R`(바꿔 넣기 mode)
- `f` `t` `;` `,`(줄 안에서 글자 찾기) 와 그 인자에 한글 되돌림을 적용할지
- `.`(되풀이)
- visual mode 에서 고른 범위를 한 글자로 덮는 것
