# ADR-0055 json 계열과 yaml 강조, 그리고 키 갈래

## 맥락

강조하는 언어가 아홉이었는데 설정 파일이 하나도 없었다. 이 저장소만 봐도 `.github/workflows`,
`go.mod` 를 뺀 도구 설정이 전부 json·yaml 이고, 그 파일들은 열면 통째로 흰 글자였다.

넣을 것은 셋이다 — json, hjson, yaml.

정해야 하는 것들:

1. 셋을 lexer 몇 개로 다루는가. hjson 은 json 의 상위집합이고 `.jsonc`·`.json5` 가 그 사이에 있다
2. `key: value` 의 키를 어떤 갈래로 내보내는가. 지금 표에 「키」가 없다
3. 언어별 칸 셋(state·indent·outline) 을 어디까지 채우는가

## 결정

### 1. json 계열은 한 lexer, yaml 은 따로

`.json`·`.jsonc`·`.json5`·`.hjson` 이 `jsonNormal` 하나를 나눠 쓴다. 넷의 차이는 **허용하는
것**뿐이고 모양은 같다 — jsonc 가 주석을, json5 가 따옴표 없는 키와 홑따옴표를, hjson 이 거기에
`#` 주석과 `'''` 여러 줄 문자열을 더한다. 나누면 거의 같은 lexer 가 넷이 되고, 넷 사이의 경계를
**색으로** 지키게 된다.

**강조는 검사가 아니다.** 그래서 `.json` 에 적은 주석도 주석 색이 입는다. 문법이 틀렸다는 것은
그 파일을 읽는 프로그램이 말할 일이고, 편집기가 색을 빼서 알리려 들면 「색이 없는 것」이
두 가지 뜻(모르는 언어 / 틀린 문법) 을 갖는다.

yaml 은 lexer 를 따로 둔다. 갈래는 같아도(키와 값) 모양이 겹치지 않는다 — 구조가 괄호가 아니라
들여쓰기이고, 따옴표 없는 값이 예외가 아니라 보통이고, anchor·tag·블록 스칼라가 있다.

**따옴표 없는 값에는 색을 넣지 않는다.** json 의 hjson 쪽과 yaml 양쪽에서 그렇다. 어디서
끝나는지가 줄 끝이라 색을 입히면 값이 있는 줄마다 뒤쪽이 통째로 물들고, 그것이 정말 문자열인지는
그 파일을 읽는 프로그램이 정한다. 대신 **뜻이 정해진 것만** 골라 낸다 — 숫자와 `true`·`null`
같은 낱말이고, 그것도 **값 전체가 그것일 때만**이다. `answer: no problem` 의 `no` 와
`date: 2026-08-23` 의 `2026` 이 색을 받지 않는 것이 이 규칙이다.

### 2. 키는 새 갈래(KindKey) 다. html·css 의 이름도 여기로 옮긴다

설정 파일은 거의 전부가 키와 값이라, 키가 값과 같은 색이면 화면에 구조가 남지 않는다.
그래서 갈래를 하나 늘렸다.

**있는 갈래를 쓰지 않은 이유는 KindVariable 의 뜻이 갈라지기 때문이다.** 그 갈래에는 두 가지가
섞여 있었다 — `$(VAR)`·`var(--x)` 처럼 **값을 가리키는** 자리와, html 속성 이름·css 사용자 속성
선언처럼 **값에 이름을 붙이는** 자리다. json·yaml 의 키를 여기 얹으면 섞임이 굳는다.

그래서 갈라면서 옛 자리도 같이 옮겼다.

| 자리 | 전 | 후 |
| --- | --- | --- |
| html 속성 이름 (`href="x"`) | KindVariable | **KindKey** |
| css 사용자 속성 선언 (`--x: red`) | KindVariable | **KindKey** |
| css 사용자 속성 참조 (`var(--x)`) | KindVariable | KindVariable |
| make·docker 의 `$(VAR)`·`${VAR}` | KindVariable | KindVariable |
| yaml 의 anchor·alias (`&a` `*a`) | — | KindVariable |
| json·yaml 의 키 | — | **KindKey** |

css 는 선언과 참조가 같은 글자(`--x`) 인데 갈래가 다르다. lexer 가 이미 `:` 뒤인지를 들고 있어서
(`cssBlock.inValue`) 자리로 가른다 — `#fff` 와 `#id` 를 가르던 것과 같은 손이다.

css 의 표준 속성(`color:`) 은 키로 옮기지 않았다. 그것은 css 가 아는 낱말이라 예약어에 가깝다.
**사람이 지은 이름만** 키다.

**색은 지금 값 참조와 같은 청록(79) 이다.** 「같이 나오지 않는 갈래만 색을 나눠 쓴다」는 규칙
(ADR-0041) 의 예외다 — css 의 `--x: red` 와 `var(--x)`, yaml 의 키와 anchor 는 한 화면에 같이
나온다. 그래도 나누지 않은 것은 **자리가 이미 갈라 주기** 때문이다: 키는 줄 앞에 서고 참조는 값
자리에 선다. 갈래를 나눠 둔 값은 여기 있다 — 색을 나눠야 할 날에 `styleSyntax` 의 한 줄만 고친다.

### 3. 칸 셋을 다 채운다

- **json 의 들여쓰기는 자기 것을 쓴다.** `braceIndent`(go·js·css) 를 나눠 쓰지 않았다. 그것은
  줄 끝의 `:` 를 switch 이름표로도 보는데(`case 1:`) json 에는 switch 가 없어서, `case` 라는
  키 하나가 이름표로 잡혀 그 아래가 들여쓰인다. **모양이 같아 보이는 것과 규칙이 같은 것은 다르다**
- **yaml 은 여는 표시가 없는데도 들여쓰기 규칙이 있다.** 구조가 곧 들여쓰기라 값 없는
  키(`services:`) 아래가 그 키의 내용이다. 블록 스칼라 표시(`|` `>-` `|2`) 와 목록 표시만 있는
  줄(`-`) 도 같다
- **yaml 은 `=` 로 다시 들여쓰지 않는다**(`Reindents() == false`). markdown 과 같은 까닭이다 —
  들여쓰기가 곧 뜻이라 규칙만으로 되짚으면 중첩된 map 이 평평해지고 **파일의 뜻이 바뀐다**.
  이 값이 거짓인 언어가 markdown 하나에서 둘로 늘었다
- **뼈대는 둘 다 `blockOutline`** 이다. 「다음 줄이 들어간다」가 곧 「아래를 거느린다」라서
  들여쓰기 규칙에 그대로 묻는다(ADR-0047). 깊은 설정 파일에서 지금 어느 키 안인지가 화면 위에
  남는 것이 이 언어들에서 가장 쓸모 있는 자리다

## 결과

- 강조하는 언어가 아홉에서 열하나가 되었다. 확장자는 여섯이 늘었다 —
  `.json`·`.jsonc`·`.json5`·`.hjson`·`.yaml`·`.yml`
- markdown 코드펜스도 같이 된다. 표의 한 줄이 alias 까지 들고 있어서(ADR-0040) ```` ```yaml ````
  블록이 저절로 색을 받는다
- 갈래가 열둘에서 열셋이 되었고 색은 아홉 그대로다
- **트리 색은 건드리지 않았다.** `.json`·`.yaml` 은 sidebar 에서 여전히 기본색이다. 그 표는
  묶음이 더 굵고 일부러 다르다(`detect.go` 의 설명) — 언어를 더할 때마다 트리 색이 조용히 바뀌지
  않게 두 표를 떼어 놓은 것이라, 트리 쪽은 팔레트를 정하는 건과 같이 본다(docs/tasks.md)
- yaml 의 따옴표는 줄을 넘을 수 있는데 문맥을 두지 않았다. 흔하지 않고, 넘어간 다음 줄은
  따옴표 없는 값과 같이 색이 없어서 **틀리지 않고 덜 보인다**. 거슬리면 그때 문맥을 하나 더 둔다
