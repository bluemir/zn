# ADR-0033: `c` 는 `d` 의 범위 계산을 쓰되 `cw` 와 `cc` 두 자리에서 vim 의 예외를 따른다

- 상태: 채택
- 날짜: 2026-08-16

## 맥락

`d`(ADR-0013) 와 `y`(ADR-0017) 가 들어오면서 operator 자리가 만들어졌다. 파서에
`normalOperator` 가 있고 범위 계산은 `rangeByMotion` 하나이며, `y` 는 그 위에 열 줄쯤을
얹은 것이 전부였다. `c` 는 v1.0.0 milestone 에 남은 마지막 항목이었다.

`c` 는 "지우고 insert mode 로 들어간다" 로 한 줄 요약되지만, 그 한 줄이 `d` 와 갈리는 자리가
넷이다.

1. **`cw` 가 `dw` 와 다르다.** vim 은 `cw` 를 `ce` 처럼 처리해서 단어 뒤 공백을 남긴다
2. **`cc` 가 `dd` 와 다르다.** 줄을 없애지 않고 비운다. 남은 줄의 들여쓰기를 어떻게 할 것인가
3. **되돌리기 구간이 지우기 하나로 끝나지 않는다.** 지운 것과 이어 친 글자가 한 동작이다
4. **커서가 줄 끝 다음 칸에 서야 한다.** `c$` 는 그 자리에서 이어 치는데 normal mode 에는 없는 자리다

## 결정

**범위 계산은 `d`·`y` 와 같이 쓴다.** `changeByMotion` 이 `rangeByMotion` 을 부르고,
줄 단위면 `changeLines`, 글자 단위면 `deleteText` 다. 파서는 `case "d", "y":` 에 `"c"` 를
한 글자 더한 것이 전부라 `cw` `c3w` `3cc` `cgg` `c$` 가 그대로 딸려 온다.

**`cw` 와 `cW` 는 커서가 공백 아닌 글자 위일 때만 `ce`·`cE` 다.** 단어 뒤 공백을 남긴다.
첫 걸음에만 예외를 두어서, 이미 단어의 마지막 글자 위면 그 글자 하나가 전부다.
`c2w` 의 둘째 걸음부터는 그냥 `e` 라 다음 단어의 끝까지 간다.

**커서가 공백 위면 예외가 아니다.** 바꿀 것이 그 공백이므로 `dw` 와 같이 건너뛴다.

**빈 줄의 `cw` 는 아무것도 바꾸지 않고 insert 로 간다.** `dw` 는 그 줄을 지우고 다음 줄을
끌어올리는데(ADR-0013), 여기서는 따르지 않는다.

**`cc` 는 줄을 없애지 않고 첫 줄의 들여쓰기만 남긴 채 비운다.** `3cc` 는 세 줄이 들여쓴 한 줄이
된다. `cj` `ck` `cG` `cgg` 같은 줄 단위 motion 도 같다.

**지운 것과 이어 친 글자가 한 번의 `u` 로 함께 돌아간다.** 지우기가 닫은 되돌리기 구간을
`resumeEdit` 로 다시 열어서 뒤따르는 타이핑이 같은 구간에 들어간다.

**모르는 motion 이면 mode 도 바뀌지 않는다.** `cq` 는 아무 일도 하지 않는다.

## 근거

### `cw` 예외

**`d` 와 `c` 는 뒤에 오는 일이 다르다.** `dw` 는 지우고 끝이라 공백까지 걷어야 앞뒤가 붙는다.
`cw` 는 그 자리에 다른 단어를 넣으려는 것이라 뒷 공백이 남아 있어야 한다. 공백까지 지우면
`foo    bar` 에서 단어 하나를 갈아 끼울 때마다 공백 네 개를 다시 쳐야 한다.

**ADR-0013 의 "범위는 이동을 실제로 실행해서 얻는다" 를 어기지 않는다.** 예외는 어느 이동을
실행할지를 고르는 자리에 있고, 고른 뒤에는 그 이동을 그대로 실행한다. `cw` 가 `e` 를 실행할 뿐
`w` 의 결과를 손으로 깎지 않는다.

**첫 걸음에만 예외를 두는 것은 vim 을 그대로 옮긴 것이다.** vim 의 `end_word` 가 `stop` 인자를
첫 번째 되풀이에만 켠다. 이미 단어 끝에 선 `cw` 가 다음 단어까지 먹으면, 단어의 마지막 글자
하나를 고치려던 손이 두 단어를 잃는다.

**공백 위에서 예외를 끄는 것도 vim 과 같다.** vim 은 `gchar_cursor()` 가 공백이 아닐 때만
예외를 켠다. 공백 위의 `cw` 는 그 공백을 바꾸려는 것이라 단어 끝까지 갈 이유가 없다.

**빈 줄만 vim 의 코드가 아니라 vim 의 결과를 따랐다.** vim 은 exclusive 보정 규칙
(`:h exclusive`) 으로 이 자리를 줄 단위 바꾸기로 돌려서 줄이 합쳐지지 않는다. 그 규칙 전체를
옮기는 것은 `docs/tasks.md` 에 따로 열린 건이라, 지금은 빈 줄 하나만 짚어서 같은 결과를 낸다.
빈 줄에 글을 쓰려고 친 `cw` 에 다음 줄이 딸려 올라오는 것은 사고다.

### `cc` 의 들여쓰기

**`cc` 는 줄을 옮기는 것이 아니라 다시 쓰는 것이다.** 그 줄이 있던 자리와 깊이는 그대로고
내용만 바뀐다. 들여쓰기를 지우면 들여쓴 코드에서 `cc` 를 칠 때마다 tab 을 다시 친다.

**`o` `O` 와 갈리는 것이 이상하지 않다.** `o` 는 없던 줄을 새로 만드는 것이라 들여쓰기를
어디서 가져올지가 곧 autoindent 결정이고 아직 열려 있다. `cc` 는 있던 줄을 비우는 것이라
가져올 곳을 정할 필요가 없다 — 그 줄에 이미 붙어 있다.

**여러 줄이 한 줄로 합쳐지는 것도 vim 과 같다.** `3cc` 로 세 줄을 다시 쓰겠다고 했으면 결과는
새로 치는 것이고, 빈 줄을 세 개 남겨두면 지우는 손이 한 번 더 든다.

### 되돌리기를 하나로

**`c` 는 한 동작이다.** vim 에서 `cwfoo<Esc>u` 는 원래 단어로 돌아온다. 지우기와 타이핑이
각자의 구간이면 `u` 를 두 번 쳐야 하고, 한 번만 친 사람은 단어가 사라진 상태에 남는다.

**`resumeEdit` 는 구간을 새로 만들지 않고 방금 닫은 것을 다시 연다.** `beginEdit` 은 열린
구간이 있으면 거기에 합치고 범위가 모자라면 넓히도록 이미 되어 있어서(edit.go), 여는 것
하나만 있으면 나머지는 그대로 돈다. 지우기 쪽에 "구간을 닫지 말라" 는 flag 를 넣는 길도
있었지만, 그러면 `deleteText` 의 서명이 부르는 쪽 사정을 받게 된다.

### 커서와 mode

**mode 를 지운 뒤에 바꾼다.** `a` `o` `O` 는 mode 를 먼저 바꾸는데(줄 끝 다음 칸으로 가야
해서) `c` 는 반대다 — 지우다 실패할 수 있고, 실패했는데 insert 에 들어가 있으면 무를 길이 없다.
대신 `deleteText` 가 normal mode 규칙으로 당겨 둔 커서를 지운 자리로 되돌린다.
`c$` 가 줄 끝 다음 칸에서 시작하는 것이 이것이다.

**모르는 motion 에서 mode 를 바꾸지 않는 것이 `d` 보다 중요하다.** `dq` 는 아무 일도 없지만,
`cq` 가 insert 로 들어가면 이어서 친 글자가 파일에 들어간다. 무엇이 잘못됐는지 알아채기
전에 이미 편집된 뒤다.

## 결과

좋은 점

- `d` 를 쓰던 손이 그대로 먹는다. `cw` `ciw` 를 뺀 `c$` `cG` `c3w` `3cc` 가 첫날부터 있다
- 단어 하나를 갈아 끼우는 가장 흔한 편집이 `cw` 세 타로 끝난다
- `u` 한 번이 `c` 한 번을 되돌린다. vim 과 같다
- 새 코드가 `change.go` 한 파일이고 범위·register·되돌리기는 있던 것을 그대로 쓴다

감수하는 것

- **`rangeByMotion` 을 그냥 부르지 않는 operator 가 처음 생겼다.** `changeRange` 가 그 앞에
  한 겹이다. motion 마다 operator 별 예외가 늘어나면 이 자리가 표가 되어야 한다
- **exclusive 보정 규칙은 여전히 없다.** 빈 줄의 `cw` 만 짚어서 막았으므로, 빈 줄이 낀
  `c2w` 처럼 흔치 않은 자리에서 vim 과 다를 수 있다. `dw` 가 진 빚과 같은 빚이다
- **`cc` 가 들여쓰기를 남기는데 `o` 는 이어받지 않는다.** 둘 다 "새로 칠 줄" 이라 손에는 같은
  일로 느껴진다. autoindent 를 정할 때 `o` 쪽이 이쪽으로 맞춰질 자리다
- **`resumeEdit` 로 구간을 다시 여는 길이 생겼다.** 지금은 `c` 만 쓰지만, 아무 데서나 부르면
  남의 편집이 한 구간에 섞인다

## 대안

**`cw` 를 `dw` 와 같이 두기** — 예외가 없어서 규칙이 하나다. 단어를 갈아 끼울 때마다 공백을
다시 쳐야 하고, vim 을 쓰던 손과 어긋나는 자리가 가장 자주 밟히는 키에 생긴다.

**`cc` 가 들여쓰기를 지우기** — `dd` 와 규칙이 같아진다. 들여쓴 코드에서 `cc` 를 칠 때마다
tab 을 다시 치게 되고, 그것은 이 편집기가 Go 소스를 쓰는 자리에서 매번 걸린다.

**`c` 를 `d` + `i` 두 동작으로 두기** — 코드가 늘지 않는다. 되돌리기가 둘로 갈리고,
`c$` 처럼 커서가 줄 끝 다음 칸에 서야 하는 자리를 `i` 가 잡아주지 못한다.

**exclusive 보정 규칙을 이번에 옮기기** — 빈 줄뿐 아니라 `c2w` 같은 자리까지 vim 과 맞는다.
`d` 와 `y` 의 결과가 같이 바뀌므로 그것들의 테스트를 전부 다시 봐야 하고, `c` 를 넣는
변경에 얹을 크기가 아니다.

## 이 ADR 이 정하지 않는 것

- `C`(= `c$`) `s`(= `cl`) `S`(= `cc`) 같은 짧은 이름. `D` `X` 와 같이 정한다
- `ciw` `ci"` 같은 text object. operator 뒤에 motion 이 아닌 것이 오는 첫 자리다
- autoindent. `o` `O` 가 들여쓰기를 이어받을지와 `cc` 가 그것과 같은 규칙을 쓸지
- `.`(되풀이). `c` 는 지우기와 타이핑이 한 동작이라 기록할 것이 두 가지다
- exclusive 보정 규칙 전체. 빈 줄의 `cw` 만 짚었다
