# ADR-0057 파일은 묻지 않고 지우고 디렉터리만 묻는다

- 상태: 채택
- 날짜: 2026-08-23

## 맥락

ADR-0054 는 `md` 를 파일이든 디렉터리든 한 번 묻게 했다. 근거는 이것이었다.

> 지우기는 편집기 안에서 되돌릴 수 없는 유일한 동작이다. undo 가 닿지 않고 `:w` 로도 돌아오지 않으므로 키 두 번으로 끝나서는 안 된다.

**쓰다 보니 마찰이 근거보다 컸다.** 지우는 것의 거의 전부가 파일이고, 그때마다 `y` 가 붙는다. 파일을 여러 개 치우는 동안 그 `y` 가 되풀이되면 손이 먼저 나가서, 정작 물음을 읽지 않게 된다. 확인이 확인 노릇을 못 하는 경우다.

## 결정

**파일은 `md` 두 키로 곧바로 지운다. 디렉터리만 묻는다.**

## 근거

### 파일과 디렉터리는 잃는 것이 다르다

파일은 트리의 그 행이 이름을 다 보여준다. 무엇을 지우는지 화면에 이미 있으므로 물음이 더해 주는 정보가 없다.

**디렉터리는 다르다.** 접혀 있으면 트리가 이름 한 줄만 보여주는데 `RemoveAll` 은 그 아래를 통째로 지운다. 화면에 없는 것이 사라지는 유일한 곳이라 여기만 남긴다. 문구도 「안의 것까지」를 이름보다 앞에 둔다. 이름만 보고 `y` 를 누르는 것을 막는 것이 이 물음이 남은 까닭이다.

### 대신 알림이 무엇이 사라졌는지 말한다

묻지 않으므로 「지웠습니다: `<이름>`」 이 무엇을 잃었는지 아는 유일한 길이 된다. 지나간 것은 `:messages` 에 남아서(ADR-0053) 잘못 지운 것을 나중에도 되짚을 수 있다.

### 걸러내는 셋은 그대로다

물음만 뗐고 `viewSidebar.deleteFile` 의 가드는 건드리지 않았다.

- 뿌리는 지우지 않는다
- **tab 에 열려 있는 파일은 지우지 않는다.** 이것이 편집 중인 파일을 지키는 곳이다. 보고 있던 파일이 `md` 하나로 사라지는 일은 이 결정 뒤에도 없다
- 읽는 중인 것은 지우지 않는다

### 무엇을 받아들였나

**잘못 누른 `md` 는 그대로 실행되고 되돌릴 길이 없다.** 트리 커서는 `j`/`k` 로 움직이고 `m` 은 트리 안에서만 접두 키라, 어느 행에 있는지 착각한 채 치면 그 파일이 사라진다. 확인이 그 착각을 잡던 유일한 것이었다.

이것을 치르기로 했다. 되살릴 수 있게 만들어 근거 자체를 없애는 길(지운 내용을 들고 있다가 `u` 로 되살리기) 과 git 이 아는 깨끗한 파일만 묻지 않는 길도 재봤지만, 앞은 「어디에 얼마나 들지」가 새 결정이고 뒤는 파일별 git 상태를 새로 재야 하는데다 「왜 이건 묻고 저건 안 묻나」가 손에 안 잡힌다. 둘 다 이 마찰 하나를 없애자고 지금 시작할 일은 아니었다.

되살리는 쪽은 `docs/tasks.md` 에 남겼다. 그것이 들어오면 디렉터리의 물음도 같이 본다.

## 관련

- ADR-0054 트리에서 파일 만들고 지우고 이름 바꾸기: §4 의 「확인 한 번」을 이것이 대신한다
- ADR-0053 알림을 기록하고 `:messages` 로 본다: 지운 기록이 그리로 남는다
- ADR-0016 되돌릴 수 없는 일 앞에서 묻기
