# ADR-0041: 본문 색은 어두운 배경에 맞춰 계층을 만든다

- 상태: 채택
- 날짜: 2026-08-21

## 맥락

ADR-0039 로 본문에 색이 들어올 때 팔레트를 이렇게 골랐다.

> 밝은 테마와 어두운 테마 양쪽에서 읽히도록 밝기를 가운데로 모았다.

그 값이 쓰다 보니 드러났다. 어두운 배경(`#1e1e1e`) 기준으로 재보니 본문 색 **전부가
3.4~4.7:1 한 띠에 뭉쳐** 있었다.

| 갈래 | 값 | `#1e1e1e` 대비 |
|---|---|---|
| keyword·강조 | 97 | **3.4:1** |
| 문자열 | 130 | **3.5:1** |
| 숫자 | 131 | 3.7:1 |
| type | 30 | 3.8:1 |
| 주석 | 65 | 4.1:1 |
| 부르는 이름·값 참조 | 67·100 | 4.4:1 |
| 값 낱말·링크 | 168·33 | 4.7:1 |

**계층이 없다.** 그리고 하필 가장 어두운 둘이 keyword 와 문자열이라, Go 의 `import` 문이
통째로 안 보였다 — 그 줄은 keyword 와 경로 문자열뿐이다. markdown 의 `**굵게**` 와 코드 스팬도
같은 이유로 묻혔다. 제목은 그 띠 안에서 굵게 해봐도 본문보다 앞으로 나오지 않았다.

양쪽을 노리다가 **한쪽에서도 안 되는 값**이 되었다.

## 결정

**어두운 배경 하나에 맞춘다.** `#1e1e1e` 기준으로 본문 색 전부를 6.8:1 이상으로 올렸다.

값을 고르는 규칙을 셋 두었다.

### 주석이 가장 흐리다

6.8:1 로 이 표에서 제일 낮다. 일부러 그렇다 — 주석은 물러나 있어야 코드를 읽는 데 끼어들지
않는다. 「가장 낮게, 그래도 읽히게」가 주석의 자리다.

회색으로 두지 않았다. 본문 영역에서 회색은 이미 두 번 쓰인다(공백 마커 240, 상대 줄번호 244).
회색 주석은 「내용이 아님」, 즉 줄번호 칸이 말하는 것과 같은 말이 된다.

### 같이 나오는 갈래끼리 색상이 25 도 이상 갈린다

언어별로 한 화면에 나오는 조합을 전부 재서 맞췄다 — go/js/py, css, html, make/docker,
markdown 다섯 묶음이다.

한 짝만 20 도로 남았다. 주석(108) 과 문자열(113) 인데 밝기가 6.8 대 9.5 로 갈리고 채도도
달라서 그대로 두었다 — 흐린 초록과 선명한 초록이다.

### 같이 나오지 않는 갈래는 색을 나눠 쓴다

강조·굵게는 keyword 와, 링크는 부르는 이름과 같은 색이다. markdown 에 keyword·부르는 이름이
없고 코드에 제목·강조·링크가 없어서 한 화면에서 만나지 않는다.

그래서 **갈래 열둘이 색 아홉**으로 된다. ADR-0040 이 「갈래를 늘리는 것이 팔레트를 반드시
늘리지 않는다」고 적어 둔 성질이 그대로 산다.

링크가 하늘 계열을 쓰지 못하는 것이 이 규칙으로 풀렸다. 제목이 거기 있고 markdown 에서 늘
같이 나오는데, 재보니 하늘 쪽 후보는 제목과 색상차가 5~20 도라 전부 섞였다. 부르는 이름의
연한 파랑(111) 이 제목과 30.6 도로 유일하게 떨어지면서 밝기도 살았다.

### `**굵게**` 를 굵게 그린다

`KindStrong` 을 갈래로 더했다. `*foo*` 와 `**foo**` 는 markdown 에서 뜻이 다른데 한 갈래로
묶여 있어서 **굵어야 할 것이 기울어져** 그려졌다. 쓴 사람이 고른 표시를 화면이 따라간다.

색은 강조와 같고 속성만 다르다(기울임 대 굵기) — 위의 나눠 쓰기 규칙 그대로다.

## 근거

**재서 정했다.** 색 이름과 「밝아 보인다」로는 3.4:1 과 6.8:1 을 가릴 수 없었다. 대비율과
색상차를 계산해서 골랐고, 같이 나오는 조합을 언어별로 전부 돌려 25 도 규칙을 확인했다.

**색표 한 곳만 바뀐다.** 갈래→style 표가 `core` 에 모여 있어서(ADR-0039) lexer 도 그리는
코드도 손대지 않았다. `KindStrong` 이 는 것만 lexer 쪽 변화다.

## 결과

| 갈래 | 값 | `#1e1e1e` |
|---|---|---|
| 주석 | 108 흐린 초록 | 6.8:1 |
| keyword·강조·굵게 | 177 자주 | 7.0:1 |
| 값 낱말 | 210 연어 | 7.2:1 |
| 부르는 이름·링크 | 111 연한 파랑 | 7.6:1 |
| 숫자 | 215 주황 | 9.2:1 |
| 값 참조 | 79 청록 | 9.4:1 |
| 문자열 | 113 초록 | 9.5:1 |
| 제목 | 45 밝은 하늘 + 굵기 | 9.7:1 |
| type | 185 노랑 | 10.9:1 |

감수하는 것

- **밝은 배경에서는 1.5~2.5:1 이라 거의 안 보인다.** 양쪽을 노리는 것을 포기한 것이 이
  결정이고, 그 대가가 이것이다. 밝은 배경으로 옮기면 이 표를 갈아야 한다.
- **테마별 팔레트를 두지 않는다.** 배경색을 알아내려면 터미널에 물어야 하고(OSC 11), 답하지
  않는 터미널이 있어서 「모를 때 무엇을 쓰나」가 다시 남는다. 값을 두 벌 들고 다니는 것도
  「config 는 compile 됨」과 어긋난다. `docs/tasks.md` 의 「밝은·어두운 테마별 팔레트」는
  이 결정으로 닫는다.
- **공백 마커(240, 2.3:1) 와 상대 줄번호(244, 4.2:1) 는 그대로다.** 둘 다 일부러 물러나 있는
  것이고 본문 색이 아니다. 마커가 이제 본문보다 훨씬 흐려졌는데, 그것이 ADR-0020 의 의도다.

## 대안

**밝기만 한 단계씩 올리기** — 색상 배치를 그대로 두고 값만 밝게 바꾼다. 가장 적게 건드린다.
고르지 않은 이유는 그렇게 하면 계열이 겹치는 것이 드러나서다 — 제목·링크·type 이 모두 푸른
쪽이었고, 밝게 올릴수록 셋이 가까워진다. 배치를 다시 짜야 했다.

**테마를 물어보고 두 벌 두기** — 양쪽에서 다 잘 보인다. OSC 11 에 답하지 않는 터미널이 있고,
값이 두 벌이면 「어느 쪽이 맞는 색인가」를 물을 자리가 늘 남는다. ADR-0028 이 ambiguous 폭을
DSR 로 재면서 「재지 못하면 물러선다」를 두어야 했던 것과 같은 비용이다.

**터미널의 ANSI 16 색만 쓰기** — 테마를 그대로 따라가니 이 문제가 사라진다. 고르지 않은 이유는
갈래가 열둘인데 쓸 수 있는 색이 그보다 적고, 이미 sidebar·검색·줄번호가 256색 고정값을 쓰고
있어서 본문만 다른 방식이 되기 때문이다(ADR-0005, ADR-0007, ADR-0010).

## 이 ADR 이 정하지 않는 것

- **검색·선택·트리·팔레트의 색.** 본문 색만 다시 잡았다.
- **공백 마커와 줄번호의 대비.**
- **`KindStrong` 밖의 갈래를 더 가르는 것**(md 의 취소선, 인용 깊이 등).
