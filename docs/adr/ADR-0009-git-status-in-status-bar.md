# ADR-0009: git 정보는 cwd 기준으로 열 때·저장할 때만 읽어 statusBar 오른쪽에 찍는다

- 상태: 채택 (읽는 시점은 ADR-0030·ADR-0043 이 바꿨고, 읽는 방법은 ADR-0042 가 바꿨다. 프로세스가 아니라 go-git 이다)
- 날짜: 2026-08-13

## 맥락

`docs/tasks.md` 에 "statusbar 우측에 git branch, commit id 그리고 dirty 여부를 표시" 가 열려 있었다. 지금 statusBar 위 줄에는 mode 와 파일 경로뿐이고, 어느 branch 에서 고치고 있는지는 편집기를 나가서 `git status` 를 쳐야 알 수 있다.

문제는 표시할 자리가 아니라 **언제 읽느냐** 다. sidebar 의 gitignore 표시(ADR-0005) 처럼 규칙을 직접 구현하지 않고 `git` 명령에게 묻기로 하면, 그 호출은 외부 프로세스 fork 다. 화면은 키를 칠 때마다 통째로 다시 그려지므로, 렌더 안에서 읽으면 `j` 한 번에 프로세스가 세 개 뜬다.

## 결정

**statusBar 위 줄 오른쪽 끝에 `master(a1b2c3d*)` 형태로 찍는다.** `*` 가 dirty 다. detached HEAD 는 가리킬 branch 가 없으므로 괄호 없이 해시만 찍는다(`a1b2c3d*`). 저장소가 아니거나 commit 이 하나도 없으면 아무것도 찍지 않는다.

**dirty 는 `git status --porcelain` 이 한 줄이라도 내면 참이다.** untracked 파일도 센다.

**cwd 저장소 하나만 본다.** 활성 tab 의 파일이 어디 있든 표시는 바뀌지 않는다.

**editor 의 필드로 들고 있다가 몇 시점에만 다시 읽는다.** 편집기를 열 때, 파일을 열 때(`openTab`), 저장할 때(`:w`, `:wq`, `:x`), `ctrl+z` 로 내려갔다 올라올 때(ADR-0023 에서 더했다). 렌더는 들고 있는 값을 그리기만 한다.

**붙일 칸이 없으면 넣지 않는다.** mode 와 파일 이름을 밀어내지 않는다. showcmd 와 같은 규칙이다.

## 근거

### 읽는 시점

**렌더마다 읽는 것은 못 쓴다.** 프로세스 세 개 × 키 입력마다다. `git status` 는 저장소가 커지면 work tree 전체를 훑으므로 큰 저장소에서는 커서 이동이 눈에 띄게 끊긴다. 편집기가 느려지는 것과 맞바꿀 만한 표시가 아니다. branch 는 몇 시간에 한 번 바뀐다.

**주기적 갱신(`tea.Tick`) 은 상태 하나와 타이머 하나를 늘린다.** 바깥 변경까지 따라오는 것이 장점이지만, 그 대가로 편집만 하고 있어도 계속 프로세스가 뜬다. 그만한 정확도가 필요하지 않다.

**고른 시점이 실제로 값이 바뀌는 때다.** 저장은 dirty 를 바꾸는 유일한 편집기 안의 동작이고, 파일을 여는 것은 바깥에서 `commit`/`checkout` 을 하고 돌아온 직후일 때가 많다. 파일 열기가 값을 바꾸지는 않지만, 편집기를 계속 띄워두고 쓰는 흐름에서 값을 새로 맞출 자연스러운 지점이다. 셸에서 올라오는 것은 그보다 더 확실하다. 바깥에서 무엇을 했는지 편집기가 아는 유일한 때다 (ADR-0023).

### cwd 기준

**sidebar 트리의 뿌리와 같은 기준이다.** 화면에 뿌리가 이미 보이고 있어서 무엇을 가리키는지 설명할 필요가 없다.

**tab 을 오갈 때 표시가 흔들리지 않는다.** 활성 파일 기준으로 하면 `gt` 마다 git 을 다시 불러야 하고(이 결정의 출발점을 스스로 깬다), tab 마다 branch 가 달라 보이는 화면은 "지금 어느 branch 에서 일하는 중인가" 라는 질문에 답하지 않는다.

### 형식

**`branch(commit*)` 는 무엇이 무엇인지 괄호로 갈린다.** 공백으로만 나누면 오른쪽 끝에서 파일 경로의 일부처럼 읽힌다. `*` 하나가 dirty 인 것은 tabline 의 `+`, statusBar 의 `[+]` 와 글자는 다르지만 같은 뜻이라 헷갈릴 여지가 있는데, 그쪽은 buffer 의 미저장 상태이고 이쪽은 저장소의 미commit 상태라 **다른 글자를 쓰는 편이 오히려 낫다**.

**detached HEAD 에 빈 괄호를 두지 않는다.** `(a1b2c3d)` 는 이름을 못 읽은 것처럼 보인다. 괄호가 없다는 것 자체가 붙어 있는 branch 가 없다는 표시다.

**untracked 를 dirty 에 넣는다.** `git status` 가 clean 이라고 부르는 기준과 같다. 기준이 두 가지면 "표시는 깨끗한데 `git status` 는 아니다" 를 매번 설명해야 한다.

### 오른쪽 끝

**왼쪽은 이미 mode 와 파일 경로가 쓰고 있고 그쪽이 자주 길어진다.** 반대편에 두면 서로 밀지 않는다. 아래 줄 오른쪽 끝은 showcmd 자리다(치는 동안 나타났다 사라지는 것이라 고정 표시와 겹치면 안 된다).

## 결과

좋은 점

- 편집기를 나가지 않고 branch 와 dirty 여부를 본다. 다른 branch 인 줄 모르고 고치는 일이 준다.
- 프로세스는 열 때·저장할 때·셸에서 올라올 때만 뜬다. 키 입력 경로에는 git 이 없다.
- 저장소가 아니어도, git 이 없어도 그냥 표시가 없을 뿐이다. sidebar 의 gitignore 표시와 같은 태도다.

감수하는 것

- **바깥에서 commit·checkout 하면 다음에 파일을 열거나 저장할 때까지 낡은 값이 보인다.** 이 결정이 고른 대가다. `ctrl+z` 로 내려갔다 올라오는 길은 ADR-0023 이 메웠고, 편집기를 띄워둔 채 다른 터미널에서 하는 경우는 그대로 남는다. 새로고침 키가 필요해지면 그때 넣는다(`docs/tasks.md`).
- **저장이 느려진다.** `:w` 하나에 프로세스 세 개가 붙는다. 큰 저장소에서 `git status` 가 오래 걸리면 저장이 그만큼 늦어진다. sidebar 의 `git check-ignore` 와 같은 동기 호출 문제다.
- **cwd 밖 파일을 열어도 cwd 의 branch 가 보인다.** 틀린 표시는 아니지만, 다른 저장소 파일을 고치는 중에는 화면이 그 사실을 알려주지 않는다.
- **statusBar 위 줄이 더 빨리 찬다.** 절대 경로로 연 파일에서는 붙일 칸이 없어 표시가 사라진다. 경로 표시 방식을 정하는 일과 같이 봐야 한다(`docs/tasks.md`).

## 대안

- **매 렌더마다 읽기**
	- 항상 정확하다.
	- 키 입력마다 프로세스 세 개라 큰 저장소에서 편집기가 느려진다. 정확도를 위해 치를 비용이 아니다.
- **주기적 갱신**
	- 바깥 변경도 몇 초 안에 따라온다.
	- 편집만 하는 동안에도 프로세스가 계속 뜨고, 타이머 상태가 늘고, 갱신 주기를 정해야 한다.
	- 새로고침 키 쪽이 더 싸고 예측 가능하다.

	> ADR-0030 이 이 대안을 골랐다. 비동기 작업 바탕이 생겨(ADR-0025, ADR-0027) 프로세스가 키 입력 경로에 붙지 않게 되었고, 낡은 값이 실제로 거슬렸다.
- **`.git/HEAD` 를 직접 읽기**
	- 프로세스 없이 branch 와 commit 을 얻는다.
	- dirty 는 여전히 못 구하고(work tree 를 훑어야 한다), packed-refs·worktree·submodule 처럼 git 이 이미 아는 것을 다시 구현하게 된다.
	- sidebar 에서 gitignore 규칙을 직접 구현하지 않기로 한 것과 같은 이유다.
- **go-git 같은 라이브러리**
	- 프로세스가 없어지고 dirty 도 구할 수 있다.
	- 의존성이 크게 늘고(`go.mod` 를 걷어낸 직후다) status 계산은 오히려 `git` 명령보다 느리다.

	> ADR-0042 가 이 대안을 골랐다. 기각의 근거 중 절반이 틀렸다. go-git 에는 index 의 stat cache 가 이미 있고 내용을 다시 hash 하지 않는다. 느린 것은 `Worktree.Status()` 하나이고, 그것을 쓰지 않고 index·HEAD 만 라이브러리에게 맡기면 `git status` 의 2 배 남짓이다. 여기서 정한 기준("untracked 를 dirty 에 넣는다", "표시가 없을 뿐 틀리지는 않는다") 은 그대로 지킨다.
- **활성 파일 기준 저장소**
	- 여러 저장소를 오갈 때 정확하다.
	- tab 전환마다 git 호출이 붙고, 표시가 tab 마다 달라 "지금 작업 중인 저장소" 로 읽히지 않는다.

## 이 ADR 이 정하지 않는 것

- 새로고침 키. 낡은 값이 실제로 거슬리면 그때 넣는다
- ahead/behind(`↑2 ↓1`), stash 개수, 변경 파일 수 같은 추가 표시
- 편집 영역 안의 git 변경 표시(줄번호 옆 gutter). ADR-0007 이 이미 미뤄둔 것이다
- statusBar 의 파일 경로 표시 방식. 자리를 다투는 상대이지만 별개 결정이다
- submodule·worktree 안에서 무엇을 뿌리로 볼지. 지금은 cwd 에서 `git` 이 답하는 그대로다
