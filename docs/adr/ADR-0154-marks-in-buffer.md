# ADR-0154 mark 는 buffer 가 들고 줄을 따라간다. 파일 안의 `a`~`z` 만 둔다

- 상태: 채택
- 날짜: 2026-10-14
- 관련: ADR-0001(줄 갈아끼우기), ADR-0013(motion 과 operator), ADR-0070(되돌아오기), ADR-0071(둘러보고 확정하는 판), ADR-0082(멀리 뛰는 이동), ADR-0089(고른 범위 주소)

## 맥락

`docs/tasks.md` 에 「mark 기능 추가」가 있었다. 찍어 둔 자리로 돌아오는 길은 `ctrl+o` 뿐이었는데, 그것은 뛴 차례를 되짚는 것이라 「아까 그 함수」처럼 이름을 붙여 둔 자리로 가는 일을 하지 못한다. `:'a` 주소는 명령줄 문법만 자리를 비워 두고 `mark 는 아직 쓸 수 없습니다` 로 거절하고 있었다(ADR-0089).

정할 것은 다섯이다.

1. 어디까지 통하는가
2. 언제까지 남는가
3. 편집이 줄을 밀면 어떻게 되는가
4. 그 줄을 지웠다가 되돌리면 어떻게 되는가
5. 무엇으로 보고 지우는가

## 1. 파일 안의 소문자 스물여섯만 둔다

vim 의 소문자 mark 와 같다. 대문자(파일을 넘는 mark) 는 두지 않았다. 파일을 넘어 이름 붙인 자리로 가는 일은 아직 손에 꼽을 필요가 없었고, 넣으면 「tab 을 닫은 파일의 mark 를 무엇으로 따라가나」가 같이 온다. 대문자는 한글 입력 상태에서 낼 수도 없다.

숫자와 기호 mark(`'0` `'[` `'.` `''`) 도 없다. vim 이 저절로 채우는 자리라 각각 무엇을 담을지가 따로 정할 일이다. `''` 는 tasks.md 에 남아 있는 건이다(ADR-0070).

## 2. buffer 가 든다. tab 을 닫으면 사라진다

mark 는 `textarea.Buffer` 의 필드다. 줄과 같은 자리에 둔 것은 3 의 까닭이다. 그래서 수명도 buffer 와 같고, tab 을 닫았다 다시 열면 없다.

**다시 읽기는 줄 번호를 이어받는다.** 밖에서 포매터를 돌리면 내용이 통째로 갈리는데 무엇이 어디로 갔는지는 모른다. 커서가 줄 번호를 이어받는 것과 같이 한다(`Adopt`). 줄이 줄었으면 끝 줄로 끌어온다.

## 3. 줄을 갈아끼우는 자리에서 앞뒤로 같은 줄을 맞대어 옮긴다

`ReplaceLines` 가 `buf.lines` 를 바꾸는 유일한 함수라(ADR-0001) 문법 캐시처럼 mark 도 거기서 옮긴다. 다만 그 함수는 「[at, at+count) 가 with 로 갈렸다」만 알고 어느 옛 줄이 어느 새 줄이 되었는지는 모른다. `O` 는 한 줄을 빈 줄과 그 줄 둘로 갈아끼우는데, 자리 순으로 짝지으면 mark 가 빈 줄에 남는다.

그래서 **앞뒤로 같은 줄을 맞댄다.** git 마커가 HEAD 와 견주는 것과 같은 셈이다.

- 줄 수가 그대로면 아무것도 옮기지 않는다. 타이핑 한 번이 거의 다 이 길이라 비교도 하지 않는다
- 앞에서 같은 줄은 그 자리에 남는다(`o`)
- 뒤에서 같은 줄은 늘고 준 만큼 밀린다(`O`, 줄 첫 칸의 Enter)
- 가운데는 자리 순으로 짝짓고 짝이 없으면 지운다. `dd` 로 그 줄이 사라진 것이다

**줄 안의 칸은 따라가지 않는다.** 찍은 칸 앞에 글자를 넣으면 `` `a `` 가 그만큼 왼쪽에 선다. 줄이 짧아졌으면 갈 때 줄 끝으로 끌어온다. vim 과 같다.

**바꿀 때마다 새 map 을 짓는다.** 창은 값으로 복사되어 돌아다니고(motion 이 복사본 위에서 이동을 돌린다) map 은 복사해도 같은 것을 가리킨다. 복사본에서 줄을 고치면 원본의 mark 가 같이 밀린다. 많아야 스물여섯이라 새로 짓는 값이 없다. 되돌리기 기록이 그 map 을 복사 없이 그대로 담을 수 있는 것도 이 덕이다.

## 4. 되돌리면 사라진 것만 되살린다

되돌리기 기록(`edit`) 이 구간을 열 때의 mark 를 담는다. 되돌리면 그중 **지금 없는 것만** 되살린다. `dd` 한 번에 mark 를 잃지 않는다. 다시 적용(`ctrl+r`) 은 다시 지우고, 다시 되돌리면 다시 돌아온다. 역방향 기록이 같은 규칙으로 담기 때문이다.

**있는 것은 덮지 않는다.** 지운 뒤 같은 이름을 다른 자리에 다시 찍었으면 그것이 더 새 뜻이다. vim 은 담아 둔 자리로 덮어쓰는데, 그러면 `u` 가 손으로 찍은 것을 무른다.

## 5. `:marks` 판에서 보고 `x` 로 지운다

`:marks` 와 팔레트의 「mark 목록」이 하단 drawer 를 연다. **`:jumps` 판과 손이 같다.** `j`/`k` 가 커서를 그 mark 로 옮겨 보여주고 `enter` 가 확정, `esc` 가 취소다(ADR-0071). 둘 다 「이 중 어디로 갈까」를 고르는 판이다. 지금 파일의 mark 만 보이므로 둘러보며 tab 을 열 일이 없고 되돌릴 것은 커서 하나다.

지우는 키는 `x` 다. `:jobs` 가 고른 작업을 거두는 키와 같다. `:delmarks` 는 두지 않았다. 지우는 일이 드물고, 같은 이름으로 다시 찍으면 옮겨진다.

줄번호 칸에 mark 글자를 그리는 것은 하지 않았다. 마커 칸은 진단·git 이 이미 나눠 쓰고 있다.

## 키

- `m` `'` `` ` `` 는 `g` 와 같은 접두 키다. 뒤의 한 키가 이름이다. 그래서 숫자 접두, operator 뒤(`d'a`), 한글 되돌리기(`ㅡㅁ` 이 `ma`), 짝 없는 조합 무르기가 `gg` 와 같은 길을 지난다
- `'a` 는 줄 단위 motion 이고 그 줄의 첫 비공백으로 간다. `` `a `` 는 글자 단위이고 찍은 칸으로 간다. vim 과 같다
- **`m` 은 operator 뒤에 오지 못한다.** 찍는 것은 이동이 아니다. `dma` 는 아무것도 아니다
- **visual 은 `'a` `` `a `` 만 받는다.** 고른 범위를 늘린다. 고르는 중에 찍는 `m` 은 받지 않았다
- **찍지 않은 이름이면 알린다.** motion 은 buffer 만 받아서 알릴 자리가 없으므로 동작이 motion 을 부르기 전에 묻는다(`refuseMissingMark`). `%` 가 짝을 못 찾았을 때 알리는 것과 같은 까닭이다
- `'a` `` `a `` 는 멀리 뛰는 이동이라 되돌아오기 이력에 담긴다(ADR-0082). `:marks` 의 `enter` 도 담는다. `:jumps` 의 `enter` 가 담지 않는 것은 그쪽이 이력을 되짚는 이동이라서다

## 명령줄 주소

`:'a,'bd` 처럼 mark 의 줄을 주소로 쓴다. 줄 단위다. 명령줄의 글자 기계는 범위를 범위 글자에서 끊는데 mark 이름은 보통 글자라서, **`'` 바로 뒤의 한 글자는 무엇이든 범위로 받는다.** 찍을 수 있는 이름인지는 주소를 뜯는 쪽이 본다. `:'A` 는 `mark 이름이 아닙니다`, 찍지 않은 것은 `찍지 않은 mark 입니다` 다.

## 기각한 것

- **편집기를 끌 때까지 경로별로 남기기.** tab 을 닫았다 다시 열어도 남는다. 대신 닫혀 있는 동안 밖에서 고친 것을 따라가지 못해 엉뚱한 줄을 가리킨다
- **파일로 남기기**(vim 의 viminfo). 저장 자리와 형식이 새로 생긴다. 설정 파일도 아직 없다
- **편집마다 줄 대응을 넘겨받기.** 정확하지만 `ReplaceLines` 를 부르는 스무 곳 넘는 자리가 저마다 「어느 줄이 어디로 갔나」를 말해야 한다. 앞뒤를 맞대는 셈이 그 자리들에서 어긋나는 경우를 찾지 못했다
- **좌표에 그대로 두기.** 위에서 한 줄만 지워도 mark 가 엉뚱한 줄을 가리킨다
- **되돌릴 때 vim 처럼 덮기.** 4 에 적었다

## 결과

- `ma` `'a` `` `a `` `d'a` `` d`a `` `:'a,'b` `:marks` 가 생겼다
- `edit` 이 구간을 열 때의 mark 를 들고 다닌다. map 을 새로 짓는 규칙 덕에 복사는 없다
- 줄 수가 바뀌는 편집마다 바뀐 구간의 앞뒤 줄을 견준다. mark 가 없으면 견주지 않는다
- 칸을 따라가지 않으므로 줄 안을 많이 고친 뒤의 `` `a `` 는 찍은 글자에서 벗어날 수 있다
- `''`(직전 자리), 대문자 mark, `gv` 는 여전히 없다
