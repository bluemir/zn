# ADR-0105 markdown 의 표와 참조 링크를 넣고, setext 제목과 들여쓴 코드블록은 넣지 않는다

- 상태: 채택
- 날짜: 2026-08-29
- 관련: ADR-0039(문법 강조 뼈대), ADR-0040(코드펜스와 안쪽 언어), ADR-0041(색표)

## 맥락

`docs/tasks.md` 의 문법 강조 후속에 넷이 한 줄로 묶여 있었다.

> markdown 의 setext 제목(`===` 밑줄)·들여쓴 코드블록·표·참조 링크. 앞의 둘은 문단 상태가 필요하다

재 보니 넷의 값이 크게 갈렸다.

| 항목 | 이 저장소에 |
|---|---|
| 표 | `docs/spec.md` 와 ADR 여럿에 있다 |
| 참조 링크 | 정의(`[ref]: 주소`) 가 하나도 없다 |
| setext 제목 | 한 번도 없다 |
| 들여쓴 코드블록 | tab 으로 들여쓴 줄은 셋 다 **목록 이어짐**이다 |

그리고 항목이 적어 둔 「앞의 둘은 문단 상태가 필요하다」가 정확하지 않았다. 하나는 문단 상태로 풀리지 않고, 다른 하나는 문단 상태로도 모자란다.

## 1. 표는 「`|` 로 시작하는 줄」이다

GFM 은 바깥 `|` 를 생략한 것도 표로 읽는다(`a | b`). 그것까지 받으면 산문의 `a | b` 와 갈리지 않는다. **시작 표시를 요구하면 줄 하나만 보고 정할 수 있다.**

- `|` 로 시작하고(들여쓰기 3 칸까지) `|` 가 하나 더 있으면 표의 행이다.
- 그중 `-` 가 있고 `|`·`-`·`:`·빈 칸으로만 된 줄은 구분줄이라 통째로 표시 색이다.

이 저장소의 표는 전부 `|` 로 시작한다. 잃는 것이 없고, 산문에 `|` 가 드는 흔한 자리를 통째로 피한다.

## 2. 앞 줄을 봐야 하는 것은 머리 행 하나다

머리 행은 「이어지는 `|` 줄의 첫 줄」이라 그것만 앞 줄을 봐야 한다. `mdNormal` 에 `afterTableRow` 칸을 하나 두어 문맥에 싣는다.

**새 상태를 만들지 않았다.** 표 안에서도 markdown 이 하던 일을 다 해야 한다 — 표 다음 줄에 코드펜스가 열리거나 제목이 올 수 있다. 상태를 가르면 그 몸을 통째로 두 벌 들거나 위임하는 겹이 생기는데, 칸 하나면 `mdNormal` 의 몸이 그대로 쓰인다. 문맥 수렴에 쓰는 `==` 도 그대로다(ADR-0039).

## 3. 칸 안의 글은 여느 줄과 같다

`|` 를 먼저 가르지 않는다. 줄을 평소대로 훑어 코드 스팬·굵게·링크를 먼저 잡고, **그 토큰들 사이에만** `|` 를 담는다. 그래서 코드 스팬 안의 `|`(`` `a | b` ``) 는 칸을 가르지 않는다. 머리 행이면 토큰 사이의 나머지 글이 굵게 들어간다.

거꾸로 했으면 칸마다 잘라 다시 훑어야 하고, 그러면 잘라낸 만큼 자리를 되돌리는 셈이 붙는다.

## 4. 참조 링크는 주소와 이름에 색을 준다

- 정의(`[ref]: 주소 "제목"`) 는 주소에만 색을 준다. 인라인 링크에서 「글은 본문, 주소는 기계가 읽는 것」으로 가른 자리와 같다.
- 본문의 `[글][ref]` 는 `ref` 에 색을 준다. 그 이름이 주소가 적힌 자리를 가리키므로 주소와 같은 갈래로 본다.

**`[ref]` 하나만 적는 꼴(shortcut) 은 받지 않는다.** 그냥 대괄호로 묶은 글과 생김새가 같아서, 받으면 이 저장소의 할 일 표시(`- [ ]` `- [x]`) 가 전부 링크가 된다. 잃는 것은 거의 없다 — 그 꼴을 쓰려면 정의가 따로 있어야 하는데 이 저장소에는 정의가 하나도 없다.

## 5. setext 제목은 지금 구조에서 「문단 상태」로 풀리지 않는다

```
제목
====
```

밑줄을 보는 순간 제목 줄은 **이미 지나갔다.** `State.Lex(line) ([]Token, State)` 는 줄을 앞에서 뒤로 한 번만 지나가고 앞 줄에 매긴 색을 되돌릴 길이 없다(ADR-0039). 문단 상태를 들어도 이 사실이 바뀌지 않는다.

할 수 있는 것은 밑줄만 칠하는 반쪽인데, 제목 줄이 본문 색으로 남아서 제목처럼 보이지 않는다. 제대로 하려면 「이 줄의 답이 다음 줄에서 정해진다」를 캐시가 받아야 하고, 그것은 담아둔 줄의 뜻과 수렴 판정이 통째로 바뀌는 일이다.

**이 저장소에는 setext 제목이 한 번도 없다.** 그 값에 그 구조를 바꾸지 않는다.

## 6. 들여쓴 코드블록은 이 저장소와 부딪힌다

4 칸(또는 tab) 들여쓴 줄이 코드블록인지는 **목록 안인지**에 달렸다. 목록 안이면 그것은 이어지는 항목이다.

이 저장소의 markdown 은 거의 전부 목록이고 `docs/tasks.md` 는 tab 들여쓰기로만 되어 있다. 목록 상태 없이 넣으면 그 문서가 통째로 코드색이 된다. 목록 상태는 이 lexer 에 없는 겹이다 — 지금 드는 것은 코드펜스 안인지뿐이고, 목록은 깊이와 이어짐 규칙을 함께 들어야 한다.

**얻는 것보다 드는 것이 크다.** 코드는 이미 코드펜스로 적고 있고, 이 저장소에 들여쓴 코드블록은 하나도 없다.

## 남는 것

- **표의 정렬 표시(`:--`·`--:`) 를 따로 보지 않는다.** 구분줄 통째로 한 색이다. 정렬을 색으로 알릴 자리가 아니다.
- **바깥 `|` 를 생략한 표.** 받으려면 산문과 가르는 규칙이 새로 필요하다. 이 저장소가 쓰지 않는다.
- setext 제목과 들여쓴 코드블록은 위에 적은 까닭으로 열어 두지 않는다. 「한 줄씩 앞으로만」을 바꾸는 결정이 따로 서면 그때 같이 본다.
