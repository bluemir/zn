# ADR-0089 고른 범위는 `:` 로 넘어간다. `'<,'>` 가 그 범위를 가리키고, 글자로 고른 것은 글자까지 지킨다

- 상태: 채택
- 날짜: 2026-08-27
- 관련: ADR-0037(visual mode), ADR-0046(줄 범위 문법), ADR-0084(`:s` 치환), ADR-0010(검색), ADR-0002(mode 를 model 로), ADR-0034(동작은 `run(e)` 만 받는다)

## 맥락

`v` 로 세 줄을 고르고 `:` 를 누르면 아무 일도 일어나지 않는다. `visual-key-parser.go` 가 그 자리를 이렇게 적어 두었다.

> `:` 는 `'<,'>` 가 서기 전에는 고른 범위를 명령줄에 실을 길이 없어서 따로 걸린 자리다.

`docs/tasks.md` 는 이 건을 두 줄로 나눠 적고 둘 다 「visual 을 나갈 때 확정된 `motionRange` 를 남기는 것이 먼저다」로 끝냈다. `gv`(마지막 선택 되살리기) 와 묶여 있었기 때문이다.

**`gv` 를 빼면 남길 자리가 필요 없다.** `selection` 을 지우는 문은 둘뿐이고(`view-editor-normal.go`, `view-editor-insert.go`) `commandMode` 는 지우지 않는다. visual 에서 `:` 로 곧바로 들어가면 고른 범위가 살아 있는 채로 명령줄이 열린다. 이 ADR 은 그 사실 위에 선다.

정할 것은 넷이다. `:` 가 무엇을 명령줄에 적는가, `'<`·`'>` 를 주소 문법에 어떻게 넣는가, normal 에서 친 `'<,'>` 를 어떻게 하는가, 글자로 고른 범위에서 `:s` 가 무엇을 바꾸는가.

## 0. 먼저 쟀다

vim 9.1 로 확인한 값이다.

| 잰 것 | vim |
| --- | --- |
| visual 에서 `:` 를 누르면 | 명령줄에 `:'<,'>` 가 미리 적힌다 |
| `V` 로 고르고 `:'<,'>s/foo/X/g` | 그 줄들 전체에서 바꾼다 |
| `v` 로 줄 가운데를 고르고 같은 명령 | **줄 전체에서 바꾼다.** 고른 글자 밖도 바뀐다 |
| 고른 글자만 바꾸려면 | 패턴에 `\%V` 를 붙여야 한다(`:'<,'>s/\%Vfoo/X/g`) |
| normal 에서 `:'<,'>d` | 된다. mark 가 남아 있다 |

마지막 두 줄이 이 ADR 이 vim 과 갈리는 자리다.

## 1. `:` 는 `'<,'>` 를 미리 적어 준다

**보이는 글자로 적는다.** 몰래 범위를 끼우는 길도 있는데, 그러면 `:s` 하나가 어느 mode 에서 들어왔는지에 따라 뜻이 갈린다. 같은 글을 쳤는데 다르게 도는 것은 되돌아볼 자리가 없다.

적어 주면 **지울 수도 있다.** `backspace` 로 `'<,'>` 를 걷어내면 그냥 커서 줄 하나짜리 명령이다. 범위가 글자로 서 있는 덕에 그것이 저절로 된다.

**고른 범위는 명령줄을 치는 동안 그대로 칠해져 있다.** 따로 한 일이 없다. 그리는 자리가 `buf.selectionRange()` 를 보고(`editor.go`) `commandMode` 는 그것을 지우지 않는다. vim 도 같은 그림이다.

`esc` 로 나가거나 명령이 끝나면 `normalMode` 를 지나면서 고른 것이 지워진다. 놓는 자리를 새로 만들지 않았다(ADR-0037 이 문을 둘로 좁혀 둔 것이 여기서 값을 낸다).

## 2. `'<`·`'>` 는 주소 하나다

ADR-0046 이 세운 주소 문법에 base 둘을 더한다. `addressSelectStart`·`addressSelectEnd` 다.

`lineAddress.resolve` 는 이미 `Buffer` 를 받는다. 고른 범위도 `Buffer` 에 있으므로(ADR-0037) **서명이 바뀌지 않는다.**

`isRangeChar` 에 `'` 를 더한다. **`:'` 로 시작하는 명령 이름은 없다.** 범위 글자로 시작하면 범위로 읽어도 이름과 부딪히지 않는다는 그 함수의 근거가 그대로 선다. 범위 토큰 안에서는 `<`·`>` 도 모은다. `:<`·`:>` 는 명령이 아니다 — 들여쓰기는 normal 의 키이고 명령줄에는 없다.

자리 옮김도 그대로 붙는다. `:'<,'>+3` 이 뜻을 갖는다.

## 3. normal 에서 친 `'<,'>` 는 거절한다

vim 은 mark 가 파일마다 남아서 된다. 여기는 안 된다.

**mark 를 넣지 않는다.** mark 를 제대로 넣는 일은 편집이 좌표를 밀 때 그것을 따라 옮기는 일까지다. 그것은 별건이고, 지금 얻을 것은 「visual 을 나간 뒤에도 `:'<,'>` 가 된다」 하나다.

`gv` 를 안 쓰기로 했으므로 남겨 둘 다른 이유도 없다. 필요해지면 그때 mark 를 열고, 그 ADR 이 `gv` 와 `'<,'>` 를 같이 답한다.

문구는 「고른 범위가 없습니다」다. 없는 줄을 댔을 때(`그런 줄이 없습니다`) 와 같은 갈래로, 주소를 풀지 못한 것이다.

## 4. 글자로 고른 것은 글자까지 지킨다

**vim 과 갈리는 자리다.** vim 은 `'<,'>` 를 늘 줄 단위로 보고, 고른 글자만 바꾸려면 패턴에 `\%V` 를 붙이게 한다.

여기서는 고른 모양을 그대로 따른다. `V` 로 고른 것은 그 줄들 전체이고, `v` 로 고른 것은 **그 글자들만**이다.

```
줄 내용:   foo bar foo
고른 것:       ^^^^^^^     (`v` 로 `bar foo`)

:'<,'>s/foo/X/g   →   foo bar X
```

까닭은 하나다. **고른 것을 보면서 명령을 치는데 고른 밖이 바뀌면 그것은 놀람이다.** `\%V` 는 그 놀람을 아는 사람에게만 있는 우회로이고, 우리는 놀랄 자리를 만들지 않는 편을 골랐다.

### 값이 싸다

`motionRange` 가 이미 그 모양을 든다. `startCol`·`endCol`·`linewise` 가 다 있다.

그리고 `buf.selectionOn(area, line)` 이 **줄마다의 byte 구간을 이미 준다.** 그리는 자리가 쓰던 함수이고, 줄 단위 범위에는 `[0, 줄끝]` 을 준다. 그래서 길이 갈리지 않는다.

`:s` 가 보는 것을 `(from, to int)` 에서 `area motionRange` 로 바꾼다. 줄 범위에서 온 것은 `linewise: true` 로 만들어 넘긴다 — `:cat` 이 이미 그렇게 한다(`view-editor-command.go` 의 `runCat`).

`:d`·`:y`·`:cat` 은 **공짜다.** 셋 다 이미 `motionRange` 를 받는다(`deleteRange`, `catLines`). 그래서 `:'<,'>d` 가 글자로 고른 것을 글자만 지우고, 그것은 visual 의 `d` 와 같은 답이다.

### 앵커는 줄에 붙는다

`^` 와 `$` 는 **줄의 끝**에 맞는다. 고른 구간의 끝이 아니다.

구간을 잘라서 정규식을 돌리면 앵커가 자른 자리에 붙는다. 그래서 자르지 않는다. **줄 전체에서 찾고, 구간 안에 온전히 든 자리만 남긴다.**

`matchesIn` 이 이미 줄 전체에서 한 번에 찾는다. 그 함수가 그렇게 된 까닭도 같은 것이었다 — 앞에서부터 자르며 이어 찾으면 `^` 가 자른 자리마다 다시 맞아서 `:s/^/> /g` 가 글자마다 붙었다.

거르는 것은 `g` 로 자리 수를 줄이기 **전에** 한다. `g` 가 없는 `:s` 는 「구간 안의 첫 자리」를 바꿔야 하고, 먼저 줄인 뒤 거르면 구간 밖의 첫 자리가 남아서 아무 일도 안 하게 된다.

구간에 걸친 자리는 바꾸지 않는다. 반만 고른 낱말을 바꾸면 고른 밖이 딸려 나간다.

## 5. 물어보며 바꾸는 길도 같이 간다

`:s///c` 가 한 자리씩 묻는 mode 다(ADR-0084). 여기도 `(from, to)` 대신 `area` 를 든다.

`seek` 이 줄에 들어설 때 `selectionOn` 으로 구간을 얻어 `matchesIn` 에 넘긴다. 일괄 치환과 **같은 함수를 쓴다** — 두 길이 다른 자리를 바꾸면 `c` 를 붙였을 때만 다른 답이 나온다.

되돌리기 구간(`beginEdit(m.from, m.to-m.from+1)`) 은 줄 수로 세므로 `area.startLine`·`area.endLine` 을 그대로 쓴다.

## 결과

- visual 에서 `:` 가 열리고 `'<,'>` 가 미리 적힌다. 고른 범위는 칠해진 채다
- `:'<,'>s/a/b/g` `:'<,'>d` `:'<,'>y` `:'<,'>cat` 이 한꺼번에 딸려온다. 범위를 받는 명령이 이미 그 다섯이다
- 글자로 고른 것은 글자만 바뀐다. `V` 로 고른 것은 줄 전체다
- 새로 저장하는 상태가 없다. `selection` 이 이미 사는 자리에 그대로 있다

감수하는 것

- **normal 에서 `:'<,'>` 가 안 된다.** vim 은 된다(§3)
- **`\%V` 가 없다.** vim 에서 그것을 손에 익힌 사람은 붙일 자리를 못 찾는다. 우리는 그것이 기본이라 붙일 것이 없다
- **줄 단위와 글자 단위가 같은 글자(`'<,'>`) 로 적힌다.** 명령줄만 보면 어느 쪽인지 모르고, 화면에 칠해진 범위가 그것을 말한다
- **앵커가 고른 구간에 붙지 않는다.** `v` 로 줄 가운데를 골라도 `:'<,'>s/^/> /` 는 아무 일도 안 한다. 줄 앞이 구간 밖이다
- **고른 범위가 편집으로 밀리면 어긋난다.** 명령줄이 열려 있는 동안 파일이 바뀌는 길이 없어서 지금은 닿지 않는 자리다

## 대안

- **`motionRange` 를 buffer 에 남기고 `gv` 와 같이 넣기**
	- vim 과 같아지고 normal 에서도 `'<,'>` 가 된다.
	- **`gv` 를 안 쓴다.** 그 하나를 위해 남길 자리와 편집이 그것을 밀 때의 규칙이 새로 생긴다.
	- 남긴 좌표가 파일 밖을 가리키는 경우를 어떻게 할지가 곧 mark 를 넣는 일이다. 얻는 것에 비해 붙는 것이 많다.

- **`'<,'>` 를 늘 줄 단위로 두기 (vim 그대로)**
	- 고칠 자리가 네 곳으로 끝난다. `:s` 를 손대지 않는다.
	- **고른 밖이 바뀐다.** 고른 것을 보면서 치는 명령이라 그것이 놀람이다(§4).
	- `\%V` 를 같이 넣으면 답이 되는데, 그것은 기본을 놀라게 두고 우회로를 얹는 것이다.

- **`v` 로 고른 상태에서는 `:` 를 거절하기**
	- 작게 끝내면서 놀랄 동작을 안 낸다.
	- `V` 로 다시 고르라고 시키는 셈이다. 고른 것을 두고 `:` 를 누르는 손짓이 갈래에 따라 되고 안 되는 것이 외울 것 하나다.

- **범위를 몰래 적용하고 명령줄에는 안 적기**
	- 치는 글자가 짧다.
	- `:s` 하나가 어디서 들어왔는지에 따라 뜻이 갈린다. 되돌아볼 자리가 없고, 지우고 싶을 때 지울 것이 없다.

- **구간을 잘라서 정규식을 돌리기**
	- 코드가 짧다.
	- **앵커가 자른 자리에 붙는다.** `matchesIn` 이 줄 전체에서 찾도록 된 까닭과 같은 실수다(§4).

## 이 ADR 이 정하지 않는 것

- **mark(`'a`) 와 `gv`.** 좌표를 남기고 편집이 그것을 미는 규칙이 필요해질 때 같이 본다 (ADR-0037, ADR-0046)
- **`:[범위]!cmd`(filter) 와 `:[범위]w`.** 범위 문법이 아니라 새 기능이라 backlog 로 내렸다 (ADR-0024, ADR-0045)
- **`:/pat/` 로 주소를 잡는 것** (ADR-0010, ADR-0046)
- **블록 visual(`ctrl+v`).** 지금 갈래는 글자와 줄 둘이다 (ADR-0037)
- **insert 에서 드래그로 범위를 여는 것** (ADR-0037)
