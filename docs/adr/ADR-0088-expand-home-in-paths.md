# ADR-0088 경로를 받는 명령의 맨 앞 `~` 를 홈으로 푼다

- 상태: 채택
- 날짜: 2026-08-27
- 관련: ADR-0021(명령줄로 파일 열기), ADR-0024(다른 파일에 쓰기), ADR-0069(갈 곳 목록, 경로를 줄여 보여주는 자리), ADR-0045(`:!` 는 터미널을 셸에 넘긴다), ADR-0077(여러 파일 검색), ADR-0084(치환), ADR-0067(심볼 이름 바꾸기), ADR-0054(트리에서 파일 만들고 이름 바꾸기)

## 맥락

`docs/tasks.md` 에 「`:tabnew` 로 파일을 열 때 `~` 를 홈폴더로 해석하기」 한 줄로 남아 있던 건이다.

**셸이 `~` 를 풀어 주는 것은 CLI 인자뿐이다.** `zn ~/.zshrc` 는 셸이 이미 절대 경로로 바꿔서 넘겨 주므로 편집기는 `~` 를 본 적이 없다. 편집기 안에서 친 `:tabnew ~/.zshrc` 는 셸을 거치지 않아서 아무도 풀어 주지 않고, 그대로 `~` 라는 이름의 디렉터리를 찾다가 「파일이 없습니다」로 끝난다. 홈 아래의 파일을 열려면 `/Users/이름/...` 을 손으로 다 쳐야 했다.

**반대 방향은 이미 있었다.** `shortenPath` 가 홈 아래의 파일을 `~/...` 로 줄여서 보여준다(ADR-0069 의 경로 줄이기, 저장 문구도 같은 손을 쓴다). 편집기가 `~/.zshrc` 라고 보여주면서 그 글자를 그대로 다시 칠 수는 없는 것이 이 구멍이었다.

정할 것은 셋이다. **어디서 푸는가**, **어느 명령에 붙는가**, **`~사용자` 도 푸는가**다.

## 1. 푸는 자리는 명령줄 한 곳이다

`viewEditorCommand.run` 이 인자 개수 가드를 지난 직후에, 경로를 받는 명령의 인자를 `expandHome` 에 통과시킨다. 그 뒤로는 아무도 `~` 를 보지 않는다.

**명령을 뜯는 자리(`parseCommand`) 에서 풀지 않았다.** 토큰 기계는 지금 문자열만 보는 순수한 손이고, 여기서 풀면 파일 시스템과 사용자 조회가 그 안으로 들어온다. 오류가 나는 자리도 늘어난다 — 「따옴표가 닫히지 않았습니다」와 「사용자를 찾을 수 없습니다」가 같은 층에서 나오면 무엇이 문법 오류인지 흐려진다.

**명령마다 각자 풀지도 않았다.** `write`·`edit`·`tabnew` 셋에 같은 세 줄을 두면, 나중에 경로를 받는 명령이 늘 때 「`~` 가 어디서 되고 어디서 안 되는지」를 세는 자리가 생긴다. 지금은 그 switch 한 곳만 보면 된다.

**푼 경로는 그대로 아래로 흐른다.** 「같은 파일은 한 tab」을 보는 `tabOf`·`samePath` 도, 트리를 그 자리로 데려가는 `revealInSidebar` 도 푼 경로를 받는다. 그래서 `~/src/zn/main.go` 로 여는 것과 절대 경로로 여는 것이 같은 tab 을 찾고, 트리도 같은 자리를 가리킨다. 풀지 않고 각 자리에서 다시 풀었다면 이 셋이 어긋날 수 있었다.

## 2. 경로를 받는 명령 셋에만 붙인다

`:w <파일>`·`:e <파일>`·`:tabnew <파일>` 셋이다. 이 편집기에서 인자가 **파일 경로**인 명령이 이 셋뿐이다.

셋을 다 붙인 것은 규칙을 하나로 두기 위해서다. `:tabnew` 만 물어서 시작한 건이지만, `:tabnew ~/x` 가 열리는데 `:w ~/x` 는 `~` 라는 디렉터리를 찾는 자리를 남기면 그것을 기억해야 할 규칙이 된다.

나머지 인자는 경로가 아니라서 지나간다.

- `:!<셸 명령>` 은 뜯지 않은 셸 줄이고 **셸이 자기 규칙으로 푼다**(ADR-0045). 여기서 손대면 셸의 `~` 처리와 두 겹이 된다.
- `:grep <패턴>`·`:s/…` 의 인자는 찾을 것이지 파일이 아니다(ADR-0077, ADR-0084).
- `:rename <새 이름>` 은 파일 이름이 아니라 코드 안 심볼의 새 이름이다(ADR-0067).
- 트리의 만들기·이름 바꾸기(ADR-0054) 는 **고른 디렉터리 안의 이름**을 받는 자리다. 거기서 `~` 가 홈으로 튀면 「이 디렉터리 안에 만든다」는 그 창의 뜻이 깨진다.

## 3. `~사용자` 도 푼다

`~bluemir`·`~bluemir/src` 는 그 사용자의 홈이다. `os/user` 로 조회한다. vim 과 같다.

**없는 사용자는 오류로 낸다.** `~nobody/x` 를 「그런 이름의 디렉터리」로 되돌리는 길도 있었지만, 그러면 뒤이어 나오는 「파일이 없습니다」가 사용자를 못 찾은 것인지 파일이 없는 것인지를 가리지 못한다. `~` 를 홈으로 푸는 규칙을 세운 자리에서 `~` 로 시작하는 것은 홈을 뜻하므로, 못 찾았으면 그것을 말하는 것이 맞다.

`~` 로 시작하는 이름의 진짜 파일은 이 규칙에서 열 수 없다. `./~foo` 로 열 수 있고, 그런 이름을 쓰는 일은 드물다.

**지금 사용자의 홈은 `os.UserHomeDir`(즉 `$HOME`) 로 본다.** `~사용자` 만 passwd 를 본다. 이름 없는 `~` 까지 조회로 보내면 `$HOME` 을 옮겨 놓고 일하는 자리에서 편집기만 다른 홈을 가리킨다.

## 4. 맨 앞의 `~` 만 푼다

`docs/~backup` 은 그런 이름의 파일이다. 사용자 이름은 `~` 다음부터 첫 `/` 까지로 끊는다. 구분자는 `/` 만 본다 — 여기 오는 것은 사람이 명령줄에 친 것이고, `~` 를 치는 사람은 `/` 를 친다.

## 결과

- `:tabnew ~/.zshrc`·`:e ~/.vimrc`·`:w ~/backup.txt` 가 홈 아래를 가리킨다. 보여주는 `~/...` 를 그대로 다시 칠 수 있게 되었다.
- `:w <파일>` 의 저장 문구도 `shortenPath` 를 지나게 했다. `~` 로 친 것은 이미 긴 절대 경로가 되어 있어서, 그대로 두면 좁은 화면에서 문구가 잘린다. 줄이면 친 그대로인 `~/...` 로 돌아온다.
- 시험은 `$HOME` 을 임시 디렉터리로 돌려놓고 잰다(`expand-home_test.go`). `~사용자` 는 지금 사용자를 이름으로 다시 찾을 수 없는 자리(cgo 없이 빌드한 darwin) 에서는 건너뛴다.

## 남은 것

- `:tabnew ~/` 에서 tab 을 눌러 완성하는 것은 별건이다. 자동완성 자체가 아직 없어서 `docs/tasks.md` 에 그 항목으로 남아 있다.
