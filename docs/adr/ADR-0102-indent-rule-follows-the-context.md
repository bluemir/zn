# ADR-0102 들여쓰기 규칙을 파일 이름이 아니라 문맥이 고른다

- 상태: 채택
- 날짜: 2026-08-29
- 관련: ADR-0040(안쪽 언어에 강조를 넘긴다), ADR-0047·ADR-0048(들여쓰기 규칙), ADR-0080(언어가 표의 한 줄), ADR-0039(문맥 캐시)

## 맥락

`docs/tasks.md` 의 autoindent 후속에 오래 남아 있던 항목이다.

> markdown 코드펜스 안과 html 의 `<script>`·`<style>` 안이 바깥 언어의 들여쓰기 규칙을 받는다. 강조는 이미 안쪽 언어로 넘기는데(ADR-0040) 들여쓰기는 규칙을 파일 이름으로 고르기 때문이다.

한쪽만 넘기고 있었다. ADR-0040 이 `mdFence{inner State}` 와 `htmlRawText{inner State}` 로 **강조**를 안쪽 언어에 넘겼는데, 들여쓰기는 `buf.language.Indent()` 로 **파일 하나에 규칙 하나**였다. 그래서 markdown 문서 안의 ```` ```go ```` 블록에서 `{` 다음에 Enter 를 쳐도 들어가지 않고, `}` 를 쳐도 나오지 않았다.

## 1. State 가 자기 규칙을 답한다

`State` 인터페이스에 메서드를 하나 더한다.

```go
Indent() Indent
```

상태 29 개가 전부 구현한다. 스물일곱은 자기 언어의 규칙을 그대로 돌려주는 한 줄이고, 실제로 갈리는 것은 `mdFence` 와 `htmlRawText` 둘이다. 안쪽 문맥이 있으면 그쪽에 묻고 없으면 자기 규칙이다.

**type switch 하나로 모으지 않았다.** `IndentFor(state State) Indent` 자유 함수에 표를 두면 고치는 자리가 한 곳이고 29 개를 건드리지 않아도 되는데, 새 상태를 더하면서 표에 넣기를 잊으면 **조용히 바깥 언어의 규칙을 받는다.** 인터페이스에 두면 컴파일러가 잡는다. 같은 자리에서 `Kind` 는 반대로 갔는데(색표에 없으면 조용히 색이 없어지고 테스트가 지킨다, syntax.go) 저쪽은 갈래를 늘리는 값이 싸야 하는 자리이고 여기는 상태가 늘 때마다 판단이 필요한 자리다.

**한 값이 두 자리에 있게 되었다.** 표(`languageRules`) 의 `indent` 칸과 그 언어 시작 문맥의 `Indent()` 가 같은 것을 가리킨다. 표에서 칸을 빼면 「언어 하나가 표의 한 줄」(ADR-0080) 이 깨지고, 상태에서 빼면 위임할 길이 없다. 둘을 두고 **같은지를 시험이 지킨다**(`TestStateIndentMatchesTheTable`).

## 2. 규칙은 그 줄을 **시작한** 문맥이 고른다

담아 두는 것은 줄을 끝낸 문맥이라(`syntaxLine.after`) 앞 줄의 것을 꺼낸다. 첫 줄은 파일이 시작하는 문맥이다.

경계가 이렇게 선다.

| 줄 | 시작 문맥 | 규칙 |
|---|---|---|
| ```` ```go ```` | `mdNormal` | markdown |
| `func f() {` | `mdFence{inner: goNormal}` | go |
| ```` ``` ```` (닫는 것) | `mdFence{...}` | go |
| 그 다음 줄 | `mdNormal` | markdown |

**닫는 펜스가 코드 규칙을 받는다.** 그 줄을 시작한 문맥이 아직 펜스 안이라서다. go 규칙에게 ```` ``` ```` 은 여는 것도 닫는 것도 아니라 답이 0 이고, 앞 줄의 `}` 가 이미 제자리로 나와 있으므로 닫는 펜스도 여는 펜스와 같은 자리에 선다. 예외를 두지 않아도 맞는 답이 나오는 자리다.

## 3. `=` 의 판정이 파일이 아니라 줄마다다

`Reindents()` 는 「규칙만으로 다시 들여쓸 수 있는가」이고 markdown 만 거짓이다. 전에는 파일 하나로 보아서 markdown 문서에서 `=` 가 통째로 비켜 갔다. 이제 줄마다 본다. 산문과 목록은 그대로 두고 **코드펜스 안만 정리한다.**

건드리지 않는 줄도 기준선은 이어 간다. 그러지 않으면 펜스 안 첫 줄이 기준을 잃는다.

**여는 것은 앞 줄의 규칙이 본다.** `Next` 는 「이 줄 다음이 몇 단계 들어가는가」라 앞 줄에 묻는 것이고, `Close` 는 「이 줄이 나온 줄인가」라 이 줄에 묻는 것이다. 파일 하나에 규칙 하나일 때는 같아서 구별할 일이 없었는데, 경계에서 갈린다 — ```` ```go ```` 줄은 markdown 이고 그 다음 줄부터가 go 다.

## 4. 한 단계의 크기는 파일 하나에 하나다

`Unit()` 은 문맥을 따라가지 않는다. `resolveIndentUnit` 이 파일을 열 때 한 번 정하고(`.editorconfig` → 이미 쓰인 것 재기 → 언어 관례) 그것이 파일 전체의 한 단계다.

markdown 문서 안의 go 코드가 tab 을 쓰고 산문이 space 를 쓰면 같은 파일이 두 자를 갖게 된다. `.editorconfig` 도 경로별이라 한 파일에 하나를 말하고, 재는 것도 파일 전체를 본다. **문맥이 고르는 것은 「몇 단계인가」이고 「한 단계가 무엇인가」는 파일이 고른다.**

## 5. 글자마다 지나는 자리에서는 문맥을 채우지 않는다

`reindentClosing`(친 글자가 그 줄을 닫는 줄로 만들었으면 당긴다) 은 insert 에서 **글자마다** 불린다. 여기에 `lexSyntaxTo` 를 끼웠더니 아직 다 치지 않은 줄에서 수렴 판정이 돌아 캐시가 흔들렸다(`TestSyntaxCacheKeepsGoingWhenContextChanges` 가 잡았다). `/` 만 친 순간의 문맥은 아직 안 바뀌어서 「수렴했다」로 읽히고, 찬 만큼이 통째로 되살아난다.

그래서 이 자리는 **담아둔 것을 쓰고 없으면 파일 언어의 규칙으로 물러난다.** 편집기가 키마다 화면을 한 번 그리고 그리는 쪽이 화면 아래까지 채우므로 실제로는 늘 차 있다. 시험에서는 그 그리기를 손으로 넣어야 한다.

`insertIndent`(`tab` 키) 는 다르다. 글자마다가 아니라 그 키를 칠 때만 지나므로 채운다.

## 고르지 않은 것

- **위임하는 상태만 드러내는 인터페이스**(`Inner() State`). 29 개 중 둘만 뜻이 있어서 나머지가 `return nil` 한 줄인 것은 같은데, 안쪽 문맥에서 규칙을 되찾으려면 `State` → `Language` 를 잇는 표가 또 필요하다. 그 표가 곧 §1 이 피한 type switch 다
- **표에서 `indent` 칸을 없애고 `lang.state.Indent()` 로 끌어오기.** 값이 한 자리가 되는데 「언어 하나가 표의 한 줄」(ADR-0080) 이 깨지고, `outline` 칸이 같은 값을 참조하고 있어서 표에서 그 이름이 사라지지도 않는다
- **코드펜스 안에서 안쪽 언어의 `Unit()` 쓰기.** §4 대로 한 파일이 두 자를 갖게 된다. markdown 문서 안 go 코드가 gofmt 처럼 tab 으로 들어가지 않는 것이 그 값이다. `docs/tasks.md` 에 남겼다
- **`Reindents()` 를 파일 하나로 두기.** 고칠 것이 없었지만 markdown 문서의 코드펜스가 `=` 를 영영 못 받는다. 그 블록이 이 ADR 이 손보려던 바로 그 자리다
