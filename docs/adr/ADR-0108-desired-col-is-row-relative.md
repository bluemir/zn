# ADR-0108 유지할 칸을 화면 행 기준으로 둔다

- 상태: 채택
- 날짜: 2026-08-31
- 닫는 것: ADR-0006 §「이 ADR 이 정하지 않는 것」의 「`desiredCol` 을 줄 기준으로 둘지 화면 행 기준으로 둘지」
- 관련: ADR-0006(normal mode 키 상태 기계), ADR-0076(`home`·`end` 는 화면 행을 본다), ADR-0081(화면 행과 논리 줄이 이름과 count 를 나란히 받는다)

## 맥락

위아래로 움직일 때 유지할 칸을 `desiredCol` 하나가 든다(`buffer.go`). 그 값을 **화면 행 안에서 센 칸**으로 담는데, 읽는 자리가 둘이고 틀이 서로 다르다.

읽는 자리 | 키 | 어디서부터 세어 놓는가
---|---|---
`placeCursorInRow` | `↑` `↓` | 행 시작
`placeCursorInLine` | `j` `k` `10j` | 줄 시작

그래서 wrap 된 줄의 둘째 행 이후에서 `j` 를 누르면 vim 과 다른 칸에 선다. ADR-0006 이 이것을 「감수하는 것」에 적고, 표현 방식은 정하지 않은 것으로 남겼다.

## 1. 재본 값

폭 20, 50 글자 줄 열둘. 첫 줄 offset 25(`z`, 둘째 화면 행의 6 번째 칸) 에서 `10j` 를 친다.

| | 떨어지는 자리 | 그 줄의 화면 행 |
|---|---|---|
| vim 9.1 | offset 25 (`z`) | 둘째 행 |
| zn | offset 5 (`f`) | 첫 행 |

`desiredCol` 은 행 안에서 센 값이라 늘 `width` 보다 작다. 그래서 `j`/`k` 가 놓는 자리는 wrap 된 줄이 몇 행이든 **언제나 첫 화면 행**이다. 셋째 행에서 눌렀으면 두 행 몫이 당겨진다.

wrap 되지 않은 줄에서는 두 틀이 같은 값이라 vim 과 같다. 첫 화면 행에 있을 때도 같다. **드러나는 것은 커서가 둘째 행 이후에 있는 상태에서 `j`/`k` 를 누를 때뿐이다.**

## 2. 그대로 둔다

`↑`/`↓` 가 화면 행 기준인 편집기에서는 이쪽이 그 키들과 앞뒤가 맞는다. 화살표로 wrap 된 줄 안을 오가는 동안 화면 x 가 그대로 유지되는 것이 이 표현이 곧바로 주는 값이고, 그것이 `↑`/`↓` 를 화면 행 단위로 둔 이유(ADR-0006, ADR-0076) 와 같은 방향이다.

**두 키가 서로 다른 양을 원한다.** `↑`/`↓` 는 화면 x 를 지키려 하고 `j`/`k` 는 줄 안의 칸을 지키려 한다. wrap 이 없으면 두 값이 같아서 필드 하나로 충분하고, wrap 이 생기면 갈라져서 한쪽만 맞는다. 지금은 화살표 쪽으로 맞춰 두었다.

바꾸지 않기로 한 것은 **얻는 것이 vim 과의 일치 하나**이고, 그것이 드러나는 자리가 위에 적은 좁은 조건뿐이기 때문이다. 치를 것은 §3 에 적는다.

## 3. 되돌려 계산할 수는 없다. 그래서 고치려면 갱신 규칙이 하나 생긴다

「`updateDesiredCol` 에서 행 시작을 빼지 않으면 된다」로 끝나지 않는다. 지금 `desiredCol=5` 에서 원래 25 를 되찾으려면 「어느 행에서 출발했는지」가 필요한데 그것을 버렸다.

줄 기준으로 바꾸면 `↑`/`↓` 가 이어서 눌릴 때 화면 x 가 어긋난다. 폭 20, `desiredCol=25` 로 둘째 행(행 시작 20) 에 있다고 하자. `↓` 로 셋째 행(행 시작 40) 에 가면 화면 x 를 `25 - 40` 으로 셈하게 된다.

**vim 은 필드를 둘 두지 않는다. 대신 갱신한다.** 재보니 `gj` 는 `curswant` 를 그 자리의 줄 기준 칸으로 다시 쓴다.

```
시작:   line=1 col=26
gj 뒤:  line=1 col=46
gj→j:   line=2 col=46
```

`gj` 뒤의 `j` 가 26 이 아니라 46 으로 갔다. 그러니 zn 도 필드 하나로 할 수 있다. `desiredCol` 을 줄 기준으로 두고, `placeCursorInRow` 가 화면 x 를 셈해 다음 행에 놓은 뒤 그 자리의 줄 기준 칸을 다시 적으면 된다.

다만 그러면 **`placeCursorInRow` 가 `desiredCol` 을 갱신하게 된다.** 지금 그 함수와 `placeCursorInLine` 둘만 「기억한 것을 읽어 쓰는」 자리이고, 나머지 37 곳이 새로 정하는 자리다. 그 가름이 흐려진다. 짧은 줄을 지나 원래 칸으로 돌아오는 성질(`placeCursorInLine` 의 주석) 이 행 이동에서도 지켜지는지를 시험으로 덮어야 하고, `↑`/`↓` 와 `j`/`k` 를 섞는 조합이 그 시험의 몫이 된다.

## 4. 사람에게는 문서로 알린다

동작을 정한 것이므로 `docs/spec.md` 의 「이동 키의 단위와 숫자」에 한 줄 적는다. 단위가 갈린다는 것은 이미 적혀 있었고, **유지하는 칸도 같이 갈린다**는 것이 빠져 있었다.

## 이 ADR 이 정하지 않는 것

- 화면 분할이 들어와 같은 파일에 커서가 둘이 될 때 이 필드를 어디에 둘지(`buffer.go` 가 이미 적어 둔 자리다)
- `ctrl+d`·`ctrl+f` 계열이 유지하는 칸. 그쪽은 커서를 화면 안 같은 자리에 남기는 것이라 다른 건이다(ADR-0062, ADR-0063)
