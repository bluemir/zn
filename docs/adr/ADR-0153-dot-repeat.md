# ADR-0153 `.` 으로 마지막 고치기를 되풀이한다. insert 에서 친 것은 키 단위로 담는다

- 상태: 채택
- 날짜: 2026-10-06
- 관련: ADR-0034(동작은 자기가 어떻게 실행되는지 안다), ADR-0033(`c` 는 한 구간이다), ADR-0066(자동완성), ADR-0017(register)

## 맥락

같은 고치기를 여러 자리에 하려면 매번 처음부터 다시 쳐야 했다. vim 의 `.` 이 이 일을 한다. 넣으려면 다섯을 정해야 한다.

1. 무엇이 「고치기」인가
2. insert 에서 친 것을 어떻게 담는가
3. insert 도중에 커서를 옮기면 어디까지 담는가
4. `3.` 의 숫자는 무엇인가
5. undo 는 어떻게 묶는가

## 1. 고치는 normal 동작과 그 뒤 insert 에서 친 것

`d` `c` `x` `r` `~` `J` `>` `<` `=` `p` `P` 와 `i` `a` `o` `O` 다. insert 로 들어가는 것은 거기서 친 것까지 하나로 본다.

- **`y` 는 빠진다.** 고치지 않는다. vim 과 같다
- **visual 에서 한 동작은 빠진다.** vim 은 지금 커서에서 같은 크기 범위에 다시 거는데, 그 크기를 무엇으로 셀지(줄 수, 글자 수, 화면 칸) 가 따로 정할 일이다. 이번에는 normal 만 연다
- **표 맞추기(`\mt`) 는 빠진다.** 파일 전체를 맞추는 것이라 되풀이해도 바뀔 것이 없다

동작이 이미 type 이라(ADR-0034) 담는 것은 그 값 하나다. 키를 다시 파싱하지 않는다. 어느 type 이 고치기인지는 `repeatable` 의 type switch 하나가 안다. 동작마다 표시 메서드를 다는 interface 는 두지 않았다. 묻는 곳이 하나뿐이다.

## 2. insert 에서 친 것은 키 단위로 담고, 자동완성만 결과를 담는다

글자, `enter`, `backspace`, `delete`, `tab`, `shift+tab` 을 친 차례대로 담는다. 되풀이할 때는 손으로 칠 때와 같은 함수(`applyInsertKey`) 를 다시 지난다. 그래서 들여쓰기와 닫는 괄호의 당김이 **새 자리의 규칙**을 따른다. vim 과 같다.

자동완성 목록에서 고른 것은 다시 묻지 않는다. 그때 넣은 글과 커서 앞뒤로 갈아끼운 폭을 담아서 그대로 넣는다. 다시 물으면 서버가 다른 답을 줄 수 있고, 답을 기다리는 동안 되풀이를 멈출 수도 없다. 붙여넣은 것은 글 덩이 그대로 담는다.

## 3. 커서를 옮기면 거기까지다

방향키, 클릭, `ctrl+p`(팔레트) 에서 담기를 멈춘다. 이미 담은 것은 남는다. `iab←X` 를 되풀이하면 `iab` 다.

undo 구간이 끊기는 자리와 같다. 옮긴 뒤에 친 것은 다른 자리의 일이고, 그것까지 되풀이하려면 「어디로 옮겼는가」를 새 자리에서 다시 해석해야 한다.

## 4. `3.` 은 원래 숫자를 갈아 낀다

`2dw` 뒤의 `3.` 은 `3dw` 다. 그 숫자가 남아서 다음 `.` 도 `3dw` 다. vim 과 같다. 숫자를 쓰지 않는 동작(`i` `o`) 에는 숫자가 뜻이 없다. `3i` 가 `i` 인 것과 같은 자리다.

## 5. `.` 한 번이 `u` 한 번이다

동작을 실행한 뒤 담아 둔 단계를 같은 undo 구간 안에서 잇고, 마지막에 insert 의 `esc` 처럼 구간을 닫는다. `c` 가 지운 뒤 구간을 열어 둔 채 insert 로 넘기므로(ADR-0033) 따로 묶을 일이 없다. `i` `o` 는 친 첫 글자가 구간을 연다.

## 그 밖

- **editor 에 둔다.** register 처럼 tab 을 넘는다. 한 파일에서 고친 것을 옆 tab 에 그대로 하는 것이 흔하다
- **register 는 담은 그대로다.** `"add` 뒤의 `.` 은 다시 `"a` 에 담는다. vim 의 `"1p` 뒤 `.` 이 `"2p` 가 되는 것은 넣지 않았다
- **고친 것이 없으면 알린다.** 아무 일도 안 나면 키가 안 먹은 것으로 읽힌다

## 기각한 것

- **insert 를 나올 때 들어간 글을 통째로 떼어 오기.** 시작 자리부터 커서까지를 글자 그대로 넣는다. 들여쓰기까지 처음과 같지만, 시작 줄의 들여쓰기가 insert 안에서 바뀌면(`o` 뒤 `}`) 시작 칸이 글 밖으로 나가 떼어 올 자리가 어긋난다
- **친 키를 insert 화면에 그대로 다시 먹이기.** 자동완성이 다시 물어서 다른 답을 넣을 수 있다
- **커서를 옮긴 뒤에 친 것을 되풀이하기.** vim 은 이쪽이다. 들어간 동작(`o` 같은 것) 이 빠지므로 `.` 이 무엇을 할지 화면에서 읽기 어렵다

## 결과

- `.` 으로 normal 의 고치기를 되풀이한다. `cw` 처럼 insert 로 들어간 것도 친 글자까지 되풀이한다
- insert 의 편집 키가 `applyInsertKey` 하나로 모였다. 손으로 친 것과 되풀이한 것이 같은 길을 지난다
- visual 에서 한 고치기는 되풀이하지 않는다
- 새 고치기 동작을 넣으면 `repeatable` 과 `withCount` 에도 더해야 한다. 빠뜨리면 그 동작이 `.` 에 걸리지 않는다
