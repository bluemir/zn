# ADR-0128: 글과 창을 `internal/textarea` 로 낸다

## 맥락

ADR-0100 이 「`Buffer` 를 별도 패키지로」를 열어 두었고 ADR-0117 이 시도했다가 커서에 걸려 물러섰다. ADR-0119 는 `internal/lines` 를 물리며 **「나가는 의존이 0 인 잎이어도 편집기의 결정을 몸에 지니면 경계가 샌다」**를 적었다.

그 뒤로 매듭을 하나씩 풀었다.

| | 무엇을 풀었나 |
|---|---|
| ADR-0121 | 커서를 `Buffer` 밖으로 내어 `viewport` 를 만들었다 |
| ADR-0123 | 화면 폭을 인자에서 창의 상태로 옮겼다 |
| ADR-0124 | `register` 의 말과 자료를 갈랐다 |
| ADR-0125 | 창이 언어 서버를 모르게 했다 |
| ADR-0126 | 창에서 한 언어만의 기능(표 맞추기) 을 뺐다 |
| ADR-0127 | 안쪽 살림을 필드가 아니라 문으로 냈다 |

## 1. 재는 대신 컴파일러에게 물었다

가르기 전에 「열어야 할 면」을 재려 했는데 **도구가 세 번 틀렸다.**

1. 이름으로만 맞추는 무리 계산이 `for _, token := range` 같은 지역 변수를 패키지 이름으로 셌다
2. 도구에 넘기는 파일 목록이 비어서 227 가지·1,950 곳이라는 값을 냈다(실제 216·1,399)
3. 메서드 **서명**의 타입을 안 봐서 `saveHook`·`substitution` 이 무리에서 빠졌다

그래서 재는 것을 멈추고 **파일을 먼저 옮겨 컴파일러에게 목록을 받았다.** 커밋이 남아 있어 언제든 돌아올 수 있다는 것이 근거였다. `go build -gcflags=-e` 가 열 개 제한 없이 전부 내놓는다.

**이 길이 옳았다.** 세 번째 오류(서명 미검사)는 재는 도구로는 끝내 못 잡았을 것이고, 컴파일러는 첫 빌드에서 짚었다.

## 2. 이름은 `textarea` 다

HTML 의 `<textarea>` 처럼 **글을 넣는 창**이다. `text` 만큼 범용이지 않으면서 글(`Buffer`) 과 창(`Viewport`) 둘을 품는다.

`internal/buffer` 는 창을 그 이름 아래 숨기고, `internal/view` 는 글을 숨긴다. 둘 다 반쪽만 말한다.

## 3. 밖으로 필요했던 것은 넷뿐이었다

| 무엇 | 어떻게 풀었나 |
|---|---|
| `semanticToken` | 창이 드는 자료라 같이 옮겼다 |
| `saveHook` | **`SaveFormat{Name, Run}`** 으로 바꿨다 |
| `substitution` | 루프를 core 로 올리고 창은 갈아끼우기만 한다 |
| `widthOf` | 글의 화면 폭을 재는 것이라 같이 옮겼다 |

### `SaveFormat` — 찾고 깔고 돌리는 것은 밖의 일이다

창이 `saveHook` 에서 쓰던 것은 `hook.name` 과 `hook.run(in)` 둘뿐이었다.

```go
type SaveFormat struct {
	Name string
	Run  func(in []byte) ([]byte, error)
}
```

**interface 를 두지 않았다.** 부르는 쪽이 하나이고 그것이 자기 것을 이 꼴로 싸서 넘기면 된다(`saveHook.saveFormat()`). 그 명령이 저장소의 `go tool` 인지 PATH 의 것인지, 없으면 깔지는 편집기의 결정이라 창이 알 것이 아니다.

### `ReplaceRun` — 새 줄을 짓는 것과 갈아끼우는 것을 가른다

```go
func (buf *Viewport) ReplaceRun(at int, next [][]byte)
```

「이 범위를 이 줄들로 바꾸고 **한 번의 되돌리기로 묶어라**」 하나다. 무엇으로 바꿀지는 부르는 쪽이 안다 — ADR-0126 이 표 맞추기에서 세운 손을 치환에도 그대로 썼다.

**덤이 크다.** 이것이 없으면 `beginEdit`·`replaceLines`·`endEdit` 셋을 밖으로 열어야 했고, 그러면 밖에서 되돌리기를 건너뛰고 줄을 갈아끼울 수 있게 된다. ADR-0100 이 「줄 하나를 한 번의 되돌리기로 갈아끼우는 손 여덟 자리」를 묶을지 미뤄 두었는데, **패키지 경계가 그 답을 강제했다.**

## 4. 비계를 두었다

```go
// internal/core/textarea-shim.go
type viewport = textarea.Viewport
const pageFull = textarea.PageFull
var newBuffer = textarea.NewBuffer
...
```

core 가 쓰던 소문자 이름을 그대로 쓰게 해 주는 별칭 예순 줄이다. **여기 있는 줄 하나하나가 「core 가 그 패키지에 기대는 것」**이고, 컴파일러가 만들어 준 목록이다.

비계를 둔 까닭은 **가르기와 이름 고치기를 한 커밋에 섞지 않으려는 것**이다. 별칭을 하나씩 지우면서 부르는 자리를 `textarea.X` 로 바꾸는 것은 따로 할 일이고, 그 파일이 비면 가르기가 끝난다.

### 비웠다

별칭 일흔을 하나씩 지웠다. 하나 지울 때마다 부르는 자리를 `textarea.X` 로 바꾸고 곧바로 빌드로 확인했다 — 한 번에 쓸면 무엇이 무엇을 깨뜨렸는지 알 수 없다.

이름으로 맞추지 않고 `go/types` 로 **그 별칭 객체의 쓰임**만 고쳤다. 같은 이름의 지역 변수와 남의 필드가 있어서다.

걸린 것이 셋이다.

- **한 줄짜리 `import "..."`.** 블록으로 바꿔야 하는데 그냥 뒤에 붙여서 `motion.go` 가 깨졌다
- **`type viewport = textarea.Viewport` 별칭.** Go 1.23 부터 `types.Alias` 라는 별도 노드다. `Unalias` 를 안 지나면 `*types.Named` 검사에 걸러진다
- **embed 한 별칭은 필드 이름이 별칭 이름을 따라간다.** `register` 가 `textBlock` 을 품고 있어서 `reg.textBlock` 이 `reg.TextBlock` 이 되어야 했는데, 그것은 별칭의 쓰임이 아니라 **필드의 쓰임**이라 `Uses` 에 안 걸린다. 컴파일러가 짚었다

`core` 의 121 파일이 바뀌었고 동작은 안 바뀐다. 이제 core 가 창에 기대는 것이 전부 `textarea.` 로 보인다.

## 규모

| | |
|---|---|
| `internal/textarea` | 62 파일 |
| 대문자로 연 이름 | 169 (type 16 · func 124 · field 46 · const 33 중 겹침 제외) |
| 고친 자리 | 3,000 남짓. 전부 기계가 했다 |
| 비계 별칭 | 60 줄 |

동작은 안 바뀐다. 앱에서 강조·줄번호·git 마커·복사와 붙여넣기·되돌리기를 몰아 확인했다.

## 되짚은 것

**ADR-0119 의 함정을 피한 것은 매듭을 미리 푼 덕이다.** 그때 `internal/lines` 가 샌 까닭은 tab 폭과 제어문자 폭이라는 편집기의 결정을 몸에 지녔기 때문인데, 이번에는 그런 결정을 하나씩 밖으로 내거나(register·표 맞추기·언어 서버) 안으로 들여(화면 크기·앞 칸 상수) 두었다. **가르기 자체는 마지막 한 걸음이었다.**

그리고 **일괄 치환이 남의 type 을 건드렸다.** 소문자→대문자를 `.name` 기준으로 돌렸더니 `treeNode.path`·`inputLine.cursor` 까지 바뀌었다. 되돌린 뒤로는 컴파일러가 준 **파일·줄·열**로만 고쳤다 — 오류 메시지가 「이 자리의 이 이름을 저것으로」까지 말해 준다.
