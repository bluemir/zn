# Spec

## UI 구성

- 편집 영역 위 tabline
	- 열린 파일 목록
	- 1줄로 표시. 파일이 하나여도 그린다
	- 편집 영역 위에만 그린다. sidebar 가 열려 있으면 그만큼 짧다
- 편집 영역 맨 위 sticky 머리줄
	- 화면 위로 올라가 버린 제목·정의를 붙인다. 자리를 떼지 않고 본문 위 몇 행을 덮는다
- 편집 영역 왼쪽 줄번호
	- 절대번호와 상대번호를 나란히. 상대번호가 본문에 붙는 쪽이다
	- 항상 그린다. 번호 칸을 떼고 나면 본문이 20칸 아래로 떨어지면 그리지 않는다
- 좌측 sidebar
	- filetree. 기본으로 열려 있다
	- 32칸 고정. 화면 맨 윗줄부터 statusBar 앞줄까지를 차지한다
	- 편집 영역이 20칸 아래로 떨어지면 켜져 있어도 그리지 않는다
- 하단 statusBar
	- mode 는 sidebar 아래, 파일 경로는 편집 영역 아래
	- 2줄로 표시
	- 첫 줄만 반전. 둘째 줄은 명령줄이라 배경을 그대로 둔다(ADR-0004)
	- 첫 줄 오른쪽 끝에 git branch·commit·dirty 여부(ADR-0009)
- 하단 drawer
	- statusbar 바로 상단, 편집영역 아래
	- 폭은 편집영역과 같고, 높이는 필요에 따라 가변
	- 필요할때만 펼쳐짐. 관련작업이 끝나면 닫힘
	- register 내용을 확인하거나, 상세 오류내역을 보는등 편집맥락에서 필요한 부가 정보/list 등 다양한 용도로 사용됨
	- 지금 쓰는 곳은 특수문자 입력(아래 「특수문자 mode」) 과 register 목록(아래 「register
	  목록」) 둘이다. 편집 영역에 얹지 않고 그 행을 가져간다 — 얹으면 커서가 판 밑에
	  가려진다(ADR-0056)
	- 판을 그리는 코드는 둘이 나눠 쓰지 않는다. 안쪽이 완전히 달라서 공유될 것이 테두리뿐이다.
	  가져간 행 수(`drawerHeight`) 만 공유한다(ADR-0058)
	- sidebar 옆은 지나가지 않는다. drawer 를 열어도 트리 높이는 그대로다

sidebar 가 화면 위쪽을 세로로 가르고 tabline 과 편집 내용이 그 오른쪽에 쌓인다.
맨 아래 statusBar 두 줄만 그 가름을 지나 화면을 가로지른다.

sidebar 구분선·tabline 구분자·팔레트 테두리는 `│ ─ ┌ ┐ ├ ┤ └ ┘` 이지만, 이 글자들은
East Asian Width 가 Ambiguous 라 폭이 터미널마다 다르다. 시작할 때 한 번 재서 한 칸으로
확인된 터미널에서만 쓰고, 두 칸이거나 재지 못하면 ASCII `| - +` 로 그린다(ADR-0028).
아래 그림은 모두 유니코드 쪽이다.

### tabline

CLI 인자로 받은 파일이 각각 tab 이 된다. `:tabnew` 로 이름 없는 빈 tab 을 더 열 수 있고,
새 tab 은 맨 뒤가 아니라 보고 있던 tab 바로 뒤에 생긴다.

tab 하나는 `번호 파일이름` 이고, 이름은 경로가 아니라 파일 이름만 쓴다.
이름이 없으면 `[No Name]` 이고, 저장하지 않은 변경이 있으면 뒤에 `+` 가 붙는다.

보고 있는 tab 만 편집 내용과 같은 색이고 나머지는 반전이다(ADR-0004). 활성 tab 이 아래 내용과
이어져 보인다. 줄 끝의 남은 칸까지 반전이라 줄 전체가 한 덩어리로 보인다.

```
 1 buffer.go │ 2 editor.go+ │ 3 core.go
└─ 활성 ────┘└─ 여기부터 줄 끝까지 반전 ───┘
```

tab 이 편집 영역 너비보다 많아지면 활성 tab 이 보이는 자리까지 가로로 민다. 화면 밖으로 나간
만큼만 밀어서 `gt` 한 번에 한 tab 씩 움직인다. 가려진 것은 양끝에서 `<n`(왼쪽)·`n>`(오른쪽)
이 개수로 알린다. tab 을 닫거나 화면이 넓어져 오른쪽에 자리가 남으면 왼쪽에 가려둔 것을 도로
당겨 온다(ADR-0029).

```
<2│ 3 core.go │ 4 editor.go+ │ 5 mouse.go │1>
└ 왼쪽으로 2 개                  오른쪽으로 1 개 ┘
```

반쯤 걸친 tab 은 그리지 않는다. 양끝 표시를 누르면 보고 있는 tab 은 그대로 두고 그 방향으로
한 tab 씩 민다 — 편집하던 파일을 놓지 않고 가려진 쪽을 훑을 수 있다. 그렇게 밀어둔 것은
`gt`/`gT` 로 tab 을 옮기는 순간 활성 tab 을 따라 다시 맞는다.

tabline 은 편집 영역 위에만 있다. sidebar 위에는 걸치지 않고, sidebar 가 열려 있으면
편집 영역 너비만큼만 그려진다(ADR-0005). tab 목록은 sidebar 가 아니라 지금 보고 있는 파일에
딸린 것이기 때문이다. statusBar 는 글자 시작 위치만 그것에 맞추고 줄은 끊지 않는다.

파일별 커서 위치와 스크롤은 tab 을 오가도 그대로 남는다.

### 공백 표시

tab 과 space 는 화면에서 똑같은 빈 칸이라 들여쓰기가 둘로 섞여도 알아챌 수 없다.
tab 은 `»`(U+00BB), space 는 `⋅`(U+22C5) 로 찍어 눈으로 가른다. 항상 켜져 있고 끄는 방법은 없다.
space 마커가 흔한 `·`(U+00B7) 가 아닌 것은 그것이 East Asian Width 가 Ambiguous 라
터미널에 따라 두 칸이 되기 때문이다(ADR-0020).

찍는 자리는 **줄 앞 들여쓰기와 줄 끝 공백뿐**이다. 줄 가운데까지 찍으면 산문과 주석이
점으로 뒤덮여 읽기 어렵다. 가운데 tab 은 마커 없이 빈 칸으로만 벌어진다.
공백뿐인 줄은 줄 전체가 들여쓰기라 전부 찍힌다.

tab 마커는 tab 이 시작하는 한 칸뿐이고 남는 칸은 빈 칸이다 — 남는 칸까지 점으로 채우면
space 와 같아 보인다. tab 폭은 4 칸이므로 줄 앞 tab 하나는 `»` 와 빈 칸 3 개다.

```
»   println("hello")⋅⋅      ← tab 들여쓰기 + 줄 끝 공백 2 개
⋅⋅⋅⋅spaces indent           ← space 4 개 들여쓰기
»   ⋅⋅mixed indent          ← tab 뒤에 space 2 개
a b c                       ← 줄 가운데 공백은 그대로
```

마커는 본문보다 흐린 색(256색 240) 이다. 검색으로 강조된 구간 안에서도 마커는 흐린 색이고
강조 배경은 그대로 이어진다.

### 문법 강조

파일 이름으로 언어를 알아보고 본문에 색을 입힌다(ADR-0039). 열한 언어다 — golang, markdown,
html, css, js, python, shell, makefile, dockerfile, json, yaml. 모르는 확장자(`.txt` 등) 는
색이 없다.

json 은 계열 넷을 한 lexer 로 훑는다 — `.json`·`.jsonc`·`.json5`·`.hjson` (ADR-0055). 넷이 같은
모양에 허용하는 것만 달라서 주석·따옴표 없는 키·`'''` 여러 줄 문자열을 어느 확장자에서나 알아본다.
**강조는 검사가 아니다** — `.json` 에 적은 주석도 주석 색이 입고, 문법이 틀렸다는 것은 그 파일을
읽는 프로그램이 말한다. yaml(`.yaml`·`.yml`) 은 모양이 아주 달라서 lexer 를 따로 둔다.

갈래 | 색 | 나오는 자리
--- | --- | ---
주석 | 108 | 모든 언어 / markdown 의 인용문. **이 표에서 가장 흐리다** — 물러나 있어야 한다
문자열 | 113 | 따옴표 안 / markdown 의 코드 스팬
숫자 | 215 | 숫자 literal / css 의 `#fff`
예약어 | 177 | keyword / html tag 이름, docker 명령, make 지시자, css 속성, yaml 의 `---`
type | 185 | 미리 선언된 이름·새 type / python 의 class, css 선택자, 코드펜스의 언어 이름, yaml 의 `!!str`
부르는 이름 | 111 | 함수 / make 의 대상 이름
값 낱말 | 210 | `nil` `true` `None` / html 의 `&amp;`, css 의 값, json·yaml 의 `true` `null`
값 참조 | 79 | `$(VAR)` `${VAR}` / css 의 `var(--x)`, yaml 의 anchor·alias
키 | 79 | json·yaml 의 키, html 속성 이름, css 의 `--x` 선언
제목 | 45 + 굵게 | markdown 의 `#`
강조 | 177 + 기울임 | markdown 의 `*foo*`
굵게 | 177 + 굵기 | markdown 의 `**foo**`
링크 | 111 | markdown 의 `[글](주소)` 의 주소와 `<주소>`

**어두운 배경에 맞춘 값이다**(ADR-0041). `#1e1e1e` 기준으로 전부 6.8:1 이상이고, 주석이 가장
낮다 — 일부러 그렇다. 밝은 배경에서는 1.5~2.5:1 로 약하다.

같이 나오는 갈래끼리는 색상이 25 도 이상 갈린다. 반대로 **같이 나오지 않는 갈래는 색을 나눠
쓴다** — 강조·굵게가 예약어와, 링크가 부르는 이름과 같은 색이다. markdown 에 예약어·부르는
이름이 없고 코드에 제목·강조·링크가 없어서 한 화면에서 만나지 않는다. 그래서 갈래 열셋이
색 아홉이다.

**키와 값 참조는 예외로 한 화면에 같이 나오면서 같은 색이다.** css 의 `--x: red` 와 `var(--x)`,
yaml 의 키와 anchor 가 그렇다. 자리가 이미 갈라 주기 때문이다 — 키는 줄 앞에 서고 참조는 값
자리에 선다. 갈래를 나눠 둔 것은 색을 나눠야 할 날에 표 한 줄만 고치기 위해서다(ADR-0055).

**겹치면 검색 > 선택 > 문법이다.** 찾은 자리와 고른 범위는 글자색과 배경을 함께 정하고 문법은
글자색만 정해서, 그 구간에서는 문법 색이 보이지 않는다. vim 과 같다. 공백 마커는 그 안에서도
자기 칸을 지킨다 — 주석 안의 줄 끝 공백은 주석색이 아니라 흐린 마커로 그려진다.

여러 줄에 걸치는 것(블록 주석, raw string, 코드펜스, `<script>` 안, 세 겹 따옴표) 은 줄 단위로
문맥을 이어 가며 판정하므로 파일이 아무리 길어도 색이 어긋나지 않는다.

링크는 **주소만** 칠한다. `[글]` 의 글은 읽는 사람에게 보일 문장이라 본문과 같이 둔다.
상대 경로(`[명세](docs/spec.md)`) 도 링크다. 인용문(`>`) 은 줄 단위라 그 안의 링크는 따로
칠하지 않는다.

**코드펜스 안은 그 언어로 훑는다**(ADR-0040). 여는 표시 뒤 첫 낱말이 언어를 정한다 —
`go`(`golang`), `md`(`markdown`), `html`, `js`(`javascript`), `css`, `py`(`python`),
`sh`(`bash` `shell` `zsh`), `make`(`makefile`), `docker`(`dockerfile`) 다. **모르는 이름이나
이름이 없으면 색이 없다.** 펜스는 겹칠 수 있다.

html 의 `<script>` 안은 js, `<style>` 안은 css 다. `type` 속성은 보지 않는다.

**닫는 표시가 안쪽 언어보다 세다.** 펜스의 닫는 줄과 `</script>` 는 안쪽에서 문자열이나 주석이
열려 있어도 블록을 끝낸다. 브라우저가 `</script>` 를 js 문자열 안에서도 끝으로 읽는 것과 같다.

### 줄번호

편집 영역 왼쪽에 `절대 상대` 순서로 붙는다. 상대번호가 본문에 붙는 쪽이라 `5j` 처럼 셀 때
눈이 덜 움직인다. 커서 줄의 상대번호는 `0` 이다 — 절대번호가 바로 옆에 있어서 거기에 또 찍지 않는다.

```
  1  4 package main
  2  3
  3  2 func main() {
  4  1         println("hi")
  5  0         return          ← 커서
  6  1 }
```

상대번호만 흐린 색이다(256색 244, sidebar 와 같은 값). 절대번호는 노랑(ANSI 3) 이다.
본문 색은 위 「문법 강조」에 있다.

자릿수는 절대번호가 전체 줄 수를, 상대번호가 화면 높이를 따라간다. 상대번호는 화면 밖으로
나가면 볼 수 없으므로 줄 수와 무관하다. 각각 최소 3 칸과 2 칸이라 짧은 파일에서도 본문이
너무 왼쪽에서 시작하지 않는다.

wrap 되어 이어지는 화면 행은 번호 칸이 빈 칸이다. 번호가 있는 행이 곧 논리 줄의 시작이다.

번호 칸만큼 본문이 좁아지므로 줄바꿈도 그 너비에서 일어난다. 떼고 나면 본문이 20칸 아래로
떨어지는 좁은 화면에서는 sidebar 와 같은 규칙으로 그리지 않는다.

### sticky 머리줄

지금 보는 곳을 감싸는 제목·정의를 편집 영역 맨 위에 붙인다. VSCode 의 sticky scroll 과 같다
(ADR-0049).

**기준은 커서가 아니라 화면 맨 윗줄이다.** 그래서 위로 밀려 안 보이게 된 것만 붙는다 —
화면에 이미 있는 제목이 위에 한 번 더 그려지지 않고, 파일 첫 화면에서는 아무것도 붙지 않는다.

```
  1    # Spec                    ← 감싸는 제목들. 줄번호가 이어지지 않는다
332 88 ## Mode
345 75 ### Normal mode
408 12 #### 단어 경계
412  8 `foo.bar` 는 세 단어다.   ← 여기부터 본문
413  7
```

감싸는 것을 전부 붙인다. markdown 은 `#` 개수가 깊이라 최대 여섯이고, 코드는 들여쓰기가
깊이다. 늘 켜져 있고 끄는 길은 없다 — 강조하지 않는 파일에서는 저절로 붙지 않는다.

**본문과 색으로 가르지 않는다.** 줄번호가 늘 나오므로 번호가 뚝 끊기는 것이 곧 표시다.
상대번호는 그 줄까지 가는 실제 `k` 수이고, 화면 높이보다 멀면 그 칸이 빈다.

**자리를 떼지 않고 덮는다.** 그래서 가려지는 본문 줄이 생기고, 화면 기하는 하나도 바뀌지 않는다.
커서는 덮이지 않는다 — 화면이 그만큼 더 올라간다. 편집 영역 절반을 넘게 덮지 않으며, 넘치면
바깥쪽부터 버린다.

머리줄을 누르면 그 줄로 간다.

무엇이 아래 줄들을 거느리는지는 언어가 정한다. markdown 은 제목이고(코드펜스 안의 `#` 은
아니다), makefile 은 대상 줄이고, dockerfile 에는 없다. 나머지는 블록을 여는 줄이라
autoindent 와 같은 규칙을 쓴다.

### sidebar (filetree)

기본으로 열려 있다.`:tree` 로 여닫는다. cwd 가 뿌리이고, 디렉터리를 펼치면 그 자리에서
들여쓰기로 벌어진다. cwd 를 읽지 못하면 트리 없이 연다.
`.git` 은 어느 깊이에서든 감추고 나머지 숨김 파일은 보인다.

sidebar 는 화면 맨 윗줄부터 statusBar 앞줄까지다. tabline 은 그 오른쪽, 편집 영역 위에만 있다.
statusBar 는 sidebar 아래를 지나 화면을 가로지르고, 그 아래 칸에는 mode 가 온다.

```
▾ zn/                         │ 1 main.go
  ▸ docs/                     │  1  0 package main
  ▾ internal/                 │  2  1
      main.go                 │  3  2 func main() {
    README.md                 │  4  3 }
                                NORMAL  main.go
                                1:1  (5 줄)
└──────────── 32칸 ────────────┘└─ 나머지가 편집 영역 ─┘
                               └ 줄번호 ┘└ 본문 ┘
```

디렉터리는 먼저 오고 그 안은 이름순이다. 펼침 표시는 `▾`(펼침) `▸`(접힘) 이고 파일은 그 자리가
빈 칸이라 같은 깊이의 이름이 나란히 선다. symlink 는 따라가지 않고 `@` 를 붙인다.

펼칠 때마다 그 디렉터리를 다시 읽는다. 접었다 펴는 것이 곧 새로고침이다.

보는 파일이 바뀌면 트리가 그 자리를 펼치고 고른다(ADR-0019). CLI 인자로 시작할 때, 팔레트나
트리에서 파일을 열 때, `gt`/`gT`·tabline 클릭으로 tab 을 옮길 때, `:q` 로 tab 을 닫아 다른
파일이 드러날 때, `:tree` 로 트리를 다시 열 때다.
지나는 길의 디렉터리 중 접혀 있는 것만 펼치고 이미 펼쳐진 것은 다시 읽지 않는다 —
다시 읽으면 그 아래 펼쳐 둔 것이 통째로 접힌다.
읽어야 할 디렉터리가 있으면 한 층씩 읽어 내려가므로 자리를 잡는 것이 한 박자 늦을 수 있다.

이때 sidebar 를 열지는 않는다. `:tree` 로 닫아둔 상태면 아무 일도 하지 않고, 좁은 화면이라
감춰진 상태면 트리만 펼쳐 둔다. 뿌리 밖의 파일, symlink 디렉터리 안쪽, 이름 없는 buffer 는
고른 자리를 건드리지 않는다.

색은 파일 종류로 나뉜다(ADR-0005). 256색 고정값이다.

종류 | 색
-----|----
디렉터리 | 117
`.go` | 81
`.md` `.txt` | 150
`.html` `.css` `.js` | 179
그 외 | 기본색
gitignore 된 것 | 244 (종류별 색을 덮어쓴다)

무시 여부는 규칙을 직접 구현하지 않고 디렉터리를 펼칠 때 `git check-ignore` 에 한 번 묻는다.
git 이 없거나 저장소 밖이면 아무것도 흐리게 하지 않는다. 묻는 것도 읽기와 같은 작업 안에서
돌므로 펼치는 키가 그것을 기다리지 않는다(아래 「큰 디렉터리」).

**지금 보고 있는 파일은 굵은 글씨다.** 종류별 색 위에 덧입힌다 — 색은 그 파일이 무엇인지,
굵기는 지금 보고 있는지다. 고른 자리를 나타내는 터미널 커서는 포커스가 트리에 있을 때만
그려지므로, 편집 중에 트리가 지금 자리를 나타내는 것은 이 굵기뿐이다.

굵기는 이 한 뜻으로만 쓴다. 디렉터리는 색(117) 과 `▸`/`▾` 표시와 `/` 접미로 이미 갈리므로
굵게 하지 않는다. 열려 있는 tab 을 **전부** 구분하지는 않는다 — 그것은 tabline 이 한다(ADR-0022).

#### 큰 디렉터리

**디렉터리 읽기는 백그라운드 작업이다**(ADR-0032). 펼침 표시(`▾`) 는 누른 그 자리에서 서고
자식 자리에는 `… 읽는 중` 한 행이 선다.

```
▾ big/
    … 읽는 중
```

다 읽으면 그 행이 자식으로 바뀐다. 편집기는 그동안 멈추지 않고, 도는 작업은 `:jobs` 에
`디렉터리 읽기 <경로>` 로 보인다. 읽는 중에 접으면 그 작업이 취소된다 — 늦게 도착한 결과는
접힌 것을 도로 펼치지 않는다.

**항목 수에 상한은 없다.** 십만 개짜리 디렉터리도 끝까지 읽어 다 보여준다. 감추면 그 파일로 갈
길이 트리에서 없어지고, 행이 많아도 그리는 값이 사람에게 닿지 않는다(자식 5 만 개에서 키 한 번이
1.2ms 다). 다 읽은 개수는 `:jobs` 의 그 줄에 `50,001 개` 로 남는다.

`… 읽는 중` 은 파일이 아니다. gitignore 된 항목과 같은 흐린 색이고, 골라서 `Enter` 를 눌러도
아무 일도 하지 않으며 "보고 있는 파일" 표시도 받지 않는다.

#### 포커스와 key mapping

`Ctrl+W` 는 vim 의 window 명령 접두 키다. pane 이 둘뿐이라 순환이 곧 왕래다.
sidebar 가 안 보이면 편집 영역에 머물고 왜 못 갔는지 아래 줄에 알린다 —
`:tree` 로 닫아 두었으면 「트리가 닫혀 있습니다」, 화면이 좁아 감춘 것이면 「화면이 좁아 트리를
열 수 없습니다」다. 아무 일도 나지 않으면 키가 먹었는지 알 수 없다.

키 | 기능 | 기타
---|------|-----
ctrl+w ctrl+w | 편집 영역 ↔ sidebar | `ctrl+w w` 도 같다
esc | 편집 영역으로 | sidebar 에서만
↑ ↓ | 트리 이동 | `k` `j` 도 같다
enter | 디렉터리면 펼치기/접기, 파일이면 열기 | 파일을 열면 포커스도 편집 영역으로 간다
mc | 새 파일·디렉터리 만들기 | 아래 「파일 만들고 지우고 이름 바꾸기」
md | 고른 항목 지우기 | 파일은 곧바로, 디렉터리는 묻고 나서(ADR-0057)
mm | 이름 바꾸기·자리 옮기기 | 지금 경로가 채워진 칸을 준다
클릭 | 그 항목을 고르고 `enter` 와 같이 연다 | 포커스도 sidebar 로 온다
휠 | 트리를 굴린다 | 고른 항목은 움직이지 않는다

sidebar 에 포커스가 있으면 statusBar 의 mode 가 `TREE` 이고 아래 줄에 고른 항목의
뿌리 기준 상대 경로가 뜬다. `ctrl+w` 를 누르고 다음 키를 기다리는 동안은 그 줄 오른쪽 끝에
누른 접두 키가 보인다(편집 영역과 같다). **고른 항목 위에 터미널 커서가 놓이는 것이 곧 포커스 표시다** —
따로 반전을 칠하지 않는다(ADR-0005).

`enter` 로 파일을 열면 새 tab 이 된다. 이미 열려 있으면 새로 열지 않고 그 tab 으로 옮긴다.
일반 파일이 아니면(디렉터리를 가리키는 symlink, FIFO 등) 열지 않고 아래 줄에 알린다.

sidebar 는 `:` 를 받지 않는다.

트리 아래 빈 자리를 클릭하면 아무 일도 하지 않는다. 트리가 화면보다 짧아도 구분선은
아래까지 이어지므로, 그 빈 행은 누를 것이 없는 자리다. 휠로 고른 항목이 화면 밖으로
나가면 커서를 놓을 곳이 없어 포커스 표시가 잠시 보이지 않는다 — 다음 `j`/`k` 가 데려온다.

한글 입력 상태의 키는 편집 영역과 같이 두벌식 자리의 영문 키로 되돌려 받는다
(`ㅓ` 가 `j` 다). Normal mode 의 「한글 입력 상태」 를 참고한다.

#### 파일 만들고 지우고 이름 바꾸기

`mc` 로 만들고 `md` 로 지우고 `mm` 으로 이름을 바꾼다(ADR-0054). `m` 은 `ctrl+w` 와 같은 접두
키라 기다리는 동안 showcmd 자리에 보이고, 짝이 없는 조합(`mx`) 은 아무 일도 하지 않는다.

**`mc` 는 이름을 받는다.** statusBar 아래 줄이 `새 파일: docs/` 가 되고 그 뒤에 치는 것이
이름이다. 만들 자리는 고른 항목 기준이다 — 디렉터리를 골랐으면 그 안, 파일을 골랐으면 그 파일이
있는 디렉터리다. 접혀 있던 디렉터리는 만든 뒤 펼쳐진다.

```
새 파일: docs/guide.md
```

`enter` 가 만들고 `esc` 는 그만둔다. 이름을 다 지워도(`backspace`) 그만두는 것이다 —
명령줄에서 `:` 까지 지우면 나가는 것과 같다. 이름은 글자라 한글 입력 상태에서도 되돌려지지
않는다 — `한글.txt` 를 치면 그 이름 그대로다(ADR-0008).

이름 | 하는 일
-----|--------
`main.go` | 그 자리에 빈 파일을 만들고 **tab 으로 열어 편집 영역으로 간다**
`a/b/c.go` | 없는 `a/`·`a/b/` 를 같이 만든다
`docs/` | 디렉터리만 만든다. 열 것이 없으므로 트리에 머문다

이미 있는 이름은 만들지 않고 「이미 있습니다」로 알린다. 뿌리 밖으로 나가는 이름도 만들지
않는다 — 뿌리 안에 머무는 `../` 는 위층을 가리키는 것이라 된다.

**`md` 는 파일을 묻지 않고 지운다.** 두 키로 끝나고 트리에 머문다. 무엇이 사라졌는지는
아래 줄의 `지웠습니다: docs/spec.md` 가 말한다 — 묻지 않으므로 이것이 아는 유일한 자리이고,
지나간 것은 `:messages` 에 남는다(ADR-0053, ADR-0057).

**디렉터리만 묻는다.** 안의 것까지 통째로 지우는데 접혀 있으면 트리는 이름 한 줄만 보여줘서,
화면에 없는 것이 사라지는 유일한 자리이기 때문이다. 아래 줄이
`안의 것까지 모두 지울까요? docs/ (y/n)` 이 되고 커서는 지울 행에 그대로 남는다.
**`y` 만 지우고 다른 키는 전부 취소다** — `ctrl+c` 도 여기서는 편집기를 끄지 않는다.

지우지 않는 셋이 있다. **tab 에 열려 있는 파일**(디렉터리면 그 아래 전부를 본다) 은
「먼저 닫아 주세요」로 돌려보낸다 — buffer 와 디스크가 어긋난 채로 남으면 `:w` 한 번에 지운 것이
되살아난다. **뿌리**는 트리 자체라 지울 수 없고, `… 읽는 중` 은 파일이 아니다.

**`mm` 은 지금 경로를 채워 준다.** 아래 줄이 `새 이름: docs/spec.md` 가 되고 커서는 그 끝이다.
한 글자만 고치거나 확장자만 두고 앞을 고치는 일이 대부분이라 빈 칸에서 시작하지 않는다.

```
새 이름: docs/design.md
```

**치는 것은 이름이 아니라 경로다.** 그래서 앞부분을 고치면 자리를 옮기는 것이 된다 —
`docs/spec.md` 를 `notes/spec.md` 로 고치면 `notes/` 로 옮겨지고, 없는 디렉터리는 같이 만들어진다.
기준은 고른 자리가 아니라 뿌리다. 디렉터리도 같은 길로 이름을 바꾸고 안의 것은 딸려 간다.
`backspace` 로 다 지워도 이 화면에 남는다 — 그만두는 것은 `esc` 다.

**그 파일을 열어둔 tab 은 새 이름을 따라간다.** 편집하던 내용과 커서 자리는 그대로이고,
저장하지 않은 변경도 새 이름으로 저장된다. 디렉터리를 옮기면 그 아래 파일을 보던 tab 도 같이
따라간다. 문법 강조는 새 확장자로 다시 고른다.

이미 있는 이름 위로는 옮기지 않는다 — `os.Rename` 은 묻지 않고 덮어쓴다. 대소문자만 바꾸는 것
(`readme.md` → `README.md`) 은 같은 파일이라 된다. 뿌리, 자기 안으로 옮기기, 뿌리 밖도 거절한다.
확인은 묻지 않는다 — 잃는 것이 없고 `mm` 을 한 번 더 눌러 되돌릴 수 있다.

만들거나 지우거나 옮긴 뒤에는 그 디렉터리를 다시 읽어 트리를 맞춘다. 그 아래 펼쳐 두었던 것은
접힌다 — 새로고침이 곧 접었다 펴는 것이기 때문이다(ADR-0032). 옮긴 것은 옮겨간 자리를 펼쳐서
고른 자리가 그 파일을 따라간다. **지운 것은 되돌릴 수 없다.** `u` 는 buffer 안의 일이라
지운 파일에는 닿지 않는다.

### statusBar

화면 아래 두 줄이다. 위 줄은 mode 와 파일 경로, 그리고 오른쪽 끝에 git 상태다.
경로 뒤에는 마커가 붙는다 — `[+]` 는 저장하지 않은 내 변경이고, `[!]` 는 마지막으로 맞춰 봤을 때
파일이 밖에서 달라져 있었다는 것이다(ADR-0031). 둘이 같이 붙으면 양쪽에 잃을 것이 있다는 뜻이다.
아래 줄은 mode 가 정한다 — normal/insert 는 `줄:칸  (N 줄)`, command mode 는 치고 있는 명령,
sidebar 는 고른 항목의 경로다. 아래 줄 오른쪽 끝은 showcmd 자리다.

mode 는 sidebar 아래 칸에, 파일 경로는 편집 영역 아래에 놓는다. 둘 다 자기가 가리키는 것
바로 밑에 서게 된다 — `TREE` 는 트리 아래에, 경로는 그 파일을 편집하는 자리 아래에 온다.
아래 줄은 mode 를 따라가지 않고 위 줄의 경로와 세로로 맞춘다. 명령줄과 커서 위치는
편집 중인 파일에 딸린 것이기 때문이다.

```
▾ zn/                         │ 1 editor.go
  ▸ docs/                     │  1  0 package core
NORMAL                          internal/core/editor.go    master(f6cacbd*)
                                1:1  (550 줄)                            3g
└─ mode ────┘└─ 위 줄만 반전 ──────────────────────────────────────────────┘
                                                                       └ showcmd
```

sidebar 가 없으면 mode 를 놓을 왼쪽 칸 자체가 없으므로 경로 앞에 나란히 붙인다.

```
NORMAL  internal/core/editor.go              master(f6cacbd*)
1:1  (550 줄)                                              3g
```

#### git 표시

`branch(commit)` 이고 저장하지 않은 변경이 있으면 commit 뒤에 `*` 가 붙는다.
detached HEAD 는 가리킬 branch 가 없어서 괄호 없이 짧은 해시만 찍는다(`a1b2c3d*`).
저장소가 아니거나 commit 이 하나도 없으면 아무것도 찍지 않는다.

dirty 는 `git status --porcelain` 기준이라 untracked 파일도 센다. tabline 의 `+` 와 파일 경로
뒤의 `[+]` 는 buffer 의 미저장 상태이고, 이 `*` 는 저장소의 미commit 상태다.

기준은 활성 파일이 아니라 cwd 다 — sidebar 트리의 뿌리와 같다. 그래서 tab 을 오가도 바뀌지 않는다.

값은 5 초마다, 그리고 저장한 직후와 파일을 연 직후에 다시 읽는다(ADR-0009, ADR-0030). 화면을 그릴 때는 읽지
않는다 — 외부 프로세스라 키 입력마다 부를 수 없다. 읽는 것은 `git 상태` 라는 백그라운드
작업이라 편집기가 멈추지 않고, 도는 동안에는 `:jobs` 목록과 statusBar 진행 표시에 보인다.
바깥에서 `commit`/`checkout` 을 하면 키를 누르지 않아도 5 초 안에 따라온다.
편집기를 여는 길에는 읽지 않아서 첫 화면에서는 잠깐 비어 있다.

붙일 칸이 없으면 넣지 않는다. mode 와 파일 이름이 먼저다.


## Mode

모드는 다음과 같이 구성 한다.

- normal mode
- insert mode
- visual mode
- copy mode
- command-line mode
- search mode

mouse 는 mode 마다 조금씩 다르게 받는다. 「Mouse」 절에 모아 적는다.

### Normal mode

vim 의 normal mode 와 동일하다.
cursor 를 옮기고, 파일을 편집 한다.

커서는 글자 위에 있다. 줄 끝 다음 칸에는 설 수 없다. 그 자리는 insert mode 에서만 간다.

#### key mapping

키 | 기능 | 기타
---|------|-----
i | 현재 커서 자리에서 insert mode 로 | 커서는 그대로
a | 현재 커서 바로 뒤에서 insert mode 로 | 줄 끝 다음 칸까지 갈 수 있다
o O | 아래 / 위에 줄을 만들고 insert mode 로 | 새 줄은 들여쓰기를 받는다. 아래 「자동 들여쓰기」 참고
v V | 글자 / 줄 단위로 범위를 고른다. visual mode 로 | 아래 「visual mode」 참고

#### 이동 키의 단위와 숫자

`j`/`k` 는 논리 줄이고 `↓`/`↑` 는 화면 행이다. 짧은 줄에서는 둘이 같고, 화면보다 긴 줄에서만
갈린다 — `j` 는 그 줄을 통째로 건너뛰고 `↓` 는 그 줄 안에서 한 행 내려간다.
vim 의 `j` 와 `gj` 가 나뉜 것과 같다(ADR-0006).

이동 키 앞에 숫자를 치면 그만큼 움직인다(`10j`, `20k`, `5l`, `3w`). 갈 곳이 모자라면 양끝에서
멈춘다. 숫자는 이동 키와 `x`·`d` 에만 붙고, 다른 키가 오면 버려진다 — `3i` 는 `i` 와 같다.
`$` `gg` `G` 는 숫자의 뜻이 다르다 — `$` 는 줄 수(`3$` 는 두 줄 아래의 줄 끝) 고
`gg`/`G` 는 줄 번호(`42G`) 다.
`0` 은 숫자의 첫 자리가 될 수 없다. 줄 맨 앞으로 가는 키이기 때문이다.
`10j` 처럼 둘째 자리부터는 숫자다.

#### 단어 경계

단어는 글자 부류가 바뀌는 자리에서 끊는다. 부류는 넷이다 — 공백 / 단어 글자(영문·숫자·`_`) /
한글·한자·가나 / 그 밖의 문장부호. vim 과 같은 나눔이라 `한글abc` 는 두 단어이고
`foo.bar` 는 세 단어다. `foo_bar` 와 `fooBar` 는 한 단어다.

`W` `B` `E` 는 공백으로만 끊어서 `foo.bar(baz)` 가 한 덩어리다.

#### 지우기

`d` 는 뒤에 이동 키가 붙어서 지울 범위를 정한다. 이동 키는 위 표의 것을 그대로 쓴다 —
`dw` `dW` `de` `dE` `db` `dB` `dh` `dl` `d←` `d→` `d0` `d^` `d$` `dj` `dk` `dgg` `dG` 다.
`dd` 는 커서 줄이다. 지울 범위는 그 이동을 실제로 실행해서 얻으므로 "`w` 가 가는 데까지" 가
곧 "`dw` 가 지우는 데까지" 다(ADR-0013).

`dd` `dj` `dk` `dgg` `dG` 는 줄 단위다. 커서 칸과 상관없이 줄 전체가 사라지고 커서는 그 자리를
메운 줄의 첫 비공백에 선다. 나머지는 글자 단위이고 커서는 지운 자리에 선다.
`e` `E` 는 커서가 선 글자까지 지운다.

숫자는 `d` 앞뒤에 각각 붙고 곱해진다 — `3dd` 는 세 줄, `d3w` 는 세 단어, `3d2w` 는 여섯 단어다.
`dG` `dgg` 의 숫자는 이동 키에서와 같이 줄 번호다(`d2G` 는 둘째 줄까지).

`dw` 는 줄을 넘지 않는다. 줄의 마지막 단어에서 쳐도 줄 끝까지만 지우고 다음 줄이 올라오지
않는다. 줄을 없애는 키는 `dd` 다. 숫자가 붙었을 때 중간 걸음은 줄을 넘는다 — `2dw` 는 다음
줄의 단어까지 지운다. vim 과 같다.

검색 키(`n` `N` `*` `#` `/` `?`) 와 `↑` `↓` 는 `d` 뒤에 받지 않는다. 짝이 없는 조합은 아무 일도
하지 않으므로 잘못 누른 `d` 는 `esc` 로 무른다. `c` `y` 도 같은 범위를 쓴다.

`x` 는 커서 자리 글자를 지운다. `dl` 과 같아서 줄 끝을 넘지 않고, 빈 줄에서는 아무 일도 없다.

지우기 한 번이 되돌리기 한 구간이다. 지운 내용은 무명 register 에 남고 `p`/`P` 로 도로 붙인다 —
아래 「복사와 붙여넣기」다.

숫자나 접두 키를 치는 동안 그것을 statusBar 아래 줄 오른쪽 끝에 보여준다(vim 의 `showcmd`).
붙일 칸이 없으면 보여주지 않는다 — 커서 위치가 밀려나는 것이 더 나쁘다.

#### 바꾸기

`c` 는 지우고 insert mode 로 들어간다. 범위 계산은 `d` 와 같은 것을 써서 `cw` `c3w` `3cc`
`cgg` `c$` `cj` `cG` 가 `d` 쪽 표를 그대로 따라온다. 바꾼 내용은 `d` 처럼 register 에 남는다.

**`cw` 는 단어 뒤 공백을 남긴다.** 커서가 공백 아닌 글자 위에 있으면 `ce` 처럼 단어 끝까지만
바꾼다 — 단어를 갈아 끼우고 나면 뒷 공백이 그대로 있어야 하기 때문이다. `dw` 와 갈리는 자리다.

```
foo    bar     커서가 f 위
dw  →  bar         공백까지 지운다
cw  →     bar      foo 만 지우고 공백 네 개는 남긴다
```

이미 단어의 마지막 글자 위면 그 글자 하나가 전부다. 예외는 첫 걸음에만 걸려서 `c2w` 의
둘째 걸음부터는 그냥 `e` 다. 커서가 공백 위면 예외가 아니라 `dw` 와 같이 건너뛴다 —
바꿀 것이 그 공백이다. 빈 줄에서는 아무것도 바꾸지 않고 insert 로 간다(ADR-0033).

**`cc` 는 줄을 없애지 않는다.** `dd` 는 줄이 사라지지만 `cc` 는 그 자리에서 다시 치는 것이라
빈 줄 하나가 남는다. **첫 줄의 들여쓰기는 남긴다** — 들여쓴 코드에서 `cc` 를 칠 때마다 tab 을
다시 치지 않는다. `3cc` 는 세 줄이 들여쓴 한 줄이 되고, `cj` `ck` `cG` `cgg` 도 같다.

```
func main() {          `cc` 를 둘째 줄에서
»   foo                →  »              tab 은 남고 그 뒤에서 친다
}
```

`o` `O` 도 이제 들여쓰기를 받는다(아래 「자동 들여쓰기」). 다만 가져오는 곳이 다르다 —
`cc` 는 있던 줄을 비우는 것이라 들여쓰기가 이미 그 줄에 붙어 있고, `o` `O` 는 없던 줄을
만드는 것이라 언어 규칙이 앞 줄을 보고 정한다.

**지운 것과 이어 친 글자가 한 번의 `u` 로 함께 돌아간다.** `c` 한 번이 되돌리기 한 구간이다.
vim 과 같다.

모르는 motion 이면 mode 도 바뀌지 않는다. `cq` 는 아무 일도 하지 않으므로 잘못 누른 `c` 는
`esc` 로 무른다 — `dq` 와 달리 이것이 중요한 것은, insert 로 들어가 버리면 이어서 친 글자가
파일에 들어가기 때문이다.

#### 복사와 붙여넣기

`y` 는 `d` 와 똑같은 operator 다. 범위 계산을 같이 쓰므로 `yy` `y3w` `3yy` `ygg` `y$` 가
`d` 쪽 표를 그대로 따라온다. `w` 의 줄끝 예외도 물려받아서 `y2w` 는 줄을 넘지 않는다(ADR-0017).

`y` 는 파일을 건드리지 않는다 — dirty 도 되돌리기 구간도 서지 않는다. 커서는 그 motion 이
데려다 놓는 자리 그대로다. 뒤로 가는 motion 이면 범위의 시작으로 가고(`yb` `yk` `ygg`)
앞으로 가는 것이면 제자리다(`yw` `yy` `y$` `yG`).

**register 는 무명, 숫자 열 개, 문자 스물여섯 개다.** `editor` 가 들고 있어 tab 을 넘어 붙는다.

register | 무엇이 들어가나
---------|----------------
무명 | 마지막으로 담거나 지운 것. 이름을 대지 않은 `p`/`P` 가 읽는다. 이름을 대도 여기에 같이 담긴다
`"0` | 마지막으로 **복사한** 것. 지우기는 여기를 건드리지 않는다
`"1`~`"9` | 지우거나 바꾼 것. 지울 때마다 한 칸씩 밀려 `"9` 를 넘어간 것은 사라진다
`"a`~`"z` | 손으로 이름을 대서 담는 자리. 저절로 밀리지 않는다
`"A`~`"Z` | `"a`~`"z` 와 같은 자리인데 덮지 않고 **뒤에 잇는다**

`x` 로 글자 하나를 지운 것도 숫자 링을 민다. **vim 과 갈리는 자리다** — vim 은 한 줄 안에서
지운 것을 소삭제 register(`"-`) 로 보내고 숫자 링을 건드리지 않는다. 규칙을 하나로 둔 까닭은
ADR-0058 에 적었다. 바꿀 것이 없었던 `c`(빈 줄의 `cw`) 는 링을 밀지 않는다.

`"{이름}` 을 앞에 붙여 자리를 고른다.

- **붙일 때** — `"1p` 는 마지막으로 지운 것, `"3P` 는 세 번 전에 지운 것을 위에, `"ap` 는
  `"a` 에 모아 둔 것을 붙인다. 숫자 되풀이는 이름 앞뒤 어디에 붙여도 된다(`3"1p` = `"13p`)
- **담을 때** — `"ayy` `"add` `"acw` `"ax` 가 `"a` 에 담는다. `"Ayy` 는 `"a` 에 잇는다.
  visual 에서는 범위를 고른 뒤에 댄다 — `V j "ay` 다
- **이름을 대면 숫자는 건드리지 않는다** — `"add` 는 `"a` 와 무명에만 담고 링을 밀지 않는다.
  `"ayy` 도 `"0` 을 건드리지 않는다. vim 과 같다

덧붙일 때 둘 중 하나라도 줄 단위면 결과도 줄 단위다. 둘 다 글자 단위면 이음매에서 줄이 하나로
붙는다 — `"ayw` `"Ayw` 로 낱말 둘을 모으면 한 줄이다.

**담는 것은 문자 이름만 받는다.** `"1yy` 처럼 숫자에 담는 것은 없고, 그렇게 치면 지우지도
담지도 않고 아무 일도 일어나지 않는다. 이름을 받지 않는 키(`"aw` `"agg` `"a>>`) 도 같다.
`"` 뒤의 `esc`·`ctrl+c` 는 이름을 무르고, 한 번 더 누르면 제 일을 한다.

담긴 것 없는 이름(`"q`) 은 빈 register 라 `"qp` 도 조용하다.

담긴 것은 `:registers` 로 본다(아래 「register 목록」).

붙이는 자리는 register 가 줄 단위인지 글자 단위인지로 갈린다.

register | `p` | `P` | 커서가 서는 자리
---------|-----|-----|------------------
줄 단위(`dd` `yy` `dj` …) | 커서 줄 **아래**에 줄로 끼운다 | 커서 줄 **위** | 붙인 첫 줄의 첫 비공백
글자 단위(`dw` `yw` `x` …) | 커서가 선 글자 **뒤** | 커서 **자리** | 한 줄이면 붙인 마지막 글자, 여러 줄이면 첫 글자

숫자는 되풀이라 `3p` 는 세 번 붙인다. 붙여넣기 한 번이 되돌리기 한 구간이라 `3p` 도 `u` 한 번에
전부 사라진다. register 가 비어 있으면 아무 일도 하지 않는다 — 알림도 없고 dirty 도 서지 않는다.

시스템 클립보드와는 잇지 않았다. 터미널 쪽 붙여넣기는 insert mode 에서 그대로 받는다.

#### 한글 입력 상태

입력기가 한글인 채로 normal mode 에 오면 자모를 **두벌식 자리의 영문 키로 되돌려** 받는다.
`ㅁ` 은 `a` 이고 `ㅓ` 는 `j` 다(ADR-0008).

조합된 음절과 겹자모는 그것을 만든 키 여럿으로 풀린다 — `ㅘ` 는 `h` `k`, `어` 는 `d` `j`,
`값` 은 `r` `k` `q` `t` 다. 그래서 키 하나가 동작 여럿이 될 수 있다. 풀린 키를 먹이는 도중
mode 가 바뀌면 남은 키는 버린다 — `얌`(`d` `i` `a`) 은 insert mode 로 들어가고 `a` 는 버려진다.

키가 곧 동작인 mode 에만 적용된다 — normal, sidebar, 종료 확인창. insert mode 와 명령줄
mode 에서는 한글이 글자다.

`G` `B` `V` 는 한글 상태에서 낼 수 없다. `ㅎ` `ㅠ` `ㅍ` 는 shift 자리에 다른 글자가 없어서
`g` `b` `v` 와 구분되지 않는다. 된소리가 있는 `W`(`ㅉ`) `E`(`ㄸ`) `T`(`ㅆ`) 는 낼 수 있다.

마지막으로 누른 키는 입력기가 조합 중이라 편집기에 도착하지 않는다. 그만큼 동작이 밀리는 것은
편집기 밖의 일이라, 확실하게 하려면 입력기를 mode 에 맞춰 바꾸는 설정을 같이 써야 한다.

### insert mode

vim 의 insert mode 와 동일 하다.
현재 커서 위치에 내용을 삽입한다.

커서는 글자 사이에 있다. 줄 끝 다음 칸까지 갈 수 있다.

#### key mapping

키 | 기능 | 기타
---|------|-----
(글자) | 커서 자리에 넣는다 | grapheme cluster 단위. 한글·이모지도 한 글자
enter | 줄을 나눈다 | 새 줄이 들여쓰기를 받는다. 아래 「자동 들여쓰기」 참고
backspace | 앞 글자를 지운다 | 줄 시작이면 앞 줄과 합친다. 커서 앞이 들여쓰기뿐이면 한 단위를 지운다
tab | 한 단위 들여쓴다 | 다음 단위 경계까지 민다. markdown 목록에서는 줄 전체가 들어간다
shift+tab | 한 단위 내어쓴다 | 지금 줄을 당긴다. 커서는 치던 자리를 따라간다
esc | normal mode 로 | 커서가 왼쪽으로 한 글자 간다. vim 과 같다
↑ ↓ ← → | 커서 이동 | 되돌리기 구간이 끊긴다. vim 과 같다

붙여넣기는 여러 줄이어도 그대로 들어간다. **자동 들여쓰기가 붙지 않는다** — 붙으면 원래
들여쓰기 위에 얹혀 줄마다 오른쪽으로 밀린 계단이 된다.

### 자동 들여쓰기

줄을 새로 만들면 그 줄이 들여쓰기를 받는다. insert 의 `enter`, `o`, `O`, `r<Enter>` 넷이다.
붙여넣기는 아니다. 끄는 방법은 없다(ADR-0047).

**언어를 보고 정한다.** 파일 이름으로 언어를 알아보는 것은 문법 강조와 같은 표다(ADR-0039).

언어 | 한 단계 더 들어가는 자리 | 한 단계 나오는 자리
--- | --- | ---
golang js css | 닫히지 않은 `{` `(` `[`, `case`/`default` 로 끝나는 `:` | `}` `)` `]`, `case` `default`
python | 줄 끝의 `:`, 닫히지 않은 괄호 | `else` `elif` `except` `finally` `case`, `)` `]` `}`
shell | 줄 끝의 `then` `do` `in` `else`, `{` `(` | `fi` `done` `esac` `else` `elif` `;;`, `}` `)`
html | 같은 줄에서 닫히지 않은 tag | `</tag>`
dockerfile | `\` 로 이어지기 시작하는 줄 | 이어짐이 끝난 다음 줄
makefile | 대상 줄 다음은 언제나 tab 하나 | 없음
markdown | 없음 — 목록 표시를 이어 쓴다 | 없음
그 밖 | 앞 줄의 공백을 그대로 잇는다 | 없음

**한 번에 한 단계뿐이다.** 한 줄에서 두 겹을 열어도(`foo({`) 한 단계다.

문자열과 주석 안의 괄호는 세지 않는다. `s := "{"` 다음 줄은 들어가지 않는다.

#### 닫는 표시를 치는 순간

줄 앞이 들여쓰기뿐인 자리에서 닫는 표시를 치면 **그 줄이 통째로 한 단계 당겨진다.**
화면에 이미 있는 글자가 움직이는 자리는 여기 하나뿐이다.

```
func f() {
»   »   foo()
»   »   |          ← 여기서 `}` 를 치면
        ↓
func f() {
»   »   foo()
»   }|             ← 줄이 당겨진다
```

커서 앞에 글자가 하나라도 있으면 움직이지 않는다. 글을 쓰다 만난 `}` 는 그 줄의 자리를
바꾸지 않는다.

낱말로 닫는 언어(shell 의 `fi`) 는 **낱말이 끝나야** 당긴다. `fi` 두 글자만으로 당기면
`file=x` 를 칠 때 줄이 튄다. 뒤에 공백이나 `;` 가 오거나 Enter 로 줄을 떠나면 끝난 것이다.

#### markdown 의 목록

markdown 만 공백이 아닌 글자를 낸다. 목록 안에서 Enter 를 치면 표시가 따라온다.

```
- 첫째              1. 하나            »   - 깊은 것
- |                 2. |              »   - |
```

`- ` `* ` `+ ` `> ` 는 같은 표시를, `1. ` `1) ` 은 다음 번호를 같은 구두점으로 낸다.
**표시만 있고 내용이 없는 항목에서 Enter 를 치면 목록이 끝난다** — 표시를 내지 않는다.

#### 한 단계

한 단계가 tab 인지 space 몇 칸인지는 파일마다 다르다. 세 가지를 순서대로 본다(ADR-0048).

1. `.editorconfig` 의 `indent_style` · `indent_size` · `tab_width`
2. 그 파일이 이미 쓰고 있는 것. 앞의 들여쓴 줄 500 개까지 훑어 이웃한 두 줄의 걸음을 센다
3. 그 언어의 관례. golang·makefile 은 tab, python 은 space 넷, 나머지는 space 둘

makefile 만 이 셋 밖이다. GNU make 가 조리법 줄을 tab 으로만 알아보므로 언제나 tab 이다.

**들여쓰기를 움직이는 모든 키가 이 한 단계를 쓴다.** `tab` `shift+tab` `backspace`
`>` `<` `=` 와 새 줄이 받는 들여쓰기가 전부 같은 값이다 — `tab` 은 tab 글자를 넣는 키가
아니라 **한 단계 들여쓰는 키**다. space 로 쓰는 파일에서 `tab` 을 치면 space 가 들어가고,
그것을 `backspace` 한 번으로 되돌린다.

세는 단위는 byte 가 아니라 **화면 칸**이다. tab 파일에 space 로 들여쓴 줄이 섞여 있어도
한 단계는 한 단계다. 재는 자리가 화면이라 tab 은 zn 이 실제로 그리는 폭(4 칸) 으로 세고,
`.editorconfig` 의 `tab_width` 는 보지 않는다 — 눈에 보이는 것과 움직이는 것이 어긋나면 안 된다.

칸 수만 맞추고 **그 줄이 쓰던 글자는 그대로 둔다.** tab 파일에서 space 로 들여쓴 줄에 `>` 를
쳐도 space 가 늘어날 뿐 tab 으로 바뀌지 않는다.

```
단위 = space 4 칸

⋅⋅⋅⋅⋅⋅⋅⋅deep()      backspace → ⋅⋅⋅⋅deep()   한 칸이 아니라 한 단계
보통 글|            tab       → 보통 글⋅|     7 칸이라 다음 경계는 한 칸 뒤
```

**자동으로 넣은 들여쓰기는 지우지 않는다.** 아무것도 치지 않고 그 줄을 떠나도 공백이 남는다.
줄 끝 공백을 지우는 것은 팔레트 명령으로 따로 있다.

#### 이미 있는 줄 다시 들여쓰기

`>` `<` `=` 는 `d` `y` `c` 와 같은 operator 라 motion 을 받는다(ADR-0013). 같은 글자를 두 번
치면 줄 하나이고 숫자는 줄 수다. visual 에서는 고른 범위 위에 그대로 친다.

키 | 하는 일
--- | ---
`>>` `3>>` `>j` `>G` | 한 단계 민다
`<<` `<j` | 한 단계 당긴다
`==` `=j` `=G` | 규칙이 정한 자리로 다시 계산한다
visual 의 `>` `<` `=` | 고른 범위에 같은 것을 하고 normal 로 돌아온다

범위가 글자 단위여도(`>w`) **걸친 줄 전체가 움직인다.** 들여쓰기는 줄의 성질이라 반쪽을 밀
수 없다. 커서는 첫 줄의 들여쓰기 다음에 선다. 한 번의 `u` 로 범위 전체가 돌아온다.

`>` `<` 는 언어를 보지 않는다. 손으로 미는 것이라 규칙이 끼어들 자리가 없고, **빈 줄은
건드리지 않는다** — 밀면 줄 끝 공백만 남는다. 한 단계로 딱 떨어지지 않는 줄(space 두 칸
파일의 세 칸짜리 줄) 에서 `<` 는 한 단계 칸 수만큼 떼고 남는 것을 그대로 둔다.

`=` 는 위에서 아래로 훑으며 줄마다 자리를 다시 잡는다. 기준은 **범위 바로 위 줄의 지금
들여쓰기**이고 그 줄은 건드리지 않는다 — 규칙은 절대 자리를 모르고 앞 줄과의 차이만 안다.
공백뿐인 줄은 비운다. 빈 줄이 블록을 끊지는 않는다.

**markdown 과 모르는 확장자에서 `=` 는 아무 일도 하지 않는다.** 목록의 깊이와 네 칸 들여쓴
코드 블록은 글쓴이가 정한 것이라 앞 줄에서 되짚을 수 없다 — 되짚으려 들면 중첩 목록이
평평해진다. `>` `<` 는 그 둘에서도 그대로 된다.

### visual mode

normal mode 에서 `v`(글자 단위) `V`(줄 단위) 로 들어간다. 범위를 눈으로 고르고 그 위에
`d` `y` `c` 를 친다 — operator 뒤에 이동 키를 붙이는 것과 같은 일을 순서만 바꿔 하는 것이다.
**blockwise(`ctrl+v`) 는 아직 없다**(ADR-0037).

**고른 범위는 커서가 선 글자까지다.** `v` 만 누르고 `d` 를 치면 커서 아래 한 글자가 지워져서
`x` 와 같다. grapheme cluster 단위라 한글·이모지도 통째로 든다. vim 과 같다.

`v` 는 글자 단위라 `G` `gg` 도 줄 단위가 되지 않는다 — `vG` 는 마지막 줄의 첫 글자까지고,
파일 끝까지 줄로 지우려면 `VG` 다.

statusBar 의 mode 는 `VISUAL` 과 `VISUAL LINE` 이고, 아래 줄은 normal 과 같다.

담을 자리는 범위를 고른 **뒤에** 고른다 — `V j "ay` 다. normal 에서 이름이 operator 앞에
오는 것(`"ayy`) 과 순서가 다른데, 여기서는 범위가 이미 있어서 이름이 마지막 키 앞이다.
`"a` 뒤에 이동 키가 오면 이름과 이동이 같이 버려진다(ADR-0058).

#### key mapping

키 | 기능 | 기타
---|------|-----
(이동 키) | 범위를 늘린다 | normal 의 이동 키를 그대로 받는다. 숫자 접두와 `gg` 도 같다
d x | 고른 범위를 지운다 | normal 로 돌아간다. `x` 는 `d` 와 같다 — 지울 범위가 이미 정해져 있다
y | 고른 범위를 register 에 담는다 | 파일을 건드리지 않는다. 커서는 범위의 시작으로 간다
c | 지우고 insert mode 로 | 줄 단위면 줄을 없애지 않고 첫 줄의 들여쓰기를 남긴다. `cc` 와 같다
> < | 고른 줄들을 한 단계 밀거나 당긴다 | normal 로 돌아간다. 글자 단위로 골랐어도 걸친 줄 전체다
= | 고른 줄들을 규칙이 정한 자리로 다시 들여쓴다 | 위와 같다. markdown 에서는 아무 일도 하지 않는다
v V | 같은 키면 나가고 다른 키면 갈래를 바꾼다 | `v` 뒤의 `V` 는 고른 것을 그대로 두고 줄 단위가 된다
"{문자} | `d`·`y`·`c` 가 담을 register 를 고른다 | `V j "ay` 다. 범위를 고른 뒤에 댄다. 숫자 이름에는 담지 못한다
esc | 고른 것을 놓고 normal 로 |
ctrl+c | 전체 종료 | 다른 mode 와 같다

`:` `/` `gt` `gT` `ctrl+w` `ctrl+p` 는 받지 않는다. 짝이 없는 조합이 아무 일도 하지 않는 것과
같아서(`dgt`) 잘못 누른 키는 그냥 먹히고 만다.

`V` 는 한글 입력 상태에서 낼 수 없다. `ㅍ` 의 shift 자리에 다른 글자가 없어 `G` `B` 와 같다.
`v` 는 `ㅍ` 으로 낸다.

#### 강조

고른 범위는 회색 바탕(256색 238) 에 밝은 글자(231) 다. 반전은 statusBar·tabline 이 쓰고 있어서
(ADR-0004) 검색 강조와 같이 256색 고정값이다.

**검색 강조와 겹치면 검색이 위다.** 고른 범위는 커서로도 드러나지만 매칭은 색이 유일한
표시라, 선택 배경이 덮으면 `n` 이 데려다 놓은 곳이 어디인지 보이지 않는다.
공백 마커는 검색 강조에서와 같이 흐린 색이고 배경만 이어진다.

**줄 끝을 넘어가는 선택은 개행 자리에 빈 칸 하나를 더 칠한다.** `V` 로 고른 빈 줄은 칠할
글자가 없어서 이 칸이 없으면 골랐다는 것이 화면에 드러나지 않는다.

### copy mode

**아직 없다.** cat 의 text 출력과 동일하게 표현한다. 다른점은 현재 보던줄들을 출력 한다는 것이다.
mouse 를 끌 수 없어서 막힌 터미널 드래그 복사의 진짜 해결이 이것이다(ADR-0012).

### command-line mode

vim 의 command-line mode 와 동일하다.
normal mode 에서 `:` 로 들어간다. 치는 명령은 statusBar 의 아래 줄에 보인다.
줄을 새로 만들지 않고 아래 줄을 바꿔 쓰므로 편집 영역 높이가 흔들리지 않는다.

명령 | 기능
-----|-----
:w | 저장. 이름 없는 tab 은 쓸 곳이 없어서 알리고 만다
:w \<파일\> | 그 파일에 사본을 쓴다. 이름 없는 tab 은 그 이름을 받는다
:e | 보고 있는 파일을 디스크에서 다시 읽는다
:e \<파일\> | 보고 있는 tab 을 그 파일로 갈아끼운다. tab 은 늘지 않는다
:tabnew | 이름 없는 빈 tab 을 지금 tab 바로 뒤에 연다
:tabnew \<파일\> | 그 파일을 지금 tab 바로 뒤에 새 tab 으로 연다
:tree | 좌측 sidebar(filetree) 를 여닫는다
:\<범위\>d | 그 줄들을 지운다. 범위를 안 쓰면 커서 줄이다. 아래 「줄 범위」 참고
:\<범위\>y | 그 줄들을 복사한다. 파일도 커서도 그대로다
:\<범위\> | 이름 없이 범위만. 그 줄로 간다(`:5`). 두 자리면 뒤쪽이다
:!\<셸 명령\> | 터미널을 셸에 넘겨 그 명령을 돌린다. 아래 「셸 명령」 참고
:jobs | 백그라운드 작업 목록을 연다. 도는 것과 최근에 끝난 것이 함께 보이고 `x` 로 취소한다
:messages, :mes | 지나간 알림 목록을 연다. 아래 「알림 목록」 참고
:registers, :reg | 담긴 register 를 하단 drawer 에 보인다. 아래 「register 목록」 참고
:noh, :nohlsearch | 검색 강조만 끈다. 마지막 검색은 남아서 `n` 이 계속 먹는다
:version | 이름·버전·빌드시각·go 런타임을 아래 줄에 찍는다. 버그 신고에 그대로 붙일 수 있다
:q | 지금 보고 있는 tab 을 닫는다. 마지막 tab 이면 종료다
:wq, :x | 저장하고 tab 을 닫는다. `:x` 는 `:wq` 의 별칭이다
:q! | 저장하지 않고 tab 을 닫는다
:qa | 전체 종료
:qa! | 저장하지 않고 전체 종료

`esc` 로 취소한다. `backspace` 로 `:` 까지 지워도 나간다.
명령 결과와 오류는 아래 줄에 뜨고 다음 키를 누르면 사라진다 — 사라져도 기록에는 남아서
`:messages` 로 다시 볼 수 있다(아래 「알림 목록」).

#### 명령 문법

한 줄은 `[범위]이름[!] [인자 ...]` 다. `!` 는 이름의 일부가 아니라 "묻지 말고 해라" 는 표시라서
`:q` 와 `:q!` 는 같은 명령이다. 인자는 공백으로 끊고, 공백이 든 파일 이름은 이렇게 쓴다.

```
:w "my notes.txt"     따옴표 안은 전부 글자 그대로다. `\` 도 글자다
:w my\ notes.txt      `\` 뒤의 한 글자는 뜻 없이 그대로 받는다
:w \"quoted\"         따옴표 자체는 따옴표 밖에서 이스케이프한다
```

따옴표가 닫히지 않았거나 `\` 로 끝나면 실행하지 않고 아래 줄에 알린다.
인자를 받는 명령은 `:w`, `:e`, `:tabnew`, `:!` 뿐이고 파일 이름 하나만 받는다. 나머지 명령에
인자를 붙이면 알 수 없는 명령으로 친다 — 조용히 버리면 `:wq foo` 가 foo 에 저장한 것처럼 보인다.
`:wq <파일>` 과 `:x <파일>` 도 여기에 든다 — vim 은 받지만 사본을 쓰고 닫아서 편집이 사라지므로
따르지 않았다(ADR-0024). 줄 범위를 받는 명령도 셋뿐이다(아래 「줄 범위」).

**이름 자리의 `!` 는 뜻이 다르다.** 이름 뒤에 붙는 `!` 는 강제(`:q!`) 지만, 이름이 올 자리의
`!` 는 그 자체가 이름이고 **뒤를 통째로 셸에 넘긴다**. 범위를 앞에 쳤으면 그 뒤가 이름 자리다. 그래서 위의 따옴표·`\` 규칙이 `:!` 뒤에는 적용되지
않는다 — 그것을 읽는 것은 셸이다. `:!echo "a b"` 의 따옴표도, 닫히지 않은 따옴표도 셸이 본다
(ADR-0045).

```
:!ls -la              공백으로 끊지 않는다. `ls -la` 한 덩어리다
:!grep -r "a b" .     따옴표는 셸이 읽는다
:w !foo               이름 자리가 아닌 `!` 는 파일 이름의 글자다
```

#### 줄 범위

이름 앞에 줄 범위를 붙일 수 있다. 받는 명령은 `:d`(지우기)·`:y`(복사) 와 이름 없는 것뿐이고,
나머지에 붙이면 `이 명령은 줄 범위를 받지 않습니다` 다 — 조용히 버리면 `:1,5w` 가 그 줄만 쓴
것처럼 보인다(ADR-0046).

```
:5d          5 줄
:1,5d        1 부터 5 줄
:.d          커서 줄. `:d` 와 같다
:.,$d        커서 줄부터 끝까지
:%d          파일 전체. `:1,$d` 와 같다
:.,+3d       커서 줄부터 아래 3 줄
:-2,.d       위 2 줄부터 커서 줄
:$-1,$d      끝에서 두 줄
:,5d         쉼표 한쪽이 비면 커서 줄이다
:+3d         base 를 안 쓰면 커서 줄에서 옮긴 자리다
:1,5         이름이 없으면 그 줄로 간다. 두 자리면 뒤쪽(5 줄) 이다
```

주소는 줄 번호(1 부터)·`.`(커서 줄)·`$`(마지막 줄) 이고 `+N` `-N` 으로 옮긴다. 숫자를 안 붙인
`+` 는 한 줄이다. `%` 는 주소가 아니라 범위 전체라서 `:%,5d` 처럼 쓸 수 없다.

**없는 줄은 거절한다.** `:1,500d` 는 `그런 줄이 없습니다: 500` 이고 파일 끝으로 잘라 주지
않는다 — 손이 미끄러진 것과 시킨 것을 가를 수 없기 때문이다. **뒤집힌 범위(`:5,1d`) 는 되묻지
않고 바로잡는다.**

지우기는 지운 줄 수를 알린다(`3 줄 지웠습니다`). 키로 치는 `dd` 는 사라지는 것이 화면에 보여서
알리지 않는데, 손으로 친 범위는 화면 밖일 수 있다. 지운 줄과 복사한 줄은 register 에 줄 단위로
들어가서 `p` 가 줄로 붙인다(ADR-0017). 범위 하나가 되돌리기 한 구간이라 `u` 한 번에 다 돌아온다.

마크(`:'<,'>`) 와 검색(`:/pat/`) 주소는 아직 없다.

#### 셸 명령

`:!<셸 명령>` 은 **터미널을 셸에 그대로 넘긴다.** 편집 화면이 물러나고 명령이 터미널에 직접
쓰므로, `git commit`·`less`·`htop` 처럼 화면과 stdin 을 쓰는 명령도 그대로 돈다. 도는 동안
편집기는 멈춰 있다.

셸은 `$SHELL` 이고 비어 있으면 `sh` 다. `$SHELL -c '<친 것>'` 으로 돈다.

무엇이 돌았는지 알 수 있게 `:!<친 것>` 을 한 줄 먼저 찍는다. 끝나면 `계속하려면 Enter 를
누르세요` 에서 멈춘다 — 돌아가는 순간 대체 화면이 출력을 덮기 때문에, 그 틈이 없으면 출력이
있었다는 것조차 알 수 없다(vim 의 「Press ENTER」와 같은 자리다). 출력이 없는 명령도 묻는다.

**출력은 남기지 않는다.** Enter 를 누르면 사라진다. 결과를 buffer 로 가져오는 것은 아직 없다.

도는 동안 `ctrl+c` 는 **명령에** 간다. 편집기는 그 신호를 무시하므로 살아남고, 끊긴 것은
실패로 알리지 않는다 — 그만하라고 한 사람이 결과를 이미 안다. 종료 코드가 0 이 아니면
아래 줄에 `셸 명령이 실패했습니다: exit status 1` 이 뜬다. 성공은 조용하다.

돌아오면 보고 있는 파일을 다시 검사한다. 셸에서 고쳤고 편집기 쪽에 잃을 것이 없으면 그대로
가져온다(ADR-0038). 끝나면 언제나 normal 이다.

`:!` 만 치면 `셸 명령이 없습니다` 다.

#### 밖에서 바뀐 것 알기

보고 있는 파일이 밖에서 달라졌는지는 **터미널 포커스가 돌아올 때**(다른 창을 만지고 왔다는 뜻),
**셸에서 올라올 때**(`ctrl+z` 뒤 `fg`), **`:!` 로 돌린 셸 명령이 끝날 때**,
그리고 **저장하기 직전**에 본다. 판정은 내용 해시라
mtime 만 바뀐 것은 세지 않는다(ADR-0015).

포커스 복귀는 normal·insert·트리에서 받는다. 발견하면 statusBar 경로 뒤에 `[!]` 가 붙고,
아래 줄에 `파일이 밖에서 바뀌었습니다. 다시 읽으려면 `:e` 입니다` 가 한 번 뜬다. 알림은 다음
키에 사라지지만 마커는 남는다. 이미 마커가 붙은 파일이 또 바뀌어도 다시 알리지 않고, 밖의
변경이 되돌아가면 마커가 조용히 사라진다(ADR-0031).

가져오는 것은 `:e`, 덮어쓰는 것은 `:w!` 다. 편집기가 알아서 다시 읽지는 않는다(ADR-0016).
보고 있지 않은 tab 은 검사하지 않는다 — 마커가 없다고 그 파일이 깨끗한 것은 아니다.

#### 파일에 쓰기

인자 없는 `:w` 는 보고 있는 파일에 쓴다. 읽은 뒤 밖에서 바뀌었으면 쓰지 않고 알린다(ADR-0015).

`:w <파일>` 은 **사본을 쓴다.** 그 파일에 내용을 쓰기만 하고 보고 있는 파일도 tab 이름도
변경 표시도 그대로라, 이어지는 `:w` 는 여전히 원래 파일에 쓴다. vim 과 같고 이름을 옮기는
`:saveas` 는 두지 않았다(ADR-0024).

**이름 없는 tab 만 예외로 그 이름을 받는다.** 붙어 있을 원래 파일이 없어서 사본이라는 말이
성립하지 않는다. `:tabnew` 로 만든 tab 을 저장하는 길이 이것이고, 저장한 뒤에는 그 파일의
tab 이 되어 그냥 `:w` 로 이어서 저장한다. undo 이력은 그대로 남는다.

명령 | 하는 일 | 쓸 파일이 이미 있을 때
-----|---------|----------------------
`:w` | 보고 있는 파일에 쓴다 | (밖에서 바뀌었으면 알리고 만다)
`:w!` | 보고 있는 파일에 쓴다 | (밖에서 바뀌어도 덮어쓴다)
`:w <파일>` | 그 파일에 쓴다 | 알리고 만다
`:w! <파일>` | 그 파일에 쓴다 | 덮어쓴다

이미 있는 파일을 막는 것은 vim 의 E13 과 같다. 다른 파일은 읽은 적이 없어서 ADR-0015 의
해시 비교로 무엇이 달라졌는지 볼 수 없고, 있는지 없는지만 볼 수 있다.

쓸 곳이 보고 있는 파일과 같으면(`:w ./a.txt`) 사본이 아니라 제자리 저장이다. 경로는
정규화해서 비교한다 — tab 을 찾는 것과 같은 기준이다.

**이름을 받으려는 파일이 이미 다른 tab 에 열려 있으면 쓰지 않고 알린다.** 이름이 붙는 순간
같은 파일에 Buffer 가 둘이 되기 때문이다. 사본을 쓸 때는 Buffer 가 늘지 않으므로 걸리지 않는다.

#### 파일 열기

`:e <파일>` 은 보고 있는 tab 을 그 파일로 갈아끼우고, `:tabnew <파일>` 은 새 tab 을 연다.
없는 파일은 그 이름의 빈 buffer 가 된다. CLI 인자와 같다.

**둘 다 이미 열려 있는 파일이면 그 tab 으로 옮겨가기만 한다.** tab 마다 Buffer 가 독립이라
같은 파일이 두 tab 에 있으면 한쪽 저장이 다른 쪽 편집을 덮어쓴다. 팔레트·트리로 여는 것과
CLI 인자도 같은 규칙이다(ADR-0021).

인자 없는 `:e` 는 보고 있는 파일을 다시 읽는다. 팔레트의 「파일 다시 읽기」와 같다(ADR-0016).

명령 | 하는 일 | 잃을 것이 있을 때
-----|---------|------------------
`:e` | 다시 읽는다 | 확인창
`:e!` | 다시 읽는다 | 묻지 않는다
`:e <파일>` | 활성 tab 을 갈아끼운다 | 확인창
`:e! <파일>` | 활성 tab 을 갈아끼운다 | 묻지 않는다

이미 열린 tab 으로 옮겨가기만 할 때는 잃을 것이 없으므로 변경이 남아 있어도 묻지 않는다.
갈아끼운 tab 의 undo 이력은 다시 읽기와 마찬가지로 사라진다.

`:wq` 는 `:w` 와 `:q` 의 조합이 아니라 그 자체로 이름 하나다. vim 의 ex command 표와 같다.
`:x` 도 마찬가지다 — 다만 vim 의 `:x` 는 변경이 있을 때만 쓰는 반면 여기서는 `:wq` 의 별칭이라
항상 쓴다. 명령을 조합하는 문법(vim 의 `:w | q`) 은 두지 않았다.

`:q` 는 tab 을 닫고 `Ctrl+C` 는 `:qa` 와 같이 전체를 끝낸다(ADR-0003).
어느 쪽이든 잃을 것이 있을 때만 확인창이 뜨고, 없으면 묻지 않는다.
묻는 범위는 각자 잃는 것에 맞춘다 — `:q` 는 닫는 tab 의 변경만 보고,
`:qa` 와 `Ctrl+C` 는 어느 tab 이든 변경이 남아 있는지를 본다.


### search mode

normal mode 에서 `/`(아래로) `?`(위로) 로 들어간다. 치는 패턴은 command-line mode 와 같은
자리, statusBar 의 아래 줄에 보인다. `esc` 로 취소하고 `backspace` 로 여는 글자까지 지워도 나간다.

**패턴은 Go 의 정규식(RE2) 이다**(ADR-0010). vim 의 magic 규칙으로 옮기지 않으므로 `(` 이 그룹이고
`\(` 이 글자다. 단어 경계는 `\<`·`\>` 가 아니라 `\b` 다.

#### flag

**패턴 뒤에 `/글자들` 로 붙인다.** 지금 있는 것은 대소문자를 무시하는 `i` 하나이고 모르는 flag 는
오류다. 붙이지 않으면 대소문자를 구분한다 — smartcase 를 두지 않았다(팔레트의 매칭과 다른 자리다).

```
/abcd/i     대소문자를 가리지 않고 abcd
?abcd/i     위로 찾는다. 구분자는 방향과 상관없이 늘 `/` 다
/http://    마지막 `/` 뒤가 비어 있어서 flag 가 아니다. 친 그대로 찾는다
/a\/b       flag 로 읽힐 `/` 는 `\/` 로 막는다. Go 정규식에서도 `/` 한 글자다
```

마지막 `/` 뒤가 비어 있거나 ASCII 영문자가 아닌 것이 섞여 있으면 flag 가 아니라 패턴의 일부다.
그래서 `/foo/bar/` 는 친 그대로이고, 실제로 걸리는 것은 `/a/b` 처럼 짧은 경로 조각인데
그때는 조용히 다르게 동작하지 않고 「모르는 flag」라고 알린다.

#### 치는 동안과 찾은 뒤

**치는 동안 첫 매칭으로 커서와 화면이 따라간다(incsearch).** 늘 검색을 시작한 자리에서 다시
찾으므로 글자를 지우면 앞의 자리로 되돌아온다. `esc` 로 나가면 커서·화면·직전 검색이 모두
시작 상태로 돌아간다. 치는 도중에는 오류를 띄우지 않는다 — `(` 까지 친 순간은 늘 잘못된
정규식이다. 오류는 `enter` 에 낸다.

**찾은 자리는 모두 칠하되 커서가 선 것만 색이 다르다.** 나머지는 노랑(256색 220) 바탕이고
커서가 선 것은 주황(208) 바탕에 검은 글자다. 「커서가 선 매칭」은 커서 자리에서 시작하는
매칭이라, 다른 키로 커서를 옮기면 자연히 사라진다.

강조는 검색할 때마다 켜지고 `:noh` 로 끈다. 끄는 것은 강조뿐이라 마지막 검색은 남아서 `n` 이
계속 먹는다.

**파일 끝에 닿으면 반대쪽 끝에서 이어 보고, 감쌌으면 아래 줄에 알린다.**

#### `n` `N` `*` `#`

`n` 은 같은 방향, `N` 은 반대 방향으로 다음 매칭이다. **마지막 검색은 `editor` 가 들고 있어서**
tab 을 옮겨도 `n` 이 같은 것을 찾는다 — 여러 파일에서 같은 이름을 훑는 흐름이 끊기지 않는다.

`*` `#` 는 커서 아래 단어를 아래·위로 찾는다. 커서를 그 단어 앞으로 옮긴 뒤 거기서 시작하므로
`*` 를 눌렀는데 한 칸 옆으로 가고 마는 일이 없다. 단어 경계는 `w` 와 같은 부류 나누기이고
(ADR-0006), 양끝이 ASCII 단어 글자일 때만 `\b` 를 붙인다 — 한글 단어에 `\b` 를 붙이면
Go 의 `\b` 가 ASCII 기준이라 아무것도 찾지 못한다. 그래서 `한글` 을 찾으면 `한글자` 도 걸린다.

검색은 **줄 단위**라 줄바꿈을 건너뛰는 패턴(`func\s*\n`) 은 맞지 않는다.
검색 키는 `d` 뒤에 받지 않는다 — `d/foo` `dn` 은 없다(ADR-0013).

### 특수문자 mode

command palette 의 `>` 목록에서 「특수문자 넣기」로 들어간다. 편집 영역 아래에 하단 drawer 가
펼쳐지고 이름으로 걸러 격자에서 고른다. statusBar 의 mode 는 `SYMBOL` 이다(ADR-0056).

```
│ 200  0 line 200                                     │  ← 커서 줄은 늘 판 위에 남는다
┌─────────────────────────────────────────────────────┐
│ 삼각형                                    21/12265  │  ← 입력줄과 걸린 수
├─────────────────────────────────────────────────────┤
│ ⊿   △   ◁   ▲   ▽   ◀   ▷   ▼   ▶   ◤   ◣   ▵      │
│ ◥   ◃   ▴   ◢   ▿   ◂   ▹   ▾   ▸                  │
│ ⊿   직각 삼각형          삼각형 세모 triangle right │  ← 고른 것의 이름
└─────────────────────────────────────────────────────┘
```

판은 편집 영역에 **얹지 않고 그 행을 가져간다.** 그래서 넣는 자리인 커서가 판에 가리지 않는다.
폭은 편집 영역과 같아서 sidebar 옆을 지나가지 않는다 — 트리 높이는 그대로다.

격자는 최대 4 행이고 한 칸은 4 칸이다. 화면이 짧아지면 행이 먼저 줄고, 격자가 한 행도 안
나오거나 편집 영역에 세 줄이 안 남으면 열지 않고 아래 줄에 알린다. 열려 있는 동안 좁아지면
normal 로 빠져나온다 — 팔레트와 같은 방어다.

#### key mapping

키 | 기능 | 기타
---|------|-----
(글자) | 입력줄에 넣는다 | 한글은 여기서 글자다(ADR-0008)
← → | 이전 / 다음 글자 | 양끝에서 멈춘다. 둘러 가지 않는다
↑ ↓ | 격자 한 행 위 / 아래 |
enter | 커서 뒤에 넣는다 | **판은 열린 채다.** 연달아 넣을 수 있다
esc | 나간다 | 언제나 normal 로. insert mode 의 `esc` 와 같은 자리에 선다
backspace | 한 글자 지우기 | 다 지우고 또 누르면 나간다. 팔레트와 같다
ctrl+p | 아무 일도 하지 않는다 | 팔레트가 자기 키에 그렇게 하는 것과 같다
ctrl+c | 전체 종료 | 다른 mode 와 같다
휠 | 격자 한 행 위 / 아래 | 포인터가 어디 있든 목록을 움직인다

넣는 자리는 `a` 와 같다. 연달아 넣은 것은 한 undo 단위라 `u` 한 번에 통째로 돌아온다.
아무것도 안 넣고 `esc` 하면 `a<Esc>` 처럼 열기 전 자리다 — 커서가 줄 맨 앞이었을 때만
한 칸 오른쪽에서 시작한다.

읽기 전용 파일에서는 열지 않고 알린다(ADR-0016).

#### 목록

큐레이션한 한국어 표가 앞이고 유니코드를 훑어 얻은 것이 뒤다. 아무것도 치지 않았을 때 보이는
첫 화면이 손으로 적은 것들이다.

- **큐레이션 표** — 화살표·도형·수학·구두점·괄호·통화·괘선·기호·문자와 숫자, 그리고 자주 쓰는
  이모지. 한국어 이름과 별칭이 붙어 있어서 `삼각형`·`하트`·`화살표` 로 찾힌다.
  새 글자는 `internal/core/symbol-table.go` 에 한 줄이 는다
- **훑어서 얻은 것** — `runenames` 의 영문 이름이다. `flatness` 처럼 영문으로만 찾힌다.
  글자와 숫자는 뺀다 — 한글 음절과 CJK 만 10 만 개가 넘어 목록이 그것으로 뒤덮인다

훑기는 백그라운드 작업이고 프로세스에 한 번뿐이다. 여는 순간 큐레이션 표를 곧바로 쓰므로
훑기를 기다리지 않는다.

격자 칸은 East Asian Width 가 Ambiguous 인 글자(`→ ± × °`) 를 시작할 때 잰 폭으로 센다.
재지 못했으면 두 칸으로 본다 — 좁게 잡으면 행이 넘쳐 아래가 통째로 밀린다(ADR-0028).

### register 목록

`:registers`(`:reg`) 나 팔레트의 「register 목록」으로 연다. 특수문자 판과 같은 자리에 하단
drawer 로 펼쳐지고, statusBar 의 mode 는 `REGISTERS` 다(ADR-0058).

```
│   3  2 foxtrot six                                  │  ← 커서 줄은 판 위에 남는다
┌─────────────────────────────────────────────────────┐
│ "" 줄   delta four⏎                                 │  ← 무명이 맨 위
│ "0 줄   delta four⏎                                 │
│ "1 글자 a                                           │
│ "2 줄   bravo two⏎                                  │
│ "a 줄   alpha one⏎bravo two⏎                        │  ← 문자는 숫자 뒤
└─────────────────────────────────────────────────────┘
```

화면을 통째로 쓰는 `:jobs`·`:messages` 와 달리 편집 영역의 행을 가져간다. **어느 것을 붙일지
보려고 여는 목록이라 붙일 자리가 같이 보여야 한다.**

**담긴 것만 보인다.** 그래서 판 높이가 담긴 개수에 따라 달라진다. 하나도 없으면 그 사실을
한 줄로 알린다. 편집 영역에 세 줄을 남기고도 다 못 그릴 만큼 낮으면 들어가는 만큼만 그리고
`j`/`k` 로 훑는다 — 열지 못하는 경우는 없다.

순서는 무명·숫자·문자다. 숫자가 앞인 것은 저절로 채워지는 자리라서다 — 무엇이 방금 지워졌는지가
손으로 모아 둔 것보다 급하다. 대문자 줄은 없다. `"A` 는 `"a` 와 같은 자리다.

한 줄은 이름·갈래·내용이다. 갈래(`줄`/`글자`) 를 글자로 적는 것은 그것이 `p` 를 어디에 붙일지를
정하는 값이기 때문이다. 줄바꿈은 `⏎` 로 잇고, 줄 단위 register 는 마지막 줄에도 그것이 붙는다.
길면 오른쪽부터 `…` 로 줄인다.

#### key mapping

키 | 기능 | 기타
---|------|-----
j k ↓ ↑ | 한 줄 훑기 | 다 보이면 아무 일도 하지 않는다. 양끝에서 멈춘다
g G | 처음 / 끝 |
q esc | 닫는다 | normal 로 돌아온다. 편집 영역이 그대로 돌아온다
ctrl+c | 전체 종료 | 다른 mode 와 같다
휠 | 위 / 아래 | 포인터가 어디 있든 목록을 움직인다

담긴 것을 지우거나 고치는 키는 없고 골라 붙이는 키도 없다. 읽는 판이다 — 무엇을 붙일지 보고
나가서 `"1p` 를 친다. 커서는 편집 내용에 그대로 있다.


## Mouse

mouse 는 mode 를 가로지르므로 따로 적는다(ADR-0012). 항상 켜져 있고 끄는 방법은 없다.

누른 화면 자리가 곧 무엇을 눌렀는지다. 화면은 네 영역으로 갈린다 —
sidebar, tabline, 편집 영역(줄번호 칸을 포함), statusBar.
statusBar 는 눌러도 아무 일이 없다.

**왼쪽 버튼을 누를 때** 반응한다. 뗄 때는 보지 않는다 — 누르고 그대로 뗐으면 누른 자리로
가고, 끌었으면 끄는 동안 범위가 자란 채로 멈춘다(아래 「드래그」). 가운데·오른쪽 버튼과
double-click 은 쓰지 않는다.

영역 | 클릭 | 휠
-----|------|----
sidebar | 그 항목을 고르고 `enter` 와 같이 연다 | 트리를 굴린다
tabline | 그 tab 으로 옮겨간다 | 아무 일도 없다
편집 영역 | 그 자리로 커서를 옮긴다 | 화면을 굴린다
statusBar | 아무 일도 없다 | 아무 일도 없다

**다른 영역을 클릭하면 포커스도 그리로 간다.** `ctrl+w ctrl+w` 로 오가는 것과 같은
왕래다. 단 편집 영역을 클릭할 때 insert mode 는 유지한다 — 눌러서 자리를 잡고 이어 치는
것이 mouse 를 쓰는 이유다. 이때 커서 이동이므로 undo 구간은 끊긴다(화살표 이동과 같다).

**줄번호 칸을 누르면 그 행의 시작이다.** wrap 되어 이어지는 행이면 그 행의 시작이다.
**파일 마지막 줄 아래 빈 자리는 누를 것이 없는 자리다** — 커서가 움직이지 않는다.
tab 자리 안이나 두 칸짜리 글자의 오른쪽 칸을 누르면 그 글자의 시작으로 맞춘다.
tabline 의 구분선과 오른쪽 빈 칸, 잘려서 안 보이는 tab 자리도 아무 일도 하지 않는다.

**휠은 화면만 굴리고 커서는 그대로 둔다.** 커서가 화면을 벗어나면 그때만 밀려난 쪽
끝 행으로 데려온다. vim 과 같다. 한 번에 3 행이고 좌우 휠은 쓰지 않는다.

**휠이 움직이는 것은 포커스가 아니라 포인터가 얹힌 영역이다.** 편집 영역을 보면서
sidebar 위에서 굴리면 트리만 굴러간다.

**명령줄(`:`) 과 검색(`/`) 을 치는 중에는 휠만 받고 클릭은 무시한다.** 치던 것이 클릭
한 번에 사라지지 않는다. 다만 검색은 다음 글자를 치면 incsearch 가 첫 매칭으로 화면을
다시 잡아당기므로 굴려둔 것이 그때 사라진다. 종료 확인창은 클릭도 휠도 받지 않는다.

**팔레트(`ctrl+p`) 에서는 휠이 목록을 오르내린다.** 화면 위에 얹힌 박스라 아래 편집 내용을
굴려도 볼 수 없으므로, 여기서만 포인터 위치를 보지 않고 화살표와 같이 움직인다.
클릭은 받지 않는다.

**작업 목록(`:jobs`) 도 같다.** 화면을 통째로 쓰므로 굴릴 다른 영역이 없다. 휠이 고른 자리를
`j`/`k` 와 같이 옮기고 클릭은 받지 않는다.

### 드래그

**편집 영역에서 버튼을 누른 채 끌면 범위를 고른다.** 누른 자리가 anchor 이고, 포인터가
움직이는 순간 글자 단위 visual mode 로 들어간다. 뗀 뒤에도 visual 에 머물러서 이어서
`d` `y` `c` 를 친다. 클릭만 하는 것은 커서 이동 그대로다 — vim 과 같다(ADR-0037).

여는 것은 편집 영역 안의 움직임뿐이다. 일단 열린 뒤에는 밖으로 나가도 따라가서, sidebar 쪽으로
끌면 줄 시작까지고 statusBar 아래로 끌면 맨 아랫행까지다. 이때 포커스는 옮기지 않는다 —
끄는 중이라 「다른 영역을 눌렀다」가 아니다. 편집 영역 위아래로 나가면 그 방향으로 한 행씩
굴린다. 다만 잡은 채 가만히 있으면 굴러가지 않는다. 움직여야 이벤트가 온다.

**visual mode 에서 클릭하면 고른 것을 놓는다.** 누른 자리가 새 시작이다. statusBar 만은
눌러도 아무 일이 없고 visual 도 그대로다.

vim 의 double-click(단어) 과 triple-click(줄) 은 없다. 누른 횟수를 알 수 없다(ADR-0012).

mouse 를 켜 두는 동안 터미널 자체의 드래그 복사가 막힌다. 대부분의 터미널에서
`shift` 를 누른 채 드래그하면 터미널 쪽 선택이 된다.


## Command Palette

`Ctrl+P` 로 연다. normal mode 와 sidebar 둘 다에서 받는다. 화면 위쪽 가운데에 박스가 떠서
편집 화면과 sidebar 위에 겹친다. 기본은 파일 찾기이고, 맨 앞 글자가 갈래를 정한다 —
`>` 는 명령 목록, `!` 는 셸 명령이다. 그 글자를 지우면 파일 찾기로 돌아온다.

```
▾ zn/                    │ 1 editor.go
  ▸ docs/     ┌──────────────────────────────────┐
  ▸ internal/ │ edit                             │
    README.md ├──────────────────────────────────┤
              │ internal/core/edit.go            │  ← 고른 행은 반전
              │ internal/core/editor.go          │
              │ internal/core/edit_test.go       │
              └──────────────────────────────────┘
                            PALETTE  internal/core/editor.go
                            13/123
```

박스는 **화면** 가운데다. 편집 영역 가운데가 아니라서 sidebar 를 여닫아도 자리가 그대로다.
너비는 최대 64 칸이고 화면이 좁으면 그만큼 줄어든다. tabline 은 덮지 않고(맨 윗줄 아래에서
시작한다) statusBar 앞에서 멈춘다. 목록은 최대 10 행이고, 걸린 것이 적으면 박스도 그만큼 짧다.

24 칸을 못 채우거나 목록 행이 한 줄도 안 나오는 좁은 화면에서는 **열지 않고** 아래 줄에 알린다.
열린 뒤에 좁아지면 normal 로 나온다 — 보이지 않는 mode 에 갇히면 키를 쳐도 아무 일이 안 난다.

statusBar 아래 줄은 `걸린 수/전체 수` 다. 어디서 열었든 팔레트가 끝나면 편집 영역으로 나온다.

`!` 갈래는 고를 목록이 없다. 목록 자리에 안내 한 줄(`! 뒤에 셸 명령을 칩니다`, 치면
`Enter 로 셸에서 실행합니다`) 이 들어가고 아래 줄의 `걸린 수/전체 수` 는 비운다 — 셀 것이 없다.
`Enter` 는 고르는 것이 아니라 친 것을 실행하는 것이고, 하는 일은 `:!` 와 같다(ADR-0045).

```
┌────────────────────────────────────────────────────────┐
│ !go test ./...                                         │
├────────────────────────────────────────────────────────┤
│ Enter 로 셸에서 실행합니다                             │
└────────────────────────────────────────────────────────┘
```

### key mapping

키 | 기능 | 기타
---|------|-----
ctrl+p | 팔레트 열기 | normal·insert·sidebar 에서. **팔레트 안에서는 아무 일도 하지 않는다**
(글자) | 입력줄에 넣는다 | 한글은 여기서 글자다(ADR-0008)
↑ ↓ | 이전 / 다음 후보 | 양끝에서 멈춘다. 둘러 가지 않는다
enter | 고른 것을 연다 / 실행한다 |
esc | 취소 | 언제나 편집 영역으로 나온다
backspace | 한 글자 지우기 | 다 지우고 또 누르면 나간다. `:` `/` 와 같다
ctrl+c | 전체 종료 | 다른 mode 와 같다

### 파일 목록

cwd 가 뿌리다. sidebar 트리와 같은 기준이라 무엇을 찾는지 화면이 이미 보여준다.

저장소 안이면 `git ls-files --cached --others --exclude-standard` 로 한 번에 받는다.
추적 중인 파일과 아직 추가하지 않은 파일이 함께 오고 `.gitignore` 된 것은 빠진다.
저장소가 아니거나 git 이 없으면 직접 훑고 `.git` 만 건너뛴다. 목록은 이름순이다.

열 때마다 새로 읽는다. 캐시하지 않으므로 바깥에서 만든 파일이 바로 나온다(ADR-0011).

파일을 고르면 새 tab 으로 열린다. 이미 열려 있으면 새로 열지 않고 그 tab 으로 옮긴다.
일반 파일이 아니거나 그 사이에 지워졌으면 열지 않고 아래 줄에 알린다. sidebar 의 `Enter` 와 같다.

열면 sidebar 트리도 그 파일 자리를 펼치고 고른다(ADR-0019).

### 명령 목록

입력 맨 앞에 `>` 를 치면 명령 목록이다. 지우면 파일 목록으로 저절로 돌아온다.

`:` 명령과 별개의 표다. `:` 는 짧은 것이 미덕이지만 이쪽은 목록에서 눈으로 읽는 것이라
이름이 설명적이다. 오른쪽에 영문 설명과 짝이 되는 `:` 명령이 흐리게 붙고, 둘 다 검색 대상이라
`trim` 이나 `:tree` 로도 찾힌다. 붙일 칸이 없으면 오른쪽은 통째로 빠진다.

이름 | 오른쪽 | 하는 일
-----|--------|--------
줄 끝 공백 지우기 | `trim trailing space` | 모든 줄 끝의 공백과 tab 을 지운다. 한 번의 `u` 로 전부 돌아온다
파일 다시 읽기 | `reload file :e` | `:e` 와 같다. 파일을 디스크에서 다시 읽는다. 저장하지 않은 변경이 있으면 확인창을 띄운다
다른 tab 모두 닫기 | `close other tabs` | 보고 있는 tab 만 남기고 나머지를 닫는다. 짝이 되는 `:` 명령은 없다
파일 트리 열기/닫기 | `toggle file tree :tree` | `:tree` 와 같다
검색 강조 끄기 | `disable search highlight :noh` | `:noh` 와 같다. 강조만 끄고 마지막 검색은 남는다
작업 목록 | `jobs :jobs` | `:jobs` 와 같다. 백그라운드 작업 목록 화면을 연다
알림 목록 | `messages :messages` | `:messages` 와 같다. 지나간 알림 목록 화면을 연다
register 목록 | `registers :registers` | `:registers` 와 같다. 담긴 register 를 하단 drawer 에 보인다
정의로 가기 | `go to definition` | normal 의 `\gd` 와 같다. 커서 자리의 정의로 뛴다(ADR-0051)
특수문자 넣기 | `insert symbol` | 하단 drawer 를 열어 이름으로 찾은 글자를 커서 뒤에 넣는다(ADR-0056)

「줄 끝 공백 지우기」는 활성 buffer 만 건드린다. 지우는 것은 `' '` 와 `'\t'` 뿐이고
유니코드 공백(NBSP 등) 은 그대로 둔다 — 눈에 보이지 않는 글자가 조용히 사라지는 편이 더 나쁘다.
공백뿐인 줄은 빈 줄이 된다. 지울 것이 없으면 아무 흔적도 남기지 않는다.

「다른 tab 모두 닫기」는 보고 있는 tab 은 건드리지 않는다. 커서도 편집 내용도 그대로고 tab 만
하나가 된다. tab 이 하나뿐이면 아무것도 닫지 않고 아래 줄에 알린다. 닫으려는 tab 중에
저장하지 않은 변경이 있으면 확인창을 띄우고, 취소하면 팔레트가 아니라 normal 로 돌아간다 —
보고 있지 않은 tab 이라 무엇을 잃는지 화면에 드러나지 않기 때문이다. 닫고 나면 몇 개를
닫았는지 아래 줄에 남는다.

### 매칭

친 글자가 순서대로 들어 있기만 하면 걸린다(fzf 와 같은 부분수열). `icedit` 이
`internal/core/edit.go` 를 찾는다. 맞은 글자는 목록에서 색이 붙는다(256색 214).

점수는 붙어 있는 것, 단어 경계(`/ . - _ 공백`) 에서 시작하는 것, camelCase 경계,
그리고 **파일 이름의 시작**(마지막 `/` 뒤) 을 위로 올린다. 그래서 `edit` 은
`internal/core/edit.go` 를 `internal/core/view-editor-command.go` 보다 먼저 보여준다.
건너뛴 칸은 점수를 깎는다.

대소문자는 smartcase 다. 친 것이 전부 소문자면 가리지 않고, 대문자가 하나라도 있으면 가린다.
가리지 않는 중에도 대소문자까지 맞은 쪽이 조금 위로 온다.

같은 점수면 짧은 것이 위고, 그것도 같으면 목록에 있던 차례다. 아무것도 치지 않았으면
거르지도 정렬하지도 않고 앞에서부터 보여준다.


## 백그라운드 작업

오래 걸리는 일은 편집기를 멈추지 않는다. 지금 있는 작업은 셋이다 — 팔레트의 파일 목록을 모으는
「파일 인덱싱」, 저장소 상태를 읽는 「git 상태」, 트리를 펼칠 때 도는 「디렉터리 읽기」다
(ADR-0027, ADR-0032).

이름이 곧 신원이라 **같은 이름은 한 번에 하나만 돈다**. 이미 돌고 있으면 새로 시작하지 않고
돌고 있는 것에 붙는다 — 팔레트를 빠르게 여닫아도 인덱싱이 겹쳐 돌지 않는다.
「디렉터리 읽기」의 이름에 경로가 들어가는 것이 이 때문이다. 이름이 그냥 「디렉터리 읽기」면
두 디렉터리를 잇따라 펼칠 때 뒤엣것이 시작되지 않는다.

작업은 진행(`한 것/전체`)을 조금씩 알린다. 전체를 아직 모르는 동안에는 지금까지 한 개수만
센다. 끝나면서 무엇을 했는지 한 줄을 남긴다 — 인덱싱의 `151,933 개` 가 그것이다.

### statusBar 진행 표시

도는 작업은 statusBar 위 줄, git 표시 왼쪽에 보인다.

```
NORMAL  internal/core/editor.go     파일 인덱싱 ⣿⣿⣿⣿⣄⣀⣀⣀⣀⣀ 42% (+1)  master(f6cacbd*)
```

목록 맨 앞, 곧 가장 먼저 시작한 것 하나만 찍는다. 끝날 때까지 가리키는 것이 바뀌지 않아야
눈이 따라갈 수 있다. 나머지는 `(+N)` 으로 개수만 알린다.

막대는 열 칸이고 칸 하나가 여섯 단계라 예순 단계다. 점자(`⣀⣄⣆⣇⣧⣷⣿`) 로 그린다 —
블록 문자와 달리 폭이 확실해서 터미널이 두 칸으로 잡아 statusBar 를 밀어내지 않는다(ADR-0020 과
같은 기준이다). 전체를 모르면 막대를 그리지 않고 개수만 찍는다 — 반쯤 찬 막대가 거짓말이 된다.

칸이 모자라면 진행 표시부터 줄인다. 먼저 막대를 떼고, 그래도 모자라면 진행 표시를 통째로
뺀다. git 은 늘 같은 자리에 있어야 눈이 찾는다.

### 작업 목록

`:jobs` 나 팔레트의 「작업 목록」으로 연다. mode 는 `JOBS` 다.

```
작업  도는 중 1 · 끝난 것 2
 ▸ 파일 인덱싱      ⣿⣿⣿⣿⣄⣀⣀⣀⣀⣀  42%   0:03
   git 상태         끝남  master(f6cacbd*)   0:00
   파일 인덱싱      취소됨   0:12
 j/k 이동  x 취소  q 닫기
JOBS  internal/core/editor.go                      master(f6cacbd*)
```

팔레트처럼 박스로 얹지 않고 화면을 통째로 쓴다. 목록이 실시간으로 자라고 줄어들어서 아래
화면이 비치면 무엇이 움직이는 것인지 읽기 어렵다. tabline 과 sidebar 도 그리지 않는다 —
편집기 틀을 쓰면 "파일을 보고 있는 화면" 으로 읽혀서 여기서 치는 키가 편집기 키인 줄 알게 된다.
맨 위 제목줄이 tabline 자리를 대신하고, statusBar 만 남아 mode 와 git·알림이 늘 같은 자리에 있다.
트리가 열려 있었어도 statusBar 는 트리가 없는 것으로 치고 그린다 — 목록이 왼쪽 끝에서
시작하는데 statusBar 만 32 칸 들여쓰면 화면이 반쪽만 바뀐 것처럼 보인다(ADR-0005).

고른 행은 `▸` 가 붙고 그 줄 왼쪽 끝에 커서가 선다. 키 안내는 statusBar 안이 아니라 그 바로 위
줄이다 — 아래 줄은 알림 자리로 비워 두어서, 취소가 실패하거나 작업이 실패했을 때 안내를
밀어내지 않고 나란히 보인다.

**도는 것이 위, 최근에 끝난 것이 아래다.** 도는 것은 진행 막대와 백분율을, 끝난 것은 상태와
요약(`끝남 <요약>` · `취소됨` · `실패 <이유>`) 을 같은 칸에 보여준다. 오른쪽 끝은 걸린 시간
(`분:초`) 이고, 끝난 작업은 끝날 때까지 걸린 시간에서 멈춘다. 도는 것도 끝난 것도 없으면
`도는 작업이 없습니다` 를 적는다 — 빈 화면만 두면 목록을 못 연 것처럼 보인다.

끝난 목록은 **이름당 마지막 결과 하나**다. 개수 상한은 두지 않는다 — 이름은 코드에 있는 종류만큼만
있다. 끝난 순서대로 쌓으면 5 초마다 도는 git 갱신이 목록을 자기 이름으로 뒤덮어서, 조용히
실패한 다른 작업을 찾으라고 남겨둔 자리가 그것으로 다 찬다(ADR-0030).

실패는 목록을 열지 않아도 statusBar 아래 줄에 `<이름> 실패: <이유>` 로 알린다. 취소는 알리지
않는다 — 그만하라고 한 사람이 결과를 이미 안다.

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 다음 / 이전 작업 | 양끝에서 멈춘다. 둘러 가지 않는다
휠 | 목록 오르내리기 | 한 번에 3 행. 팔레트·트리와 같다
x | 고른 작업 취소 | 끝난 작업이면 `이미 끝난 작업입니다` 라고만 알린다
q, esc | 닫고 normal 로 | 도는 작업은 그대로 돈다
ctrl+c | 전체 종료 | 다른 mode 와 같다

한글 입력 상태에서 온 키는 두벌식 자리의 영문 키로 되돌린다(ADR-0008). 이 화면의 키가 전부
글자 키라 되돌리지 않으면 아무것도 먹지 않는다.

`x` 는 작업의 ctx 를 끊는다. 목록에서 바로 빼지는 않는다 — 언제 진짜 끝났는지는 작업이 알고,
채널이 닫히면 「취소됨」으로 끝난 목록에 옮겨간다. 편집기를 끝내면 도는 작업이 전부 같이 정리된다.

작업이 도는 동안에도 목록에 갇히지 않는다. 진행은 어느 mode 에서든 도착해서 statusBar 에
반영되므로, 닫고 편집을 계속하다 다시 열어도 그동안의 진행이 그대로 이어져 있다.

## 알림과 알림 목록

statusBar 아래 줄에 뜨는 한 줄이 알림이다. 명령 결과(`저장함: …`), 거절(`읽기 전용 파일입니다`),
실패(`git 상태 실패: …`), 진행 중(`정의를 찾는 중입니다`) 이 모두 그 자리에 온다.
**다음 키를 누르면 사라진다.** 명령줄과 검색은 그 줄을 자기 입력에 쓰므로 알림을 그리지 않는다.

사라져도 **기록에는 남는다**(ADR-0053). 사람이 키를 누르지 않았는데 도착하는 알림이 넷 있어서다 —
바깥 파일이 바뀐 것, 백그라운드 작업 실패, gopls 기동 실패다. 이것들은 도착한 직후 아무 키나
누르면 사라져서, 기록이 없으면 일이 일어났다는 사실 자체를 놓친다.

알림은 두 갈래다. **`error` 값에서 온 것이 실패**이고 나머지가 그 밖이다. 거절(`알 수 없는 명령`)은
실패가 아니다 — 선은 「사람이 거절당했는가」가 아니라 「코드가 `error` 를 만들 만큼 예상 밖이었는가」다.

### 알림 목록

`:messages`(`:mes`) 나 팔레트의 「알림 목록」으로 연다. mode 는 `MESSAGES` 다.

```
알림  3 개 · 실패 1
   13:22:28   알 수 없는 명령: qqq
   13:22:29   저장함: internal/core/core.go
 ▸ 13:22:58 ! is a directory
 j/k 이동  g/G 처음·끝  q 닫기
MESSAGES  internal/core/core.go                          master(aa4bf78*)
```

화면 문법은 작업 목록과 같다 — 화면을 통째로 쓰고, 맨 위가 제목 띠, 키 안내가 statusBar 바로
위 줄, statusBar 는 트리가 없는 것으로 치고 그린다.

**오래된 것이 위, 최근이 아래다.** 작업 목록과 반대인데, 알림은 뒤에만 붙어야 이미 있는 줄의
자리가 밀리지 않기 때문이다 — 목록을 보는 동안 새 알림이 도착해도 고른 줄이 다른 알림으로
바뀌지 않는다. 열 때는 맨 아래(가장 최근) 를 고른 채로 연다. 맨 아래를 보고 있는 동안 새 알림이
오면 따라 내려가고, 위쪽을 보고 있으면 그 자리에 그대로 있는다.

시각은 `시:분:초` 로 늘 여덟 칸이다. 날짜는 찍지 않는다. 실패한 줄에는 `!` 가 붙고 색도 달라진다 —
색만으로 가르지 않는 것은 화면을 글자로 떠서 보는 길이 있어서다. 문구가 화면보다 길면
**오른쪽을 접는다**(`…`). 정의 후보 목록이 경로를 왼쪽부터 접는 것과 반대인데, 알림은 앞머리가
무엇이 일어났는지이기 때문이다.

기록에 상한이 없고 같은 문구를 접지도 않는다. 되풀이된 횟수가 정보다. 편집기를 끄면 사라진다.

목록을 여는 것 말고 알림을 지우거나 고치는 키는 없다.

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 다음 / 이전 알림 | 양끝에서 멈춘다. 둘러 가지 않는다
g / G | 처음 / 끝으로 | 목록이 길어지는 유일한 화면이라 여기만 있다
휠 | 목록 오르내리기 | 한 번에 3 행. 다른 목록과 같다
q, esc | 닫고 normal 로 | 기록은 그대로 남는다
ctrl+c | 전체 종료 | 다른 mode 와 같다

한글 입력 상태에서 온 키는 두벌식 자리의 영문 키로 되돌린다(ADR-0008). 작업 목록과 같은 이유다.

작업 목록과 하는 일이 다르다. `:jobs` 는 **무엇이 돌고 있나**를 보고 취소하는 화면이고,
여기는 **무슨 말을 들었나**를 읽는 화면이다. 작업의 실패는 그 자체가 알림이라 이 목록에도
들어오지만 성공은 들어오지 않는다 — 5 초마다 도는 git 갱신이 목록을 채우기 때문이다.
