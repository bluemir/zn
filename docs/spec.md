# Spec

## UI 구성

- 편집 영역 위 tabline
	- 열린 파일 목록
	- 1줄로 표시. 파일이 하나여도 그린다. 열린 tab 이 없으면 줄만 남고 비어 있다
	- 편집 영역 위에만 그린다. sidebar 가 열려 있으면 그만큼 짧다
- 편집 영역 맨 위 sticky 머리줄
	- 화면 위로 올라가 버린 제목·정의를 붙인다. 자리를 떼지 않고 본문 위 몇 행을 덮는다
- 편집 영역 왼쪽 줄번호
	- 절대번호와 상대번호를 나란히. 상대번호가 본문에 붙는 쪽이다
	- 맨 앞 두 칸은 마커 자리다. 진단 마커와 git 마커가 각각 한 칸씩 서고, 아무것도 없어도 비워 둔다
	- 항상 그린다. 번호 칸을 떼고 나면 본문이 20칸 아래로 떨어지면 그리지 않는다
	- 열린 tab 이 없으면 그리지 않는다. 붙일 줄이 없다
- 좌측 sidebar
	- filetree. 기본으로 열려 있다
	- 32칸 고정. 화면 맨 윗줄부터 statusBar 앞줄까지를 차지한다
	- 편집 영역이 20칸 아래로 떨어지면 켜져 있어도 그리지 않는다
- 하단 statusBar
	- mode 는 sidebar 아래, 파일 경로는 편집 영역 아래
	- 2줄로 표시
	- 첫 줄만 반전. 둘째 줄은 명령줄이라 배경을 그대로 둔다(ADR-0004)
	- 첫 줄 오른쪽 끝에 git branch·commit·dirty 여부(ADR-0009)
- 하단 drawer
	- statusbar 바로 상단, 편집영역 아래
	- 폭은 편집영역과 같고, 높이는 필요에 따라 가변
	- 필요할때만 펼쳐짐. 관련작업이 끝나면 닫힘
	- register 내용을 확인하거나, 상세 오류내역을 보는등 편집맥락에서 필요한 부가 정보/list 등 다양한 용도로 사용됨
	- 지금 쓰는 곳은 특수문자 입력(아래 「특수문자 mode」) 과 register 목록(아래 「register
	  목록」) 둘이다. 편집 영역에 얹지 않고 그 행을 가져간다 — 얹으면 커서가 판 밑에
	  가려진다(ADR-0056)
	- 판을 그리는 코드는 둘이 나눠 쓰지 않는다. 안쪽이 완전히 달라서 공유될 것이 테두리뿐이다.
	  가져간 행 수(`drawerHeight`) 만 공유한다(ADR-0058)
	- sidebar 옆은 지나가지 않는다. drawer 를 열어도 트리 높이는 그대로다

sidebar 가 화면 위쪽을 세로로 가르고 tabline 과 편집 내용이 그 오른쪽에 쌓인다.
맨 아래 statusBar 두 줄만 그 가름을 지나 화면을 가로지른다.

sidebar 구분선·tabline 구분자·팔레트 테두리는 `│ ─ ┌ ┐ ├ ┤ └ ┘` 이지만, 이 글자들은
East Asian Width 가 Ambiguous 라 폭이 터미널마다 다르다. 시작할 때 한 번 재서 한 칸으로
확인된 터미널에서만 쓰고, 두 칸이거나 재지 못하면 ASCII `| - +` 로 그린다(ADR-0028).
아래 그림은 모두 유니코드 쪽이다.

### 터미널 창 제목

편집기가 창 제목에 지금 고치고 있는 파일을 적는다(ADR-0110).

```
zn                                  볼 파일이 없을 때
zn editor.go (internal/core)        저장소 아래의 파일
zn editor.go + (internal/core)      저장하지 않은 변경이 있을 때
zn go.mod                           뿌리에 있는 파일이라 적을 폴더가 없다
zn [No Name]                        아직 이름이 없는 buffer
```

`zn` 이 앞인 것은 창 목록과 tmux 상태줄이 뒤를 자르기 때문이다. `+` 는 tabline 이 쓰는 것과 같은 글자다 — 창을 여럿 띄워 둔 사람이 어느 창에 저장하지 않은 것이 있는지 보는 자리다. tab 개수와 mode 는 적지 않는다.

**터미널이 받지 않으면 아무 일도 일어나지 않는다.** 되묻지 않는 일방 통보라 답을 기다리는 자리가 없다.

**tmux 안에서는 pane 제목이 바뀐다.** tmux 의 `set-titles` 가 기본이 꺼짐이라 바깥 창 제목까지는 가지 않는다. 상태줄의 `#T` 로는 보이고, 그 설정을 켠 사람은 창 제목으로도 본다.

**편집기를 나가면 제목이 빈다.** 원래 제목으로 되돌리지 않는다. 대개 셸 프롬프트가 다음 줄에서 다시 쓴다.

### tabline

CLI 인자로 받은 파일이 각각 tab 이 된다. `:tabnew` 로 이름 없는 빈 tab 을 더 열 수 있고,
새 tab 은 맨 뒤가 아니라 보고 있던 tab 바로 뒤에 생긴다.

**인자가 없으면 tab 없이 시작한다.** 그때 편집 영역에 오는 것이 아래 「빈 화면」 이다
(ADR-0064).

tab 하나는 `번호 파일이름` 이고, 이름은 경로가 아니라 파일 이름만 쓴다.
이름이 없으면 `[No Name]` 이고, 저장하지 않은 변경이 있으면 뒤에 `+` 가 붙는다.

보고 있는 tab 만 편집 내용과 같은 색이고 나머지는 반전이다(ADR-0004). 활성 tab 이 아래 내용과
이어져 보인다. 줄 끝의 남은 칸까지 반전이라 줄 전체가 한 덩어리로 보인다.

```
 1 buffer.go │ 2 editor.go+ │ 3 core.go
└─ 활성 ────┘└─ 여기부터 줄 끝까지 반전 ───┘
```

tab 이 편집 영역 너비보다 많아지면 활성 tab 이 보이는 자리까지 가로로 민다. 화면 밖으로 나간
만큼만 밀어서 `gt` 한 번에 한 tab 씩 움직인다. 가려진 것은 양끝에서 `<n`(왼쪽)·`n>`(오른쪽)
이 개수로 알린다. tab 을 닫거나 화면이 넓어져 오른쪽에 자리가 남으면 왼쪽에 가려둔 것을 도로
당겨 온다(ADR-0029).

```
<2│ 3 core.go │ 4 editor.go+ │ 5 mouse.go │1>
└ 왼쪽으로 2 개                  오른쪽으로 1 개 ┘
```

반쯤 걸친 tab 은 그리지 않는다. 양끝 표시를 누르면 보고 있는 tab 은 그대로 두고 그 방향으로
한 tab 씩 민다 — 편집하던 파일을 놓지 않고 가려진 쪽을 훑을 수 있다. 그렇게 밀어둔 것은
`gt`/`gT` 로 tab 을 옮기는 순간 활성 tab 을 따라 다시 맞는다.

tabline 은 편집 영역 위에만 있다. sidebar 위에는 걸치지 않고, sidebar 가 열려 있으면
편집 영역 너비만큼만 그려진다(ADR-0005). tab 목록은 sidebar 가 아니라 지금 보고 있는 파일에
딸린 것이기 때문이다. statusBar 는 글자 시작 위치만 그것에 맞추고 줄은 끊지 않는다.

파일별 커서 위치와 스크롤은 tab 을 오가도 그대로 남는다.

tab 을 하나씩 닫아 마지막까지 닫으면 tab 이 없는 상태가 된다. tabline 은 그 줄을 비운 채로
남고 편집 영역이 빈 화면으로 바뀐다 — 줄까지 없애면 tab 을 여닫을 때마다 편집 영역이 한 행
튄다(ADR-0064).

### 공백 표시

tab 과 space 는 화면에서 똑같은 빈 칸이라 들여쓰기가 둘로 섞여도 알아챌 수 없다.
tab 은 `»`(U+00BB), space 는 `⋅`(U+22C5) 로 찍어 눈으로 가른다. 항상 켜져 있고 끄는 방법은 없다.
space 마커가 흔한 `·`(U+00B7) 가 아닌 것은 그것이 East Asian Width 가 Ambiguous 라
터미널에 따라 두 칸이 되기 때문이다(ADR-0020).

찍는 자리는 **줄 앞 들여쓰기와 줄 끝 공백뿐**이다. 줄 가운데까지 찍으면 산문과 주석이
점으로 뒤덮여 읽기 어렵다. 가운데 tab 은 마커 없이 빈 칸으로만 벌어진다.
공백뿐인 줄은 줄 전체가 들여쓰기라 전부 찍힌다.

tab 마커는 tab 이 시작하는 한 칸뿐이고 남는 칸은 빈 칸이다 — 남는 칸까지 점으로 채우면
space 와 같아 보인다. tab 폭이 4 칸인 파일에서 줄 앞 tab 하나는 `»` 와 빈 칸 3 개다.

```
»   println("hello")⋅⋅      ← tab 들여쓰기 + 줄 끝 공백 2 개
⋅⋅⋅⋅spaces indent           ← space 4 개 들여쓰기
»   ⋅⋅mixed indent          ← tab 뒤에 space 2 개
a b c                       ← 줄 가운데 공백은 그대로
```

마커는 본문보다 흐린 색(256색 240) 이다. 검색으로 강조된 구간 안에서도 마커는 흐린 색이고
강조 배경은 그대로 이어진다.

### 문법 강조

파일 이름으로 언어를 알아보고 본문에 색을 입힌다(ADR-0039). 열한 언어다 — golang, markdown,
html, css, js, python, shell, makefile, dockerfile, json, yaml. 모르는 확장자(`.txt` 등) 는
색이 없다.

json 은 계열 넷을 한 lexer 로 훑는다 — `.json`·`.jsonc`·`.json5`·`.hjson` (ADR-0055). 넷이 같은
모양에 허용하는 것만 달라서 주석·따옴표 없는 키·`'''` 여러 줄 문자열을 어느 확장자에서나 알아본다.
**강조는 검사가 아니다** — `.json` 에 적은 주석도 주석 색이 입고, 문법이 틀렸다는 것은 그 파일을
읽는 프로그램이 말한다. yaml(`.yaml`·`.yml`) 은 모양이 아주 달라서 lexer 를 따로 둔다.

갈래 | 색 | 나오는 자리
--- | --- | ---
주석 | 108 | 모든 언어 / markdown 의 인용문. **이 표에서 가장 흐리다** — 물러나 있어야 한다
문자열 | 113 | 따옴표 안 / markdown 의 코드 스팬
숫자 | 215 | 숫자 literal / css 의 `#fff`
예약어 | 177 | keyword / html tag 이름, docker 명령, make 지시자, css 속성, yaml 의 `---`
type | 185 | 미리 선언된 이름·새 type / python 의 class, css 선택자, 코드펜스의 언어 이름, yaml 의 `!!str`
부르는 이름 | 111 | 함수 / make 의 대상 이름
값 낱말 | 210 | `nil` `true` `None` / html 의 `&amp;`, css 의 값, json·yaml 의 `true` `null`
값 참조 | 79 | `$(VAR)` `${VAR}` / css 의 `var(--x)`, yaml 의 anchor·alias
키 | 79 | json·yaml 의 키, html 속성 이름, css 의 `--x` 선언
제목 | 45 + 굵게 | markdown 의 `#`
강조 | 177 + 기울임 | markdown 의 `*foo*`
굵게 | 177 + 굵기 | markdown 의 `**foo**`
링크 | 111 | markdown 의 `[글](주소)` 의 주소와 `<주소>`

**어두운 배경에 맞춘 값이다**(ADR-0041). `#1e1e1e` 기준으로 전부 6.8:1 이상이고, 주석이 가장
낮다 — 일부러 그렇다. 밝은 배경에서는 1.5~2.5:1 로 약하다.

같이 나오는 갈래끼리는 색상이 25 도 이상 갈린다. 반대로 **같이 나오지 않는 갈래는 색을 나눠
쓴다** — 강조·굵게가 예약어와, 링크가 부르는 이름과 같은 색이다. markdown 에 예약어·부르는
이름이 없고 코드에 제목·강조·링크가 없어서 한 화면에서 만나지 않는다. 그래서 갈래 열셋이
색 아홉이다.

**키와 값 참조는 예외로 한 화면에 같이 나오면서 같은 색이다.** css 의 `--x: red` 와 `var(--x)`,
yaml 의 키와 anchor 가 그렇다. 자리가 이미 갈라 주기 때문이다 — 키는 줄 앞에 서고 참조는 값
자리에 선다. 갈래를 나눠 둔 것은 색을 나눠야 할 날에 표 한 줄만 고치기 위해서다(ADR-0055).

**겹치면 검색 > 선택 > 문법이다.** 찾은 자리와 고른 범위는 글자색과 배경을 함께 정하고 문법은
글자색만 정해서, 그 구간에서는 문법 색이 보이지 않는다. vim 과 같다. 공백 마커는 그 안에서도
자기 칸을 지킨다 — 주석 안의 줄 끝 공백은 주석색이 아니라 흐린 마커로 그려진다.

여러 줄에 걸치는 것(블록 주석, raw string, 코드펜스, `<script>` 안, 세 겹 따옴표) 은 줄 단위로
문맥을 이어 가며 판정하므로 파일이 아무리 길어도 색이 어긋나지 않는다.

링크는 **주소만** 칠한다. `[글]` 의 글은 읽는 사람에게 보일 문장이라 본문과 같이 둔다.
상대 경로(`[명세](docs/spec.md)`) 도 링크다. 인용문(`>`) 은 줄 단위라 그 안의 링크는 따로
칠하지 않는다.

**코드펜스 안은 그 언어로 훑는다**(ADR-0040). 여는 표시 뒤 첫 낱말이 언어를 정한다 —
`go`(`golang`), `md`(`markdown`), `html`, `js`(`javascript`), `css`, `py`(`python`),
`sh`(`bash` `shell` `zsh`), `make`(`makefile`), `docker`(`dockerfile`) 다. **모르는 이름이나
이름이 없으면 색이 없다.** 펜스는 겹칠 수 있다.

html 의 `<script>` 안은 js, `<style>` 안은 css 다. `type` 속성은 보지 않는다.

**닫는 표시가 안쪽 언어보다 세다.** 펜스의 닫는 줄과 `</script>` 는 안쪽에서 문자열이나 주석이
열려 있어도 블록을 끝낸다. 브라우저가 `</script>` 를 js 문자열 안에서도 끝으로 읽는 것과 같다.

### 줄번호

편집 영역 왼쪽에 `진단 git 절대 상대` 순서로 붙는다. 상대번호가 본문에 붙는 쪽이라 `5j` 처럼 셀 때 눈이 덜 움직인다. 커서 줄의 상대번호는 `0` 이다. 절대번호가 바로 옆에 있어서 거기에 또 찍지 않는다.

맨 앞 두 칸은 마커 자리다. 왼쪽이 진단(아래 「진단 마커」), 오른쪽이 git(아래 「git 마커」) 이고, 아무것도 없어도 늘 비워 둔다. 있을 때만 잡으면 첫 오류가 뜨는 순간 본문 전체가 한 칸 밀린다.

둘을 한 칸에 겹치지 않는다. 오류가 있는 줄은 대개 방금 고친 줄이라, 나눠 쓰면 정작 보고 싶을 때 git 표시가 가려진다.

```
    1  4 package main
    2  3
    3  2 func main() {
 ~  4  1         println("hi")
✖+  5  0         return          ← 커서
    6  1 }
```

상대번호만 흐린 색이다(256색 244, sidebar 와 같은 값). 절대번호는 노랑(ANSI 3) 이다.
본문 색은 위 「문법 강조」에 있다.

자릿수는 절대번호가 전체 줄 수를, 상대번호가 화면 높이를 따라간다. 상대번호는 화면 밖으로
나가면 볼 수 없으므로 줄 수와 무관하다. 각각 최소 3 칸과 2 칸이라 짧은 파일에서도 본문이
너무 왼쪽에서 시작하지 않는다.

wrap 되어 이어지는 화면 행은 번호 칸이 빈 칸이다. 번호가 있는 행이 곧 논리 줄의 시작이다.

칸만큼 본문이 좁아지므로 줄바꿈도 그 너비에서 일어난다. 떼고 나면 본문이 20칸 아래로
떨어지는 좁은 화면에서는 sidebar 와 같은 규칙으로 그리지 않는다. 마커 칸도 그때 같이 사라진다.

### 진단 마커

언어 서버가 붙는 파일을 열면 서버가 오류와 경고를 보내오고, 그것이 줄번호 왼쪽 마커 칸에 선다(ADR-0086). Go 는 gopls, python 은 pyright 다(ADR-0107). 컴파일 오류도 여기 든다. 따로 `go build` 를 돌리지 않는다.

```
✖   8  1         fmt.Println(undefinedThing)
    9  0         x := 1                        ← 커서
⚠  10  1         fmt.Printf("%d", "글자")
   11  2 }
```

`✖`(빨강, ANSI 1) 이 오류이고 `⚠`(밝은 노랑, ANSI 11) 이 경고다. 색만으로 가르지 않아서 흑백 화면에서도 읽힌다. 한 줄에 둘이 같이 있으면 오류가 이긴다. wrap 되어 이어지는 행에는 마커가 서지 않는다. 정보·힌트 갈래는 그리지 않는다.

**커서가 그 줄에 서면 statusBar 아래 줄에서 무엇인지 읽는다.** 커서 자리 뒤에 붙고 tip 이 그만큼 물러난다. 여럿이면 심한 것 하나와 개수다.

```
12:5  (550 줄)  ✖ undefined: undefinedThing (2)
```

알림이 뜨는 순간에는 알림이 그 줄을 쓴다. 다음 키에 알림이 걷히면 진단이 다시 드러난다.

**오류를 다 고치기 전에는 경고가 뜨지 않는다.** gopls 가 타입 오류가 있는 패키지에서는 분석기를 돌리지 않는다. 경고 마커가 갑자기 늘어나는 순간이 있는데 그것이 이 까닭이다.

**타이핑 중에는 마커가 한두 줄 어긋나 있을 수 있다.** 서버에 보내는 것이 마지막 키에서 250ms 뒤라서다. 보정하지 않고 다음 진단이 오면 제자리를 찾는다.

열려 있는 파일만 그린다. gopls 는 같은 패키지의 열지 않은 파일 진단도 보내는데 그것은 버린다. 파일 트리와 tabline 은 조용하고, 진단 목록을 여는 길도 아직 없다.

### 언어 서버

**어느 파일에 어느 서버가 붙는지는 표 한 줄이 정한다**(ADR-0107). 지금 두 줄이다.

서버 | 확장자 | 찾는 순서 | 없을 때 깔는 명령
---|---|---|---
gopls | `.go` | PATH → `GOBIN` → `GOPATH/bin` | `go install golang.org/x/tools/gopls@latest`
pyright | `.py` | `VIRTUAL_ENV` → 저장소의 `.venv`·`venv` → PATH → `uv tool dir --bin` | `uv tool install 'pyright[nodejs]'`

그 언어의 파일을 처음 열 때 서버가 뜬다. 서버마다 하나씩이고, 서버가 없으면 `\gd`·`\gr`·`\rn` 이 설치를 한 번 묻는다. **서버 하나가 깔려 있지 않은 것이 다른 언어를 막지 않는다** — 뜨는 중인지·실패했는지·몇 번 죽었는지가 서버마다 따로다.

**서버마다 자기 언어의 파일만 받는다.** 열린 tab 이 여러 언어여도 각 서버는 자기 몫만 안다.

**python 의 색은 lexer 가 낸다.** pyright 는 문법 토큰을 주지 않아서(재서 확인했다) 서버가 색을 갈아끼우는 길(ADR-0103) 이 python 에서는 돌지 않는다. Go 만 그 길을 탄다.

### git 마커

**HEAD 와 다른 줄**이 줄번호 왼쪽, 진단 칸 오른쪽에 선다(ADR-0094).

```
    7  2 func main() {
 ~  8  1         println("안녕")
 +  9  0         println("반가워")          ← 커서
 _ 10  1 }
```

`+`(초록) 가 새로 넣은 줄, `~`(파랑) 가 고친 줄, `_`(빨강) 가 **그 줄 다음에 없어진 줄이 있다**는 표시다. 지운 줄은 화면에 자리가 없어서 앞 줄에 남긴다. 파일 맨 앞이 지워졌으면 첫 줄에 선다. 한 줄에 둘이 겹치면 그 줄 자신에 대한 사실(넣음·고침) 이 이긴다.

**기준이 HEAD 다.** `git add` 를 해도 표시가 남는다. 「마지막 commit 이후 바뀐 줄」이 사람이 묻는 것이라, stage 한 것을 빼면 commit 을 빠뜨리는 쪽으로 틀린다.

**저장하지 않은 편집도 센다.** 디스크가 아니라 지금 화면의 내용을 견준다. 다시 내는 때는 마지막 키에서 250ms 뒤이고(진단과 같은 자리다) `git commit`·`checkout` 으로 기준이 움직이면 5 초 안에 따라온다.

**추적하지 않는 새 파일에는 마커가 없다.** 견줄 원본이 없다. 그 파일이 새것이라는 말은 트리의 `?` 가 한 번 한다.

### 마커 사이를 뛰기

`]c` 로 다음 변경, `[c` 로 앞 변경, `]d` 로 다음 진단, `[d` 로 앞 진단으로 간다(ADR-0095). 숫자를 앞에 붙이면 그만큼 건너뛴다(`3]c`).

`]c`·`[c` 는 vim 에 있는 키다. 다만 그쪽에서는 `vimdiff` 로 연 diff mode 안에서만 뜻이 있고, 우리는 diff mode 가 없어서 그 자리를 HEAD 와의 차이로 쓴다. `]d`·`[d` 는 vim 에서 `#define` 을 찾는 자리인데 우리에게 그 기능이 없어서 Neovim 처럼 진단으로 쓴다.

**잇달아 붙은 변경은 한 자리다.** 열 줄을 고쳤으면 마커가 열 개 서지만 `]c` 는 그 첫 줄로 한 번만 간다. 진단은 묶지 않는다 — 잇달아 선 오류는 저마다 다른 오류다.

**감아 돈다.** 마지막 다음은 처음이고, 감았으면 아래 줄이 알린다(`아래에서 처음으로 돌아옴`). 검색의 `n`·`N` 과 같다. 하나도 없으면 커서를 두고 알리기만 한다.

**뛰기 전 자리는 되돌아오기 이력에 담긴다.** `ctrl+o` 로 돌아오고 `:jumps`·`:jumplogs` 에도 남는다.

**operator 뒤에는 오지 않는다.** `d]c` 는 아무 일도 하지 않는다.

### 파일 트리의 git 마커

트리의 각 행 오른쪽 끝, 구분선 앞 한 칸이다.

```
▾ internal/          M│
    editor.go        M│
    new.go           ?│
    editor_test.go    │
```

`M`(파랑) 이 HEAD 와 다른 파일, `?`(초록) 가 git 이 모르는 새 파일이다. `git status --short` 와 같은 글자이고, 줄 마커와 같은 색이라 왼쪽 칸의 `~` 와 트리의 `M` 이 같은 것을 가리킨다는 것이 이어진다.

**디렉터리에도 선다.** 안에 달라진 것이 있으면 그 위 디렉터리마다 표시가 서서, 접혀 있어도 「이 안에 뭔가 있다」가 보인다. 안에 고친 파일과 새 파일이 섞여 있으면 고친 쪽으로 적는다. 뿌리에는 서지 않는다.

**무시된 파일은 세지 않는다.** statusBar 의 `*` 와 같은 기준이고(ADR-0009), 실은 같은 표를 센 것이다.

**5 초마다 다시 읽는다.** 다른 터미널에서 `commit` 하고 돌아오는 사이에 값이 맞는 정도다(ADR-0043).

### sticky 머리줄

지금 보는 곳을 감싸는 제목·정의를 편집 영역 맨 위에 붙인다. VSCode 의 sticky scroll 과 같다
(ADR-0049).

**기준은 커서가 아니라 화면 맨 윗줄이다.** 그래서 위로 밀려 안 보이게 된 것만 붙는다 —
화면에 이미 있는 제목이 위에 한 번 더 그려지지 않고, 파일 첫 화면에서는 아무것도 붙지 않는다.

```
   1    # Spec                   ← 감싸는 제목들. 줄번호가 이어지지 않는다
 332 88 ## Mode
 345 75 ### Normal mode
 408 12 #### 단어 경계
 412  8 `foo.bar` 는 세 단어다.  ← 여기부터 본문
 413  7
```

감싸는 것을 전부 붙인다. markdown 은 `#` 개수가 깊이라 최대 여섯이고, 코드는 들여쓰기가
깊이다. 늘 켜져 있고 끄는 길은 없다 — 강조하지 않는 파일에서는 저절로 붙지 않는다.

**본문과 색으로 가르지 않는다.** 줄번호가 늘 나오므로 번호가 뚝 끊기는 것이 곧 표시다.
상대번호는 그 줄까지 가는 실제 `k` 수이고, 화면 높이보다 멀면 그 칸이 빈다.

**자리를 떼지 않고 덮는다.** 그래서 가려지는 본문 줄이 생기고, 화면 기하는 하나도 바뀌지 않는다.
커서는 덮이지 않는다 — 화면이 그만큼 더 올라간다. 편집 영역 절반을 넘게 덮지 않으며, 넘치면
바깥쪽부터 버린다.

머리줄을 누르면 그 줄로 간다.

무엇이 아래 줄들을 거느리는지는 언어가 정한다. markdown 은 제목이고(코드펜스 안의 `#` 은
아니다), makefile 은 대상 줄이고, dockerfile 에는 없다. 나머지는 블록을 여는 줄이라
autoindent 와 같은 규칙을 쓴다.

### sidebar (filetree)

기본으로 열려 있다.`:tree` 로 여닫는다. cwd 가 뿌리이고, 디렉터리를 펼치면 그 자리에서
들여쓰기로 벌어진다. cwd 를 읽지 못하면 트리 없이 연다.
`.git` 은 어느 깊이에서든 감추고 나머지 숨김 파일은 보인다.

sidebar 는 화면 맨 윗줄부터 statusBar 앞줄까지다. tabline 은 그 오른쪽, 편집 영역 위에만 있다.
statusBar 는 sidebar 아래를 지나 화면을 가로지르고, 그 아래 칸에는 mode 가 온다.

```
▾ zn/                         │  1 main.go
  ▸ docs/                     │     1  0 package main
  ▾ internal/                M│     2  1
      main.go                M│  ~  3  2 func main() {
    README.md                 │     4  3 }
NORMAL                          internal/main.go
                                1:1  (4 줄)
└──────────── 32칸 ────────────┘└─ 나머지가 편집 영역 ─┘
                                └ 마커·줄번호 ┘└ 본문 ┘
```

sidebar 의 32 칸은 **이름 29 칸 + git 마커 한 칸 + 구분선 + 그 뒤 빈 칸**이다. 이름이 길면
29 칸에서 잘리고 마커는 잘려도 늘 같은 자리에 선다(아래 「파일 트리의 git 마커」).
편집 영역의 맨 앞은 마커 두 칸과 줄번호이고(위 「줄번호」) 그 뒤가 본문이다.

디렉터리는 먼저 오고 그 안은 이름순이다. 펼침 표시는 `▾`(펼침) `▸`(접힘) 이고 파일은 그 자리가
빈 칸이라 같은 깊이의 이름이 나란히 선다. symlink 는 따라가지 않고 `@` 를 붙인다.

펼칠 때마다 그 디렉터리를 다시 읽는다. 접었다 펴는 것이 곧 새로고침이다.

보는 파일이 바뀌면 트리가 그 자리를 펼치고 고른다(ADR-0019). CLI 인자로 시작할 때, 팔레트나
트리에서 파일을 열 때, `gt`/`gT`·tabline 클릭으로 tab 을 옮길 때, `:q` 로 tab 을 닫아 다른
파일이 드러날 때, `:tree` 로 트리를 다시 열 때다.
지나는 길의 디렉터리 중 접혀 있는 것만 펼치고 이미 펼쳐진 것은 다시 읽지 않는다 —
다시 읽으면 그 아래 펼쳐 둔 것이 통째로 접힌다.
읽어야 할 디렉터리가 있으면 한 층씩 읽어 내려가므로 자리를 잡는 것이 한 박자 늦을 수 있다.

이때 sidebar 를 열지는 않는다. `:tree` 로 닫아둔 상태면 아무 일도 하지 않고, 좁은 화면이라
감춰진 상태면 트리만 펼쳐 둔다. 뿌리 밖의 파일, symlink 디렉터리 안쪽, 이름 없는 buffer 는
고른 자리를 건드리지 않는다.

색은 파일 종류로 나뉜다(ADR-0005). 256색 고정값이다.

종류 | 색
-----|----
디렉터리 | 117
`.go` | 81
`.md` `.txt` | 150
`.html` `.css` `.js` | 179
그 외 | 기본색
gitignore 된 것 | 244 (종류별 색을 덮어쓴다)

무시 여부는 규칙을 직접 구현하지 않고 디렉터리를 펼칠 때 `git check-ignore` 에 한 번 묻는다.
git 이 없거나 저장소 밖이면 아무것도 흐리게 하지 않는다. 묻는 것도 읽기와 같은 작업 안에서
돌므로 펼치는 키가 그것을 기다리지 않는다(아래 「큰 디렉터리」).

**지금 보고 있는 파일은 굵은 글씨다.** 종류별 색 위에 덧입힌다 — 색은 그 파일이 무엇인지,
굵기는 지금 보고 있는지다. 고른 자리를 나타내는 터미널 커서는 포커스가 트리에 있을 때만
그려지므로, 편집 중에 트리가 지금 자리를 나타내는 것은 이 굵기뿐이다.

굵기는 이 한 뜻으로만 쓴다. 디렉터리는 색(117) 과 `▸`/`▾` 표시와 `/` 접미로 이미 갈리므로
굵게 하지 않는다. 열려 있는 tab 을 **전부** 구분하지는 않는다 — 그것은 tabline 이 한다(ADR-0022).

#### 큰 디렉터리

**디렉터리 읽기는 백그라운드 작업이다**(ADR-0032). 펼침 표시(`▾`) 는 누른 그 자리에서 서고
자식 자리에는 `… 읽는 중` 한 행이 선다.

```
▾ big/
    … 읽는 중
```

다 읽으면 그 행이 자식으로 바뀐다. 편집기는 그동안 멈추지 않고, 도는 작업은 `:jobs` 에
`디렉터리 읽기 <경로>` 로 보인다. 읽는 중에 접으면 그 작업이 취소된다 — 늦게 도착한 결과는
접힌 것을 도로 펼치지 않는다.

**항목 수에 상한은 없다.** 십만 개짜리 디렉터리도 끝까지 읽어 다 보여준다. 감추면 그 파일로 갈
길이 트리에서 없어지고, 행이 많아도 그리는 값이 사람에게 닿지 않는다(자식 5 만 개에서 키 한 번이
1.2ms 다). 다 읽은 개수는 `:jobs` 의 그 줄에 `50,001 개` 로 남는다.

`… 읽는 중` 은 파일이 아니다. gitignore 된 항목과 같은 흐린 색이고, 골라서 `Enter` 를 눌러도
아무 일도 하지 않으며 "보고 있는 파일" 표시도 받지 않는다.

#### 포커스와 key mapping

`Ctrl+W` 는 vim 의 window 명령 접두 키다. pane 이 둘뿐이라 순환이 곧 왕래다.
sidebar 가 안 보이면 편집 영역에 머물고 왜 못 갔는지 아래 줄에 알린다 —
`:tree` 로 닫아 두었으면 「트리가 닫혀 있습니다」, 화면이 좁아 감춘 것이면 「화면이 좁아 트리를
열 수 없습니다」다. 아무 일도 나지 않으면 키가 먹었는지 알 수 없다.

키 | 기능 | 기타
---|------|-----
ctrl+w ctrl+w | 편집 영역 ↔ sidebar | `ctrl+w w` 도 같다
esc | 편집 영역으로 | sidebar 에서만
↑ ↓ | 트리 이동 | `k` `j` 도 같다
{숫자}j {숫자}k | 그만큼 뛴다 | `20j` 다. 양끝에서 멈춘다(ADR-0059)
G | 마지막 행 | `20G` 는 보이는 행 스무 번째다
gg | 뿌리로 | `20gg` 도 `20G` 와 같다. normal 과 같은 손버릇이다
ctrl+d ctrl+u | 반 화면 아래 / 위 | 고른 항목과 트리 화면이 같이 움직인다(ADR-0062)
ctrl+f ctrl+b | 한 화면 아래 / 위 | 두 행을 겹쳐 둔다. 편집 영역과 같다(ADR-0063)
pgdown pgup | 한 화면 아래 / 위 | `ctrl+f` `ctrl+b` 와 같다
home end | 첫 행 / 마지막 행 | **숫자를 보지 않는다.** `gg` `G` 와 갈리는 자리다(ADR-0076)
enter | 디렉터리면 펼치기/접기, 파일이면 열기 | 파일을 열면 포커스도 편집 영역으로 간다
mc | 새 파일·디렉터리 만들기 | `ma` 도 같다. 아래 「파일 만들고 지우고 이름 바꾸기」
md | 고른 항목 지우기 | 파일은 곧바로, 디렉터리는 묻고 나서(ADR-0057)
mm | 이름 바꾸기·자리 옮기기 | 지금 경로가 채워진 칸을 준다
클릭 | 그 항목을 고르고 `enter` 와 같이 연다 | 포커스도 sidebar 로 온다
휠 | 트리를 굴린다 | 고른 항목은 움직이지 않는다

**숫자를 보는 것은 이동 여덟뿐이다.** `3md` 는 `md` 이고 `3enter` 는 `enter` 다 — 편집 영역에서
`3i` 가 `i` 인 것과 같은 자리다. 행 번호는 **보이는 행**을 1 부터 센 것이라, 접힌 디렉터리
안쪽은 세지 않는다. `0` 은 숫자의 첫 자리가 될 수 없다(ADR-0059).

sidebar 에 포커스가 있으면 statusBar 의 mode 가 `TREE` 이고 아래 줄에 고른 항목의
뿌리 기준 상대 경로가 뜬다. `ctrl+w` 를 누르고 다음 키를 기다리는 동안은 그 줄 오른쪽 끝에
누른 접두 키가 보인다 — 모으던 숫자도 같이 보인다(`20g`). 편집 영역과 같다.
**고른 항목 위에 터미널 커서가 놓이는 것이 곧 포커스 표시다** — 따로 반전을 칠하지
않는다(ADR-0005).

`enter` 로 파일을 열면 새 tab 이 된다. 이미 열려 있으면 새로 열지 않고 그 tab 으로 옮긴다.
일반 파일이 아니면(디렉터리를 가리키는 symlink, FIFO 등) 열지 않고 아래 줄에 알린다.

sidebar 는 `:` 를 받지 않는다.

트리 아래 빈 자리를 클릭하면 아무 일도 하지 않는다. 트리가 화면보다 짧아도 구분선은
아래까지 이어지므로, 그 빈 행은 누를 것이 없는 자리다. 휠로 고른 항목이 화면 밖으로
나가면 커서를 놓을 곳이 없어 포커스 표시가 잠시 보이지 않는다 — 다음 `j`/`k` 가 데려온다.

한글 입력 상태의 키는 편집 영역과 같이 두벌식 자리의 영문 키로 되돌려 받는다
(`ㅓ` 가 `j` 다). Normal mode 의 「한글 입력 상태」 를 참고한다.

#### 파일 만들고 지우고 이름 바꾸기

`mc` 로 만들고 `md` 로 지우고 `mm` 으로 이름을 바꾼다(ADR-0054). `m` 은 `ctrl+w` 와 같은 접두
키라 기다리는 동안 showcmd 자리에 보이고, 짝이 없는 조합(`mx`) 은 아무 일도 하지 않는다.

**만들기는 `ma` 로도 된다.** NERDTree 의 파일 메뉴가 `a`(add) 로 만들어서, 그 손버릇으로 온 손이
`mc` 를 찾지 않아도 되게 둘 다 받는다. 하는 일은 똑같다.

**`mc`(`ma`) 는 이름을 받는다.** statusBar 아래 줄이 `새 파일: docs/` 가 되고 그 뒤에 치는 것이
이름이다. 만들 자리는 고른 항목 기준이다 — 디렉터리를 골랐으면 그 안, 파일을 골랐으면 그 파일이
있는 디렉터리다. 접혀 있던 디렉터리는 만든 뒤 펼쳐진다.

```
새 파일: docs/guide.md
```

`enter` 가 만들고 `esc` 는 그만둔다. 이름을 다 지워도(`backspace`) 그만두는 것이다 —
명령줄에서 `:` 까지 지우면 나가는 것과 같다. 이름은 글자라 한글 입력 상태에서도 되돌려지지
않는다 — `한글.txt` 를 치면 그 이름 그대로다(ADR-0008).

이름 | 하는 일
-----|--------
`main.go` | 그 자리에 빈 파일을 만들고 **tab 으로 열어 편집 영역으로 간다**
`a/b/c.go` | 없는 `a/`·`a/b/` 를 같이 만든다
`docs/` | 디렉터리만 만든다. 열 것이 없으므로 트리에 머문다

이미 있는 이름은 만들지 않고 「이미 있습니다」로 알린다. 뿌리 밖으로 나가는 이름도 만들지
않는다 — 뿌리 안에 머무는 `../` 는 위층을 가리키는 것이라 된다.

**`md` 는 깨끗한 파일을 묻지 않고 지운다.** 두 키로 끝나고 트리에 머문다. 무엇이 사라졌는지는 아래 줄의 `지웠습니다: docs/spec.md` 가 말한다. 묻지 않으므로 이것이 아는 유일한 자리이고, 지나간 것은 `:messages` 에 남는다(ADR-0053, ADR-0057).

**tab 에 열려 있어도 지우고, 그 tab 을 같이 닫는다.** 디렉터리면 그 아래 열린 tab 을 전부 닫는다. 닫은 수도 알림이 말한다(`지웠습니다: docs/ (tab 1 개를 닫았습니다)`). 트리는 지운 자리에 머문다. 닫은 tab 자리에 드러난 파일로 따라가지 않는다(ADR-0130).

**물을 일이 있으면 화면 가운데 창이 뜬다.** 디렉터리이거나, 저장하지 않은 tab 이 딸려 있을 때다. 잃는 것마다 한 줄이고 없는 것은 그 줄이 없다.

```
┌─────────────────────────────────────────────┐
│                                             │
│ 지우면 되돌릴 수 없습니다.                  │
│                                             │
│ 안의 것까지 모두 지웁니다.                  │
│ 저장하지 않은 tab 1 개가 같이 닫힙니다.     │
│                                             │
│ docs/ 를 지울까요?                          │
│                                             │
│ > Yes      No                               │
│                                             │
└─────────────────────────────────────────────┘
```

디렉터리를 묻는 것은 안의 것까지 통째로 지우는데 접혀 있으면 트리가 이름 한 줄만 보여주기 때문이다. 저장하지 않은 tab 을 묻는 것은 그 편집이 트리의 행에 드러나지 않기 때문이다. 깨끗한 tab 은 잃을 것이 커서와 스크롤뿐이라 묻지 않는다.

**Yes/No 를 골라 `enter` 다.** 처음 고른 자리는 Yes 이고 `y`·`n` 은 고르기만 한다. 종료 확인창과 같은 손이다. `esc`·`ctrl+c` 는 곧바로 무른다. `ctrl+c` 도 여기서는 편집기를 끄지 않는다. 창은 트리를 깔고 그리므로 커서가 지울 행에 그대로 남아서, 창의 이름과 커서 자리를 맞춰 볼 수 있다.

지우지 않는 둘이 있다. **뿌리**는 트리 자체라 지울 수 없고, `… 읽는 중` 은 파일이 아니다.

**`mm` 은 지금 경로를 채워 준다.** 아래 줄이 `새 이름: docs/spec.md` 가 되고 커서는 그 끝이다.
한 글자만 고치거나 확장자만 두고 앞을 고치는 일이 대부분이라 빈 칸에서 시작하지 않는다.

```
새 이름: docs/design.md
```

**치는 것은 이름이 아니라 경로다.** 그래서 앞부분을 고치면 자리를 옮기는 것이 된다 —
`docs/spec.md` 를 `notes/spec.md` 로 고치면 `notes/` 로 옮겨지고, 없는 디렉터리는 같이 만들어진다.
기준은 고른 자리가 아니라 뿌리다. 디렉터리도 같은 길로 이름을 바꾸고 안의 것은 딸려 간다.
`backspace` 로 다 지워도 이 화면에 남는다 — 그만두는 것은 `esc` 다.

**그 파일을 열어둔 tab 은 새 이름을 따라간다.** 편집하던 내용과 커서 자리는 그대로이고,
저장하지 않은 변경도 새 이름으로 저장된다. 디렉터리를 옮기면 그 아래 파일을 보던 tab 도 같이
따라간다. 문법 강조는 새 확장자로 다시 고른다.

이미 있는 이름 위로는 옮기지 않는다 — `os.Rename` 은 묻지 않고 덮어쓴다. 대소문자만 바꾸는 것
(`readme.md` → `README.md`) 은 같은 파일이라 된다. 뿌리, 자기 안으로 옮기기, 뿌리 밖도 거절한다.
확인은 묻지 않는다 — 잃는 것이 없고 `mm` 을 한 번 더 눌러 되돌릴 수 있다.

만들거나 지우거나 옮긴 뒤에는 그 디렉터리를 다시 읽어 트리를 맞춘다. 그 아래 펼쳐 두었던 것은
접힌다 — 새로고침이 곧 접었다 펴는 것이기 때문이다(ADR-0032). 옮긴 것은 옮겨간 자리를 펼쳐서
고른 자리가 그 파일을 따라간다. **지운 것은 되돌릴 수 없다.** `u` 는 buffer 안의 일이라
지운 파일에는 닿지 않는다.

### statusBar

화면 아래 두 줄이다. 위 줄은 mode 와 파일 경로, 그리고 오른쪽 끝에 git 상태다.
경로 뒤에는 마커가 붙는다 — `[+]` 는 저장하지 않은 내 변경이고, `[!]` 는 마지막으로 맞춰 봤을 때
파일이 밖에서 달라져 있었다는 것이다(ADR-0031). 둘이 같이 붙으면 양쪽에 잃을 것이 있다는 뜻이다.
아래 줄은 mode 가 정한다 — normal/insert 는 `줄:칸  (N 줄)`, command mode 는 치고 있는 명령,
sidebar 는 고른 항목의 경로다. 아래 줄 오른쪽 끝은 showcmd 자리이고, 보여줄 showcmd 가
없으면 그 자리에 tip 이 선다.

mode 는 sidebar 아래 칸에, 파일 경로는 편집 영역 아래에 놓는다. 둘 다 자기가 가리키는 것
바로 밑에 서게 된다 — `TREE` 는 트리 아래에, 경로는 그 파일을 편집하는 자리 아래에 온다.
아래 줄은 mode 를 따라가지 않고 위 줄의 경로와 세로로 맞춘다. 명령줄과 커서 위치는
편집 중인 파일에 딸린 것이기 때문이다.

```
▾ zn/                         │  1 editor.go
  ▸ docs/                     │     1  0 package core
NORMAL                          internal/core/editor.go    master(f6cacbd*)
                                1:1  (550 줄)                            3g
└─ mode ────┘└─ 위 줄만 반전 ──────────────────────────────────────────────┘
                                                                       └ showcmd
```

sidebar 가 없으면 mode 를 놓을 왼쪽 칸 자체가 없으므로 경로 앞에 나란히 붙인다.

```
NORMAL  internal/core/editor.go              master(f6cacbd*)
1:1  (550 줄)                                              3g
```

#### tip

**아래 줄 오른쪽 끝이 비는 동안 그 자리에 tip 한 문장이 선다**(ADR-0061). 키는 계속 쓰지
않으면 까먹으므로, 편집기에 있는 것을 짧은 문장으로 스치게 보여준다.

```
NORMAL  internal/core/editor.go              master(f6cacbd*)
1:1  (550 줄)                    `"Ay` 는 register 에 잇습니다
```

**showcmd 가 먼저다.** 접두 키를 치는 동안에는 tip 이 사라지고 그 자리에 치던 키가 선다.
알림이 아래 줄을 쓰는 동안에도 비켜난다.

**들어가는 문장을 골라 보여준다.** 자르지 않는다 — 뒤가 잘린 tip 은 무엇을 누르라는 것인지
알려주지 못한다. 그래서 좁은 화면에서는 짧은 문장만 돌고, 하나도 들어가지 않으면 아무것도
보이지 않는다. git 표시와 같은 규칙이다.

**스스로 움직이지 않는다.** 알림이 뜰 때 다음 문장으로 넘어가므로, 가만히 보고 있는 화면에서는
글자가 바뀌지 않는다. 저장하거나 명령을 칠 만큼 새 문장이 돈다.

편집 화면(normal·insert·visual) 과 트리에 보인다. 명령줄(`:`) 과 검색(`/`) 은 그 줄에 커서가
서므로 없고, `:jobs`·`:messages` 같은 판도 그 줄을 자기 안내에 쓰므로 없다.

#### git 표시

`branch(commit)` 이고 저장하지 않은 변경이 있으면 commit 뒤에 `*` 가 붙는다.
detached HEAD 는 가리킬 branch 가 없어서 괄호 없이 짧은 해시만 찍는다(`a1b2c3d*`).
저장소가 아니거나 commit 이 하나도 없으면 아무것도 찍지 않는다.

dirty 는 `git status --porcelain` 기준이라 untracked 파일도 센다. tabline 의 `+` 와 파일 경로
뒤의 `[+]` 는 buffer 의 미저장 상태이고, 이 `*` 는 저장소의 미commit 상태다.

기준은 활성 파일이 아니라 cwd 다 — sidebar 트리의 뿌리와 같다. 그래서 tab 을 오가도 바뀌지 않는다.

값은 5 초마다, 그리고 저장한 직후와 파일을 연 직후에 다시 읽는다(ADR-0009, ADR-0030). 화면을 그릴 때는 읽지
않는다 — 외부 프로세스라 키 입력마다 부를 수 없다. 읽는 것은 `git 상태` 라는 백그라운드
작업이라 편집기가 멈추지 않고, 도는 동안에는 `:jobs` 목록과 statusBar 진행 표시에 보인다.
바깥에서 `commit`/`checkout` 을 하면 키를 누르지 않아도 5 초 안에 따라온다.
편집기를 여는 길에는 읽지 않아서 첫 화면에서는 잠깐 비어 있다.

붙일 칸이 없으면 넣지 않는다. mode 와 파일 이름이 먼저다.

### 빈 화면

열린 tab 이 하나도 없을 때 편집 영역에 오는 화면이다. 인자 없이 시작했을 때와 마지막 tab 을
닫았을 때 둘이다(ADR-0064).

```
                              │
                              │      ┌──────────────────────────┐
    ▸ docs/                   │      │ 30                 65.38 │
    ▸ internal/               │      │ 전이 금속                │
      CLAUDE.md               │      │                          │
      main.go                 │      │    █████████             │
                              │      │          ██              │
                              │      │        ██     ███████    │
                              │      │      ██       ██   ██    │
                              │      │    ██         ██   ██    │
                              │      │    █████████  ██   ██    │
                              │      │                          │
                              │      │           ZINC           │
                              │      └──────────────────────────┘
                              │
                              │   zn v0.3.1 (2026-08-24T…, go1.26.4)
                              │
                              │       `ctrl+p` 팔레트를 엽니다
NORMAL                                             master(c376d1c*)
└─ tabline 자리는 비어 있고 sidebar·statusBar 는 그대로다
```

**본문 자리만 갈아끼운다.** tabline 은 줄만 남고 비어 있다 — 적을 tab 이 없고, 무언가 적으면
tab 이 아닌 것을 누를 수 있는 것처럼 보인다. sidebar 와 statusBar 는 그대로다.
mode 도 normal 이다 — mode 가 바뀐 것이 아니라 편집할 것이 없는 것이다.

본문에는 원소 칸 로고와 버전, 그리고 tip 한 줄이 온다. 편집기 이름이 아연의 원소기호라
주기율표의 칸을 그렸다. 빈 판에 무언가를 적는 것은 `:jobs` 의 `도는 작업이 없습니다` 와 같은
자리다(아래 「작업 목록」) — 아무것도 없으면 편집기가 덜 뜬 것처럼 보인다. 화면이 좁거나
낮으면 **자르지 않고 버린다** — 원소 칸이 안 들어가면 `zn` 한 줄로 내리고, 그래도 자리가
없으면 버전 줄만 남긴다. tip 을 고르는 규칙과 같은 태도다(아래 「tip」).

statusBar 에서 사라지는 것은 파일에 딸린 것들이다. 파일 경로와 `[No Name]`, `[+]`·`[!]`·
`[읽기 전용]` 표시, 커서 자리와 줄 수가 없다. **`[No Name]` 을 적지 않는다** — 그것은 이름
없는 tab 의 이름이라, 적으면 「tab 이 없는 것」 과 「이름 없는 tab 이 하나 있는 것」 이 사람이
보는 유일한 자리에서 같은 글자가 된다. `NORMAL` 과 오른쪽 끝의 git 은 남는다 — git 은 cwd 를
보는 것이라 보고 있는 파일과 무관하다(위 「git 표시」). 커서는 놓을 글자가 없어서 세우지 않는다.

**편집하는 키는 조용히 아무 일도 하지 않는다.** 커서를 옮기고 글자를 넣고 지우는 키, `gt`·`gT`,
검색(`/` `?` `n` `N` `*` `#`), 붙여넣기가 다 그렇다. `g` 뒤에 짝이 없는 키가 조용한 것과 같은
자리다(ADR-0003) — 편집할 것이 없다는 것은 화면이 이미 말하고 있다. 숫자 접두와 접두 키는
그대로 먹어서 showcmd 에 뜬다.

**이름을 대고 부른 것은 조용하지 않다.** `:w`·`:wq`·`:5`·`:d`·`:registers` 처럼 볼 파일이
있어야 하는 명령과 팔레트 항목은 「열린 파일이 없습니다」 를 적고 물러난다. 키는 눌러 본
것이지만 이쪽은 골라서 부른 것이라 아무 일도 안 나면 편집기가 먹지 않는 것으로 읽힌다.

하단 drawer 를 쓰는 것(`:registers`, `:symbols`) 은 되지 않는다 — drawer 는 편집 맥락에
딸린 자리이고(위 「UI 구성」) 특수문자는 넣을 커서가 없다. 화면을 통째로 쓰는 `:jobs`·
`:messages` 는 편집기 틀을 쓰지 않아서 그냥 열린다. 경계는 「판(drawer) 이냐 화면을 통째로 쓰느냐」 하나다.

**담아둔 것은 남는다.** register 와 마지막 검색은 tab 이 아니라 편집기에 딸린 것이라 빈 화면을
지나도 그대로다. tab 을 열면 `p` 와 `n` 이 이어서 먹는다.

sidebar 는 열려 있고 오르내릴 수 있다. 보고 있는 파일이 없으므로 굵은 행이 없고, 마지막 tab 을
닫아도 트리는 그 자리에 그대로 남는다 — 닫은 사람은 대개 그 옆의 것을 열려는 참이다.

tab 을 만드는 길은 `:tabnew`, `:e <파일>`, `:tabnew <파일>`, 팔레트에서 파일 고르기, 트리에서
`enter`, 트리에서 `mc` 로 파일 만들기다. 어느 길이든 열고 나면 normal 이다. tab 이 없으면
`:e <파일>` 은 갈아끼우는 것이 아니라 새로 여는 것이라 확인창도 뜨지 않는다.

**여기서 치는 `:q` 는 종료다.** 닫을 tab 이 없다는 것이 화면에 이미 드러나 있는데 `:q` 를 친
것은 닫으라는 것이 아니라 나가겠다는 뜻이다. 그래서 tab 하나를 `:q` 로 닫고 한 번 더 치면
편집기가 끝난다 — vim 에서 오는 손버릇이 그대로 산다(ADR-0064).


## Mode

모드는 다음과 같이 구성 한다.

- normal mode
- insert mode
- visual mode
- command-line mode
- search mode

mouse 는 mode 마다 조금씩 다르게 받는다. 「Mouse」 절에 모아 적는다.

### Normal mode

vim 의 normal mode 와 동일하다.
cursor 를 옮기고, 파일을 편집 한다.

커서는 글자 위에 있다. 줄 끝 다음 칸에는 설 수 없다. 그 자리는 insert mode 에서만 간다.

leader 로 받는다(ADR-0008).

#### 이동 키의 단위와 숫자

`j`/`k` 는 논리 줄이고 `↓`/`↑` 는 화면 행이다. 짧은 줄에서는 둘이 같고, 화면보다 긴 줄에서만
갈린다 — `j` 는 그 줄을 통째로 건너뛰고 `↓` 는 그 줄 안에서 한 행 내려간다.
vim 의 `j` 와 `gj` 가 나뉜 것과 같다(ADR-0006).

**유지하는 칸도 화면 행 기준이다.** 위아래로 움직일 때 지키는 칸을 그 화면 행 안에서 세므로, wrap 된 줄의 둘째 행 이후에서 `j`/`k` 를 누르면 다음 줄의 **첫 화면 행**에 선다. 화살표로 wrap 된 줄 안을 오갈 때 화면 위 가로 자리가 그대로 유지되는 것이 같은 규칙의 앞면이다. vim 은 이 칸을 줄 시작에서 세므로 이 자리에서 결과가 다르다. wrap 되지 않은 줄과 첫 화면 행에서는 같다(ADR-0108).

이동 키 앞에 숫자를 치면 그만큼 움직인다(`10j`, `20k`, `5l`, `3w`). 갈 곳이 모자라면 양끝에서
멈춘다. 숫자는 이동 키와 `x`·`d`·`r`·`~` 에만 붙고, 다른 키가 오면 버려진다 — `3i` 는 `i` 와 같다.
`$` `gg` `G` 는 숫자의 뜻이 다르다 — `$` 는 줄 수(`3$` 는 두 줄 아래의 줄 끝) 고
`gg`/`G` 는 줄 번호(`42G`) 다.
`0` 은 숫자의 첫 자리가 될 수 없다. 줄 맨 앞으로 가는 키이기 때문이다.
`10j` 처럼 둘째 자리부터는 숫자다.

#### 화면 단위 이동

`ctrl+d`·`ctrl+u`(반 화면) 와 `ctrl+f`·`ctrl+b`(한 화면) 넷이다. **화면과 커서가 같이**
움직여서 커서는 화면 안 같은 자리에 남고, 세는 단위는 논리 줄이 아니라 **화면 행**이다 —
화면을 다 차지하는 wrap 된 긴 줄에서는 그 줄 안에서 움직인다(`↓` 와 같은 단위다).
(ADR-0062, ADR-0063)

키 | 움직이는 행 수
---|---
ctrl+d ctrl+u | 편집 영역 높이의 **절반**
ctrl+f ctrl+b | 편집 영역 높이에서 **두 행을 뺀 것**

**한 화면은 두 행을 겹쳐 둔다.** 앞 화면의 마지막 두 행이 다음 화면 맨 위에 다시 서서, 넘긴
자리가 어떻게 이어지는지 보인다 — vim 의 `ctrl+f` 와 같고 `less` 도 같다. 반 화면에는 이
겹침이 없다. 절반씩 가면 앞 화면의 아래쪽 절반이 그대로 위쪽 절반이 되기 때문이다.
높이가 두 행 아래인 화면에서는 겹칠 자리가 없어 한 행씩 간다.

**vim 과 갈리는 자리가 하나 있다.** vim 은 `ctrl+f` 뒤 커서를 새 화면 맨 위 줄에 놓는데
여기서는 화면과 같이 움직인다. `ctrl+d` 와 `ctrl+f` 뒤 커서가 어디 있는지를 키마다 따로
기억하지 않아야 해서다(ADR-0063).

숫자는 되풀이다 — `3ctrl+d` 는 반 화면 세 번이고 `2ctrl+f` 는 한 화면 두 번이다. vim 은
`ctrl+d` 의 숫자를 `scroll` 에 기억해 다음 `ctrl+d` 까지 바꾸는데, 기억하는 설정을 두지 않았다.

가로 칸은 `j`/`k` 와 같이 지킨다. vim 은 `startofline` 이 켜져 있어 줄의 첫 비공백으로 가는데,
이 편집기에서는 「이동하면 칸은 살아남는다」가 한 벌이라야 해서 따르지 않았다.

**파일 끝을 지나서까지 굴리지 않는다.** 마지막 줄이 화면 맨 아래에 오면 거기서 화면이 멈추고
커서만 마지막 줄로 간다. 휠에는 이 한계가 없다 — 눌러도 빈 행만 늘어나는 이동 키를 두지
않는 것이고, 굴려서 보고 싶은 것은 휠로 한다.

operator 뒤에는 오지 않는다. `d ctrl+d` 는 아무것도 지우지 않는다 — 화면 단위 이동은 화면
높이가 있어야 정해지는 것이라 motion 이 아니다. vim 도 같다.

visual mode 에서는 다른 이동 키와 같이 고른 범위를 늘린다. 트리에서도 같은 키다
(「sidebar」 참고).

#### 단어 경계

단어는 글자 부류가 바뀌는 자리에서 끊는다. 부류는 넷이다 — 공백 / 단어 글자(영문·숫자·`_`) /
한글·한자·가나 / 그 밖의 문장부호. vim 과 같은 나눔이라 `한글abc` 는 두 단어이고
`foo.bar` 는 세 단어다. `foo_bar` 와 `fooBar` 는 한 단어다.

`W` `B` `E` 는 공백으로만 끊어서 `foo.bar(baz)` 가 한 덩어리다.

#### 지우기

`d` 는 뒤에 이동 키가 붙어서 지울 범위를 정한다. 이동 키는 위 표의 것을 그대로 쓴다 —
`dw` `dW` `de` `dE` `db` `dB` `dh` `dl` `d←` `d→` `d0` `d^` `d$` `dj` `dk` `dgg` `dG` 다.
`dd` 는 커서 줄이다. 지울 범위는 그 이동을 실제로 실행해서 얻으므로 "`w` 가 가는 데까지" 가
곧 "`dw` 가 지우는 데까지" 다(ADR-0013).

`dd` `dj` `dk` `dgg` `dG` 는 줄 단위다. 커서 칸과 상관없이 줄 전체가 사라지고 커서는 그 자리를
메운 줄의 첫 비공백에 선다. 나머지는 글자 단위이고 커서는 지운 자리에 선다.
`e` `E` 는 커서가 선 글자까지 지운다.

숫자는 `d` 앞뒤에 각각 붙고 곱해진다 — `3dd` 는 세 줄, `d3w` 는 세 단어, `3d2w` 는 여섯 단어다.
`dG` `dgg` 의 숫자는 이동 키에서와 같이 줄 번호다(`d2G` 는 둘째 줄까지).

`dw` 는 줄을 넘지 않는다. 줄의 마지막 단어에서 쳐도 줄 끝까지만 지우고 다음 줄이 올라오지
않는다. 줄을 없애는 키는 `dd` 다. 숫자가 붙었을 때 중간 걸음은 줄을 넘는다 — `2dw` 는 다음
줄의 단어까지 지운다. vim 과 같다.

검색 키(`n` `N` `*` `#` `/` `?`) 와 `↑` `↓` 는 `d` 뒤에 받지 않는다. 짝이 없는 조합은 아무 일도
하지 않으므로 잘못 누른 `d` 는 `esc` 로 무른다. `c` `y` 도 같은 범위를 쓴다.

**`iw` `aw` `iW` `aW` 는 이동 키가 아니라 「커서가 든 단어」다**(아래 「text object」).

`x` 는 커서 자리 글자를 지운다. `dl` 과 같아서 줄 끝을 넘지 않고, 빈 줄에서는 아무 일도 없다.

지우기 한 번이 되돌리기 한 구간이다. 지운 내용은 무명 register 에 남고 `p`/`P` 로 도로 붙인다 —
아래 「복사와 붙여넣기」다.

숫자나 접두 키를 치는 동안 그것을 statusBar 아래 줄 오른쪽 끝에 보여준다(vim 의 `showcmd`).
붙일 칸이 없으면 보여주지 않는다 — 커서 위치가 밀려나는 것이 더 나쁘다.
그 자리를 tip 과 나눠 쓰는데 showcmd 가 먼저다 — 치는 동안 tip 이 비켜난다(ADR-0061).

#### text object

**operator 뒤에 오는 「무엇의 안쪽/둘레」다.** 이동 키가 아니라 범위만 준다(ADR-0091).

```
diw   커서가 든 단어를 지운다
daw   그 단어와 뒤 공백까지. 뒤에 없으면 앞 공백이다
diW   공백으로만 끊은 단어. `foo.bar` 가 한 낱말이다
ciw   그 단어를 지우고 insert mode 로
yiw   그 단어를 register 에 담는다
>iw   그 단어가 걸친 줄을 한 단계 민다
```

**여섯 operator 에 다 붙는다.** `d` `y` `c` `>` `<` `=` 다. 범위 하나를 만드는 일이라 operator
마다 따로 정할 것이 없다.

경계는 `w` 가 걷는 것과 같은 `charClass` 다. 그래서 `foo.bar` 에서 `iw` 는 `foo`·`.`·`bar` 를
각각 한 낱말로 보고, `한글abc` 에서는 `한글` 과 `abc` 가 갈린다(위 「단어 단위 이동」).

**커서가 공백 위에 있으면 아무 일도 하지 않는다.** vim 은 그 공백 덩어리를 지우는데, 같은 키가
커서 한 칸에 따라 「단어를 바꾼다」와 「공백을 지운다」로 갈리면 눌러 보고 아는 키가 된다.
빈 줄과 줄 끝도 같이 걸린다. 파일도 dirty 도 건드리지 않는다.

**줄을 넘지 않는다.** 단어는 줄 안의 것이다.

**숫자를 받지 않는다.** `3diw` 도 `d3iw` 도 `diw` 와 같다. vim 의 `d2iw` 는 단어와 공백을
번갈아 세서 「단어와 그 뒤 공백」인데, 모르면 「단어 둘」로 읽힌다. 틀리게 읽히는 숫자를
받지 않는다.

`i`·`a` 를 홀로 치면 insert mode 그대로다. operator 를 먹은 뒤에만 text object 가 된다.
짝이 없는 조합(`ciz`) 은 아무 일도 하지 않는다.

**따옴표(`i"` `i'`)·짝괄호(`i(` `i{` `i[`)·tag(`it`)·문단(`ip`) 는 아직 없다.** 경계를 찾는
값이 갈래마다 달라서 각각 별건이다. **visual 에도 없다** — `viw` 는 `i` 가 버려지고 `w` 가
이동 키로 먹혀서 고른 범위가 한 낱말 늘어난다.

#### 바꾸기

`c` 는 지우고 insert mode 로 들어간다. 범위 계산은 `d` 와 같은 것을 써서 `cw` `c3w` `3cc`
`cgg` `c$` `cj` `cG` 가 `d` 쪽 표를 그대로 따라온다. 바꾼 내용은 `d` 처럼 register 에 남는다.

**`cw` 는 단어 뒤 공백을 남긴다.** 커서가 공백 아닌 글자 위에 있으면 `ce` 처럼 단어 끝까지만
바꾼다 — 단어를 갈아 끼우고 나면 뒷 공백이 그대로 있어야 하기 때문이다. `dw` 와 갈리는 자리다.

```
foo    bar     커서가 f 위
dw  →  bar         공백까지 지운다
cw  →     bar      foo 만 지우고 공백 네 개는 남긴다
```

이미 단어의 마지막 글자 위면 그 글자 하나가 전부다. 예외는 첫 걸음에만 걸려서 `c2w` 의
둘째 걸음부터는 그냥 `e` 다. 커서가 공백 위면 예외가 아니라 `dw` 와 같이 건너뛴다 —
바꿀 것이 그 공백이다. 빈 줄에서는 아무것도 바꾸지 않고 insert 로 간다(ADR-0033).

**`cc` 는 줄을 없애지 않는다.** `dd` 는 줄이 사라지지만 `cc` 는 그 자리에서 다시 치는 것이라
빈 줄 하나가 남는다. **첫 줄의 들여쓰기는 남긴다** — 들여쓴 코드에서 `cc` 를 칠 때마다 tab 을
다시 치지 않는다. `3cc` 는 세 줄이 들여쓴 한 줄이 되고, `cj` `ck` `cG` `cgg` 도 같다.

```
func main() {          `cc` 를 둘째 줄에서
»   foo                →  »              tab 은 남고 그 뒤에서 친다
}
```

`o` `O` 도 이제 들여쓰기를 받는다(아래 「자동 들여쓰기」). 다만 가져오는 곳이 다르다 —
`cc` 는 있던 줄을 비우는 것이라 들여쓰기가 이미 그 줄에 붙어 있고, `o` `O` 는 없던 줄을
만드는 것이라 언어 규칙이 앞 줄을 보고 정한다.

**지운 것과 이어 친 글자가 한 번의 `u` 로 함께 돌아간다.** `c` 한 번이 되돌리기 한 구간이다.
vim 과 같다.

모르는 motion 이면 mode 도 바뀌지 않는다. `cq` 는 아무 일도 하지 않으므로 잘못 누른 `c` 는
`esc` 로 무른다 — `dq` 와 달리 이것이 중요한 것은, insert 로 들어가 버리면 이어서 친 글자가
파일에 들어가기 때문이다.

#### 줄 이어 붙이기

`J` 는 커서 줄과 다음 줄을 한 줄로 잇는다. `3J` 는 세 줄이 한 줄이 되고, 세지 않은 `J` 와 `1J` 와 `2J` 는 모두 두 줄이다. 남은 줄이 세는 수보다 적으면 있는 만큼 잇고, 마지막 줄에서는 아무 일도 없다.

**다음 줄의 들여쓰기를 걷고 공백 하나로 잇는다.** 넣지 않는 경우가 넷이다. 앞 줄이 비었을 때, 걷고 난 다음 줄이 비었을 때, 앞 줄이 이미 공백이나 tab 으로 끝났을 때, 다음 줄이 `)` 로 시작할 때다. 앞 셋은 없는 곳에 공백을 만들지 않는다는 뜻이고, 마지막 하나는 `foo(` 와 `)` 를 이으면 `foo()` 여야 하기 때문이다.

```
func main() {              `J` 를 첫 줄에서
»   foo()             →    func main() { foo()
}

foo(                       `J` 를 첫 줄에서
»   )                 →    foo()

Sentence.                  `J` 를 첫 줄에서
»   Next            →      Sentence. Next          공백 하나다
```

마지막 예가 vim 과 갈리는 자리다. vim 은 기본값(`joinspaces`) 이 켜져 있어서 `.` `?` `!` 뒤에 공백 둘을 넣는데, 그것은 영문 타이프라이터 관습이라 우리는 하나만 넣는다. neovim 의 기본값과 같다(ADR-0087).

**커서는 마지막으로 이은 자리에 선다.** 공백을 넣었으면 그 공백이고, 넣지 않았으면 올라온 글자의 첫 자리다. 이은 자리가 줄 끝을 넘으면(다음 줄이 비어 있었을 때) normal 커서 자리로 당겨진다.

`3J` 한 번이 되돌리기 한 구간이다. `u` 한 번에 세 줄이 되돌아온다.

공백을 손대지 않는 `gJ` 와 visual 의 `J` 는 없다. `J` 를 세서 치는 길이 같은 일을 하고, 이은 자리의 공백 규칙이 하나로 남는다(ADR-0087).

#### 복사와 붙여넣기

`y` 는 `d` 와 똑같은 operator 다. 범위 계산을 같이 쓰므로 `yy` `y3w` `3yy` `ygg` `y$` 가
`d` 쪽 표를 그대로 따라온다. `w` 의 줄끝 예외도 물려받아서 `y2w` 는 줄을 넘지 않는다(ADR-0017).

`y` 는 파일을 건드리지 않는다 — dirty 도 되돌리기 구간도 서지 않는다. 커서는 그 motion 이
데려다 놓는 자리 그대로다. 뒤로 가는 motion 이면 범위의 시작으로 가고(`yb` `yk` `ygg`)
앞으로 가는 것이면 제자리다(`yw` `yy` `y$` `yG`).

**register 는 무명, 숫자 열 개, 문자 스물여섯 개다.** `editor` 가 들고 있어 tab 을 넘어 붙는다.

register | 무엇이 들어가나
---------|----------------
무명 | 마지막으로 담거나 지운 것. 이름을 대지 않은 `p`/`P` 가 읽는다. 이름을 대도 여기에 같이 담긴다
`"0` | 마지막으로 **복사한** 것. 지우기는 여기를 건드리지 않는다
`"1`~`"9` | 지우거나 바꾼 것. 지울 때마다 한 칸씩 밀려 `"9` 를 넘어간 것은 사라진다
`"a`~`"z` | 손으로 이름을 대서 담는 자리. 저절로 밀리지 않는다
`"A`~`"Z` | `"a`~`"z` 와 같은 자리인데 덮지 않고 **뒤에 잇는다**

`x` 로 글자 하나를 지운 것도 숫자 링을 민다. **vim 과 갈리는 자리다** — vim 은 한 줄 안에서
지운 것을 소삭제 register(`"-`) 로 보내고 숫자 링을 건드리지 않는다. 규칙을 하나로 둔 까닭은
ADR-0058 에 적었다. 바꿀 것이 없었던 `c`(빈 줄의 `cw`) 는 링을 밀지 않는다.

`"{이름}` 을 앞에 붙여 자리를 고른다.

- **붙일 때** — `"1p` 는 마지막으로 지운 것, `"3P` 는 세 번 전에 지운 것을 위에, `"ap` 는
  `"a` 에 모아 둔 것을 붙인다. 숫자 되풀이는 이름 앞뒤 어디에 붙여도 된다(`3"1p` = `"13p`)
- **담을 때** — `"ayy` `"add` `"acw` `"ax` 가 `"a` 에 담는다. `"Ayy` 는 `"a` 에 잇는다.
  visual 에서는 범위를 고른 뒤에 댄다 — `V j "ay` 다
- **이름을 대면 숫자는 건드리지 않는다** — `"add` 는 `"a` 와 무명에만 담고 링을 밀지 않는다.
  `"ayy` 도 `"0` 을 건드리지 않는다. vim 과 같다

덧붙일 때 둘 중 하나라도 줄 단위면 결과도 줄 단위다. 둘 다 글자 단위면 이음매에서 줄이 하나로
붙는다 — `"ayw` `"Ayw` 로 낱말 둘을 모으면 한 줄이다.

**담는 것은 문자 이름만 받는다.** `"1yy` 처럼 숫자에 담는 것은 없고, 그렇게 치면 지우지도
담지도 않고 아무 일도 일어나지 않는다. 이름을 받지 않는 키(`"aw` `"agg` `"a>>`) 도 같다.
`"` 뒤의 `esc`·`ctrl+c` 는 이름을 무르고, 한 번 더 누르면 제 일을 한다.

담긴 것 없는 이름(`"q`) 은 빈 register 라 `"qp` 도 조용하다.

담긴 것은 `:registers` 로 본다(아래 「register 목록」).

붙이는 자리는 register 가 줄 단위인지 글자 단위인지로 갈린다.

register | `p` | `P` | 커서가 서는 자리
---------|-----|-----|------------------
줄 단위(`dd` `yy` `dj` …) | 커서 줄 **아래**에 줄로 끼운다 | 커서 줄 **위** | 붙인 첫 줄의 첫 비공백
글자 단위(`dw` `yw` `x` …) | 커서가 선 글자 **뒤** | 커서 **자리** | 한 줄이면 붙인 마지막 글자, 여러 줄이면 첫 글자

숫자는 되풀이라 `3p` 는 세 번 붙인다. 붙여넣기 한 번이 되돌리기 한 구간이라 `3p` 도 `u` 한 번에
전부 사라진다. register 가 비어 있으면 아무 일도 하지 않는다 — 알림도 없고 dirty 도 서지 않는다.

시스템 클립보드와는 잇지 않았다. 터미널 쪽 붙여넣기는 insert mode 에서 그대로 받는다.

#### 한글 입력 상태

입력기가 한글인 채로 normal mode 에 오면 자모를 **두벌식 자리의 영문 키로 되돌려** 받는다.
`ㅁ` 은 `a` 이고 `ㅓ` 는 `j` 다(ADR-0008).

조합된 음절과 겹자모는 그것을 만든 키 여럿으로 풀린다 — `ㅘ` 는 `h` `k`, `어` 는 `d` `j`,
`값` 은 `r` `k` `q` `t` 다. 그래서 키 하나가 동작 여럿이 될 수 있다. 풀린 키를 먹이는 도중
mode 가 바뀌면 남은 키는 버린다 — `얌`(`d` `i` `a`) 은 insert mode 로 들어가고 `a` 는 버려진다.

키가 곧 동작인 mode 에만 적용된다 — normal, sidebar, 종료 확인창. insert mode 와 명령줄
mode 에서는 한글이 글자다.

`G` `B` `V` `U` 는 한글 상태에서 낼 수 없다. `ㅎ` `ㅠ` `ㅍ` `ㅕ` 는 shift 자리에 다른 글자가
없어서 `g` `b` `v` `u` 와 구분되지 않는다. 된소리가 있는 `W`(`ㅉ`) `E`(`ㄸ`) `T`(`ㅆ`) 는
낼 수 있다. **넷을 위한 우회로는 두지 않는다** — 한글로 온 키를 되돌려 받는 것은 최소한의
방어책이자 편의이지 주요 역할이 아니다(ADR-0083).

마지막으로 누른 키는 입력기가 조합 중이라 편집기에 도착하지 않는다. 그만큼 동작이 밀리는 것은
편집기 밖의 일이라, 확실하게 하려면 입력기를 mode 에 맞춰 바꾸는 설정을 같이 써야 한다.

**같은 일이 검색과 명령줄에서는 Enter 를 한 번 더 치는 모습으로 온다.** `/한글` 처럼 한글로
치면 마지막 글자가 아직 조합 중이라, 첫 Enter 는 그 조합을 확정하는 데 쓰이고 편집기까지
오지 않는다. 화면이 그대로여서 아무 일도 없어 보이지만 한 번 더 누르면 그때 돈다
(`docs/issues/0003`).

### insert mode

vim 의 insert mode 와 동일 하다.
현재 커서 위치에 내용을 삽입한다.

커서는 글자 사이에 있다. 줄 끝 다음 칸까지 갈 수 있다.

#### key mapping

키 | 기능 | 기타
---|------|-----
(글자) | 커서 자리에 넣는다 | grapheme cluster 단위. 한글·이모지도 한 글자
enter | 줄을 나눈다 | 새 줄이 들여쓰기를 받는다. 아래 「자동 들여쓰기」 참고
backspace | 앞 글자를 지운다 | 줄 시작이면 앞 줄과 합친다. 커서 앞이 들여쓰기뿐이면 한 단위를 지운다
delete | 커서 자리 글자를 지운다 | 줄 끝이면 다음 줄을 끌어올린다. **들여쓰기 단위로 묶지 않는다**(ADR-0076)
tab | 한 단위 들여쓴다 | 다음 단위 경계까지 민다. markdown 목록에서는 줄 전체가 들어간다
shift+tab | 한 단위 내어쓴다 | 지금 줄을 당긴다. 커서는 치던 자리를 따라간다
esc | normal mode 로 | 커서가 왼쪽으로 한 글자 간다. vim 과 같다
↑ ↓ ← → | 커서 이동 | 되돌리기 구간이 끊긴다. vim 과 같다
home end | **화면 행**의 앞 / 끝 | normal 과 같은 단위다. 되돌리기 구간이 끊긴다(ADR-0076)
pgdown pgup | 한 화면 아래 / 위 | 되돌리기 구간이 끊긴다

**`delete` 는 normal 에 없다.** 그 자리에는 `x` 가 이미 있고 register 에 담는 것까지 정해져
있어서, 같은 일을 하는 길을 하나 더 두면 「담느냐 마느냐」를 두 벌로 기억하게 된다(ADR-0076).

붙여넣기는 여러 줄이어도 그대로 들어간다. **자동 들여쓰기가 붙지 않는다** — 붙으면 원래
들여쓰기 위에 얹혀 줄마다 오른쪽으로 밀린 계단이 된다.

### 자동 들여쓰기

줄을 새로 만들면 그 줄이 들여쓰기를 받는다. insert 의 `enter`, `o`, `O`, `r<Enter>` 넷이다.
붙여넣기는 아니다. 끄는 방법은 없다(ADR-0047).

**언어를 보고 정한다.** 파일 이름으로 언어를 알아보는 것은 문법 강조와 같은 표다(ADR-0039).

언어 | 한 단계 더 들어가는 자리 | 한 단계 나오는 자리
--- | --- | ---
golang js css | 닫히지 않은 `{` `(` `[`, `case`/`default` 로 끝나는 `:` | `}` `)` `]`, `case` `default`
python | 줄 끝의 `:`, 닫히지 않은 괄호 | `else` `elif` `except` `finally` `case`, `)` `]` `}`
shell | 줄 끝의 `then` `do` `in` `else`, `{` `(` | `fi` `done` `esac` `else` `elif` `;;`, `}` `)`
html | 같은 줄에서 닫히지 않은 tag | `</tag>`
dockerfile | `\` 로 이어지기 시작하는 줄 | 이어짐이 끝난 다음 줄
makefile | 대상 줄 다음은 언제나 tab 하나 | 없음
markdown | 없음 — 목록 표시를 이어 쓴다 | 없음
그 밖 | 앞 줄의 공백을 그대로 잇는다 | 없음

**한 번에 한 단계뿐이다.** 한 줄에서 두 겹을 열어도(`foo({`) 한 단계다.

문자열과 주석 안의 괄호는 세지 않는다. `s := "{"` 다음 줄은 들어가지 않는다.

#### 닫는 표시를 치는 순간

줄 앞이 들여쓰기뿐인 자리에서 닫는 표시를 치면 **그 줄이 통째로 한 단계 당겨진다.**
화면에 이미 있는 글자가 움직이는 자리는 여기 하나뿐이다.

```
func f() {
»   »   foo()
»   »   |          ← 여기서 `}` 를 치면
        ↓
func f() {
»   »   foo()
»   }|             ← 줄이 당겨진다
```

커서 앞에 글자가 하나라도 있으면 움직이지 않는다. 글을 쓰다 만난 `}` 는 그 줄의 자리를
바꾸지 않는다.

낱말로 닫는 언어(shell 의 `fi`) 는 **낱말이 끝나야** 당긴다. `fi` 두 글자만으로 당기면
`file=x` 를 칠 때 줄이 튄다. 뒤에 공백이나 `;` 가 오거나 Enter 로 줄을 떠나면 끝난 것이다.

#### markdown 의 목록

markdown 만 공백이 아닌 글자를 낸다. 목록 안에서 Enter 를 치면 표시가 따라온다.

```
- 첫째              1. 하나            »   - 깊은 것
- |                 2. |              »   - |
```

`- ` `* ` `+ ` `> ` 는 같은 표시를, `1. ` `1) ` 은 다음 번호를 같은 구두점으로 낸다.
**표시만 있고 내용이 없는 항목에서 Enter 를 치면 목록이 끝난다** — 표시를 내지 않는다.

#### 한 단계

한 단계가 tab 인지 space 몇 칸인지는 파일마다 다르다. 세 가지를 순서대로 본다(ADR-0048).

1. `.editorconfig` 의 `indent_style` · `indent_size` · `tab_width`
2. 그 파일이 이미 쓰고 있는 것. 앞의 들여쓴 줄 500 개까지 훑어 이웃한 두 줄의 걸음을 센다
3. 그 언어의 관례. golang·makefile 은 tab, python 은 space 넷, 나머지는 space 둘

makefile 만 이 셋 밖이다. GNU make 가 조리법 줄을 tab 으로만 알아보므로 언제나 tab 이다.

**들여쓰기를 움직이는 모든 키가 이 한 단계를 쓴다.** `tab` `shift+tab` `backspace`
`>` `<` `=` 와 새 줄이 받는 들여쓰기가 전부 같은 값이다 — `tab` 은 tab 글자를 넣는 키가
아니라 **한 단계 들여쓰는 키**다. space 로 쓰는 파일에서 `tab` 을 치면 space 가 들어가고,
그것을 `backspace` 한 번으로 되돌린다.

세는 단위는 byte 가 아니라 **화면 칸**이다. tab 파일에 space 로 들여쓴 줄이 섞여 있어도
한 단계는 한 단계다. 재는 자리가 화면이라 tab 은 zn 이 그 파일을 실제로 그리는 폭으로 센다 —
눈에 보이는 것과 움직이는 것이 어긋나면 안 된다. 그 폭이 곧 아래의 `tab_width` 다.

칸 수만 맞추고 **그 줄이 쓰던 글자는 그대로 둔다.** tab 파일에서 space 로 들여쓴 줄에 `>` 를
쳐도 space 가 늘어날 뿐 tab 으로 바뀌지 않는다.

```
단위 = space 4 칸

⋅⋅⋅⋅⋅⋅⋅⋅deep()      backspace → ⋅⋅⋅⋅deep()   한 칸이 아니라 한 단계
보통 글|            tab       → 보통 글⋅|     7 칸이라 다음 경계는 한 칸 뒤
```

**자동으로 넣은 들여쓰기는 지우지 않는다.** 아무것도 치지 않고 그 줄을 떠나도 공백이 남는다.
줄 끝 공백을 지우는 것은 팔레트 명령으로 따로 있다.

#### tab 폭

tab 하나를 몇 칸으로 그릴지도 파일마다 다르다. `.editorconfig` 의 `tab_width` 를 따르고, 적힌 것이 없으면 4 칸이다(ADR-0096).

터미널과 vim 의 기본값인 8 을 쓰지 않는 것은 8 칸이 깊게 들여쓴 코드를 화면 밖으로 밀어내기 때문이다. 적어 둔 저장소에서만 그 값으로 간다.

**`indent_size` 만 적어도 그 값이 tab 폭이 된다.** editorconfig 명세가 「`tab_width` 의 기본값은 `indent_size`」라고 정해 두었고 zn 도 그대로 읽는다. `tab_width` 와 `indent_size` 가 둘 다 적혀 있으면 `tab_width` 가 이긴다.

폭이 걸리는 자리는 그리기·커서 칸·줄바꿈·공백 마커, 그리고 위의 한 단계를 재는 것까지 전부다. 한 화면에 폭이 다른 파일이 tab 으로 같이 열려 있어도 각자의 폭으로 그린다.

```
tab_width = 8                       적힌 것 없음(4 칸)

»       for i := range n {          »   for i := range n {
»       »       f(i)                »   »   f(i)
»       }                           »   }
```

**검색 결과 판(`:grep`) 의 줄 내용은 기본 폭으로 그린다.** 그 판은 앞의 들여쓰기를 떼고 보여서 tab stop 의 원점이 파일과 이미 어긋나 있다 — 파일의 폭을 가져와도 파일에서 보이던 자리가 되지 않는다(ADR-0098).

#### 이미 있는 줄 다시 들여쓰기

`>` `<` `=` 는 `d` `y` `c` 와 같은 operator 라 motion 을 받는다(ADR-0013). 같은 글자를 두 번
치면 줄 하나이고 숫자는 줄 수다. visual 에서는 고른 범위 위에 그대로 친다.

키 | 하는 일
--- | ---
`>>` `3>>` `>j` `>G` | 한 단계 민다
`<<` `<j` | 한 단계 당긴다
`==` `=j` `=G` | 규칙이 정한 자리로 다시 계산한다
visual 의 `>` `<` `=` | 고른 범위에 같은 것을 하고 normal 로 돌아온다

범위가 글자 단위여도(`>w`) **걸친 줄 전체가 움직인다.** 들여쓰기는 줄의 성질이라 반쪽을 밀
수 없다. 커서는 첫 줄의 들여쓰기 다음에 선다. 한 번의 `u` 로 범위 전체가 돌아온다.

`>` `<` 는 언어를 보지 않는다. 손으로 미는 것이라 규칙이 끼어들 자리가 없고, **빈 줄은
건드리지 않는다** — 밀면 줄 끝 공백만 남는다. 한 단계로 딱 떨어지지 않는 줄(space 두 칸
파일의 세 칸짜리 줄) 에서 `<` 는 한 단계 칸 수만큼 떼고 남는 것을 그대로 둔다.

`=` 는 위에서 아래로 훑으며 줄마다 자리를 다시 잡는다. 기준은 **범위 바로 위 줄의 지금
들여쓰기**이고 그 줄은 건드리지 않는다 — 규칙은 절대 자리를 모르고 앞 줄과의 차이만 안다.
공백뿐인 줄은 비운다. 빈 줄이 블록을 끊지는 않는다.

**markdown 과 모르는 확장자에서 `=` 는 아무 일도 하지 않는다.** 목록의 깊이와 네 칸 들여쓴
코드 블록은 글쓴이가 정한 것이라 앞 줄에서 되짚을 수 없다 — 되짚으려 들면 중첩 목록이
평평해진다. `>` `<` 는 그 둘에서도 그대로 된다.

### visual mode

normal mode 에서 `v`(글자 단위) `V`(줄 단위) 로 들어간다. 범위를 눈으로 고르고 그 위에
`d` `y` `c` 를 친다 — operator 뒤에 이동 키를 붙이는 것과 같은 일을 순서만 바꿔 하는 것이다.
**blockwise(`ctrl+v`) 는 아직 없다**(ADR-0037).

**고른 범위는 커서가 선 글자까지다.** `v` 만 누르고 `d` 를 치면 커서 아래 한 글자가 지워져서
`x` 와 같다. grapheme cluster 단위라 한글·이모지도 통째로 든다. vim 과 같다.

`v` 는 글자 단위라 `G` `gg` 도 줄 단위가 되지 않는다 — `vG` 는 마지막 줄의 첫 글자까지고,
파일 끝까지 줄로 지우려면 `VG` 다.

statusBar 의 mode 는 `VISUAL` 과 `VISUAL LINE` 이고, 아래 줄은 normal 과 같다.

담을 자리는 범위를 고른 **뒤에** 고른다 — `V j "ay` 다. normal 에서 이름이 operator 앞에
오는 것(`"ayy`) 과 순서가 다른데, 여기서는 범위가 이미 있어서 이름이 마지막 키 앞이다.
`"a` 뒤에 이동 키가 오면 이름과 이동이 같이 버려진다(ADR-0058).

#### key mapping

키 | 기능 | 기타
---|------|-----
(이동 키) | 범위를 늘린다 | normal 의 이동 키를 그대로 받는다. 숫자 접두와 `gg` 도 같다
ctrl+d ctrl+u | 반 화면 아래 / 위로 늘린다 | 이동 키와 같다. 숫자도 받는다(`2ctrl+d`)
ctrl+f ctrl+b | 한 화면 아래 / 위로 늘린다 | 위와 같다
d x | 고른 범위를 지운다 | normal 로 돌아간다. `x` 는 `d` 와 같다 — 지울 범위가 이미 정해져 있다
y | 고른 범위를 register 에 담는다 | 파일을 건드리지 않는다. 커서는 범위의 시작으로 간다
c | 지우고 insert mode 로 | 줄 단위면 줄을 없애지 않고 첫 줄의 들여쓰기를 남긴다. `cc` 와 같다
~ u U | 고른 범위를 뒤집기 / 소문자 / 대문자 | normal 로 돌아간다. 커서는 범위의 시작으로 간다(ADR-0083)
\c | 고른 범위를 평문으로 낸다 | 위와 같다. 파일은 건드리지 않는다. 아래 「평문으로 내보내기」 참고
\mt | 고른 범위에 걸친 markdown 표를 맞춘다 | normal 로 돌아간다. 범위가 표의 가운데를 잘라도 그 표를 통째로 맞춘다(ADR-0106)
> < | 고른 줄들을 한 단계 밀거나 당긴다 | normal 로 돌아간다. 글자 단위로 골랐어도 걸친 줄 전체다
= | 고른 줄들을 규칙이 정한 자리로 다시 들여쓴다 | 위와 같다. markdown 에서는 아무 일도 하지 않는다
v V | 같은 키면 나가고 다른 키면 갈래를 바꾼다 | `v` 뒤의 `V` 는 고른 것을 그대로 두고 줄 단위가 된다
"{문자} | `d`·`y`·`c` 가 담을 register 를 고른다 | `V j "ay` 다. 범위를 고른 뒤에 댄다. 숫자 이름에는 담지 못한다
esc | 고른 것을 놓고 normal 로 |
: | 고른 범위를 명령줄에 실어 보낸다 | `'<,'>` 가 미리 적힌다. **고른 것을 두고 연다.** 위 「고른 범위」 참고
ctrl+p | command palette 열기 | **고른 것을 두고 연다.** 아래 참고
ctrl+z | 셸로 내려간다(suspend) | `fg` 로 올라오면 고른 것이 그대로다
ctrl+c | 전체 종료 | 다른 mode 와 같다

`/` `gt` `gT` `ctrl+w` 는 받지 않는다. 짝이 없는 조합이 아무 일도 하지 않는 것과
같아서(`dgt`) 잘못 누른 키는 그냥 먹히고 만다.

**`:` 는 고른 것을 두고 연다.** `ctrl+p` 와 달리 무엇을 고르는 순간에도 놓지 않는다 —
명령이 걸릴 자리가 그 고른 범위이고, `:'<,'>` 가 그것을 가리키기 때문이다. `esc` 로 명령줄을
나가거나 명령이 끝나면 normal 로 돌아가면서 놓는다(ADR-0089).

**`ctrl+p` 는 고른 것을 두고 연다.** 팔레트는 화면 위에 얹히는 상자라 고른 범위가 그 뒤로
그대로 칠해져 있다. **무엇을 고르는 순간 놓는다** — `esc` 로 물러도 놓는다. 그래서 팔레트의
「화면을 평문으로 내보내기」는 고른 것이 아니라 화면을 낸다. 고른 것을 내는 길은 `\c` 다
(ADR-0085).

**`ctrl+c`·`ctrl+z` 는 편집기 밖으로 나가는 손짓이라 mode 를 가리지 않는다.** 둘 다 고른 것을
건드리지 않아서, 셸에서 `fg` 로 올라오면 고른 그대로 이어 간다(ADR-0023).

**leader(`\`) 는 받는다.** 받는 조합은 둘이다 — `\c`(평문으로 내보내기) 는 두 키이고
`\mt`(표 맞추기) 는 normal 과 같은 세 키다. 숫자를 앞에 쳐도(`2\c`) 같고 숫자는 버려진다.
고른 범위가 이미 정해져 있어 되풀이할 것이 없다(ADR-0085, ADR-0106).

`V` 와 `U` 는 한글 입력 상태에서 낼 수 없다. `ㅍ`·`ㅕ` 의 shift 자리에 다른 글자가 없어
`G` `B` 와 같다. `v` 는 `ㅍ` 으로, `u` 는 `ㅕ` 로 낸다.

#### 강조

고른 범위는 회색 바탕(256색 238) 에 밝은 글자(231) 다. 반전은 statusBar·tabline 이 쓰고 있어서
(ADR-0004) 검색 강조와 같이 256색 고정값이다.

**검색 강조와 겹치면 검색이 위다.** 고른 범위는 커서로도 드러나지만 매칭은 색이 유일한
표시라, 선택 배경이 덮으면 `n` 이 데려다 놓은 곳이 어디인지 보이지 않는다.
공백 마커는 검색 강조에서와 같이 흐린 색이고 배경만 이어진다.

**줄 끝을 넘어가는 선택은 개행 자리에 빈 칸 하나를 더 칠한다.** `V` 로 고른 빈 줄은 칠할
글자가 없어서 이 칸이 없으면 골랐다는 것이 화면에 드러나지 않는다.

### command-line mode

vim 의 command-line mode 와 동일하다.
normal mode 에서 `:` 로 들어간다. 치는 명령은 statusBar 의 아래 줄에 보인다.
줄을 새로 만들지 않고 아래 줄을 바꿔 쓰므로 편집 영역 높이가 흔들리지 않는다.

명령 | 기능
-----|-----
:w | 저장. 밖에서 바뀐 파일이면 알리고 만다. 이름 없는 tab 도 쓸 곳이 없어서 알리고 만다
:w! | 밖에서 바뀐 파일도 덮어쓴다
:w \<파일\> | 그 파일에 사본을 쓴다. 이미 있으면 알리고 만다. 이름 없는 tab 은 그 이름을 받는다
:w! \<파일\> | 이미 있는 파일도 덮어쓴다
:e | 보고 있는 파일을 디스크에서 다시 읽는다. 저장하지 않은 변경이 있으면 확인창을 띄운다
:e! | 묻지 않고 다시 읽는다
:e \<파일\> | 보고 있는 tab 을 그 파일로 갈아끼운다. tab 은 늘지 않는다. 잃을 것이 있으면 확인창을 띄운다
:e! \<파일\> | 묻지 않고 갈아끼운다
:tabnew | 이름 없는 빈 tab 을 지금 tab 바로 뒤에 연다
:tabnew \<파일\> | 그 파일을 지금 tab 바로 뒤에 새 tab 으로 연다
:tree | 좌측 sidebar(filetree) 를 여닫는다
:\<범위\>d | 그 줄들을 지운다. 범위를 안 쓰면 커서 줄이다. 아래 「줄 범위」 참고
:\<범위\>y | 그 줄들을 복사한다. 파일도 커서도 그대로다
:\<범위\>s/찾을 것/바꿀 글/flag, :\<범위\>substitute/… | 치환. 범위를 안 쓰면 커서 줄이다. 아래 「치환」 참고
:\<범위\>cat | 그 줄들을 평문으로 낸다. 범위를 안 쓰면 **화면에 보이는 줄들**이다. 아래 「평문으로 내보내기」 참고
:\<범위\> | 이름 없이 범위만. 그 줄로 간다(`:5`). 두 자리면 뒤쪽이다
:!\<셸 명령\> | 터미널을 셸에 넘겨 그 명령을 돌린다. 아래 「셸 명령」 참고
:grep \<패턴\> | 프로젝트 전체를 검색한다. 패턴을 안 쓰면 박스에서 받는다. 아래 「여러 파일 검색」 참고
:replace/a/b/g | 여러 파일에 걸쳐 바꾼다. 찾아서 판을 열고 거기서 확정한다. 아래 「여러 파일 치환」 참고
:rename | 커서 자리 이름을 프로젝트 전체에서 바꾼다. 새 이름은 커서 옆 창에서 받는다. normal 의 `\rn` 과 같다(ADR-0067)
:rename \<이름\> | 창을 띄우지 않고 곧바로 그 이름으로 바꾼다
:graph | 커밋 기록을 화면 가득 연다. 아래 「커밋 기록」 참고(ADR-0115)
:jobs | 백그라운드 작업 목록을 연다. 도는 것과 최근에 끝난 것이 함께 보이고 `x` 로 취소한다
:messages, :mes | 지나간 알림 목록을 연다. 아래 「알림 목록」 참고
:jumps | `ctrl+o`·`ctrl+i` 가 데려갈 자리들을 하단 drawer 에 보인다. `●` 가 지금 서 있는 자리다(ADR-0070)
:jumplogs | 지금까지 다녀온 자리를 최근 순으로 하단 drawer 에 보인다. 앞쪽을 버리지 않는 방문 기록이다(ADR-0074)
:registers, :reg | 담긴 register 를 하단 drawer 에 보인다. 아래 「register 목록」 참고
:symbols | 특수문자를 이름으로 찾아 넣는 하단 drawer 를 연다. 아래 「특수문자 mode」 참고
:noh, :nohlsearch | 검색 강조만 끈다. 마지막 검색은 남아서 `n` 이 계속 먹는다
:version | 이름·버전·빌드시각·go 런타임을 아래 줄에 찍는다. 버그 신고에 그대로 붙일 수 있다
:q | 지금 보고 있는 tab 을 닫는다. 마지막 tab 을 닫으면 빈 화면이고, 그 화면에서 다시 치면 종료다
:wq, :x | 저장하고 tab 을 닫는다. 마지막 tab 이어도 종료가 아니다. `:x` 는 `:wq` 의 별칭이다
:wq!, :x! | 밖에서 바뀐 파일도 덮어쓰고 닫는다
:q! | 저장하지 않고 tab 을 닫는다. 마지막 tab 이면 빈 화면이 된다
:qa | 전체 종료
:qa! | 저장하지 않고 전체 종료

`esc` 로 취소한다. `backspace` 로 `:` 까지 지워도 나간다.
명령 결과와 오류는 아래 줄에 뜨고 다음 키를 누르면 사라진다 — 사라져도 기록에는 남아서
`:messages` 로 다시 볼 수 있다(아래 「알림 목록」).

#### 명령 문법

한 줄은 `[범위]이름[!] [인자 ...]` 다. `!` 는 이름의 일부가 아니라 "묻지 말고 해라" 는 표시라서
`:q` 와 `:q!` 는 같은 명령이다. 인자는 공백으로 끊고, 공백이 든 파일 이름은 이렇게 쓴다.

```
:w "my notes.txt"     따옴표 안은 전부 글자 그대로다. `\` 도 글자다
:w my\ notes.txt      `\` 뒤의 한 글자는 뜻 없이 그대로 받는다
:w \"quoted\"         따옴표 자체는 따옴표 밖에서 이스케이프한다
```

따옴표가 닫히지 않았거나 `\` 로 끝나면 실행하지 않고 아래 줄에 알린다.
인자를 받는 명령은 정해져 있고 파일 이름 하나만 받는다. 나머지 명령에
인자를 붙이면 알 수 없는 명령으로 친다 — 조용히 버리면 `:wq foo` 가 foo 에 저장한 것처럼 보인다.
`:wq <파일>` 과 `:x <파일>` 도 여기에 든다 — vim 은 받지만 사본을 쓰고 닫아서 편집이 사라지므로
따르지 않았다(ADR-0024). 줄 범위를 받는 명령도 정해져 있다(아래 「줄 범위」).

**뒤를 뜯지 않고 통째로 받는 이름이 넷 있다.** `:!` 는 셸 줄이고 `:grep`·`:s`·`:replace` 는 정규식이라,
공백으로 끊고 `\` 를 먹어 버리면 패턴이 조용히 다른 뜻이 된다. `:s` 와 `:replace` 는 이름과
인자 사이에 공백이 없어서(`:%s/a/b/g`) **이름 다음 글자가 곧 구분자**다 — 띄어 쓴 `:s /a/b/` 도
같이 받는다 (ADR-0077, ADR-0084, ADR-0097).

**이름 자리의 `!` 는 뜻이 다르다.** 이름 뒤에 붙는 `!` 는 강제(`:q!`) 지만, 이름이 올 자리의
`!` 는 그 자체가 이름이고 **뒤를 통째로 셸에 넘긴다**. 범위를 앞에 쳤으면 그 뒤가 이름 자리다. 그래서 위의 따옴표·`\` 규칙이 `:!` 뒤에는 적용되지
않는다 — 그것을 읽는 것은 셸이다. `:!echo "a b"` 의 따옴표도, 닫히지 않은 따옴표도 셸이 본다
(ADR-0045).

```
:!ls -la              공백으로 끊지 않는다. `ls -la` 한 덩어리다
:!grep -r "a b" .     따옴표는 셸이 읽는다
:w !foo               이름 자리가 아닌 `!` 는 파일 이름의 글자다
```

#### `%` 는 지금 보고 있는 파일

이름 **뒤**의 `%` 는 지금 tab 이 연 파일 경로로 펴진다. 이름 **앞**의 `%` 는 그대로 줄 범위다(아래 「줄 범위」). 자리가 뜻을 가르는 것이 `!` 와 같다 (ADR-0114).

```
:!cat %               지금 파일을 셸 명령에 넘긴다
:!cp % %.bak          한 줄에 여러 번 펴진다
:e %                  파일 이름 자리에서도 펴진다
:%s/a/%/              범위 자리의 `%` 도, `:s` 의 패턴 안의 `%` 도 펴지지 않는다
:!echo 100\%          `\%` 는 글자 `%` 다
```

펴 넣는 경로는 **늘 상대**다. cwd 아래면 상대 경로, 아니면 `~` 나 절대 경로다 — 화면이 경로를 줄여 보이는 규칙과 같아서 보이는 것과 펴지는 것이 어긋나지 않는다. 같은 파일이 CLI 로 열렸는지 트리로 열렸는지에 따라 달라지지도 않는다.

**감싸지 않는다.** 공백이 든 이름은 셸에서 두 토큰이 되므로 `:!cat "%"` 처럼 친 사람이 감싼다. vim 과 같은 자리다.

펴지는 자리는 파일 이름 자리와 `:!` 의 셸 줄이다. 통째로 받는 정규식(`:grep`·`:s`·`:replace`) 에서는 펴지 않는다 — 그곳의 `%` 는 찾을 글자다. 이름 없는 tab 에서 `%` 를 치면 명령을 세우고 아래 줄에 알린다. 조용히 빈 문자열로 펴면 `:!rm %` 가 뒤엣것을 지운다.

#### `tab` 으로 경로 채우기

경로를 받는 명령(`:tabnew`·`:e`·`:w`) 에서 `tab` 이 마지막 조각을 채운다. 셸·vim 의 기본 손이다 — 하나면 통째로 채우고, 여럿이면 **공통된 데까지만** 채운 뒤 후보를 명령줄 위 창에 늘어놓는다(ADR-0099).

```
:tabnew int → tab
:tabnew internal/

:tabnew internal/core/buf → tab
┌──────────────────────┐
│buffer-case.go        │
│buffer-cat.go         │
│buffer-change.go      │
├ 8/28                 ┤
└──────────────────────┘
:tabnew internal/core/buffer-
```

**후보는 그때그때 디렉터리를 읽어 만든다.** 팔레트의 파일 목록을 쓰지 않는다 — 그것은 팔레트를 한 번 열어야 채워지고 저장소 안만 담긴다. 여기서 치는 것은 「지금 이 경로 다음에 무엇이 있나」라 `~`·절대 경로·저장소 밖도 되어야 한다. 갈래도 그렇게 나뉜다. 저장소 안을 흐릿하게 찾는 것은 팔레트가 하고, 경로를 또박또박 짚는 것은 명령줄이 한다.

디렉터리에는 `/` 를 붙여서 곧바로 이어 칠 수 있다. 숨김 파일은 앞글자가 `.` 일 때만 나온다. `~` 는 읽을 때만 풀고 명령줄에는 친 그대로 남는다.

**창은 고르는 화면이 아니다.** 짚어 둔 줄도 없고 키도 받지 않는다. 무엇이 있는지만 보이고 고르는 것은 이어 치는 글자이며, 다음 키에 사라진다.

이름 자리는 채우지 않는다(명령을 고르는 자리는 팔레트다). `:grep`·`:s`·`:replace` 의 인자는 경로가 아니라 정규식이라 채우지 않는다. 따옴표가 든 줄도 건드리지 않는다.

#### 줄 범위

이름 앞에 줄 범위를 붙일 수 있다. 받는 명령은 `:d`(지우기)·`:y`(복사)·`:s`(치환)·`:cat`(평문으로
내보내기) 와 이름 없는 것뿐이고,
나머지에 붙이면 `이 명령은 줄 범위를 받지 않습니다` 다 — 조용히 버리면 `:1,5w` 가 그 줄만 쓴
것처럼 보인다(ADR-0046).

```
:5d          5 줄
:1,5d        1 부터 5 줄
:.d          커서 줄. `:d` 와 같다
:.,$d        커서 줄부터 끝까지
:%d          파일 전체. `:1,$d` 와 같다
:.,+3d       커서 줄부터 아래 3 줄
:-2,.d       위 2 줄부터 커서 줄
:$-1,$d      끝에서 두 줄
:,5d         쉼표 한쪽이 비면 커서 줄이다
:+3d         base 를 안 쓰면 커서 줄에서 옮긴 자리다
:1,5         이름이 없으면 그 줄로 간다. 두 자리면 뒤쪽(5 줄) 이다
:'<,'>d      visual 로 고른 범위. 아래 「고른 범위」 참고
```

주소는 줄 번호(1 부터)·`.`(커서 줄)·`$`(마지막 줄)·`'<` `'>`(고른 범위의 두 끝) 이고 `+N` `-N`
으로 옮긴다. 숫자를 안 붙인 `+` 는 한 줄이다. `%` 는 주소가 아니라 범위 전체라서 `:%,5d` 처럼
쓸 수 없다.

**없는 줄은 거절한다.** `:1,500d` 는 `그런 줄이 없습니다: 500` 이고 파일 끝으로 잘라 주지
않는다 — 손이 미끄러진 것과 시킨 것을 가를 수 없기 때문이다. **뒤집힌 범위(`:5,1d`) 는 되묻지
않고 바로잡는다.**

지우기는 지운 것을 알린다(`3 줄 지웠습니다`. 글자로 고른 범위면 `3 글자 지웠습니다`). 키로 치는 `dd` 는 사라지는 것이 화면에 보여서
알리지 않는데, 손으로 친 범위는 화면 밖일 수 있다. 지운 줄과 복사한 줄은 register 에 줄 단위로
들어가서 `p` 가 줄로 붙인다(ADR-0017). 범위 하나가 되돌리기 한 구간이라 `u` 한 번에 다 돌아온다.

mark(`:'a`) 와 검색(`:/pat/`) 주소는 아직 없다. mark 를 치면 `mark 는 아직 쓸 수 없습니다` 다.

#### 고른 범위

**visual 에서 `:` 를 누르면 명령줄에 `:'<,'>` 가 미리 적힌다.** 고른 범위는 치는 동안 화면에
그대로 칠해져 있고, `backspace` 로 `'<,'>` 를 걷어내면 그냥 커서 줄 하나짜리 명령이다(ADR-0089).

**고른 모양을 그대로 따른다.** `V` 로 고른 것은 그 줄들 전체이고, `v` 로 고른 것은 **그 글자들
만**이다.

```
줄 내용:   foo bar foo
고른 것:       ^^^^^^^     `v` 로 `bar foo` 를 고른 것

:'<,'>s/foo/X/g   →   foo bar X      앞의 foo 는 고른 밖이라 그대로
:'<,'>d           →   foo            고른 글자만 지운다
```

**vim 과 갈리는 자리다.** vim 은 `'<,'>` 를 늘 줄 단위로 보고 고른 글자만 바꾸려면 패턴에
`\%V` 를 붙이게 하는데, 고른 것을 보면서 치는 명령이라 고른 밖이 바뀌는 것이 놀람이다.

`^` 와 `$` 는 **줄의 끝**에 맞는다. 고른 구간의 끝이 아니다. 그래서 줄 가운데만 골랐으면
`:'<,'>s/^/> /` 는 아무 일도 하지 않는다 — `^` 가 맞는 자리가 고른 밖이다. 고른 구간에 걸친
자리도 바꾸지 않는다.

`g` 를 안 붙인 `:s` 는 **고른 구간 안의** 첫 자리를 바꾼다.

**normal 에서 친 `:'<,'>` 는 `고른 범위가 없습니다` 다.** vim 은 mark 가 파일마다 남아서 되는데
여기는 남기지 않는다. `gv`(마지막 선택 되살리기) 도 그래서 없다.

한쪽만 `'<` 인 것(`:'<,2d`) 과 자리를 옮긴 것(`:'<,'>+1d`) 은 줄 단위다. 줄 번호를 섞어 넣은
것이라 글자 구간을 지킬 뜻이 없어졌다.

`:'<,'>y` 만 커서가 범위 시작으로 간다. visual 의 `y` 와 같다. 손으로 친 범위(`:1,5y`) 는
커서가 그 자리에 남는다.

#### 치환

`:[범위]s/찾을 것/바꿀 글/flag` 다. 범위를 안 쓰면 커서 줄 하나이고 `%` 가 파일 전체다.
**패턴은 `/` 검색과 같은 정규식**이라 아래 「검색」의 규칙이 그대로 온다(ADR-0010).

```
:%s/a/b/         파일 전체에서 줄마다 첫 자리 하나씩
:%s/a/b/g        줄마다 모든 자리
:1,5s/a/b/       1 부터 5 줄
:s/a/b/          커서 줄 하나
:%s/a/b          마지막 구분자는 생략할 수 있다. 뒤에 올 것이 flag 뿐이다
:%s/a//          바꿀 글이 비면 지운다
```

flag 는 셋이다.

flag | 뜻
-----|----
g | 한 줄의 모든 자리. 없으면 줄마다 첫 자리 하나다
i | 대소문자를 무시한다. `/` 검색의 flag 와 같은 것이다
c | 한 자리씩 물어본다. 아래 참고

**구분자는 아무 글자나 쓸 수 있다.** 이름 다음 글자가 곧 구분자다 — 경로를 바꿀 때 `/` 를
막지 않아도 되는 것이 그 값이다. 영문자·숫자·공백과 `\` `"` 는 쓸 수 없다.

```
:%s#internal/core#internal/ui#     `/` 를 막지 않는다
:%s,a,b,
:%s!a!b!                           `:s` 의 `!` 는 강제가 아니라 구분자다
:%s/a\/b/c/                        `/` 로 쓰려면 막는다
```

**바꿀 글에서 잡은 것을 되쓴다.** vim 의 문법이다.

친 것 | 뜻
-----|----
`&` | 잡은 것 전체
`\0` … `\9` | 잡은 것. `\0` 은 `&` 와 같다
`\&` | `&` 한 글자
`\t` | tab. 명령줄에서 tab 글자를 낼 다른 길이 없다
`\x` | 그 밖의 글자는 그대로다. 구분자를 넣는 `\/` 도 이 길이다
`$` | 사람이 친 `$` 는 글자다. 잡은 것을 뜻하지 않는다

```
:%s/(\w+)Buffer/\1Screen/g        fooBuffer → fooScreen
:%s/(\w)-(\w)/\2-\1/             a-b → b-a
:%s/b/[&]/                        abc → a[b]c
```

**`c` 는 편집 화면 그대로에서 묻는다.** 커서가 지금 물어보는 자리에 서고 아래 줄이 묻는다.
화면의 매칭이 칠해지고 그중 물어보는 한 자리만 색이 다르다 — `:s` 가 찾은 패턴을 마지막
검색으로 굳히기 때문이고, 그래서 끝난 뒤에 `n` 으로 남은 자리를 훑을 수 있다(vim 과 같다).

키 | 하는 일
---|--------
y | 바꾸고 다음으로
n | 두고 다음으로
a | 남은 것 전부
q, esc | 그만

vim 의 `l`(이것만 하고 그만) 은 없다 — `y` 다음 `q` 가 같은 일이다. 넷 다 한글 입력
상태에서도 낸다(`ㅛ` `ㅜ` `ㅁ` `ㅂ`). mode 는 `SUBSTITUTE` 다.

아직 하나도 안 바꾼 동안 밖에서 파일이 바뀌면 자동으로 다시 읽히는데(위 「밖에서 바뀐 것
알기」), 그때는 `파일이 밖에서 바뀌어 치환을 멈췄습니다` 로 그 자리에서 멈춘다.

**한 번 친 것이 되돌리기 한 구간이다.** 파일 전체를 고쳤어도 `u` 한 번에 다 돌아오고,
`c` 로 하나씩 고른 것들도 한 판이 하나다. **못 찾으면 파일도 되돌리기 이력도 건드리지 않는다**
— `찾을 수 없음: <패턴>` 만 뜬다. 바꿨으면 몇 곳을 몇 줄에서 바꿨는지 알린다
(`12 곳을 4 줄에서 바꿨습니다`). 커서는 마지막으로 바꾼 줄의 첫 비공백으로 간다.

없는 것들이다. 빈 패턴이 마지막 검색이 되지 않고(`:%s//b/`), `:s` 만 쳐서 마지막 치환을
되풀이할 수 없고, 바꿀 글로 줄을 가를 수 없다(vim 의 `\r`). 여러 파일에 걸친 치환도 아직
없다(ADR-0084).

#### 셸 명령

`:!<셸 명령>` 은 **터미널을 셸에 그대로 넘긴다.** 편집 화면이 물러나고 명령이 터미널에 직접
쓰므로, `git commit`·`less`·`htop` 처럼 화면과 stdin 을 쓰는 명령도 그대로 돈다. 도는 동안
편집기는 멈춰 있다.

셸은 `$SHELL` 이고 비어 있으면 `sh` 다. `$SHELL -c '<친 것>'` 으로 돈다.

무엇이 돌았는지 알 수 있게 `:!<친 것>` 을 한 줄 먼저 찍는다. 끝나면 `계속하려면 Enter 를
누르세요` 에서 멈춘다 — 돌아가는 순간 대체 화면이 출력을 덮기 때문에, 그 틈이 없으면 출력이
있었다는 것조차 알 수 없다(vim 의 「Press ENTER」와 같은 자리다). 출력이 없는 명령도 묻는다.

**출력은 남기지 않는다.** Enter 를 누르면 사라진다. 결과를 buffer 로 가져오는 것은 아직 없다.

도는 동안 `ctrl+c` 는 **명령에** 간다. 편집기는 그 신호를 무시하므로 살아남고, 끊긴 것은
실패로 알리지 않는다 — 그만하라고 한 사람이 결과를 이미 안다. 종료 코드가 0 이 아니면
아래 줄에 `셸 명령이 실패했습니다: exit status 1` 이 뜬다. 성공은 조용하다.

돌아오면 보고 있는 파일을 다시 검사한다. 셸에서 고쳤고 편집기 쪽에 잃을 것이 없으면 그대로
가져온다(ADR-0038). 끝나면 언제나 normal 이다.

`:!` 만 치면 `셸 명령이 없습니다` 다.

#### 밖에서 바뀐 것 알기

보고 있는 파일이 밖에서 달라졌는지는 **터미널 포커스가 돌아올 때**(다른 창을 만지고 왔다는 뜻),
**셸에서 올라올 때**(`ctrl+z` 뒤 `fg`), **`:!` 로 돌린 셸 명령이 끝날 때**,
그리고 **저장하기 직전**에 본다. 판정은 내용 해시라
mtime 만 바뀐 것은 세지 않는다(ADR-0015).

포커스 복귀는 normal·insert·트리에서 받는다. 발견하면 statusBar 경로 뒤에 `[!]` 가 붙고,
아래 줄에 `파일이 밖에서 바뀌었습니다. 다시 읽으려면 `:e` 입니다` 가 한 번 뜬다. 알림은 다음
키에 사라지지만 마커는 남는다. 이미 마커가 붙은 파일이 또 바뀌어도 다시 알리지 않고, 밖의
변경이 되돌아가면 마커가 조용히 사라진다(ADR-0031).

가져오는 것은 `:e`, 덮어쓰는 것은 `:w!` 다. 편집기가 알아서 다시 읽지는 않는다(ADR-0016).
보고 있지 않은 tab 은 검사하지 않는다 — 마커가 없다고 그 파일이 깨끗한 것은 아니다.

#### 파일에 쓰기

인자 없는 `:w` 는 보고 있는 파일에 쓴다. 읽은 뒤 밖에서 바뀌었으면 쓰지 않고 알린다(ADR-0015).

`:w <파일>` 은 **사본을 쓴다.** 그 파일에 내용을 쓰기만 하고 보고 있는 파일도 tab 이름도
변경 표시도 그대로라, 이어지는 `:w` 는 여전히 원래 파일에 쓴다. vim 과 같고 이름을 옮기는
`:saveas` 는 두지 않았다(ADR-0024).

**이름 없는 tab 만 예외로 그 이름을 받는다.** 붙어 있을 원래 파일이 없어서 사본이라는 말이
성립하지 않는다. `:tabnew` 로 만든 tab 을 저장하는 길이 이것이고, 저장한 뒤에는 그 파일의
tab 이 되어 그냥 `:w` 로 이어서 저장한다. undo 이력은 그대로 남는다.

명령 | 하는 일 | 쓸 파일이 이미 있을 때
-----|---------|----------------------
`:w` | 보고 있는 파일에 쓴다 | (밖에서 바뀌었으면 알리고 만다)
`:w!` | 보고 있는 파일에 쓴다 | (밖에서 바뀌어도 덮어쓴다)
`:w <파일>` | 그 파일에 쓴다 | 알리고 만다
`:w! <파일>` | 그 파일에 쓴다 | 덮어쓴다

이미 있는 파일을 막는 것은 vim 의 E13 과 같다. 다른 파일은 읽은 적이 없어서 ADR-0015 의
해시 비교로 무엇이 달라졌는지 볼 수 없고, 있는지 없는지만 볼 수 있다.

쓸 곳이 보고 있는 파일과 같으면(`:w ./a.txt`) 사본이 아니라 제자리 저장이다. 경로는
정규화해서 비교한다 — tab 을 찾는 것과 같은 기준이다.

**이름을 받으려는 파일이 이미 다른 tab 에 열려 있으면 쓰지 않고 알린다.** 이름이 붙는 순간
같은 파일에 Buffer 가 둘이 되기 때문이다. 사본을 쓸 때는 Buffer 가 늘지 않으므로 걸리지 않는다.

#### 파일 열기

`:e <파일>` 은 보고 있는 tab 을 그 파일로 갈아끼우고, `:tabnew <파일>` 은 새 tab 을 연다.
없는 파일은 그 이름의 빈 buffer 가 된다. CLI 인자와 같다.

**둘 다 이미 열려 있는 파일이면 그 tab 으로 옮겨가기만 한다.** tab 마다 Buffer 가 독립이라
같은 파일이 두 tab 에 있으면 한쪽 저장이 다른 쪽 편집을 덮어쓴다. 팔레트·트리로 여는 것과
CLI 인자도 같은 규칙이다(ADR-0021).

인자 없는 `:e` 는 보고 있는 파일을 다시 읽는다. 팔레트의 「파일 다시 읽기」와 같다(ADR-0016).

tab 이 하나도 없으면 `:e <파일>` 은 갈아끼우는 것이 아니라 새로 여는 것이라 잃을 것이 없다 —
확인창이 뜨지 않는다. 인자 없는 `:e` 는 다시 읽을 파일이 없다고 알린다(위 「빈 화면」).

명령 | 하는 일 | 잃을 것이 있을 때
-----|---------|------------------
`:e` | 다시 읽는다 | 확인창
`:e!` | 다시 읽는다 | 묻지 않는다
`:e <파일>` | 활성 tab 을 갈아끼운다 | 확인창
`:e! <파일>` | 활성 tab 을 갈아끼운다 | 묻지 않는다

이미 열린 tab 으로 옮겨가기만 할 때는 잃을 것이 없으므로 변경이 남아 있어도 묻지 않는다.
갈아끼운 tab 의 undo 이력은 다시 읽기와 마찬가지로 사라진다.

`:wq` 는 `:w` 와 `:q` 의 조합이 아니라 그 자체로 이름 하나다. vim 의 ex command 표와 같다.
`:x` 도 마찬가지다 — 다만 vim 의 `:x` 는 변경이 있을 때만 쓰는 반면 여기서는 `:wq` 의 별칭이라
항상 쓴다. 명령을 조합하는 문법(vim 의 `:w | q`) 은 두지 않았다.

`:q` 계열은 tab 을 닫고 `Ctrl+C` 는 `:qa` 와 같이 전체를 끝낸다(ADR-0003).
**`:q` 로는 편집기가 끝나지 않는다** — 마지막 tab 을 닫으면 빈 화면이 남고, 닫을 tab 이 없는
그 화면에서 다시 치면 그때 끝난다(ADR-0064, 위 「빈 화면」).
어느 쪽이든 잃을 것이 있을 때만 확인창이 뜨고, 없으면 묻지 않는다.
묻는 범위는 각자 잃는 것에 맞춘다 — `:q` 는 닫는 tab 의 변경만 보고,
`:qa` 와 `Ctrl+C` 는 어느 tab 이든 변경이 남아 있는지를 본다. 마지막 tab 이어도 `:q` 는
그 tab 만 본다.


#### 경로의 `~`

경로를 받는 명령(`:w <파일>`, `:e <파일>`, `:tabnew <파일>`) 은 **맨 앞의 `~` 를 홈 디렉터리로 푼다**(ADR-0088). CLI 인자는 셸이 이미 풀어서 넘겨 주지만 편집기 안에서 친 것은 아무도 풀어 주지 않는다.

친 것 | 여는 곳
-----|--------
`~` | 내 홈
`~/.zshrc` | 내 홈 아래
`~bluemir` | 그 사용자의 홈
`~bluemir/src` | 그 사용자의 홈 아래
`docs/~backup` | 그대로. 맨 앞이 아닌 `~` 는 그런 이름의 파일이다

없는 사용자면(`~nobody/x`) 사용자를 찾을 수 없다고 알리고 만다. `~` 로 시작하는 이름의 진짜 파일은 `./~foo` 로 연다.

`:!<셸 명령>` 의 `~` 는 셸이 자기 규칙으로 푼다. `:grep`·`:s`·`:replace`·`:rename` 의 인자와 트리의 만들기·이름 바꾸기는 파일 경로가 아니라서 풀지 않는다.

### search mode

normal mode 에서 `/`(아래로) `?`(위로) 로 들어간다. 치는 패턴은 command-line mode 와 같은
자리, statusBar 의 아래 줄에 보인다. `esc` 로 취소하고 `backspace` 로 여는 글자까지 지워도 나간다.

**패턴은 Go 의 정규식(RE2) 이다**(ADR-0010). vim 의 magic 규칙으로 옮기지 않으므로 `(` 이 그룹이고
`\(` 이 글자다. 단어 경계는 `\<`·`\>` 가 아니라 `\b` 다.

#### flag

**패턴 뒤에 `/글자들` 로 붙인다.** 지금 있는 것은 대소문자를 무시하는 `i` 하나이고 모르는 flag 는
오류다. 붙이지 않으면 대소문자를 구분한다 — smartcase 를 두지 않았다(팔레트의 매칭과 다른 자리다).

```
/abcd/i     대소문자를 가리지 않고 abcd
?abcd/i     위로 찾는다. 구분자는 방향과 상관없이 늘 `/` 다
/http://    마지막 `/` 뒤가 비어 있어서 flag 가 아니다. 친 그대로 찾는다
/a\/b       flag 로 읽힐 `/` 는 `\/` 로 막는다. Go 정규식에서도 `/` 한 글자다
```

마지막 `/` 뒤가 비어 있거나 ASCII 영문자가 아닌 것이 섞여 있으면 flag 가 아니라 패턴의 일부다.
그래서 `/foo/bar/` 는 친 그대로이고, 실제로 걸리는 것은 `/a/b` 처럼 짧은 경로 조각인데
그때는 조용히 다르게 동작하지 않고 「모르는 flag」라고 알린다.

#### 치는 동안과 찾은 뒤

**치는 동안 첫 매칭으로 커서와 화면이 따라간다(incsearch).** 늘 검색을 시작한 자리에서 다시
찾으므로 글자를 지우면 앞의 자리로 되돌아온다. `esc` 로 나가면 커서·화면·직전 검색이 모두
시작 상태로 돌아간다. 치는 도중에는 오류를 띄우지 않는다 — `(` 까지 친 순간은 늘 잘못된
정규식이다. 오류는 `enter` 에 낸다.

**찾은 자리는 모두 칠하되 커서가 선 것만 색이 다르다.** 나머지는 노랑(256색 220) 바탕이고
커서가 선 것은 주황(208) 바탕에 검은 글자다. 「커서가 선 매칭」은 커서 자리에서 시작하는
매칭이라, 다른 키로 커서를 옮기면 자연히 사라진다.

강조는 검색할 때마다 켜지고 `:noh` 로 끈다. 끄는 것은 강조뿐이라 마지막 검색은 남아서 `n` 이
계속 먹는다.

**파일 끝에 닿으면 반대쪽 끝에서 이어 보고, 감쌌으면 아래 줄에 알린다.**

#### `n` `N` `*` `#`

`n` 은 같은 방향, `N` 은 반대 방향으로 다음 매칭이다. **마지막 검색은 `editor` 가 들고 있어서**
tab 을 옮겨도 `n` 이 같은 것을 찾는다 — 여러 파일에서 같은 이름을 훑는 흐름이 끊기지 않는다.

`*` `#` 는 커서 아래 단어를 아래·위로 찾는다. 커서를 그 단어 앞으로 옮긴 뒤 거기서 시작하므로
`*` 를 눌렀는데 한 칸 옆으로 가고 마는 일이 없다. 단어 경계는 `w` 와 같은 부류 나누기이고
(ADR-0006), 양끝이 ASCII 단어 글자일 때만 `\b` 를 붙인다 — 한글 단어에 `\b` 를 붙이면
Go 의 `\b` 가 ASCII 기준이라 아무것도 찾지 못한다. 그래서 `한글` 을 찾으면 `한글자` 도 걸린다.

검색은 **줄 단위**라 줄바꿈을 건너뛰는 패턴(`func\s*\n`) 은 맞지 않는다.
검색 키는 `d` 뒤에 받지 않는다 — `d/foo` `dn` 은 없다(ADR-0013).

### 특수문자 mode

`:symbols` 나 command palette 의 `>` 목록에서 「특수문자 넣기」로 들어간다. 편집 영역 아래에
하단 drawer 가 펼쳐지고 이름으로 걸러 격자에서 고른다. statusBar 의 mode 는 `SYMBOL` 이다
(ADR-0056).

```
│  200  0 line 200                                    │  ← 커서 줄은 늘 판 위에 남는다
┌─────────────────────────────────────────────────────┐
│ 삼각형                                    21/12265  │  ← 입력줄과 걸린 수
├─────────────────────────────────────────────────────┤
│ ⊿   △   ◁   ▲   ▽   ◀   ▷   ▼   ▶   ◤   ◣   ▵      │
│ ◥   ◃   ▴   ◢   ▿   ◂   ▹   ▾   ▸                  │
│ ⊿   직각 삼각형          삼각형 세모 triangle right │  ← 고른 것의 이름
└─────────────────────────────────────────────────────┘
```

판은 편집 영역에 **얹지 않고 그 행을 가져간다.** 그래서 넣는 자리인 커서가 판에 가리지 않는다.
폭은 편집 영역과 같아서 sidebar 옆을 지나가지 않는다 — 트리 높이는 그대로다.

격자는 최대 4 행이고 한 칸은 4 칸이다. 화면이 짧아지면 행이 먼저 줄고, 격자가 한 행도 안
나오거나 편집 영역에 세 줄이 안 남으면 열지 않고 아래 줄에 알린다. 열려 있는 동안 좁아지면
normal 로 빠져나온다 — 팔레트와 같은 방어다.

#### key mapping

키 | 기능 | 기타
---|------|-----
(글자) | 입력줄에 넣는다 | 한글은 여기서 글자다(ADR-0008)
← → | 이전 / 다음 글자 | 양끝에서 멈춘다. 둘러 가지 않는다
↑ ↓ | 격자 한 행 위 / 아래 |
enter | 커서 뒤에 넣는다 | **판은 열린 채다.** 연달아 넣을 수 있다
esc | 나간다 | 언제나 normal 로. insert mode 의 `esc` 와 같은 자리에 선다
backspace | 한 글자 지우기 | 다 지우고 또 누르면 나간다. 팔레트와 같다
ctrl+p | 아무 일도 하지 않는다 | 팔레트가 자기 키에 그렇게 하는 것과 같다
ctrl+c | 전체 종료 | 다른 mode 와 같다
휠 | 격자 한 행 위 / 아래 | 포인터가 어디 있든 목록을 움직인다

넣는 자리는 `a` 와 같다. 연달아 넣은 것은 한 undo 단위라 `u` 한 번에 통째로 돌아온다.
아무것도 안 넣고 `esc` 하면 `a<Esc>` 처럼 열기 전 자리다 — 커서가 줄 맨 앞이었을 때만
한 칸 오른쪽에서 시작한다.

읽기 전용 파일에서는 열지 않고 알린다(ADR-0016).

#### 목록

큐레이션한 한국어 표가 앞이고 유니코드를 훑어 얻은 것이 뒤다. 아무것도 치지 않았을 때 보이는
첫 화면이 손으로 적은 것들이다.

- **큐레이션 표** — 화살표·도형·수학·구두점·괄호·통화·괘선·기호·문자와 숫자, 그리고 자주 쓰는
  이모지. 한국어 이름과 별칭이 붙어 있어서 `삼각형`·`하트`·`화살표` 로 찾힌다.
  새 글자는 `internal/assets/symbols.go` 에 한 줄이 는다
- **훑어서 얻은 것** — `runenames` 의 영문 이름이다. `flatness` 처럼 영문으로만 찾힌다.
  글자와 숫자는 뺀다 — 한글 음절과 CJK 만 10 만 개가 넘어 목록이 그것으로 뒤덮인다

훑기는 백그라운드 작업이고 프로세스에 한 번뿐이다. 여는 순간 큐레이션 표를 곧바로 쓰므로
훑기를 기다리지 않는다.

격자 칸은 East Asian Width 가 Ambiguous 인 글자(`→ ± × °`) 를 시작할 때 잰 폭으로 센다.
재지 못했으면 두 칸으로 본다 — 좁게 잡으면 행이 넘쳐 아래가 통째로 밀린다(ADR-0028).

### register 목록

`:registers`(`:reg`) 나 팔레트의 「register 목록」으로 연다. 특수문자 판과 같은 자리에 하단
drawer 로 펼쳐지고, statusBar 의 mode 는 `REGISTERS` 다(ADR-0058).

```
│    3  2 foxtrot six                                 │  ← 커서 줄은 판 위에 남는다
┌─────────────────────────────────────────────────────┐
│ "" 줄   delta four⏎                                 │  ← 무명이 맨 위
│ "0 줄   delta four⏎                                 │
│ "1 글자 a                                           │
│ "2 줄   bravo two⏎                                  │
│ "a 줄   alpha one⏎bravo two⏎                        │  ← 문자는 숫자 뒤
└─────────────────────────────────────────────────────┘
```

화면을 통째로 쓰는 `:jobs`·`:messages` 와 달리 편집 영역의 행을 가져간다. **어느 것을 붙일지
보려고 여는 목록이라 붙일 자리가 같이 보여야 한다.**

**담긴 것만 보인다.** 그래서 판 높이가 담긴 개수에 따라 달라진다. 하나도 없으면 그 사실을
한 줄로 알린다. 편집 영역에 세 줄을 남기고도 다 못 그릴 만큼 낮으면 들어가는 만큼만 그리고
`j`/`k` 로 훑는다 — 열지 못하는 경우는 없다.

순서는 무명·숫자·문자다. 숫자가 앞인 것은 저절로 채워지는 자리라서다 — 무엇이 방금 지워졌는지가
손으로 모아 둔 것보다 급하다. 대문자 줄은 없다. `"A` 는 `"a` 와 같은 자리다.

한 줄은 이름·갈래·내용이다. 갈래(`줄`/`글자`) 를 글자로 적는 것은 그것이 `p` 를 어디에 붙일지를
정하는 값이기 때문이다. 줄바꿈은 `⏎` 로 잇고, 줄 단위 register 는 마지막 줄에도 그것이 붙는다.
길면 오른쪽부터 `…` 로 줄인다.

#### key mapping

키 | 기능 | 기타
---|------|-----
j k ↓ ↑ | 한 줄 훑기 | 다 보이면 아무 일도 하지 않는다. 양끝에서 멈춘다
g G | 처음 / 끝 |
q esc | 닫는다 | normal 로 돌아온다. 편집 영역이 그대로 돌아온다
ctrl+c | 전체 종료 | 다른 mode 와 같다
휠 | 위 / 아래 | 포인터가 어디 있든 목록을 움직인다

담긴 것을 지우거나 고치는 키는 없고 골라 붙이는 키도 없다. 읽는 판이다 — 무엇을 붙일지 보고
나가서 `"1p` 를 친다. 커서는 편집 내용에 그대로 있다.


## Mouse

mouse 는 mode 를 가로지르므로 따로 적는다(ADR-0012). 항상 켜져 있고 끄는 방법은 없다.

누른 화면 자리가 곧 무엇을 눌렀는지다. 화면은 네 영역으로 갈린다 —
sidebar, tabline, 편집 영역(줄번호 칸을 포함), statusBar.
statusBar 는 눌러도 아무 일이 없다.

**왼쪽 버튼을 누를 때** 반응한다. 뗄 때는 보지 않는다 — 누르고 그대로 뗐으면 누른 자리로
가고, 끌었으면 끄는 동안 범위가 자란 채로 멈춘다(아래 「드래그」). **오른쪽 버튼은 tabline
에서만 뜻이 있다**(아래 「우클릭」). 가운데 버튼과 double-click 은 쓰지 않는다.

영역 | 클릭 | 우클릭 | 휠
-----|------|--------|----
sidebar | 그 항목을 고르고 `enter` 와 같이 연다 | 아무 일도 없다 | 트리를 굴린다
tabline | 그 tab 으로 옮겨간다. 끌면 순서를 바꾼다 | 그 tab 을 닫는다 | 아무 일도 없다
편집 영역 | 그 자리로 커서를 옮긴다 | 아무 일도 없다 | 화면을 굴린다
statusBar | 아무 일도 없다 | 아무 일도 없다 | 아무 일도 없다

**다른 영역을 클릭하면 포커스도 그리로 간다.** `ctrl+w ctrl+w` 로 오가는 것과 같은
왕래다. 단 편집 영역을 클릭할 때 insert mode 는 유지한다 — 눌러서 자리를 잡고 이어 치는
것이 mouse 를 쓰는 이유다. 이때 커서 이동이므로 undo 구간은 끊긴다(화살표 이동과 같다).

**마커 칸과 줄번호 칸을 누르면 그 행의 시작이다.** wrap 되어 이어지는 행이면 그 행의 시작이다.
**파일 마지막 줄 아래 빈 자리는 누를 것이 없는 자리다** — 커서가 움직이지 않는다.
tab 자리 안이나 두 칸짜리 글자의 오른쪽 칸을 누르면 그 글자의 시작으로 맞춘다.
tabline 의 구분선과 오른쪽 빈 칸, 잘려서 안 보이는 tab 자리도 아무 일도 하지 않는다.

**우클릭은 누른 tab 을 닫는다**(ADR-0060). **보고 있던 파일은 그대로 본다** — 남의 tab 을
닫아도 커서와 화면이 움직이지 않고 왼쪽을 닫았으면 번호만 하나 당겨진다. 보고 있던 tab 을
닫았으면 그 자리에 드러나는 파일을 보고(오른쪽 끝이었으면 왼쪽) insert·visual 이었으면
normal 로 나온다. 트리에 포커스가 있었으면 트리에 남는다.

**tab 이 하나뿐이어도 닫는다.** 닫으면 빈 화면이 남고 편집기는 끝나지 않으므로 `:q` 와 갈릴
이유가 없다 — 예전에는 손이 미끄러진 한 번으로 편집기가 닫히지 않게 마지막 tab 만 거부했다
(ADR-0064). 전체 종료는 `ctrl+c`·`:qa` 다.
저장하지 않은 변경이 있으면 확인창이 뜨고, 보고 있지 않은 tab 이라 물음에 파일 이름을
적는다(`b.txt tab 을 닫으시겠습니까?`). 구분선과 빈 칸, 가려짐 표시는 tab 이 아니라
아무 일도 없다 — 표시를 우클릭해도 밀지 않는다.

**휠은 화면만 굴리고 커서는 그대로 둔다.** 커서가 화면을 벗어나면 그때만 밀려난 쪽
끝 행으로 데려온다. vim 과 같다. 한 번에 3 행이고 좌우 휠은 쓰지 않는다.
`ctrl+d`·`ctrl+f` 와 갈리는 자리다 — 그쪽은 커서를 데리고 간다(「화면 단위 이동」 참고).

**휠이 움직이는 것은 포커스가 아니라 포인터가 얹힌 영역이다.** 편집 영역을 보면서
sidebar 위에서 굴리면 트리만 굴러간다.

**명령줄(`:`) 과 검색(`/`) 을 치는 중에는 휠만 받고 클릭은 무시한다.** 치던 것이 클릭
한 번에 사라지지 않는다. 다만 검색은 다음 글자를 치면 incsearch 가 첫 매칭으로 화면을
다시 잡아당기므로 굴려둔 것이 그때 사라진다. 종료 확인창은 클릭도 휠도 받지 않는다.

**팔레트(`ctrl+p`) 에서는 휠이 목록을 오르내린다.** 화면 위에 얹힌 박스라 아래 편집 내용을
굴려도 볼 수 없으므로, 여기서만 포인터 위치를 보지 않고 화살표와 같이 움직인다.
클릭은 받지 않는다.

**작업 목록(`:jobs`) 도 같다.** 화면을 통째로 쓰므로 굴릴 다른 영역이 없다. 휠이 고른 자리를
`j`/`k` 와 같이 옮기고 클릭은 받지 않는다.

### 드래그

**편집 영역에서 버튼을 누른 채 끌면 범위를 고른다.** 누른 자리가 anchor 이고, 포인터가
움직이는 순간 글자 단위 visual mode 로 들어간다. 뗀 뒤에도 visual 에 머물러서 이어서
`d` `y` `c` 를 친다. 클릭만 하는 것은 커서 이동 그대로다 — vim 과 같다(ADR-0037).

여는 것은 편집 영역 안의 움직임뿐이다. 일단 열린 뒤에는 밖으로 나가도 따라가서, sidebar 쪽으로
끌면 줄 시작까지고 statusBar 아래로 끌면 맨 아랫행까지다. 이때 포커스는 옮기지 않는다 —
끄는 중이라 「다른 영역을 눌렀다」가 아니다. 편집 영역 위아래로 나가면 그 방향으로 한 행씩
굴린다. 다만 잡은 채 가만히 있으면 굴러가지 않는다. 움직여야 이벤트가 온다.

**visual mode 에서 클릭하면 고른 것을 놓는다.** 누른 자리가 새 시작이다. statusBar 만은
눌러도 아무 일이 없고 visual 도 그대로다.

**tabline 에서 누른 채 끌면 tab 순서가 바뀐다**(ADR-0090). 누른 순간 그 tab 으로 옮겨가므로
끄는 것은 늘 보고 있는 tab 이고, 옮긴 뒤에도 같은 파일을 그대로 본다.

**끄는 동안 순서가 실제로 바뀐다.** 놓을 자리를 알리는 표시가 따로 없고 tabline 이 그것이다.
놓는 순간에는 이미 다 옮겨져 있다.

**tabline 밖으로 나가면 아무 일도 하지 않는다.** 끌던 자리를 유지하고 포인터가 돌아오면 이어서
옮긴다. 편집 영역으로 내려가도 범위를 고르지 않는다 — tabline 이 한 행이라 가로로 끄는 손이
아래로 한 칸 새기 쉽다. 끌어내서 닫는 길은 없다. tab 을 잃는 일이고 우클릭이 이미 그 길이다.

양끝의 가려짐 표시(`<n` `n>`) 위로 끌어도 아무 일도 없다. 누르면 화면을 미는 자리인데, 끌면서
밀기 시작하면 손이 멈춰도 계속 흘러간다. 가려진 자리로 보내려면 표시를 눌러 민 다음 끈다.

순서는 **저장하지 않는다.** 다음에 열면 CLI 인자 차례다. 키로 옮기는 명령(`:tabmove`) 도 없다 —
눈으로 보고 하는 일이라 번호를 세어 치는 길이 값을 내지 않는다.

vim 의 double-click(단어) 과 triple-click(줄) 은 없다. 누른 횟수를 알 수 없다(ADR-0012).

mouse 를 켜 두는 동안 터미널 자체의 드래그 복사가 막힌다. 대부분의 터미널에서
`shift` 를 누른 채 드래그하면 터미널 쪽 선택이 되는데, 그렇게 긁어도 줄번호 칸과 공백
마커가 같이 딸려오고 긴 줄은 접힌 자리에서 끊긴다. 제대로 된 답이 아래다.

## 평문으로 내보내기

**화면(또는 visual 로 고른 범위) 을 `cat` 과 같은 평문으로 터미널에 낸다.** 복사·붙여넣기용이고,
mouse 를 끌 수 없어서 막힌 드래그 복사의 진짜 해결이 이것이다(ADR-0012, ADR-0085).

부르는 문이 넷이다.

부르는 법 | 무엇을 내는가
---|---
`\c`(normal) | 화면에 보이는 줄들
`\c`(visual) | 고른 범위. normal 로 나오고 커서는 범위의 시작이다
`:cat` | 화면에 보이는 줄들. `:%cat` 은 파일 전체, `:1,50cat` 은 그 줄들
팔레트의 「화면을 평문으로 내보내기」 | `\c` 와 같다

**mode 가 아니다.** `:!` 와 같이 터미널을 잠깐 넘긴다 — 편집 화면이 물러나고 평문이 **주 화면**에
찍힌다. 그동안 마우스 보고가 꺼져 있어서 **터미널 드래그 복사가 살아나고**, 주 화면이라 지나간
것이 스크롤백에 남는다. `계속하려면 Enter 를 누르세요` 로 멈춰 섰다가 Enter 로 돌아온다
(ADR-0045, ADR-0085).

```
:cat internal/core/editor.go 120-141
func (e *editor) editorView(shape tea.CursorShape, mode, bottom string) tea.View {
	if !e.hasTab() {
		return newView(e.renderScreen(e.renderEmptyScreen(), mode, bottom))
	}
	...

계속하려면 Enter 를 누르세요
```

**내는 것은 화면이 아니라 파일의 byte 다.** 줄번호도 공백 마커(`»` `⋅`) 도 문법 색도 없고,
tab 은 tab 그대로 나간다 — 터미널이 제 tab stop(대개 8 칸) 으로 그려서 편집 화면과 폭이
달라 보일 수 있지만 **복사되는 것은 진짜 tab** 이다.

**wrap 된 줄은 논리 줄 통째로 낸다.** 한 조각만 보여도 그 줄 전체가 든다 — 접힌 자리에서
끊어 내면 붙여넣은 글에 없던 줄바꿈이 생긴다. 감싸는 머리줄이 덮은 위 몇 행도 그대로 든다.
내는 것이 「이어진 한 덩이」여야 해서고, 머리줄이 든 줄은 화면 밖이라 앞에 붙이면 사이가 끊긴다.

첫 줄은 무엇을 낸 것인지다(`:cat <경로> <시작>-<끝>`). 주 화면에는 지난 출력이 그대로 남아
있어서 그것이 없으면 어느 것의 글인지 갈리지 않는다 — `:!` 가 친 명령을 먼저 찍는 것과 같다.

읽기 전용 파일도 그대로 낸다. 파일을 건드리지 않으므로 `:y` 와 같은 자리다.

없는 것들이다. 줄 번호를 붙이는 길(`cat -n`) 이 없고 — 붙이면 긁을 때 같이 딸려온다 —
시스템 클립보드에 바로 넣는 길(OSC 52) 도 아직 없다.


## Command Palette

`Ctrl+P` 로 연다. normal mode 와 sidebar 둘 다에서 받는다. 화면 위쪽 가운데에 박스가 떠서
편집 화면과 sidebar 위에 겹친다. 기본은 파일 찾기이고, 맨 앞 글자가 갈래를 정한다 —
`>` 는 명령 목록, `!` 는 셸 명령이다. 그 글자를 지우면 파일 찾기로 돌아온다.

```
▾ zn/                    │ 1 editor.go
  ▸ docs/     ┌──────────────────────────────────┐
  ▸ internal/ │ edit                             │
    README.md ├──────────────────────────────────┤
              │ internal/core/edit.go            │  ← 고른 행은 반전
              │ internal/core/editor.go          │
              │ internal/core/edit_test.go       │
              └──────────────────────────────────┘
                            PALETTE  internal/core/editor.go
                            13/123
```

박스는 **화면** 가운데다. 편집 영역 가운데가 아니라서 sidebar 를 여닫아도 자리가 그대로다.
너비는 최대 64 칸이고 화면이 좁으면 그만큼 줄어든다. tabline 은 덮지 않고(맨 윗줄 아래에서
시작한다) statusBar 앞에서 멈춘다. 목록은 최대 10 행이고, 걸린 것이 적으면 박스도 그만큼 짧다.

24 칸을 못 채우거나 목록 행이 한 줄도 안 나오는 좁은 화면에서는 **열지 않고** 아래 줄에 알린다.
열린 뒤에 좁아지면 normal 로 나온다 — 보이지 않는 mode 에 갇히면 키를 쳐도 아무 일이 안 난다.

statusBar 아래 줄은 `걸린 수/전체 수` 다. 어디서 열었든 팔레트가 끝나면 편집 영역으로 나온다.

`!` 갈래는 고를 목록이 없다. 목록 자리에 안내 한 줄(`! 뒤에 셸 명령을 칩니다`, 치면
`Enter 로 셸에서 실행합니다`) 이 들어가고 아래 줄의 `걸린 수/전체 수` 는 비운다 — 셀 것이 없다.
`Enter` 는 고르는 것이 아니라 친 것을 실행하는 것이고, 하는 일은 `:!` 와 같다(ADR-0045).

```
┌────────────────────────────────────────────────────────┐
│ !go test ./...                                         │
├────────────────────────────────────────────────────────┤
│ Enter 로 셸에서 실행합니다                             │
└────────────────────────────────────────────────────────┘
```

(글자) | 입력줄에 넣는다 | 한글은 여기서 글자다(ADR-0008)

### 파일 목록

cwd 가 뿌리다. sidebar 트리와 같은 기준이라 무엇을 찾는지 화면이 이미 보여준다.

저장소 안이면 `git ls-files --cached --others --exclude-standard` 로 한 번에 받는다.
추적 중인 파일과 아직 추가하지 않은 파일이 함께 오고 `.gitignore` 된 것은 빠진다.
저장소가 아니거나 git 이 없으면 직접 훑고 `.git` 만 건너뛴다. 목록은 이름순이다.

열 때마다 새로 읽는다. 캐시하지 않으므로 바깥에서 만든 파일이 바로 나온다(ADR-0011).

파일을 고르면 새 tab 으로 열린다. 이미 열려 있으면 새로 열지 않고 그 tab 으로 옮긴다.
일반 파일이 아니거나 그 사이에 지워졌으면 열지 않고 아래 줄에 알린다. sidebar 의 `Enter` 와 같다.

열면 sidebar 트리도 그 파일 자리를 펼치고 고른다(ADR-0019).

### 명령 목록

입력 맨 앞에 `>` 를 치면 명령 목록이다. 지우면 파일 목록으로 저절로 돌아온다.

`:` 명령과 별개의 표다. `:` 는 짧은 것이 미덕이지만 이쪽은 목록에서 눈으로 읽는 것이라
이름이 설명적이다. 오른쪽에 영문 설명과 짝이 되는 `:` 명령이 흐리게 붙고, 둘 다 검색 대상이라
`trim` 이나 `:tree` 로도 찾힌다. 붙일 칸이 없으면 오른쪽은 통째로 빠진다.

**지금 성립하는 명령만 뜬다.** 골라 놓고 거절하는 것보다 고를 수 없는 편이 낫다. VS Code 의 `when` 절과 같은 자리다. 거절하는 조건을 그대로 옮겨 적으므로 **목록에 뜬 것을 고르면 거절당하지 않는다.** 열린 파일이 없는 화면에서는 서른하나 중 일곱만 남고, 읽기 전용 파일에서는 고치는 열셋이 빠지며, tab 이 하나뿐이면 tab 을 닫는 둘(「다른 tab 모두 닫기」·「오른쪽 tab 모두 닫기」) 이 빠진다. 이것은 `:` 명령이 반대로 반드시 알리는 것(ADR-0064) 과 어긋나지 않는다. 이름을 대고 친 것은 답을 받아야 하고, 목록에서 고르는 것은 애초에 없으면 될 일이다.

**visual 에서 열면 고른 범위가 명령에 실린다.** 팔레트는 상자라 고른 것이 뒤로 칠해진 채 남아 있고(ADR-0037), 무엇을 고르는 순간 그 범위가 사본으로 명령에 넘어간다(ADR-0111).

**넷은 표에 두 줄로 서 있다.** 「줄 끝 공백 지우기」·「중복 공백 지우기」·「줄 정렬」·「표 맞추기」에 「선택 영역 …」 짝이 있고, **고른 범위가 있으면 「선택 영역 …」쪽만, 없으면 그냥 이름 쪽만 목록에 선다.** 무엇에 걸리는지가 고르기 전에 이름에 있다. 범위를 골라 둔 채 파일 전체에 거는 길은 없다. 그럴 일이면 `esc` 로 물러난 뒤 열면 된다(ADR-0112).

「대문자로 맞추기」·「소문자로 맞추기」는 짝이 없다. 파일 전체로 갈음할 수 없어서 고른 범위가 있을 때만 뜬다.

「줄 끝 공백 지우기」는 활성 buffer 만 건드린다. 지우는 것은 `' '` 와 `'\t'` 뿐이고
유니코드 공백(NBSP 등) 은 그대로 둔다 — 눈에 보이지 않는 글자가 조용히 사라지는 편이 더 나쁘다.
공백뿐인 줄은 빈 줄이 된다. 지울 것이 없으면 아무 흔적도 남기지 않는다.

「중복 공백 지우기」도 활성 buffer 만 건드리고 같은 두 글자만 본다. **줄 앞의 들여쓰기는 손대지 않는다** — 이 편집기가 뜻으로 다루는 공백이라(`.editorconfig`·autoindent) 줄이면 코드가 깨진다. **줄 끝도 손대지 않는다.** 그것은 「줄 끝 공백 지우기」의 몫이고, 둘을 이어 쓰면 둘 다 사라진다.

「줄 정렬」은 오름차순뿐이다. 견주는 것은 byte 순이라 대문자가 소문자보다 앞이고, UTF-8 의 byte 순이 코드포인트 순과 같아서 한글 음절은 가나다 순으로 선다. 사전 순(locale) 을 쓰지 않는 것은 그것이 판마다 다른 답을 내기 때문이다. 같은 줄끼리는 원래 차례를 지킨다. 「선택 영역 줄 정렬」로 고르면 그 줄만 자리를 바꾸고 나머지는 그대로다(ADR-0111, ADR-0112).

「대문자로 맞추기」·「소문자로 맞추기」는 **고른 범위가 있어야 목록에 뜬다.** 파일 전체로 갈음하지 않는 것은 손이 미끄러졌을 때 잃는 것이 너무 커서다. 범위를 줄로 넓히는 위 넷과 달리 고른 칸을 그대로 보므로, `v` 로 단어 가운데를 골랐으면 그 자리만 바뀐다. 커서는 범위의 시작으로 가고, 이것은 visual 의 `U`·`u` 와 같다(ADR-0100).

「오늘 날짜 넣기」·「오늘 날짜와 시각 넣기」는 넣는 서식만 갈린다. 둘 다 **커서 뒤**에 넣고 넣은 마지막 글자 위에 커서를 두므로 normal 의 `a` 와 같은 자리이며, 특수문자 넣기도 같은 손이다. 넣은 것은 한 번의 `u` 로 통째로 돌아온다. insert 에서 팔레트를 열어 골랐어도 치던 자리에 들어가고, 넣은 뒤에는 normal 로 돌아온다 — 팔레트는 어디서 열렸는지 기억하지 않는다(ADR-0011, ADR-0056).

서식은 **RFC3339 를 그대로 따른다.** 날짜와 시각 사이가 `T` 이고 시간대는 편집기가 도는 곳의 오프셋이다(UTC 면 `Z`). 초까지 찍고 소수부는 붙이지 않는다. 「오늘 날짜 넣기」는 그중 날짜 부분(`2026-09-01`) 만이라 뒤에 시각을 이어 붙여도 같은 글이 된다(ADR-0116).

「다른 tab 모두 닫기」는 보고 있는 tab 은 건드리지 않는다. 커서도 편집 내용도 그대로고 tab 만
하나가 된다. tab 이 하나뿐이면 아무것도 닫지 않고 아래 줄에 알린다. 닫으려는 tab 중에
저장하지 않은 변경이 있으면 확인창을 띄우고, 취소하면 팔레트가 아니라 normal 로 돌아간다 —
보고 있지 않은 tab 이라 무엇을 잃는지 화면에 드러나지 않기 때문이다. 닫고 나면 몇 개를
닫았는지 아래 줄에 남는다.

### 매칭

친 글자가 순서대로 들어 있기만 하면 걸린다(fzf 와 같은 부분수열). `icedit` 이
`internal/core/edit.go` 를 찾는다. 맞은 글자는 목록에서 색이 붙는다(256색 214).

점수는 붙어 있는 것, 단어 경계(`/ . - _ 공백`) 에서 시작하는 것, camelCase 경계,
그리고 **파일 이름의 시작**(마지막 `/` 뒤) 을 위로 올린다. 그래서 `edit` 은
`internal/core/edit.go` 를 `internal/core/view-editor-command.go` 보다 먼저 보여준다.
건너뛴 칸은 점수를 깎는다.

대소문자는 smartcase 다. 친 것이 전부 소문자면 가리지 않고, 대문자가 하나라도 있으면 가린다.
가리지 않는 중에도 대소문자까지 맞은 쪽이 조금 위로 온다.

같은 점수면 짧은 것이 위고, 그것도 같으면 목록에 있던 차례다. 아무것도 치지 않았으면
거르지도 정렬하지도 않고 앞에서부터 보여준다.


## 백그라운드 작업

오래 걸리는 일은 편집기를 멈추지 않는다. 지금 있는 작업은 셋이다 — 팔레트의 파일 목록을 모으는
「파일 인덱싱」, 저장소 상태를 읽는 「git 상태」, 트리를 펼칠 때 도는 「디렉터리 읽기」다
(ADR-0027, ADR-0032).

이름이 곧 신원이라 **같은 이름은 한 번에 하나만 돈다**. 이미 돌고 있으면 새로 시작하지 않고
돌고 있는 것에 붙는다 — 팔레트를 빠르게 여닫아도 인덱싱이 겹쳐 돌지 않는다.
「디렉터리 읽기」의 이름에 경로가 들어가는 것이 이 때문이다. 이름이 그냥 「디렉터리 읽기」면
두 디렉터리를 잇따라 펼칠 때 뒤엣것이 시작되지 않는다.

작업은 진행(`한 것/전체`)을 조금씩 알린다. 전체를 아직 모르는 동안에는 지금까지 한 개수만
센다. 끝나면서 무엇을 했는지 한 줄을 남긴다 — 인덱싱의 `151,933 개` 가 그것이다.

### statusBar 진행 표시

도는 작업은 statusBar 위 줄, git 표시 왼쪽에 보인다.

```
NORMAL  internal/core/editor.go     파일 인덱싱 ⣿⣿⣿⣿⣄⣀⣀⣀⣀⣀ 42% (+1)  master(f6cacbd*)
```

목록 맨 앞, 곧 가장 먼저 시작한 것 하나만 찍는다. 끝날 때까지 가리키는 것이 바뀌지 않아야
눈이 따라갈 수 있다. 나머지는 `(+N)` 으로 개수만 알린다.

막대는 열 칸이고 칸 하나가 여섯 단계라 예순 단계다. 점자(`⣀⣄⣆⣇⣧⣷⣿`) 로 그린다 —
블록 문자와 달리 폭이 확실해서 터미널이 두 칸으로 잡아 statusBar 를 밀어내지 않는다(ADR-0020 과
같은 기준이다). 전체를 모르면 막대를 그리지 않고 개수만 찍는다 — 반쯤 찬 막대가 거짓말이 된다.

칸이 모자라면 진행 표시부터 줄인다. 먼저 막대를 떼고, 그래도 모자라면 진행 표시를 통째로
뺀다. git 은 늘 같은 자리에 있어야 눈이 찾는다.

### 작업 목록

`:jobs` 나 팔레트의 「작업 목록」으로 연다. mode 는 `JOBS` 다.

```
작업  도는 중 1 · 끝난 것 2
 ▸ 파일 인덱싱      ⣿⣿⣿⣿⣄⣀⣀⣀⣀⣀  42%   0:03
   git 상태         끝남  master(f6cacbd*)   0:00
   파일 인덱싱      취소됨   0:12
 j/k 이동  x 취소  q 닫기
JOBS  internal/core/editor.go                      master(f6cacbd*)
```

팔레트처럼 박스로 얹지 않고 화면을 통째로 쓴다. 목록이 실시간으로 자라고 줄어들어서 아래
화면이 비치면 무엇이 움직이는 것인지 읽기 어렵다. tabline 과 sidebar 도 그리지 않는다 —
편집기 틀을 쓰면 "파일을 보고 있는 화면" 으로 읽혀서 여기서 치는 키가 편집기 키인 줄 알게 된다.
맨 위 제목줄이 tabline 자리를 대신하고, statusBar 만 남아 mode 와 git·알림이 늘 같은 자리에 있다.
트리가 열려 있었어도 statusBar 는 트리가 없는 것으로 치고 그린다 — 목록이 왼쪽 끝에서
시작하는데 statusBar 만 32 칸 들여쓰면 화면이 반쪽만 바뀐 것처럼 보인다(ADR-0005).

고른 행은 `▸` 가 붙고 그 줄 왼쪽 끝에 커서가 선다. 키 안내는 statusBar 안이 아니라 그 바로 위
줄이다 — 아래 줄은 알림 자리로 비워 두어서, 취소가 실패하거나 작업이 실패했을 때 안내를
밀어내지 않고 나란히 보인다.

**목록 판 열이 이동 키를 같이 쓴다**(작업·알림·커밋 기록·register·되돌아간 자리·방문한 자리·
정의 후보·특수문자·팔레트·트리). `j` `k` 와 `↑` `↓` 가 한 줄, `g` `G` 가 처음과 끝, `home` `end` 가 그 둘과
같은 자리, `pgdown` `pgup` 이 한 화면이다. 한 화면을 세는 자는 편집 영역·트리와 같아서
(높이에서 두 행을 뺀 것) 목록에 두 번째 규칙이 생기지 않는다(ADR-0076).

갈린 자리가 셋이다. 작업 목록에는 `g` `G` 가 아직 없어서 처음·끝으로 가는 키가 `home` `end`
뿐이다. 팔레트와 특수문자는 치는 중이라 `g` `G` 를 둘 수 없다 — 그 글자가 걸러낼 말의 일부다.
트리의 `home` `end` 는 숫자를 보지 않는다(`gg` `G` 는 `20G` 처럼 행 번호로 받는다).

**담는 것이 보이는 것보다 훨씬 많은 판 셋**(여러 파일 검색·방문한 자리·되돌아간 자리) 은
**아랫 테두리 오른쪽에 몇 번째를 보고 있는지를 적는다**(`30/3,548`). 목록 행을 쓰지 않고
숫자가 설명하는 대상 옆에 있다. 열여섯 줄 안에 다 들어가는 판(`GOTO`·register·특수문자) 은
훑을 일이 없어서 넣지 않았다(ADR-0079).

**도는 것이 위, 최근에 끝난 것이 아래다.** 도는 것은 진행 막대와 백분율을, 끝난 것은 상태와
요약(`끝남 <요약>` · `취소됨` · `실패 <이유>`) 을 같은 칸에 보여준다. 오른쪽 끝은 걸린 시간
(`분:초`) 이고, 끝난 작업은 끝날 때까지 걸린 시간에서 멈춘다. 도는 것도 끝난 것도 없으면
`도는 작업이 없습니다` 를 적는다 — 빈 판만 두면 목록을 못 연 것처럼 보인다.

끝난 목록은 **이름당 마지막 결과 하나**다. 개수 상한은 두지 않는다 — 이름은 코드에 있는 종류만큼만
있다. 끝난 순서대로 쌓으면 5 초마다 도는 git 갱신이 목록을 자기 이름으로 뒤덮어서, 조용히
실패한 다른 작업을 찾으라고 남겨둔 자리가 그것으로 다 찬다(ADR-0030).

실패는 목록을 열지 않아도 statusBar 아래 줄에 `<이름> 실패: <이유>` 로 알린다. 취소는 알리지
않는다 — 그만하라고 한 사람이 결과를 이미 안다.

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 다음 / 이전 작업 | 양끝에서 멈춘다. 둘러 가지 않는다
휠 | 목록 오르내리기 | 한 번에 3 행. 팔레트·트리와 같다
x | 고른 작업 취소 | 끝난 작업이면 `이미 끝난 작업입니다` 라고만 알린다
q, esc | 닫고 normal 로 | 도는 작업은 그대로 돈다
ctrl+c | 전체 종료 | 다른 mode 와 같다

한글 입력 상태에서 온 키는 두벌식 자리의 영문 키로 되돌린다(ADR-0008). 이 화면의 키가 전부
글자 키라 되돌리지 않으면 아무것도 먹지 않는다.

`x` 는 작업의 ctx 를 끊는다. 목록에서 바로 빼지는 않는다 — 언제 진짜 끝났는지는 작업이 알고,
채널이 닫히면 「취소됨」으로 끝난 목록에 옮겨간다. 편집기를 끝내면 도는 작업이 전부 같이 정리된다.

작업이 도는 동안에도 목록에 갇히지 않는다. 진행은 어느 mode 에서든 도착해서 statusBar 에
반영되므로, 닫고 편집을 계속하다 다시 열어도 그동안의 진행이 그대로 이어져 있다.

## 커밋 기록

`:graph` 나 팔레트의 「커밋 기록」으로 연다. mode 는 `GRAPH` 다.

```
커밋  196 개
▸ ● ca5e330 - Tue, 1 Sep 2026 11:26:05 +0900 (3 시간 전) (HEAD → master)
  │           feature: 명령줄의 `%` 를 지금 보고 있는 파일로 편다 - BlueMir
  ● 7e30346 - Tue, 1 Sep 2026 10:48:45 +0900 (3 시간 전) (origin/master)
  │           feature: 한 줄 입력 열에 글자 커서를 넣는다 - BlueMir
  ●   80830bf - Mon, 31 Aug 2026 15:09:13 +0900 (23 시간 전)
  │─┐           Merge branch 'release/v1.1' - BlueMir
  │ ● d0a8bd7 - Mon, 31 Aug 2026 14:39:12 +0900 (24 시간 전) (tag: v1.1.0, origin/release/v1.1)
  │ │           docs: License 를 한 줄로 줄인다 - BlueMir
 j/k 이동  enter 상세  q 닫기
GRAPH  internal/core/git.go                                     master(f6cacbd*)
```

`:jobs`·`:messages` 처럼 화면을 통째로 쓴다. tabline 과 sidebar 를 그리지 않고 맨 위 제목줄이 tabline 자리를 대신하며 statusBar 만 남는다. 같은 까닭이다(ADR-0115).

**볼 파일이 없어도 열린다.** 담는 것이 저장소에서 오지 지금 buffer 에서 오지 않아서, 빈 화면이야말로 이것이 필요한 자리다. 저장소가 아니면 열지 않고 아래 줄에 `git 저장소가 아닙니다` 라고 알린다.

**커밋 하나가 두 줄이다.** 윗줄이 짧은 해시·날짜·얼마나 전인지·ref 이름이고 아랫줄이 제목과 글쓴이다. 아랫줄의 들여쓰기는 짧은 해시와 ` - ` 를 합친 만큼이라 제목이 날짜 아래에 선다. `git log --graph --abbrev-commit --decorate --all --format='%h - %aD (%ar)%d%n          %s - %an'` 과 같은 그림이다.

**고른 커밋은 두 줄 다 반전하고 윗줄에 `▸` 가 붙는다.** 한 항목이 두 줄이라 한 줄만 칠하면 어디까지가 한 커밋인지가 갈리지 않는다.

**색은 해시가 파랑(ANSI 12), 날짜가 청록(14), 얼마나 전인지가 초록(10), ref 이름이 노랑(11) 이다.** 제목은 기본색이고 글쓴이는 흐린 회색(256색 244) 이다. 그래프의 선과 점에는 색이 없다 — 갈래를 가르는 것은 자리이지 색이 아니다. 고른 줄에도 색을 얹지 않는다. 반전 하나로 이미 다 말한다.

### 담는 범위와 차례

**모든 ref 에서 훑는다**(`git log --all`). local branch·tag·remote branch 의 끝이 모두 씨앗이다. 주석 tag 는 벗겨서 그 안의 커밋을 쓴다.

차례는 **커밋한 때 내림차순**이다. 화면에 보이는 날짜는 쓴 때(`%aD`) 이므로, rebase 로 옮겨 붙인 커밋에서는 날짜가 내림차순이 아닐 수 있다. git 도 같다.

ref 이름은 `HEAD → master`·`tag: v1.1.0`·`origin/master` 처럼 붙고 차례는 HEAD, local branch, tag, remote branch 다. HEAD 가 branch 를 가리키면 그 이름에 얹히고, 떨어져 있으면(detached) 그 해시에 `HEAD` 만 붙는다. `origin/HEAD` 처럼 상징 참조인 ref 는 서지 않는다.

### 그래프

열 하나가 두 칸이다. 커밋이 선 열에 점(`●`), 지나가는 열에 세로선(`│`) 이 온다.

**갈래가 갈리면 아랫줄에 모서리가 선다.** merge 커밋이 열을 열면 `│─┐` 처럼 점의 열에서 뻗어 나온다.

**갈래가 모이면 윗줄에 모서리가 선다.** 여러 열이 한 커밋을 기다리고 있었으면 `●─┘` 처럼 점까지 이어 붙는다. 사이에 살아 있는 열이 있으면 그 자리는 세로선이 이겨서 가로선이 한 칸 끊긴다.

**그래프 칸의 폭은 커밋마다 잰다.** 갈래가 없는 구간은 두 칸이고 merge 자리에서만 네 칸이 된다. 화면 전체로 한 번 재면 저 아래 갈래 하나 때문에 위쪽이 통째로 밀리고 훑을 때마다 본문이 좌우로 흔들린다. git 의 `--graph` 도 줄마다 따로 잰다.

Ambiguous 폭 글자를 못 쓰는 터미널에서는 `* | - +` 로 물러선다(ADR-0028). 점도 같이 물러선다 — 이 화면은 열 맞춤이 전부라 선과 점이 같은 판단을 타야 한다.

### 조금씩 읽기

**한 번에 1,000 개를 읽는다.** 고른 자리가 담긴 것의 끝에서 100 개 안으로 들어오면 다음 조각을 백그라운드에서 읽는다. 진행은 statusBar 에 보이고 `:jobs` 에도 「커밋 읽기」로 선다.

제목줄은 지금까지 읽은 수다. 다 읽기 전에는 `커밋  1,000 개 · 더 읽는 중` 이고 다 읽으면 `커밋  1,284 개` 다.

`G` 는 **지금 담긴 것의 끝**이다. 저장소의 첫 커밋이 어디인지는 다 읽어야 알 수 있고 그것을 기다리게 하지 않는다. 거기서 다음 조각이 이어 붙는다.

**열 때마다 처음부터 읽는다.** 팔레트 파일 목록과 같다 — 바깥에서 `commit`·`fetch` 를 하고 돌아왔을 때 묵은 기록을 보이지 않는다. 그래서 닫았다 다시 열면 훑어 내려간 자리를 잃는다.

### key mapping

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 다음 / 이전 커밋 | 양끝에서 멈춘다. 둘러 가지 않는다
g home / G end | 처음 / 끝 | 끝은 지금 담긴 것의 끝이다
pgdown pgup | 한 화면 | 커밋 수로 센다. 한 커밋이 두 줄이라 화면 행의 절반이다
휠 | 목록 오르내리기 | 한 번에 3 커밋. 다른 목록과 같다
enter | 고른 커밋의 상세 | 아래 「커밋 상세」
q, esc | 닫고 normal 로 | 읽던 조각은 그대로 돈다
ctrl+c | 전체 종료 | 다른 mode 와 같다

한글 입력 상태에서 온 키는 두벌식 자리의 영문 키로 되돌린다(ADR-0008). 이 화면의 키가 전부 글자 키라 되돌리지 않으면 아무것도 먹지 않는다.

`d`(diff) 는 아직 없다. 그릴 화면이 없어서 키를 두지 않았고 안내 줄에도 적지 않는다 — 먹지 않는 키를 권하지 않는다(`docs/tasks.md`).

### 커밋 상세

목록에서 `enter` 로 연다. mode 는 `COMMIT` 다. 목록 위를 통째로 덮는다.

```
커밋  ca5e330  feature: 명령줄의 `%` 를 지금 보고 있는 파일로 편다
 commit ca5e330d2ec65dc1edebfb387e478c26f87498a5 (HEAD → master)
 Author: BlueMir <bluemir@bluemir.me>
 Date:   Tue, 1 Sep 2026 11:26:05 +0900

     feature: 명령줄의 `%` 를 지금 보고 있는 파일로 편다

     `:!cat %` 가 지금 보고 있는 파일을 연다. (ADR-0114)

 M  internal/core/shell.go
 A  docs/adr/ADR-0114-percent-is-the-current-file.md
 j/k 스크롤  q 목록으로
COMMIT  ca5e330                                                 master(f6cacbd*)
```

`git show --format=fuller` 와 같은 차례다. `Merge:` 는 부모가 둘 이상일 때만, `Commit:`·`CommitDate:` 는 커밋한 사람이 쓴 사람과 다를 때만 선다.

**파일 목록은 `git log --name-status` 자리다.** `A` 새로 만듦, `M` 고침, `D` 지움, `R` 옮김이고 옮긴 것은 `R  old.go → new.go` 처럼 어디서 왔는지도 적는다. 색은 왼쪽 gutter 의 git 마커와 같다 — 넣은 것이 초록, 고친 것이 파랑, 지운 것이 빨강이다(ADR-0094). 줄 수(`+12 -3`) 는 적지 않는다.

**merge 는 첫 부모와 견준다.** `git log --name-status` 는 merge 에서 아무것도 보여주지 않는데, 그것보다는 「이 merge 로 무엇이 들어왔나」가 쓸모 있다.

읽어 오기 전에는 `읽는 중입니다` 한 줄이다.

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 한 줄 스크롤 | 양끝에서 멈춘다
g home / G end | 처음 / 끝 |
pgdown pgup | 한 화면 |
휠 | 오르내리기 | 한 번에 3 줄
q, esc | 목록으로 | 고른 자리와 스크롤이 그대로다
ctrl+c | 전체 종료 | 다른 mode 와 같다


## 알림과 알림 목록

statusBar 아래 줄에 뜨는 한 줄이 알림이다. 명령 결과(`저장함: …`), 거절(`읽기 전용 파일입니다`),
실패(`git 상태 실패: …`), 진행 중(`정의를 찾는 중입니다`) 이 모두 그 자리에 온다.
**다음 키를 누르면 사라진다.** 명령줄과 검색은 그 줄을 자기 입력에 쓰므로 알림을 그리지 않는다.

사라져도 **기록에는 남는다**(ADR-0053). 사람이 키를 누르지 않았는데 도착하는 알림이 넷 있어서다 —
바깥 파일이 바뀐 것, 백그라운드 작업 실패, gopls 기동 실패다. 이것들은 도착한 직후 아무 키나
누르면 사라져서, 기록이 없으면 일이 일어났다는 사실 자체를 놓친다.

알림은 두 갈래다. **`error` 값에서 온 것이 실패**이고 나머지가 그 밖이다. 거절(`알 수 없는 명령`)은
실패가 아니다 — 선은 「사람이 거절당했는가」가 아니라 「코드가 `error` 를 만들 만큼 예상 밖이었는가」다.

### 여러 파일 검색

`:grep <패턴>`·`:grep`·팔레트의 「프로젝트 검색」 셋으로 들어간다. mode 는 `GREP` 다.

**패턴은 박스에서 받는다.** 팔레트의 「프로젝트 검색」과 인자 없는 `:grep` 이 같은 자리로 온다 —
팔레트가 서던 자리에 같은 폭이다. 박스를 보며 골랐는데 입력이 화면 맨 아래로 떨어지면 방금
무엇을 골랐는지가 사라진다.

```
 ┌ 프로젝트 검색 ─────────────────────┐
 │ func New                           │
 └────────────────────────────────────┘
```

넘치면 **왼쪽부터 접는다** — 치고 있는 것은 뒤쪽이라 오른쪽부터 자르면 방금 친 글자가 사라진다.

**미리보기가 없다.** `/` 는 치는 동안 첫 매칭으로 화면이 따라가는데(incsearch) 여기서
그러면 글자마다 저장소를 훑는 일이 된다. 지난 패턴을 채워 주지 않는다 — 대개 다른 것을
찾으려고 여는 자리라 채워 두면 늘 먼저 지우게 된다.

패턴 문법은 `/` 와 같다 — Go 의 정규식(RE2) 이고 끝의 `/i` 는 대소문자를 무시한다.
**`:grep` 뒤는 뜯지 않고 통째로 받는다.** 빈 칸도 `\` 도 따옴표도 전부 패턴의 글자다 —
`:grep func\s+New` 가 친 그대로 간다. 뒤가 공백뿐이면 패턴을 안 댄 것으로 보고 물어본다.

훑는 것은 팔레트가 고르는 파일 목록과 같다 — 저장소면 git 에게 통으로 물어서 `.gitignore` 가
따라오고, 저장소가 아니면 직접 훑으며 `.git` 만 건너뛴다. **이진 파일은 건너뛴다**(앞부분에
NUL 이 있으면 이진으로 본다).

**열려 있고 고치던 파일은 디스크가 아니라 그 buffer 의 글을 훑는다.** 사람이 화면에서 보고
있는 글을 찾아야 방금 친 이름이 바로 걸리고 지운 이름이 결과에 안 나온다. 결과는 검색을
**시작한 순간의 글**이다.

검색은 백그라운드 작업이라 판이 곧바로 열리고 적중이 도착하는 대로 목록이 자란다.
`:jobs` 에서 「프로젝트 검색」 이름 줄 아래에 패턴이 자식 줄로 보이고 `x` 로 취소한다.

**둘러보고 확정하는 하단 drawer 다.** `GOTO`·되돌아간 자리·방문한 자리 판과 같은 손이다 —
`j`/`k` 가 커서를 실제로 그 자리로 옮겨 보여주고 `enter` 가 확정, `q`·`esc` 는 판을 열기 전
자리로 되돌리며 둘러보다 연 tab 을 닫는다. **여는 것만으로는 옮기지 않는다.**

```
  12  1
  13  0 func NewSet[T comparable]() Set[T] {     ← 커서가 둘러보러 와 있다
┌──────────────────────────────────────────────────────────────┐
│   docs/spec.md:1722               …  func NewHub(ctx contex   │
│   …ernal/pubsub/broadcaster.go:12 func NewBroadcaster[T any]  │
│ ▸ internal/datastruct/set.go:13   func NewSet[T comparable]   │
│   internal/pubsub/hub.go:40       func NewHub(ctx context.C   │
└──────────────────────────────────────────────────────────────┘
GREP  internal/core/editor.go                      master(020598b*)
검색 "func New" 9/30  j/k 둘러보기  enter 확정  / 거르기  esc 취소
```

**보이는 것은 열여섯 줄, 담는 것은 최대 5,000 곳이다.** 판이 화면을 다 먹으면 둘러보는 자리가
안 보이는데 검색 결과는 짧으면 값이 없다 — 방문 기록과 같은 생김새다.

그래서 **아랫 테두리 오른쪽이 몇 번째를 보고 있는지를 든다**(`30/3,548`). 목록 행을 쓰지 않고
숫자가 설명하는 대상 옆에 있다. 아래 줄은 무엇을 찾았는지와 키만 적는다. 거른 뒤에는 거른
수가 기준이다.

**왼쪽이 `경로:줄`, 오른쪽이 그 줄의 내용이다.** 둘러보더라도 어디를 볼지 **고르는 것은
목록에서** 하고, 그 판단에 `경로:줄` 만으로는 모자란다. 경로는 왼쪽부터 접고(`…`) 내용은
오른쪽부터 접는다 — 경로에서 값을 지닌 것은 뒤쪽이고 내용에서는 앞쪽이다. **매칭이 칸 밖으로
밀리면 내용의 앞쪽을 접어 매칭을 칸 안으로 끌어온다.** 들여쓰기는 떼고 보인다.

**줄 가운데 tab 은 빈 칸으로 펴서 그린다.** 펴지 않으면 터미널이 그것을 버리는데 칸을 채우는 자는 폭 있는 것으로 세어서, 그 행만 짧아지고 오른쪽 테두리가 들쭉날쭉해진다. 펴는 폭은 파일의 `tab_width` 가 아니라 기본값이다 — 앞의 들여쓰기를 뗀 순간 tab stop 의 원점이 파일과 어긋나서, 그 파일의 폭을 가져와도 파일에서 보이던 자리가 되지 않는다(ADR-0098).

키 | 하는 일
--- | ---
j k, ↑ ↓ | 둘러본다. **커서가 실제로 그 자리로 간다** — 닫혀 있던 파일은 tab 으로 열린다
g G, home end | 처음 / 끝
pgdown pgup | 한 화면
/ | 목록을 좁힌다. 아래 참고
enter | 확정. 판을 닫고 그 자리에 남는다
q esc | 취소. 열기 전 자리로 되돌아가고 둘러보다 연 tab 을 닫는다

`enter` 로 확정하면 그 패턴이 **마지막 검색으로 굳는다** — 간 자리에서 `n`·`N` 이 이어 짚는다.
떠난 자리는 **판을 열기 전** 자리라 `ctrl+o` 가 거기로 데려간다.

`/` 는 **담은 적중을 거른다.** 저장소를 다시 훑지 않으므로 글자마다 곧바로 좁아진다. 거르는
자는 `경로 + 줄 내용` 에 그 글자가 들었는지이고 대소문자를 보지 않는다. `enter` 는 좁힌 채로
목록에 돌아가고 `esc` 는 거르기를 물린다(판을 닫는 것이 아니다). 거르는 동안 `j` 는 글자이고
**미리보기를 태우지 않는다** — 글자 하나에 파일이 하나씩 열린다.

**상한이 있다.** 적중 5,000 곳에서 그만두고 아래 줄에 「상한」으로 적는다 — 조용히 자르면
「이게 전부」로 읽힌다. 파일 8MB·한 줄 1MB 를 넘으면 건너뛴다. 한 줄에 여러 번 걸려도
목록에는 한 줄만 온다 — 그 줄로 뛴 뒤 `n` 이 나머지를 짚는다.

**열린 파일이 없어도 띄운다.** 다른 판들은 거기서 거절하는데(register 판·정의 후보 판은 무엇에
붙일지·무엇을 물었는지가 지금 buffer 에서 온다) 검색은 담은 것이 저장소 전체에서 왔고, 여기서
고르는 일이 곧 「어느 파일을 열까」다. 빈 화면에서 `:grep` 으로 파일을 찾아 열 수 있다.

### 여러 파일 치환

`:replace/찾을 것/바꿀 글/g` 로 부르거나, 검색 판에서 `r` 을 눌러 들어간다. 문은 둘이고 끝나는 자리는 같은 판이다(ADR-0097).

**찾기만 하고 판을 연다.** 곧바로 바꾸지 않는다. 되돌리기가 약한 자리라(아래) 무엇이 바뀔지 보기 전에 저장소가 바뀌면 안 된다. 판은 이미 둘러보고 확정하는 손을 들고 있어서 미리보기가 따로 없다.

문법은 `:s` 와 같다. 구분자는 아무 글자나 되고 `g`·`c` flag 도 같은 뜻이다. 뜯는 자리가 한 파일 치환과 같아서 규칙이 갈릴 자리가 없다.

찾고 나면 아래 줄이 묻는다.

```
치환 "alpha"  파일 12 개 87 줄을 바꿉니다  a 전부  y 하나씩  q 그만
```

| 키 | 하는 일 |
|---|---|
| `a` | 목록에 있는 것을 한 번에 바꾼다 |
| `y` | 하나씩 물어본다. 그 뒤로는 `y` 바꾸기 · `n` 넘기기 · `a` 남은 것 전부 · `q` 그만 |
| `q`·`esc` | 그만둔다. 하나씩 훑다 그만두면 그때까지 답한 것은 남는다 |

`c` flag 를 대면 묻지 않고 곧바로 하나씩 간다(`:replace/a/b/gc`). `:s///c` 가 이미 쓰는 글자다.

**거른 목록이 곧 바꿀 목록이다.** `/` 로 좁혀 두었으면 좁힌 것만 바뀐다. 아래 줄이 세어 보여주는 수가 그것이다.

**바꾸는 단위는 줄이다.** 목록이 줄마다 한 줄이라(위) 물어보는 것도 줄 하나씩이고, `g` 가 있으면 그 줄의 찾은 자리가 다 바뀐다. 판에서 `r` 로 들어오면 `g` 가 켜진 채로 간다.

**담아 둔 자리를 믿지 않는다.** 찾은 순간과 바꾸는 순간 사이에 파일이 움직이므로, 적중은 「어느 파일 어느 줄인가」만 정하고 자리는 바꿀 때 그 줄에서 다시 맞춘다. 다시 맞춰서 안 걸리는 줄은 건드리지 않고 세어서 알린다.

**열려 있는 tab 은 buffer 를 고쳐 저장하고, 아닌 파일은 그 자리에서 열어 쓴다.** 치환 한 번에 tab 이 스무 개씩 열리지 않는다. 읽기 전용 파일은 건너뛰고 까닭을 남긴다. 저장 hook(포매터) 은 걸지 않는다 — 치환 하나에 남의 파일이 통째로 다시 포맷되면 그 diff 가 무엇 때문인지 알 수 없다.

**되돌리기는 갈린다.** 열려 있는 tab 은 `u` 가 살고, 열려 있지 않은 파일은 git 이 안전망이다. 그래서 무엇을 바꿨는지 알림에 적고 `:messages` 에 남긴다.

### 알림 목록

`:messages`(`:mes`) 나 팔레트의 「알림 목록」으로 연다. mode 는 `MESSAGES` 다.

```
알림  3 개 · 실패 1
   13:22:28   알 수 없는 명령: qqq
   13:22:29   저장함: internal/core/core.go
 ▸ 13:22:58 ! is a directory
 j/k 이동  g/G 처음·끝  q 닫기
MESSAGES  internal/core/core.go                          master(aa4bf78*)
```

화면 문법은 작업 목록과 같다 — 화면을 통째로 쓰고, 맨 위가 제목 띠, 키 안내가 statusBar 바로
위 줄, statusBar 는 트리가 없는 것으로 치고 그린다.

**오래된 것이 위, 최근이 아래다.** 작업 목록과 반대인데, 알림은 뒤에만 붙어야 이미 있는 줄의
자리가 밀리지 않기 때문이다 — 목록을 보는 동안 새 알림이 도착해도 고른 줄이 다른 알림으로
바뀌지 않는다. 열 때는 맨 아래(가장 최근) 를 고른 채로 연다. 맨 아래를 보고 있는 동안 새 알림이
오면 따라 내려가고, 위쪽을 보고 있으면 그 자리에 그대로 있는다.

시각은 `시:분:초` 로 늘 여덟 칸이다. 날짜는 찍지 않는다. 실패한 줄에는 `!` 가 붙고 색도 달라진다 —
색만으로 가르지 않는 것은 화면을 글자로 떠서 보는 길이 있어서다. 문구가 화면보다 길면
**오른쪽을 접는다**(`…`). 정의 후보 목록이 경로를 왼쪽부터 접는 것과 반대인데, 알림은 앞머리가
무엇이 일어났는지이기 때문이다.

기록에 상한이 없고 같은 문구를 접지도 않는다. 되풀이된 횟수가 정보다. 편집기를 끄면 사라진다.

목록을 여는 것 말고 알림을 지우거나 고치는 키는 없다.

키 | 기능 | 기타
---|------|-----
j ↓ / k ↑ | 다음 / 이전 알림 | 양끝에서 멈춘다. 둘러 가지 않는다
g / G | 처음 / 끝으로 | 목록이 길어지는 유일한 화면이라 여기만 있다
휠 | 목록 오르내리기 | 한 번에 3 행. 다른 목록과 같다
q, esc | 닫고 normal 로 | 기록은 그대로 남는다
ctrl+c | 전체 종료 | 다른 mode 와 같다

한글 입력 상태에서 온 키는 두벌식 자리의 영문 키로 되돌린다(ADR-0008). 작업 목록과 같은 이유다.

작업 목록과 하는 일이 다르다. `:jobs` 는 **무엇이 돌고 있나**를 보고 취소하는 화면이고,
여기는 **무슨 말을 들었나**를 읽는 화면이다. 작업의 실패는 그 자체가 알림이라 이 목록에도
들어오지만 성공은 들어오지 않는다 — 5 초마다 도는 git 갱신이 목록을 채우기 때문이다.
